Validation recording convention for this wave: a `## PO Validation (YYYY-MM-DD) — single path` section inserted before `## Dev Agent Record`; Change Log row `Validated GO (n/10) — Status: Draft → Ready` with a **patch** version bump; report JSON at `.ai/STUDIO-OBS-0NN-po-validation-{round}.json` following the OBS-007/009 report shape (verdict, tenPointChecklist, taskChecks 1–10, acceptanceCriteriaAssessment, antiHallucinationFindings with verified path:line anchors, sourceInventory with sha256). Rounds: `r2` = 2026-10-09 dual-path drafts (superseded), `sp` = 2026-10-10 single-path drafts. Historical reports are never modified; superseded PO sections stay in the story headed "SUPERSEDED … historical".

**Why:** the lead wants conditions visible in the story, not only in `.ai/`; ADR-SC-005 is the canonical placement map (design R3 §10 differs on the `/api/v1/studio` route move — the ADR wins); stories are re-cut in place with Status back to Draft and prior GO kept as history.

**Architect-assigned deferrals into a Ready story (2026-10-13, OBS-009 v0.3.2/0.3.4):** record each as a bold "AC-N addition/obligation (inherited from …; ruling file + id)" block under the target AC with lettered sub-items, plus a matching T-task sub-checkbox and a patch Change Log row by @po (Pax). Status stays Ready and the existing AC text is not reworded. If the deferral conflicts with the story's "Out of scope" line (e.g. the R8.2 alert vs the GA §4.G alerts line), add a narrow exception there rather than silently contradicting it. Rulings that offer options ("(a) or (b), nothing pre-decided") are recorded as probe-first, then ruling, and @po does not pick an option.

Example: R10-rev2-2 run-3 INTERNAL_ERROR → OBS-009 AC-12 a–e. Something the lead calls a "pointer only, ownership pending the gate" goes in Dev Notes, not under an AC. Example: the 012A Chromium startup hang. When the lead does not ask for a `po-placements-*.json`, @po does not write one.
