Backend `./gradlew test --tests 'com.citi.put.checks.studio.*'` does NOT fit a 10-minute bound on this host: at 14 min it had passed 1350 tests across 141 classes and was still running (killed, 0 failures seen). The guided-only package `--tests 'com.citi.put.checks.studio.guided.*' --offline` DOES fit: 8m19s standalone, 26 classes / 482 tests / 1 expected skip (GuidedProviderEvaluationTest live-provider skip); the three real-worker ITs dominate (BridgeIntegrationTest 126 s, PlanningIntegrationTest 94 s, PublicationReplayIT 54 s). `tools/corun.sh --skip-build` (StudioCoRunIT, 11 legs, real API + real runner + real Chromium) finished in ~1 min on the OLD tree and was the best single integration check then. STALE as of 2026-10-16: StudioCoRunIT and its 6 support classes under `backend/src/test/.../corun/` are deleted in the working tree (tracked at HEAD) while `tools/corun.sh:60` still points at them, so do not plan on it without checking `git status` first. Runner fixtures tier (Chromium) ~4 min full; the 7 guided/observed fixture files alone ~73 s (152 tests); runner default tier ~5 s (the 13 guided/observed unit files alone ~2.5 s, 318 tests, use `--coverage.enabled=false` for subsets or the coverage thresholds fail the run); frontend full vitest ~1 min; frontend tsc ~6 s. `node tools/check-studio-observed-contracts.cjs` < 5 s.

**Why:** the review brief capped each run at ~10 min; the backend Studio package grew past that after the OBS-001..006 wave (guided/* tests). Running Gradle concurrently with frontend vitest pushed 1-min load to 23 — the repo's own rule (closure plan §6) is one Gradle at a time, load < 5, JUnit-XML counts not exit codes. Running the small runner unit subset concurrently with Gradle only moved load from 3.5 to 4.3, which is acceptable.

**How to apply:** for bounded QA passes, run corun.sh + runner tiers + frontend suite; for the backend, pick named classes (`--tests '*RecoveryIT' ...`) or the guided package alone, or run the full package in the background with no bound and aggregate `backend/build/test-results/test/*.xml` afterwards (stale XMLs from earlier runs persist — compare mtimes against the run start). Gradle needs JDK 21 via `backend/gradle.properties` `org.gradle.java.home`; the system default is JDK 11. Vitest 1.6 in frontend/: do not pass `--poolOptions.threads.maxThreads` alone (tinypool min/max conflict → "no tests", exit 1). zsh: quote `--include='*.java'` globs. macOS has no `timeout`; use `perl -e 'alarm N; exec @ARGV' cmd...` to bound a run.
