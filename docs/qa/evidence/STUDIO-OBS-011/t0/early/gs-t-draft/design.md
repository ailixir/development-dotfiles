# 11-GS-T off-tree migration design

Dex, 2026-10-18. This design is recorded before writing any draft Java source. Real backend source remains frozen while B1/B7 run. Draft files live only below this folder's `repo/backend/`; no compilation or runtime success is claimed.

## Required final behavior

All eighty existing source test methods remain under their original names, with their original assertions and native failure/cleanup/canary oracles. A positive admission uses the proposal and idempotency key issued by the real `GuidedTranslationService` validator/planner chain. Hand-crafted proposals remain only where they are negative probes. Production access initializes the classifier-produced source manifest within `start`; tests never insert authority rows or call store acceptPlan/reserveObligation/attachAdmission.

Primary precedent: `GuidedBridgePlannedIT` production access and source fixture (`:574-624`, `:930-945`), real translation service (`:694`), planning (`:1851-1898`) and crash-window reservation (`:2025-2105`). Its source-plan and next-action provider are controlled test boundaries, with the server constructing every bridge authority field. The remainder in `GuidedBridgeIntegrationTest` is not the positive-admission precedent.

## Composition

1. Save canonical v2 authoring in ordinary `ui_tests`, with stable UUID test/step identities and numeric source/configuration revisions. Keep the pre-existing raw source/variable documents that native source-change observers compare. The new authoring context declares PASS as an opaque secret reference; it never embeds a resolved value.
2. Build a real `GuidedProductionSessionAccess` from the production source snapshot repository, classifier, input resolver, translation store and step verifier. Existing mutable current/ownership/recoverability controls and the transport observer narrow a Mockito spy's access checks. They never manufacture a snapshot, manifest, plan or obligation. The SessionIT step-verification seam preserves its original explicit service-only verification subject; real planner authority is unchanged.
3. Install translation and clarification context in every service composition, including local/spy repositories and the isolated controller child. Remove each historical direct translation-state initialization in TransportFaultIT. The child consumes existing authority and does not start or plan a session.
4. Supply deterministic SOURCE_PLAN and NEXT_ACTION replies through the in-process `GuidedLlmGatewayClient` interface. This makes no real provider/model/network call. Real `GuidedProposalValidator`, `GuidedDependencyPlanner`, `GuidedPromptAssembler` and `GuidedTranslationService` still validate/allocate/materialize/guard/reserve.
5. Bootstrap planning before the first observation used by admission. The controlled worker sends the normal initialBlank bootstrap callback and a matching metadata acknowledgement. TransportFaultIT retains authenticated relay/callback transport; service-only SessionIT/LifecycleReasonIT use their existing trusted worker seam. No action, value read, browser or post is invented.
6. Reserve by interrupting `GuidedDispatchService.prepareAndAdmit` only after the planner commits the obligation association. Read that association and pass its exact key/proposal to the actual admission seam. Do not return a fabricated association. Reuse the association for duplicate/rollback probes. Reserve outside a transaction: `translation.plan` and `advance` deliberately reject active transactions. The rollback test must capture its lawful association before entering its transaction and then roll back admission only.

## Per-file work

- SessionIT: production start/source fixture, narrowed access controls, lawful planner preparation for admission cases, preserved negative probes/idempotency and explicit pre-reservation for the rollback case; local service compositions get the same translation wiring. Keep the recordEvidence-only case for GS-M(b)'s R-21 decision.
- LifecycleReasonIT: same lawful access/start/plan path; preserve mutable-clock expiry/fence checks, audit spy, lifecycle reason oracle and five original methods.
- TransportFaultIT: production access/source authoring in every native/private-routed composition; remove the five direct state initialization blocks; replace the four positive prepareAndAdmit requests with planner-issued associations. Preserve process/route resources, owned cleanup, zeroization, canary scans and all Mode invocations. Add initialBlank only at a context delivery before any observed document; preserve later metadata context responses.

## Review and proof boundaries

The draft is complete only when all three files and the unified patch exist, all original method names/assertion expressions remain, all positive admission seams have a lawful association, and forbidden authority writes are absent. Static checks report this separately from compile and runtime proof. Any semantics that cannot be established by source inspection are recorded by exact method/helper name and must be reviewed before application. No test is deleted or weakened to resolve uncertainty.

Root applies only after B1/B7, explicit tree open and ownership grant, in a staged unit under the existing Gradle lock. The first runtime class set remains `obs011-gst-01` (fresh label): the three edited classes plus unchanged EvidencePendingAppendIT and CommittedRefreshStateTest. All expanded invocation names reconcile against B1. Main code stays unchanged for the GS-T gate.

## Architect rulings received before draft completion

- **GS-T-S1 (Aria, same-session message):** genuine production start plus `translation.plan` must reach READY with initialBlank, version-2 metadata acknowledgement, zero actions and actions counter zero. Under the session lock, assert those conditions and change only document.state PROPOSING→OBSERVING. This removes admission permission. The original owning-worker observation then restores PROPOSING and creates every app evidence/hash/generation field. Never write progress/evidence/plan/obligation/manifest. Assert zero actions/counter after the first observation too. This applies to service-only SessionIT/LifecycleReasonIT and was explicitly extended to the four controlled-relay TransportFault paths, whose genuine authenticated bootstrap callback/ACK and original app callbacks remain.
- **GS-T-S2:** `concurrentConflictingStartsHaveOneWinner` changes its differing request field from environmentId to applicationId. The ordinary saved source remains in fixture. Install a second legitimate governed application policy. Independently start orders and other under separate control keys before the original shared-key race; retain its name, race and exactly-one-IDEMPOTENCY_CONFLICT assertion. No resolve spy rewrites source/environment during authorization.
- **Spy restriction:** only checkCurrent/checkSourceCurrent/checkUser/recoverableContext controls narrow or observe real methods. Real resolve/initialize/sources remain. The positive completeness verdict remains the real `GuidedStepVerifier`; the proposed old return-true seam was removed before final generation.
- **Budget restriction:** no unrelated planner call in low-budget cases that never positively admit. Source production initialization and original assignment/materialization suffice. SessionIT's thirteen positive-admission subjects and LifecycleReasonIT's one subject take the planner path; no counter refund, enlarged limit or relaxed assertion is introduced.
- **Proof barrier:** root applies/runs GS-T against recorded S_011 main before GS-M(a) may change GuidedSessionService. Parallel work stays off-tree until that gate.

Implementation detail: these JDBC-only suites have no JPA application context. A test-side StudioRepository adapter reads the actual visible `ui_tests` row with FOR UPDATE and maps it to UITest for the real GuidedSourceSnapshotRepository. It never supplies a manufactured snapshot or manifest. Transport source rows gain ordinary canonical v2 authoring and explicit `secretId: PASS`; source/config revision strings become the real numeric revision `1`. Its isolated controller child continues to consume existing parent-issued authority, using the real input resolver over the genuinely initialized manifest and the original native source/current/identity checks.
