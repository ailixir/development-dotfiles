## Proven constructor defect: GST-SOURCE-DOUBLE-INSTALL

Archived Transport `translationTeardownService` at 4455 calls `teardownService` (4569), which calls the common six-argument `service` constructor (405). That constructor now installs translation at 419. The outer helper's second installation at 4457 therefore violates main `GuidedSessionService.installTranslation` (155): `require(translation == null, "RUNTIME_INCOMPATIBLE", 409)`. This is a deterministic source contradiction independent of any native failure log. The successor removes only that second four-line statement. The original helper, return value, first real translation installation, stop-sender installation and all eight helper callers remain. The old S011 outer installation was valid before the accepted GS-T port added installation in the common constructor.

## Ownership wait: GST-SOURCE-OWNERSHIP-OPEN

`SourceStopOwner` and `TrackingTransactionTemplate` are byte-identical class bodies to S011, with exact hashes in ownership-preservation.json. `observeCompletion` waits completed. `drainUninterruptibly` waits settled, preserves interruption and rejects guard failure; completed remains pending for rejected/unstarted work. The original sender/confirmation source increments and settles around the actual original stop/transaction. None of those oracles changes.

Expected ownership is registered before subject operations or cleanup cancellation at several existing sites (961, 1034, 1494, 1914, 2272, 2561, 2788, 2931 in the archived formatted source). `closeClaimFixture` registers expectation for a nonterminal document. `runGuidedControllerCut` cleanup uses materialization/assignment row existence to decide expectation before cancel/lostAcknowledgment. A setup/authorization/transaction exception may precede the original send. Row existence does not establish commit, a formed teardown target, or an original call. Main stop creates a PENDING request only for a formed target and schedules the send after committed completion; later executor entry is separate.

The root-provided bounded thread projection places the live worker in drainUninterruptibly -> attemptGuidedCutCleanup -> runGuidedControllerCut -> actualConsumedGuidedControllerJvmCrashBeforeResolutionReconcilesWithoutReadOrPost. This identifies a wait location only. It does not identify the preceding exception, commit state, sender entry or whether future owned work remains possible. No raw dump or runtime body was read here.

A safe lifecycle correction needs the closed primary setup failure and source-bound proof of the actual stop operation boundary: either real started/scheduled owned work that must finish, or authoritative proof that registration happened for an operation that never committed/scheduled and cannot start later. Without it, disarming expectation after a thrown call could release resources ahead of committed asynchronous work. Moving expect into send could make the preregistration guard tautological and miss pending not-yet-entered work. Counting latches, skipping settled, adding timeouts or treating a failed cancel as completed would weaken the original oracle. No such change is drafted.

The remaining lifecycle limitation is explicit and blocks treating this candidate as a complete stall remedy. Root must close actual unit02 and its restoration, preserve its native incomplete/negative disposition, and route the exact failure/operation evidence for independent review. This source package supplies no permission to inspect private payloads or run again.
