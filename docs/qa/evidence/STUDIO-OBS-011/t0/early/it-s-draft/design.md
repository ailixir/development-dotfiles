# IT-S preparation design

Scope is all six files in 11-IT-S, using direct already-available Awaitility 4.2.2. Transport starts from the exact immutable reviewed GS-T candidate (10d3706043430730edc921804dd1b8eb06a5326eb690f8c33f2571d7300fe1b5), not actual S011. Five sibling baselines are actual S011. No actual tree application, dependency edit, main change or runtime work is authorized here.

Every POLL becomes a local same-thread step, not a shared wait abstraction. The step preserves the original loop guard and body ordering, absolute monotonic deadline, first evaluation, final observation and original fallthrough. A direct initial step is followed by Awaitility's cached initial result, so the next real observation occurs after the original interval. Poll delay is explicitly zero; the cached first Awaitility tick prevents an extra immediate observation. Awaitility uses only the remaining original deadline and catches no unrelated uncaught-thread failures. On timeout one original final loop step observes its deadline/condition ordering, then original assertion/error/fallthrough runs. A local failure slot preserves the exact thrown Exception/Error rather than allowing Awaitility to reinterpret assertion failures. Interrupt checks at original sleep boundaries and after an Awaitility interval preserve InterruptedException mapping; response latency during Awaitility's uninterruptible scheduling may be up to the original poll interval and requires execution evidence. No added timer allowance or repeated action.

All ten DELIBERATE sleeps retain exact expression/duration and reason. Native streaming cadence is deliberate, not a readiness wait.
