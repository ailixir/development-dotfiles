# Gateway07 provider selection requires an owning design decision

Status: **INACTIVE_SOURCE_CONSTRAINT_REPORT — complete Gateway07 code preparation not achieved**.

The preparation task expressly permits a concrete constraint and minimal source proposal when primary-source interfaces cannot supply the required proof. That clause applies to the proposed selector below. This report does not establish that all Darwin providers are incapable of satisfying the requirement.

Apple's tagged XNU source distinguishes the process's main executable vnode from a VM region's backing vnode. `proc_pidpathinfo_internal` obtains `p_textvp`, resolves its pathname and exports that pathname. Its userspace result contains no device/inode or other vnode identity. Separately, `proc_pidregionpathinfo` uses the caller's address to select a VM region and exports that region's vnode facts. The latter function does not compare that vnode with `p_textvp` or export a main-executable discriminator. These are different object selections. [Kernel implementation](https://github.com/apple-oss-distributions/xnu/blob/xnu-12377.1.9/bsd/kern/proc_info.c#L1067), [main-executable path implementation](https://github.com/apple-oss-distributions/xnu/blob/xnu-12377.1.9/bsd/kern/proc_info.c#L1323).

Consequently, matching the returned image pathname to an executable VM region and matching that region's vnode to an opened no-follow file proves a mapped-file relation. The missing inference is that this selected region's vnode is the kernel's main executable vnode. A stable process birth, repeated matching paths, a file hash or a unique-looking pathname do not supply the missing object relation. This is a source proof gap; no actual host counterexample, replacement race or operating-system behavior was exercised or established.

The public structures describe BSD birth/UID/parent fields and region/vnode fields, without a main-image tag on `proc_regionwithpathinfo`. The inspected private `proc_uniqidentifierinfo` adds the main executable UUID and process identity versions. A UUID identifies executable content; equal-byte copies can share that content identifier, so it does not by itself supply the missing vnode-object equality. [Public structures](https://github.com/apple-oss-distributions/xnu/blob/xnu-12377.1.9/bsd/sys/proc_info.h#L54), [UUID structure](https://github.com/apple-oss-distributions/xnu/blob/xnu-12377.1.9/bsd/sys/proc_info_private.h#L41).

The minimal proposal keeps the existing required evidence and adds an explicit, independently sourced `main_object_relation` provider result. Owning Aria must select and justify the exact mechanism that relates a kernel main-executable object to the mapped object. A direct kernel main-vnode selector or an independently authenticated main-image address/object relation would be possible interface shapes; this report establishes neither their availability nor their suitability. Any additional Mach, Endpoint Security or other provider is an unselected architecture change requiring its own source and permission review. No entitlement, configuration or host inspection is proposed as an immediate action.

Until an exact selector and its semantics are approved, the provider must return `MAIN_EXECUTABLE_OBJECT_RELATION_UNPROVED`; initial binding and admission remain HOLD. An adapter that returns path-equal mapped facts as strong main identity would violate the owning blueprint. An adapter that always denies while the rest of the packet is called complete would misrepresent completion, so no operational adapter, bootstrap, guard, runtime directory, phase or native wrapper is supplied here.

`selector-model.py` and its guarded controls exercise only this logical distinction. Their synthetic trusted relation is an abstract input, not a selected or implemented Darwin provider. They do not compile, load or call libproc. Normal and optimized source evaluation use explicit guards.
