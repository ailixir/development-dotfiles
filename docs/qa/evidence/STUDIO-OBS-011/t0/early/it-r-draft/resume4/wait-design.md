# Corrected transition design — source candidate, not executed proof

The original semantic deadline, poll interval, guard expression, assertions, caller catch/finally and independent final reads remain authoritative. Every site has its own local Callable/state and one direct same-thread Awaitility chain expression; there is no shared wait helper/build/dependency edit. All chains set dontCatchUncaughtExceptions and ignoreNoExceptions. `row-classification-proof-map.json` covers all95 census rows; `interrupt-timeout-map.json` covers all74 POLL rows in73 sites.

A pending old body records `intervalOwed` and `owedUntil` at the original sleep point. A due step checks/clears a sleep-boundary interrupt before consuming the debt. Before it is due the step is a cached tick with no condition/RPC/report/lease/log/body read. A first framework callback is also a no-op, so the first manual step cannot cause an immediate repeated effect. The driver can finish only on a latched original terminal result or by throwing the first actual Exception/Error. Framework elapsed timeout does not replace the original outcome; a late terminal result is not replayed.

For condition-first guards, the fresh condition precedes the clock or original timeout assertion on every actual next transition. Rows29/31/32/33 execute that condition before deciding whether their original assertion is reached. For deadline-first while/do transitions, an expired original guard forbids a body read. Surrounding original final fresh reads remain separately present; no cached condition replaces them. The bound<=0/no-main-Await branch cannot silently leave a pending loop: it performs the same next original step. H8's unconditional loop performs its terminal observation/evidence/assertions/return exactly once or throws, including first failure after the immutable write.

Rows83/86 explicitly distinguish an entered leading-sleep iteration. Once its interval is due, it performs exactly one fresh report/HTTP read before the next original guard, including across expiry. A failed read is terminal and cannot repeat. Row5 distinguishes a blank body read (always owes its interval and interrupt transition) from genuine nonblank success (evaluates its original pure final guard, owes no sleep and preserves any flag). Fixture liveness and external caller handling remain unchanged.

The Awaitility bound is `max(original deadline remaining, already-owed single interval remaining)`. This serves an old entered iteration beyond its semantic deadline without resetting that deadline or introducing a new native retry/whole timeout. A framework timeout may end before the owed transition is due; driver reentry then serves only that pending interval, with no repeated read until due. This is a deliberate source-level distinction from v4's literal “atMost = the deadline the loop already had” convention. Root accepted preparation of this bounded candidate and requires independent QA assessment before application; this is not a rule waiver, timing guarantee, runtime approval or budget extension. At most one old interval is owed. Exact scheduling, the possible extra poll of scheduling delay and interrupt arrival around the boundary remain unproved.

These compare entered reads, condition-first/deadline-first/do transitions, real bound<=0 entry, late callback success/Exception/Error, exactly-one H8 immutable write and actual during-library-interval interruption. They have not been compiled or executed and cannot establish native/DB/ownership/privacy/timing conformance.
