# One selected public HTTPS exchange with a root-owned output relay

Aria's decision is DESIGN_ONLY_CONDITIONAL. Replace the candidate's dedicated `HttpClient.send(ofByteArray())` observer with one explicit JDK21 `Socket`/`SSLSocket` HTTPS/1.1 exchange on one observer-owned virtual thread. The original assertion thread controls one total15s observation envelope. Move all durable output writing to the root runtime adapter through one bounded local output channel carrying only the closed projection and resource-accounting facts. There is no service/private-store shortcut and no dynamic fallback. This is a concrete new design requiring an amended plan, newly authored/sealed Java and relay code, independent architecture/privacy/QA review and root qualification. It does not approve candidate01 or adapter02 for execution.

This choice preserves the existing public result route, original cookie/actor and controller authorization. It removes the high-level HTTP implementation's hidden retry paths and whole-body collector. It also avoids an unbounded filesystem operation or TLS/client close on the assertion thread. A timed wait or cancellation request never becomes a claim that a thread/socket has terminated. Unresolved resources remain HOLD. Java and the operating system are not hard real-time systems:15s is the enforced shared deadline and maximum intentional wait, with actual overruns disqualifying the observation; no portable guarantee about scheduling, safepoints or completion of arbitrary native/provider calls is invented.

## Exact network implementation contract

The new helper creates at most one unconnected `new Socket(Proxy.NO_PROXY)`, connects it once to the root-qualified local test server's fixed numeric loopback address and existing `port`, and layers `TLS.getSocketFactory().createSocket(raw,"localhost",port,true)`. The preselected address family is qualified before release; it is not DNS-resolved or tried in succession at capture time. The plan must explicitly bind the numeric loopback choice to this existing server. Keep the existing TLS context/key/trust material, enable HTTPS endpoint identification for `localhost`, and advertise only HTTP/1.1 through this socket's `SSLParameters`. No TLS/security/default-client/global JVM properties change. A certificate/ALPN/address incompatibility is UNAVAILABLE, not a reason to relax verification or try another address.

The worker performs one handshake and writes one bounded ASCII HTTP request: GET the exact owned UUID result path, Host localhost:port, the original cookie, Accept application/json, Accept-Encoding identity, Connection close, no request body. Validate UUID canonical form and reject CR/LF/non-ASCII cookie/header values before building the request. No authentication challenge retry, redirect following, reconnect, new socket, replay, automatic decompression or second request is present. A partial write or any TLS/network/parser error closes this attempt UNKNOWN. A TCP retransmission within this one connection is not another HTTP application request; the contract is one connect invocation and at most one HTTP request, not one TCP packet. Count connect, request-start and request-complete separately, so a failed/partial send is never called an observed complete send.

Use a fixed262144-byte entity buffer and a fixed8192-byte transfer buffer. Limit the response header block to16384 bytes, each chunk-size line to128 bytes and trailers cumulatively to8192 bytes. Enforce all bounds before adding/copying/growing buffers. Never use readAllBytes, readNBytes with a response-sized allocation, ofByteArray, ofString or an unbounded ByteArrayOutputStream. This entity cap is not a claim that opaque TLS/kernel buffers use262144 total bytes.

Accept one HTTP/1.0 or1.1 response with status200/202. Reject informational/redirect/challenge responses, malformed status/headers, duplicate/conflicting Content-Length, Transfer-Encoding plus Content-Length, unsupported Transfer-Encoding, nonidentity content encoding and malformed framing. Support exactly Content-Length, final chunked transfer encoding with bounded grammar, or Connection-close-delimited body; chunk sizes and their cumulative sum are checked before reading/copying their payload. Exact-cap bodies succeed only with a verified framing end; any next entity byte fails without appending it. A short body, missing chunk terminator, premature EOF or stalled trailers is unavailable. No second request is made to resolve ambiguity.

Strict UTF-8, duplicate-key and trailing-token rejection remain. Keep the existing schemaVersion3, exact owned session/execution, guided mode,200 terminal versus202 nonterminal and state-agreement validations. A202 view never qualifies an error code. Only the original35-code allowlist is exported; unknown/null/other/malformed code stays UNKNOWN. The two states remain separate observations; no assertion-time atomicity, original-check01 cause or runtime-stage claim is added.

## One deadline, explicit ownership and cancellation

At entry to the selected `observe`, before setup or any worker start, set `start=System.nanoTime()`, `workEnd=start+12s`, `networkEnd=start+14s`, `end=start+15s`. Check overflow by elapsed subtraction. These are allocations inside one existing15s ceiling, not three additive timeouts. Do not start a worker if the caller is interrupted, the root control is invalid or no budget remains.

Create exactly one named, registered virtual worker using Thread.ofVirtual; retain its actual Thread, raw socket, TLS socket and terminal immutable result in the selected observer object. There is no executor pool, HttpClient, common-pool continuation or detached timeout executor. The worker has no evidence-writing capability. Publish each acquired resource into its registry before the next blocking operation, and close every acquired resource in its finally boundary. A raw-socket constructor/connection/TLS-layer failure still records whatever was actually acquired. Close failures are closed booleans/statuses only, never exception text. Only successful close returns plus actual observed worker termination support NETWORK_CLOSED; isClosed or cancel alone does not.

Before connect and each handshake/body/header/framing read, calculate the remaining work budget. Pass a strictly positive rounded-up bounded timeout to connect/setSoTimeout; never allow zero to mean infinity. Recheck elapsed time after every operation, chunk and parse; crossing workEnd prevents capture qualification. This is a whole-operation deadline, so dribbled bytes cannot refresh it. Request writes and TLS/provider work can block despite read timeouts, so the caller must still supervise independently.

The caller performs a timed join only through workEnd. If the worker is still alive, revoke capture acceptance atomically and interrupt that one owned virtual thread once. This is cooperative Java thread cancellation, not a process signal. Join only for the remaining networkEnd budget. Never call socket.close, client.close, an unbounded join/get or an executor close on the assertion thread. If the worker remains alive, a close failed, result is absent, the caller was interrupted or actual elapsed time exceeds the relevant deadline, freeze an UNAVAILABLE/UNKNOWN tuple and UNRESOLVED resource status. Keep the worker reference and ownership registry for later unit accounting; never erase or relabel it as terminated. A late worker cannot publish, change the caller's frozen tuple or trigger another read. Restore the caller's interrupt status after finite observer handling. Original assertion and ordinary hooks then execute unchanged.

The caller's actual `!worker.isAlive()` after the join, together with the worker's returned finally-close statuses, is the network completion proof. `Future.cancel`, a completed future or a self-written marker is not substituted. The root relay receives these closed caller-observed facts. Successful public code qualification requires a timely worker, all acquired network resources closed and the original subject/state checks. A useful code does not independently release resource custody or any source/C8/IR credit.

JDK21 documents virtual-thread interruption for connect and underlying socket input/output; it does not promise every layered TLS/provider operation promptly terminates. The proposed cancellation is therefore conditional on the actual joined result, with unresolved cases HOLD. This is an inference about feasibility from the public APIs, not an installed-runtime experiment. [Java21 Socket](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/net/Socket.html), [Thread](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Thread.html), [SSLSocketFactory](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/javax/net/ssl/SSLSocketFactory.html).
