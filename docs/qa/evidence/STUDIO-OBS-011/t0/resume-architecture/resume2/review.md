## GS-M(a): actual-base-aware ruling GSM-P5

The current draft's `projectResult(..., publicationBase, ...)` flag selects receipt-path defaults/member order. Direct `service.read(..., "result")` always supplies false, including when an actual retained SUCCEEDED publication base exists. The present `!publicationBase && !publicationEnabled && SUCCEEDED` expression can therefore incorrectly introduce REFUSED on that retained base. HTTP selecting the receipt projector does not exempt the direct-service path. **Reject that expression as the final behavior.**

Approved bounded correction within the existing five draft files:

- Keep the optional existing-properties installer, but inject both `GuidedPublicationProperties` and the existing `GuidedPublicationBaseRepository` together in that package-private optional installer. No new bean, property key, configuration file or constructor parameter is needed. Production already has both beans. Preserve enabled=true for hand-built compositions that do not call it.
- Store a private base-presence predicate bound to `bases.find(id).isPresent()` (a harmless false default is sufficient while the unchanged manual enabled default remains true). The installer atomically establishes the enabled supplier and base predicate; no partially configured disabled state is permitted.
- Evaluate the repository predicate only on the authorized locked direct-result path, and only for disabled SUCCEEDED fallback projection. Preserve repository failure propagation; do not treat a query error as absent. A simple expression is `!publicationBase && !publicationEnabled.getAsBoolean() && state.equals("SUCCEEDED") && !publicationBaseExists.test(id)`. The existing short-circuit order avoids extra lookups on enabled/receipt/default paths. The flag still selects existing serialization defaults only; it grants no authority.
- Keep the receipt projector's base/receipt-first authority sequence, installed evidence/presentation forwarding, receipt/readiness overlays and HTTP status rules unchanged. Do not make raw service.read delegate into the receipt projector or introduce a dependency cycle. For direct reads of an existing base, preserve the old fallback PENDING/null receipt/NOT_PUBLISHED result; do not silently add published receipts there.
- Preserve the teardown changes and red/green/mutation staging, fallback/receipt step-index and errorCode defaults, both member orders, terminal fallback HTTP200/nonterminal202, current evidence installers and all pool/queue/window values. Regenerate patches, manifests/hashes and stage-helper inputs after authoring; stale patch hashes must fail rather than be bypassed.

Required matrix, using real repositories/HTTP where the present draft already does so:

| Configuration / actual base | Direct service result | HTTP result | Proof |
|---|---|---|---|
| disabled / absent / PREPARING and FINALIZING | full v3 result, PENDING | 202, same fallback result | Existing nonterminal test plus explicit no-base assertion |
| disabled / absent / SUCCEEDED | REFUSED, null receipt, NOT_PUBLISHED | 200, same result | Existing terminal test; actual absent repository row |
| disabled / present / SUCCEEDED, no receipt | original PENDING/null receipt/NOT_PUBLISHED | existing base projector PENDING and existing HTTP202 rule | **New regression**: real base repository capture/fixture, assert row present, compare direct read with pre-change fallback; do not create fake successful execution claims |

New red credit must include the disabled-existing-base regression failing on the currently proposed buggy behavior and passing after the actual-base correction. The original two stage reds still prove old production defects. Compilation/setup/discovery failures do not count. Keep existing three mutants; add a targeted mutation/removal of the actual-base predicate only if the new regression otherwise lacks direct red evidence. This is coverage of this discovered defect, not scope expansion. Independent QA owns final sufficiency.

## First-stop diagnostic ruling DIAG-START-1

Retained evidence binds the failing session to CONTEXT_PENDING / zero actions, observations and physical reads, SOURCE_PLAN only, and PROCESS launch ending in CANCELLED. It does **not** prove that a person cancelled or that the unbound final LEASE_LOST line belongs to that session.

Concrete diagnostic gap: ReplayIT's embedded `revStart` wrapper (near lines 27678–27689) invokes original start immediately but inserts `revRuntimes` only in its fulfillment handler. A failed PROCESS launch never gets that mapping. Its existing `revStop` observer therefore cannot be used to bind the startup stop to the case. Preserve this success-only map for its native authority/cleanup purpose; add a **separate diagnostic-only** map before invoking the original start.

Preferred first diagnostic remains test-only in ReplayIT's existing owned injected fixture script. No production runner change is authorized by this ruling. Integrate with existing wrapper ownership/restoration instead of stacking uncontrolled wrappers. Exact author proposal must be reviewed before source application:

1. Before `Reflect.apply(revStart, this, args)`, bind the runtime's hashed current session/context and closed case/epoch/producer to a diagnostic entry; record START_BEGIN. Match the existing hash convention: SHA256 of canonical JSON string, including the JSON quotes; the retained session prefix is e51dd69ff76b812b. Do not set revStarted, revRuntimes, successful native bindings or cleanup flags early.
2. Observe the existing runtime stop entry and its **first** startup AbortController.abort call, synchronously forwarding original receiver/arguments/return exactly once. Record whether the signal was already aborted on stop/abort entry. The abort observer is instance-scoped, installed before real start; never wrap the global AbortController prototype. Preserve the first abort cause, repeated-stop count and exact original closing promise. Restore or delete the owned abort descriptor according to its exact prior presence. START_SETTLE records only fulfillment/rejection, closed error chain, runtime start phase/loss and elapsed time. Do not await log writes in start/stop.
3. Observe ownership requestClaim begin/settle and checkGrant/invalidate/stopEntry using their original arguments and original return/promise. Record initial-vs-renewal, budget/lease/assignment remaining milliseconds, lease advancement, elapsed duration, closed refusal code and entry stopped flag/epoch. Also observe `applyAcknowledgedLease` to distinguish a granted renewal from its runtime installation. Merely observing an original claim is allowed; no added claim or renewal call is allowed.
4. For stop/abort origin, use a closed classification derived from a **reviewed, hash-bound call-site map** of the actual runner dist stack frames, or explicit existing-wrapper provenance: RUNTIME_TIMER, OWNERSHIP_EXPIRY_TIMER, OWNERSHIP_RENEW_FAILURE, OWNERSHIP_CONTEXT_START_FAILURE, OWNERSHIP_STOP_REQUEST, OWNERSHIP_CLOSE, BROWSER_LOSS, START_CATCH, FIXTURE, OTHER. Never export raw stacks, raw errors or argument objects. If mapping is ambiguous, persist OTHER and exact numeric call-site identifier from the reviewed allowlist; do not guess. Capturing first abort before original start settles distinguishes the initiating stop from later cleanup CONTEXT_LOST stops.
5. Fields are limited to schemaVersion, event enum, monotonic sequence, session/context hashes, numeric case/epoch/producer, relative elapsed/duration milliseconds, phase/loss/reason/code enums, numeric lease/expiry/budget deltas, booleans and the allowlisted call-site integer. Adopt Quinn's narrower cap of 32 records / 16 KiB per selected session, record truncation/instrumentationFailed explicitly, mode0600 under the already owned no-symlink evidence root. Export only this value-free ledger. No paths, URLs, source text, secret values/references, raw identities, raw stacks or request/response bodies.
6. Make instrumentation observation-only: logging failure cannot replace original return/throw/rejection, introduce a rejection or authorize cleanup. Restore exact owned descriptors and account for every owned writer through the existing final drain. Do not weaken the original close/producer ACK/canary/capture assertions to accommodate the ledger. An incomplete/truncated ledger is incomplete diagnosis, not success.

Root must first reconcile actual terminal B1/B7 and source identity, then review the author's exact diff/sites, closed enum/call-site map, output confinement and restoration before authorizing one fresh full-class ReplayIT diagnostic under the shared Gradle lock. No per-method retry or repeated full-class trial is pre-authorized. Stop after that run, bind its ledger to label/SHA and let QA identify the earliest event or report unresolved evidence. Test-only cause routes to IT-R; main/runner cause returns to root/architect for explicit lane routing. A diagnostic patch cannot silently become a product behavior fix.

No timer, deadline, expected UNKNOWN_OUTCOME, secret-fill injection, action/provider behavior, callback, cleanup guard, startup retry or native kill behavior may change. A main diagnostic is unnecessary for the first attempt if the existing test wrapper can observe these instance/method sites without altering semantics; if it cannot, return the exact limitation for another bounded ruling.
