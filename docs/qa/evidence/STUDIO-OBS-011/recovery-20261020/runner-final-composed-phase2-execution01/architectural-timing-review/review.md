# Guided secret ownership timing — architectural assessment

2026-10-20 · Astra/high · source and closed metadata only. No source/test patch, execution, private oracle/payload inspection or lifecycle verdict.

**Verdict: preserve the fixture FAIL and hold phase2 copyback/final Replay. The source has no explicit reserve against the two-second secret-control boundary; the observed overrun is real at the fixture's measurement point, but its cause and the exact instant authority became unusable remain unproved. One bounded, observation-only focused diagnostic is justified; an unchanged repeat solely to obtain green is not.**

## Contract and measurement

007 AC-13 and `secret-login-design.md` I-A3/C-4 preserve **≤2 s including request/queue time**, plus the separately acknowledged already-in-flight-step residual. The residual does not extend the deadline for refusing further work. 007's independent final review explicitly credits the original “real1s+1s control bound” and native slow/lost-response controls (`qa-independent-final-review.json:447–460`). Its earlier architectural review distinguishes a complete claim response from the ownership driver's subsequent scope/fence/lease checks (`astra-runtime-rootcause-design-review.json:10–15`). 009 AC-11 carries live polling/revocation proof, and its startup/teardown rulings do not replace this ownership contract with a launch or close timeout (`STUDIO-OBS-009.story.md:261`; `prep-20261016/t0-rulings/ruling.md:122`).

In this specific fixture:

- `t0` is `performance.now()` immediately after `guidedClaimClient` returns a successful complete authenticated, parsed/schema-validated response following native focus. It is **before** `requestClaim` finishes its own epoch/liveness/grant validation (`guided-secret-ownership.test.ts:99–103`; `ownership.ts:101–103`). It models denial/network loss immediately after the last successful confirmation, rather than measuring a backend revocation commit.
- The next claim receives HTTP 202 plus one byte, with the rest held for 1,500 ms. Headers/partial body supply no authority (`fixture:88–90`; `transport.ts:177–204`).
- `authorityStoppedAt` is recorded **after the synchronous portion of the real `GuidedRuntime.stop` returns a promise**, when `accepting` is false (`fixture:45–50`). It is not browser-close completion, lifecycle acknowledgement or backend audit. `stop` flips `stopped`, invokes `onStopping`, clears values/preparations and replaces context before returning (`runtime.ts:619–625`). The ownership entry is invalidated earlier still (`ownership.ts:161–170`). Thus the fixture observes a conservative post-invalidation point; the metadata does not timestamp each internal transition.
- The strict assertion is unchanged: `authorityStoppedAt - t0 <= 2000` (`fixture:131`). Later refusal, at-most-once, privacy and outcome assertions did not execute after this failure. Finally-observed cleanup flags are useful observations, not retrospective execution of those assertions.

## Prioritized findings

**P1 — Relative request budget can consume all nominal control slack.** Secret renewal uses absolute wall-clock cadence epochs, initialized at context scheduling and incremented by 1,000 ms after each successful renewal (`ownership.ts:58–68`, `:130–138`). This correctly avoids adding every response duration to the cadence. However, a delayed timer still receives a fresh request cap of 1,000 ms. `requestClaim` takes `min(1000, lease - Date.now() - 100)`; it does not subtract lateness against the cadence or an absolute two-second secret-control deadline (`:87–104`). The 100 ms `CLAIM_MARGIN_MS` protects the lease endpoint, not the 2 s endpoint. With a distant lease it supplies no 2 s reserve. Successful fast acknowledgements can leave only a few milliseconds of phase slack; callbacks, validation and stop-observation work can consume it. This is a demonstrated structural exposure, **not a claim that every run must be late**.

**P1 — Closed facts narrow the overrun but do not attribute it.** From `failed-fixture-closed-oracle-projection.json`:

| Interval | Observed ms |
|---|---:|
| Last acknowledged response (`t0`) → next ClaimPort start | 997.243958 |
| ClaimPort start → observed authority stop | 1003.395792 |
| ClaimPort start → adapter failure observation | 1003.404125 |
| `t0` → observed authority stop | 2000.639750 |
| Observed authority stop → adapter failure observation | 0.008333 |

The original ownership abort race can stop authority before the transport wrapper observes failure; that ordering is consistent with source and not evidence of clock corruption. The intended request cap was 1,000 ms. The record does **not** contain exact timer arming/firing, ownership invalidation, `stopped=true`, grant-validation completion or paired wall/monotonic samples. It therefore cannot separate timer dispatch lateness, synchronous work before/after a timeout, or post-invalidation measurement overhead. No clock jump, exclusive event-loop cause, secret use after loss, RT regression or timeout-fix regression is established.

**P2 — Clock domains and test precision matter, but are not a waiver.** Production derives wall-clock lease/cadence remaining time using integer `Date.now()` and then relative timers; the fixture measures elapsed time with monotonic `performance.now()`. Transport independently floors its timeout and combines it with the ownership abort signal (`transport.ts:169–187`). Quantization and callback scheduling may change which timer wins. Neither a wall→timer conversion nor nominal 1,000+1,000 arithmetic proves the strict measured bound. Conversely, neither clock quantization nor a 0.64 ms excess authorizes rounding, an epsilon, a sleep or a larger assertion.

**P2 — A “small reserve” is not yet a justified patch.** Existing unit cases explicitly require request timeout 1,000 ms, no close at 1,999 ms, close at 2,000 ms, and starts at absolute 1,000/2,000/3,000 epochs (`test/guided/ownership.test.ts:31–45`). Native slow-grant also requires successful 800–1,000 ms responses and preserves cadence (`fixture:121–126`). Silently shortening every cap, polling faster or repurposing `CLAIM_MARGIN_MS` changes these accepted semantics. The session-expiry exception (`ClaimMarginExhausted`) and EXPIRED/LEASE_LOST classification must also remain intact. A hard wall-time callback guarantee under arbitrary process suspension cannot be created by choosing another timer constant.
