## Authentication and filesystem basis

`transport.ts` requires authorized pinned mTLS plus RS256 RSA>=2048 JWT (issuer, subject, audience `studio-guided-runner`, role `backend-controller`, integer iat/exp, <=300s lifetime). Worker claims and callbacks use a separately signed worker JWT (`studio-guided-controller`, `owning-worker`, sub worker-one). The old literal callback token cannot be used: it was harmless only because the old smoke never called back. No unsigned/fake token, disabled verification or test seam enters production main.

The companion fixture follows `test/helpers/guided{,Tls}.ts` and `fixtures-tier/guided-wire.test.ts`: existing deliberately public loopback TLS pair, real signatures, pinned mTLS controller, validated Session claim, acknowledged bootstrap/lifecycle/recording. It shares **only the positive container's isolated network namespace**, so loopback certificate naming is unchanged and no host port, Internet, model, backend deployment or production secret is needed. This companion is not evidence of Kubernetes's one-container boundary. Its script is a short-lived smoke adapter, mounted read-only; production server/browser/recorder/journal code is unchanged. It copies the controlled fixture context/grant shapes into plain JavaScript because the final image deliberately contains no test TypeScript/helpers; it imports the final image's actual contract, policy-hash and JWT validators. Neither a compiler nor a test tool is installed/run by this smoke.

Use `/journal/data` below a writable `/journal` mount, disjoint from `/tmp`, replay scratch and object-store. Mount parent `/tmp`, not `/tmp/studio-runner` itself: startup/drain remove the scratch child. The draft uses exact-owned Docker named volumes for `/tmp` and `/journal` as the current chart's **disk-backed emptyDir** surrogate (rather than historical G9 tmpfs); this also permits a read-only post-drain allocation count from the still-live companion. It claims no memory/size-limit or Kubernetes-volume enforcement proof. Keep browser registry and HOME read-only. No TMPDIR or NODE_OPTIONS in the positive environment. `/tmp/.checks-guided-recordings` owns the private recording incarnation; Linux allocation uses `/proc/self/fd` (`recordingScratch.ts`). `GuidedJournal.open` synchronizes each ancestor through `/`, then creates/fsyncs exclusive owner and journal records. Assignment+context200 with nonempty journal files therefore exercises those operations on this actual read-only Linux root; file creation by the fixture is not substituted for them.
