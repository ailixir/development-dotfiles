## F1: retain source-written control-read rows

The IPC projection now requires the existing `controlReads` key and retains the original closed numeric rows in each parent projection. It validates an array of at most512 rows, exactly four integers per row: `[ms, stall, publishOverlap, killOverlap]`; the first two must be nonnegative exact JavaScript-safe integers, and the final two are numeric0/1. `controlReadCount` must equal the retained array length. The JavaScript-safe upper bound is a numeric representation check, not a timing deadline or new acceptance threshold. No timer, observer, source writer or test changed.

This is the format emitted by `revReadSettle` and included in `cutWriteDiagnostic`; the original Java `p10IpcDiagnostics` also retains the numeric rows. Root/QA can derive `readMaxMs = max(row[0])`, `readStallMaxMs = max(row[1])`, and publish/kill overlap counts from these exact retained rows. Empty arrays genuinely retain zero recorded reads, rather than an invented timing sample. Maxima over an empty set should remain unavailable; do not fabricate an observed zero-duration read.

The producer itself stores only its first512 per-execution rows. This successor preserves that bound and does not claim complete lifetime timing or cumulative maxima if the array reaches capacity. At length512, disclose possible producer truncation; derived maxima/overlap counts describe retained rows only. Existing loop-delay fields, per-C6 case/c6/ordinal identities and all other allowed fields remain unchanged. Invalid/missing control-read data makes the projection incomplete; no fallback values are fabricated.
