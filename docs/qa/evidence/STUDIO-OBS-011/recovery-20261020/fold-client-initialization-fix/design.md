# Recommendation: deploy-only constructor initialization

Move operation initialization into one new six-argument `@Autowired` constructor. It delegates to the unchanged four-argument TLS constructor and then calls the unchanged package-visible `initializeOperations(tls, contracts, environment)` method. Remove `@Autowired` from that old constructor and helper. Preserve every explicit constructor and both existing direct unit-test helper calls. This is one main-source-file correction; no fixture or test changes are proposed.

The closed FOLD03 failure is consistent with the exact source defect: Spring post-processes manually returned `@Bean` objects and resolves the initializer's required TLS argument before entering its body. Five fixture configurations supply their own TLS/origin/token/contracts through the explicit guided constructor and intentionally have no deployed StudioRunnerTls bean. That creates five bootstrap failures and82 cached-context threshold cascades. These87 failures remain real failures. A successful constructor does not prevent subsequent method injection.

There is a second configuration defect beyond the missing bean. If a TLS bean were added, the initializer would overwrite explicit guided origin/token/contracts: absent deployment origin selects `https://unconfigured.invalid` and a refusing token supplier; present origin selects the deployment origin/token file instead of fixture values. Explicit validation contracts would also be overwritten. Blindly adding a deny-all identity does not preserve those supplied clients.

The initially suggested ObjectProvider guard is incomplete for managed explicit three-argument/plain-HTTP and four-argument run-only clients: neither has guidedClient nor explicitValidationOrigin set. Protecting every explicit mode would require another construction-mode flag or broadened heuristic. Constructor-only deployed composition makes that distinction structural, preserves all five existing public constructor bodies/signatures, and avoids optional/lazy TLS semantics entirely. The source-bound DeReadyCarryForwardTest factory is a concrete managed three-argument example; no AE/U13 admission follows from this review.

Production still selects exactly one annotated constructor and must resolve StudioRunnerTls, GuidedContracts and Environment before construction. Its same TLS object is passed to base transport setup and guided setup; the original certificate/profile/configuration validation and origin/token-file guards are unchanged. The helper's body remains byte-identical, including absent-origin refusal, required configured token-file property, token I/O refusal, redirect/retry policy and TLS context use. No TLS default/fallback, optional security annotation, alternate trust bean, signal, retry, deadline, firstError/interrupt or writer behavior is introduced. Initialization also finishes before the component is published.

Use the bounded forward/inverse patches and exact source pins in design-bindings.json. Semantic compile plus changed-main static checks must precede native credit. The regression plan contains the existing87 failed cases and10 previously passing subjects whose concrete Spring construction changes: four TLS real-context cases, two full application role contexts and four profile-drift contexts. Previously passing Transport39/Session44 do not manage the concrete client and their explicit/mock operation paths are byte-identical; do not repeat those83 or all474 merely for this wiring correction. Existing direct-helper tests remain compatible; three narrow optional helper selectors are listed if root wants a small smoke check. No new test case or global case-count delta is required by this source-backed design.

Execution must show genuine context bootstrap followed by all expected case bodies/assertions passing with their unchanged names/profiles and no threshold cascades, fresh exact Counter97/zero skips, complete task-qualified reports/exec and owned cleanup. The native TLS contexts must still prove all transports share the configured TLS context and reach the peer with the backend certificate; the connector/role/profile contexts cover configured and absent guided-origin environments. Missing deployed TLS/configuration continues to fail closed by unchanged mandatory constructor/Wiring and required-property guards; retain all original certificate/refusal controls. Any newly exposed failure remains a finding. This packet has run no compiler, test, probe, native process, network, Git, CLI harness or delegation, and has changed no actual source/dist.
