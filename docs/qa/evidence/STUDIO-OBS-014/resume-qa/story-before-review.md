## Story

As the CSI owner whose application a Studio author tests, I want every action the learning run takes to be traceable to what the author wrote, bounded by a policy I own and Security approved, metered and audited per CSI, and I want the page metadata that leaves for the model gateway and the sanitized observations the database keeps to be described for compliance review, so that the first Run can never click, submit or export something nobody asked for.

## Acceptance Criteria

Residuals the security panel found at HEAD (ADR-SC-005 Panel evidence 3): **HIGH** un-requested side-effecting clicks — `targetIntent` is model-chosen and `GuidedProposalValidator` checks structure, not correspondence to the authored words; MEDIUM same-origin exfiltration; MEDIUM page-derived clarification labels; the read/discovery policy is one worker-mounted file with no owner, approval or audit (`guidedMain.ts:18-20` `applicationPolicy`, verified 2026-10-09); `studio_guided_sessions.progress` (V30:10) and `studio_guided_model_attempts.safe_result` (V32:58) persist sanitized observations and model output with no retention; guided session start is metered as an ordinary WRITE (`RateLimitClassifier.java:31-35` matches only `/studio/tests/{id}/execute`, verified). Every AC names its oracle; closed codes introduced here are fixed by @architect at T0 and recorded in the Dev Agent Record (no code name below is final).

   **AC-6 clarification — fail-closed reading of "actions the observation marks as form submission / navigation-causing" (@po (Pax) 2026-10-14; record `docs/qa/evidence/STUDIO-OBSERVED-NEXT/po-sec001-ruling-b-ack.json`; source @architect ruling AR-SEC001-FM option B, `docs/qa/evidence/STUDIO-OBS-014/ar-sec001-form-membership.json` `ownerLanes.@po`).    a. **Reading (acknowledged).** For the `DENY` and `CLARIFY_FIRST` stances, "actions the observation marks as form submission / navigation-causing" is enforced fail-closed as "actions the observation cannot prove non-activating". A click is side-effecting unless its target is one of three proven non-activating triples: a text-entry `input` (role textbox, searchbox or combobox, and control type text, search, email, tel, url or password), a `textarea` (role textbox, control type textarea), or a `select` (role combobox or listbox). Form membership does not matter. A press is side-effecting when its key is Enter, or when its target is in an exported form. `check`/`uncheck`, `fill`, `select`, reads, asserts and navigation to authored URLs are not side-effecting. Verified by @po in `GuidedActionGuard.sideEffecting`/`provenNonActivating` (`:168-192`).
   b. **Why this matches AC-6's intent.** The observation cannot mark submission reliably. A control in an unlabelled form, in a withheld form or associated through `form=` has `formId` null, and the AC-6 oracle's own OBS-007 login fixture is unlabelled (ruling V1–V4). A literal "marked by the observation" reading would let `DENY` pass the very login submit the oracle says it refuses. The story goal ("the first Run can never click, submit … something nobody asked for") and the QA focus "fail-closed defaults" both require the fail-closed reading. The rule only widens the side-effecting set. Every action that was refused before is still refused.
   c. **Resulting `DENY` scope (stated so the policy owner sees it).** Under `DENY` the learning run can navigate to authored URLs, fill, check/uncheck, select, read and assert, and can click only to focus a text field, textarea or select. It refuses clicks on buttons (in a form or not), links, labels, headings and other descendants of buttons or links, and click-toggles of checkboxes or radios. It also refuses Enter. A login or any button-driven flow therefore cannot run under `DENY`. This is the behaviour AC-6 specifies, not a regression. The author's escape for toggles is check/uncheck wording, and the owner's escape is `CLARIFY_FIRST` or `ALLOW`. The owner-facing statement is `guided-data-flow.md:147` (landed by B14). `ALLOW` is unchanged: the stance branch is the only place the classification is used (`GuidedActionGuard:154-164`).
   d. **Oracle evidence.** "Fixture login form under `DENY`" is met by the labelled variant (`governedDenyRefusesTheFormSubmitBeforeAnyDispatchAndFailsPolicyDenied`, button and input) and by the OBS-007 shape (`governedDenyRefusesAnUnlabelledOrFormAttributeSubmit`: unlabelled button, unlabelled input, `form=`), plus `governedClarifyFirstAsksOnceBeforeAnUnlabelledFormSubmit` for `CLARIFY_FIRST`.
