## 013: superseding AR-1 clauses

**A13-1 — authorize every read, including every range and download.** Ratify the stronger actual implementation: `GuidedSessionVideoController` calls `GuidedSessionController.read(user,id,request)` for each request before evidence projection, key derivation or store access. That path includes publication receipt/current-session authority as applicable. No shortcut, authorization cache, pre-authorized range token or second authorization implementation is introduced. The cost of repeated Core access/locking is accepted for this story; no measured throughput claim is made. Range-load characterization remains OBS-008 work and cannot justify weakening this authorization. Dedicated test must request an authenticated first range, revoke/refuse access, then request a second range and download: both must return the same denial as session read, with zero second store calls. Authority-unavailable must likewise match session read and touch no store. Unknown-id and unauthorized-resource responses must remain indistinguishable.

**A13-2 — identity before duplicate echo.** Ratify the implemented sequence in `GuidedSessionEvidenceService.record`: role/schema/path validation, locked session, scope/worker/fence/versions/materialization identity, then duplicate lookup, then acceptance-window/write-once checks. A matching previously accepted body/key may echo byte-identically after the settle window; that never revives authority or writes a second fact. Wrong caller, fence, scope or materialization must refuse even when the attacker supplies an existing key/body. No idempotency hit can bypass identity. The ordinary new-fact deadline still uses DB clock and terminal sessions remain admissible only under the documented settle predicate. Add explicit duplicate-after-window, unauthorized duplicate and stale-materialization duplicate assertions if the current cases do not execute them.

**A13-3 — no-store before expiry projection.** Ratify `RecordedGuidedEvidenceProjection`: an AVAILABLE persisted fact with `servesRecordings=false` projects UNAVAILABLE + the existing fixed NO_RECORDING_STORE text, null expiresAt, false partial, empty timings, even if its DB expiry passed. With a readable-store deployment it projects EXPIRED on the DB clock as before. Neither branch extends stored expiry or makes an object readable. The video route applies authorization first and then the projection; deployment-disabled evidence therefore returns VIDEO_UNAVAILABLE/404, while an authorized expired fact in an enabled deployment returns VIDEO_EXPIRED/410. Add a combined expired+disabled unit case; the existing separate tests do not alone exercise precedence. Execution video behavior is unchanged.

**A13-4 — normative PostgreSQL expression.** Supersede only AR-1 R5's literal recording_id DDL expression with `recording_id varchar(256) NOT NULL UNIQUE CHECK (recording_id ~ '^[A-Za-z0-9_-]+$')`. This is the already-installed V20 expression. For the ID alphabet accepted by the API it admits precisely 1..256 ASCII letters/digits/underscore/hyphen: `+` excludes empty, the alphabet excludes non-ASCII and separators, and varchar(256) provides the upper bound. Do not install the invalid bounded `{1,256}` PostgreSQL regular expression. Retain boundary probes for 0/1/255/256/257 characters, slash, dot/traversal and non-ASCII against actual PostgreSQL and unchanged migration checksums. This is a documentation ratification, not permission to edit frozen V20 or earlier migrations.

**A13-5 — logs retain the strict AR-1 security invariant.** The AR-1 negative expectation expressly covers logs at INFO and above, not just response bodies/headers. Current `VideoObjectServer.unreachable` attaches the raw store exception at WARN and its own comment acknowledges bucket/endpoint in the cause. Do not weaken AR-1 to accommodate that implementation. Replace exception/cause logging with a fixed operation code and already-safe resource identity only; never log key, bucket, endpoint, exception message, cause chain or stack containing those strings. Preserve shared execution/guided HTTP statuses, codes and response bytes. Add captured-log assertions with a synthetic cause containing key/bucket/endpoint/canary and nested cause text, through both metadata and read failures. Verify bodies/headers and INFO/WARN/ERROR logs are clear on guided and shared execution paths. Do not claim an existing plaintext secret leak was observed; the demonstrated defect is unsatisfied logging prohibition.

## 013: kill cleanup is a local obligation

AR-1 `negativeTestExpectations.runner_R13_R14[2]` explicitly requires evidence-directory removal after success, failure and kill. Current `guided/evidence.ts` allocates direct `checks-recording-*` children of trusted `ports.evidenceRoot ?? TMPDIR ?? tmpdir()` and deletes them only in settlement `finally`. SIGKILL cannot run JavaScript finally. Therefore no synchronous-in-victim cleanup promise is possible. The minimal safe interpretation is normal settlement cleanup plus bounded cleanup of provably owned dead-process recordings on the next worker startup, before accepting guided sessions; a real kill/restart test is required now. The previous OBS-009 placement is insufficient for strict completion of this already-planned local check.

Choose the narrow ownership-marked cleanup option. Alternatives rejected: global prefix/age sweep can delete another live worker's recording; a new recorder/storage pipeline duplicates existing mechanisms. Do not change journal consumption, browser effects, leases, evidence callbacks or public contracts.

Implementation boundaries:

1. A new runner utility under `src/run/` owns filesystem/process-liveness operations, respecting the existing child_process/process confinement. `guided/evidence.ts` delegates directory allocation/disposal through that utility. `run/guidedMain.ts` prepares/sweeps before listening. Keep the existing trusted evidenceRoot injection for tests; never take cleanup paths from app, page, proposal, recording callback or user text.
2. Use a private, mode0700 managed namespace below the canonical trusted evidence parent, separated from Chromium profiles and journals. Bind a stable worker scope from trusted workerId + canonical journalDirectory, hashed in paths. Each process incarnation gets a new unpredictable nonce directory and exclusively created mode0600 metadata file written before a browser can write. Its closed schema carries version, positive integer pid and nonce/scope hashes only; no session/page/app/secret values. Sessions still use random `checks-recording-*` leaves inside that owned incarnation. Do not adopt another incarnation's directory. A fresh process nonce prevents later processes from legitimately reusing a dead owner's path.
3. Only inspect the current trusted worker scope. Require a real same-UID private directory and regular, same-UID, non-symlink metadata with bounded bytes and exact field/schema/path binding. A PID liveness probe must return definite ESRCH before cleanup; alive (including PID reuse), EPERM, unsupported probes and all uncertainty mean skip/refuse cleanup, never 'dead'. Another live worker/incarnation must remain untouched even when it has the same stable scope. Never signal arbitrary PIDs during sweep. Legacy unmarked direct `checks-recording-*` directories cannot be proven owned and must not be silently deleted or represented as cleaned.
4. Reject symlinked managed root/namespace/incarnation and never recurse through a symlink leaf. Avoid realpath-based trust of a path after following an attacker-controlled symlink; lstat/owner/mode checks and containment must precede access. Quarantine a verified dead incarnation by atomic rename to a fresh private name within the same verified scope; recheck metadata/inode after rename before deleting. Concurrent reapers may lose a rename race and safely skip. Use bounded, no-follow traversal; symlink entries may be unlinked as links without reading targets. Do not follow outside-tree links or expose their targets in logs. Never use a broad glob rm in TMPDIR.
5. Bound startup work explicitly: at most128 candidate incarnations,32KiB metadata each,512 filesystem entries per candidate, depth4 and5seconds total deadline, with a maximum16 dead incarnations reclaimed per startup. Constants are trusted implementation limits with injected smaller test limits; no new user knobs or mounted read-policy keys are needed. Stop on limits; retain remaining candidates for a later bounded pass. Logs/report include fixed result codes and aggregate counts only. If cleanup of a positively identified owned dead incarnation fails, refuse worker readiness with a fixed data-free error rather than silently claim the check passed. Skipping live/uncertain/foreign/unmarked candidates is expected conservative behavior, reported without paths or contents.
6. Success means recorded managed directory bytes are removed; it is not an assertion that SIGKILL ran finally, uploaded evidence or resumed a session. No recovery/reupload/callback for a dead process is authorized. Marked orphan files are removed only; session evidence remains honest PROCESSING/UNAVAILABLE under existing deadline rules. Broader profile/process reclamation and folded deployed startup stay OBS-009. Existing `run/tree.ts` explains Playwright starts detached browser/encoder groups, so the real test must enumerate/terminate its own captured tree and assert no known owned process survives; never assume killing only Node also kills Chromium. The cleanup helper must neither infer ownership from arbitrary argv strings nor persist process command lines.

Required tests, runner owner, before independent QA green:

- Unit filesystem cases: success/failure settlement disposes only the owned leaf after upload; killed-owner marker is reclaimed; same-scope live process, other scope, EPERM/unknown, reused-live PID, missing/corrupt/oversized metadata and legacy unmarked directories are preserved; root/namespace/incarnation/leaf symlink negative controls preserve an external canary; nested symlink is unlinked without traversal; concurrent sweep race is harmless; bounds/deadline terminate; delete failure prevents readiness; logs contain no path/content canary.
- Real subprocess fixture: start worker-owned recorder with a real recorded guided Chromium login fixture, wait for actual app video bytes, capture owned PID tree, SIGKILL Node (no cooperative shutdown), observe the owned recording residue, terminate and verify the test's known surviving browser/encoder processes using existing tree helpers, then start a replacement worker with the same trusted scope. Before it accepts work, verify the prior managed recording bytes are gone. In parallel keep a second real worker/incarnation recording and verify its directory/bytes and ability to finish survive the sweep. Assert no victim callback/store upload is invented by restart; evidence state remains honest. Repeat with a symlink to an outside canary and verify no target read/delete. Test setup/teardown owns every directory/process it removes.
- Separate process-group termination variant may prove bounded complete tree kill and restart; it does not replace the parent-only SIGKILL case. A mocked rm call or cooperative app.close is not a kill-path proof.

## 014: guard precedence supersedes the unruled ARCH-001 point
