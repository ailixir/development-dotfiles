# Recording cleanup portability ruling — 2026-10-14

Aria, architecture review. This dated clarification applies to the kill-cleanup section of `architecture/addendum.md` and the reviewed candidate `studio-runner/src/run/recordingScratch.ts`. It does not change the requirement for real kill/restart cleanup, preserve another live worker, or prove any test passed. OBS-015 remains unstarted.

## Decision

The portable implementation may use canonical trusted root paths, private same-UID0700 managed directories, exclusive0600 markers opened with O_NOFOLLOW, O_DIRECTORY|O_NOFOLLOW directory handles, before/after device+inode fences, dead-owner fencing and atomic unpredictable quarantine names. Linux may retain `/proc/self/fd` anchoring as an additional defense. macOS must use the portable path form when directory traversal through `/dev/fd` is unavailable. Do not ship an untested `/dev/fd` assumption. No new native helper, dependency, subprocess shell traversal, filesystem privilege or browser capability is required.

This is an ownership-scoped cleanup mechanism under a trusted host/service-account boundary. It is **not** a race-free filesystem sandbox against an arbitrary malicious process already running unsandboxed with the runner UID. Ordinary path checks and O_NOFOLLOW on a final component cannot establish that stronger property. The candidate must not claim that held descriptors make all macOS descendant operations descriptor-relative: its opendir/unlink/rmdir paths remain path-based there.

## Basis and exact trust boundary

- ADR-SC-004, `Trust and data boundaries` (lines26–32), assigns the live browser/fixed collector/ephemeral store to the runner and treats page labels as untrusted model data. It separates video as a sensitive channel.
- ADR-001, section8 (lines179–187), requires a dedicated non-root runner user and Chromium sandbox, with no silent no-sandbox fallback. Section9 (lines198–203) prescribes private scratch volumes and restricted runtime privileges.
- `docs/architecture/studio-execution.md` lines128–130 rejects process/filesystem APIs and arbitrary evaluation in executable input; line331 requires non-root sandboxed browser operation, scratch cleanup at startup and restricted service access.
- ARCH.md does not define an adversary that already controls an unsandboxed native process under the trusted runner UID.

**Inference, made explicit:** trusted host/kernel, runtime image/Node implementation, mounted runner configuration and unsandboxed processes sharing the runner UID are part of the execution trust base. Page JavaScript, authored/model proposals, public/internal request bodies, and filesystem objects supplied through those untrusted channels are not trusted. A native same-UID attacker could already read/alter/delete every0700/0600 runner-owned file, forge ownership markers and replace the application source/configuration; this helper cannot create an OS isolation boundary against that principal. Such an adversary would require different UIDs, OS policy/sandboxing and fd-relative native operations, outside this narrow remediation. The absence of those features is not a waiver of an existing story promise to defend against same-UID host compromise, because no such promise was specified.

The trusted-parent assumption must be implemented: evidence parent and journalDirectory come only from trusted startup configuration/default environment or explicit trusted test injection; canonicalize platform parent aliases once. Never derive them or stable scope from a page, model, callback, uploaded file or API field. Reject symlinked managed root/scope/incarnation, non-private/wrong-UID managed directories, symlink/hardlink/oversized/non-private markers and uncertain owner liveness. Chromium remains sandboxed, downloads disabled and process/filesystem instructions unavailable to page/model input. A deployment that deliberately gives untrusted native workloads the runner UID and write access to this scratch namespace does not meet this precondition.

## Portable traversal obligations retained

1. Preserve lstat classification before access, O_NOFOLLOW on marker and directory opens, inode equivalence against held handles and rechecks around enumeration/deletion. On observed replacement, symlink, owner/mode change or inconsistent metadata, stop/refuse or conservatively skip before deletion; never convert uncertainty into a dead-owner verdict.
2. Only a marker-bound dead incarnation in the exact current stable scope may be quarantined/reclaimed. A live/unknown/EPERM/reused-live PID is skipped. Never adopt or overwrite an incarnation. Concurrent cooperating reapers may race to rename the same dead candidate; losing ENOENT must be harmless. Ordinary workers/reapers never swap the stable managed roots or another incarnation's private tree, so their concurrency does not rely on a hostile-same-UID race defense.
3. Enumerate only real checked directories. An existing symlink entry may be unlinked as a link, with no target read or recursive traversal. Reject root/scope/incarnation symlinks; preserve an external target canary. Recheck planned node identity before removal. Do not introduce recursive rm, prefix-only ownership, argv ownership guesses or temporary removal of privacy modes.
4. Preserve bounded candidates/entries/depth/reclaim count and elapsed-work checks. A deadline check between Node filesystem operations is a cooperative work budget, not proof that the OS can cancel a stalled filesystem syscall or that an active deletion sequence completes in a hard wall-clock bound. Candidate documentation and receipts must state the measured bound they prove; do not label an unmeasured or non-cancellable native operation hard-bounded. A failure to finish owned cleanup still refuses readiness; no timer may declare success while pending operations continue.
5. No user-facing warning/approval step or new mounted config is needed. Put the trust statement in utility documentation and technical evidence/runbook only.

## Exact validation required

Run the actual supported local platform path. On macOS, exercise marker reads, opendir, quarantine and every unlink/rmdir against real directories using portable paths, including actual kill/restart. On Linux, exercise descriptor anchoring in the existing supported image when available; do not claim Linux executed from a macOS result. Tests may assert both dispatch branches using injected platform seams, but those assertions are not a second OS execution.

Mandatory real filesystem negative cases remain: static symlinks at root/scope/incarnation/leaf, nested links to an external canary, invalid/hardlinked/oversized markers, wrong ownership/privacy where the host permits making them, foreign scope, live/unknown owner, PID reuse, renamed/missing entries from another cooperating reaper, and injected inode/mode changes observed at existing fences. Verify no target canary bytes are read/deleted, live-worker recording completes, fixed logs contain no paths/page/secret strings, failed deletion refuses readiness, and work-count/depth/deadline controls stop further scheduling. In-process deterministic adversarial mutation hooks are useful for **detected** race paths; do not describe any finite stress test as proof against all active same-UID rename interleavings.

The original parent-only SIGKILL/restart proof, independent process-tree cleanup, truthful unavailable evidence and successful recorder settlement proof remain required without substitution. This portability ruling supplies no automatic PASS: developer and independent QA must check the actual candidate, platform receipts and the final frozen build.

No product edits, test/build executions, lifecycle or git changes were performed for this ruling.
