## Exact permitted test-only implementation

1. Preserve all four separate persistent contexts/profiles/pages/videos and current launch options: VERSION and PREFS independently at viewport1280x720/recording640x360 and viewport800x600/recording800x600. Preserve exact destination, page-specific DOM validation and the existing two animation callbacks. Require those checks to succeed first; then attach the observer to that same page. This is preferred over the diagnosis's before-navigation subscription: a second client can inspect cached actual target pixels, while an initial blank cached frame cannot qualify. Each isolated context has only its initial blank and its one fixed target, so no prior informative page can satisfy this barrier. No new navigation, reload, paint mutation, overlay or simulated input.
2. Start with exactly `{onFrame}`. Omit `path`, `size`, `quality` and all decoration APIs. Start once. The start promise and readiness latch must both succeed before teardown, including when a cached callback arrives before start resolves. A source timestamp/callback count alone is insufficient. Cached source frames are permitted; they are actual recorder-input frames, not a separate screenshot or synthetic substitute.
3. Use a synchronous, nonthrowing callback that either drops the event immediately when busy/settled or copies one bounded JPEG and schedules one asynchronous decoder. At most one candidate/decoder may be active; keep no pending/latest frame, Promise chain or accumulated frame array. This supersedes the diagnosis's optional one-latest queue. Dropping busy callback events never drops frames from automatic recording; it merely declines redundant readiness work. Count dropped events numerically if useful. Never mutate or zero the SDK-supplied frame buffer. Only owned copies may be zeroed.
4. Decode that owned JPEG through the existing ffmpeg executable using stdin/stdout only, no temporary media paths, and discarded stderr. Validate its actual numeric JPEG dimensions in memory before RGB decoding: positive safe integers, width<=W, height<=H, and at most32MiB RGB. The existing ffprobe executable over pipes is permitted for numeric metadata if needed, but at most one owned native tool process may run at a time for this candidate. Reconstruct the same recording canvas using the installed Chromium encoder's exact existing `pad=W:H:0:0:gray,crop=W:H:0:0` filter. This transforms an in-memory readiness sample identically to the existing encoder geometry; it does not alter the original video or add an ignored-pixel exemption. Do not resize, scale, interpolate, change capture dimensions, or use viewport metadata as JPEG dimensions. Bound encoded input and decoded output at32MiB each; require exactly `3*W*H` RGB bytes, positive safe integer dimensions and successful decoder exit. Reject malformed/oversized input or output and decoder errors; do not adapt geometry or try alternative filters. Process pipes must stop accepting bytes on overrun. Limit examined candidates to400 as an additional work bound; reaching it without readiness fails rather than scheduling more work.
5. Run the unchanged `classifyNativeBlank` and unchanged `nativeControlMaxRowRuns` on the same complete resulting RGB frame. Readiness requires `!surface.accepted && surface.kind==='NONBLANK' && maxRowRuns>6`, with original tolerance12. White, exact white/native-pad, black, all-gray, malformed frame or complexity from another frame cannot qualify. Empty/no delivery cannot qualify. A valid nonqualifying source frame releases its owned buffers and allows a subsequent source event to be examined; this is an event-driven wait within one test execution, not a test retry.
6. Use one10000ms failure deadline for observer start plus all readiness/candidate decoding, measured once before subscribing. Never reset it per frame or decoder. It is a maximum wait, not a minimum dwell. No sleeps, timer-based success, automatic retry, test timeout/config change or enlarged existing native decoder budget. The current120000ms fixture timeout remains. Decoder callbacks and API completion arriving after settlement must be observed and cleaned up; a timeout race must not leave an unhandled rejection or later success. Page/context closure or crash before qualification fails the barrier. Fixed sanitized error codes only.
7. After qualification, stop only the public observer, await decoder settlement and discard owned pixels, then close the original page/context as before. Automatic `recordVideo` remains installed until its original orderly close. Additional frames may arrive between qualification and closure; no assumption about the final encoded frame may bypass the next paragraph.
