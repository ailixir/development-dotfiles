## 1. Exact opaque declaration mapping and immutable identity

The authoritative mapping source is the draft's existing `StudioVariable` declarations. For context `referenceId`, look up **exact `StudioVariable.name` equality**, with no URI interpretation, normalization, trimming or suffix extraction. `Variable.name` is a string of at most 64 characters without a token-name regex (`openapi.yaml:3100`); therefore `{name:"vault://studio/customer-password",kind:"secretRef",secretId:"LOGIN_PASSWORD"}` explicitly binds the existing context example. A context reference with no exact declaration remains syntactically valid authoring and fails runtime resolution explicitly. A reference longer than the existing declaration-name bound cannot resolve, rather than acquiring guessed semantics.

Text `<var NAME>` resolves a plain declaration by exact name. Text `<secret ID>` resolves the actual `secretId` of an explicitly declared secret. `secretId` is required and matches `^[A-Za-z0-9_.-]{1,64}$`, excluding `.` and `..` under the existing Vault name grammar; the retired null-secretId/name fallback is not part of this canonical path. Multiple differently named aliases to the same secretId are legal; the direct token maps once to that ID. Duplicate declaration names are rejected. A key that would mean different kinds or different secret IDs across the name and direct-ID indexes is rejected, including a plain name colliding with a secretId. Duplicate occurrences of the same reference within one scope de-duplicate to one identical identity.

Resolve structured step `variableRef`, step `secretRef`, and step/global default values of kind `variableRef`. Parse canonical `<var …>`/`<secret …>` tokens in `AuthoringStep.text` with the existing `VariableReferenceValidator` parser. `ContextText`, literal values, target hints and literal defaults remain literal/non-executable fields; do not introduce token interpolation into them. Global secret entries and secret defaults stay invalid under `StudioAuthoringValidation:98-116`. Collect at most 500 unique referenced identities, bounded by the existing authoring-identity collection limit. Sort reference arrays by unsigned UTF-8 bytes of `referenceId` (Java byte comparator, JS Buffer comparator, PostgreSQL C collation), not locale order.

Missing runtime reference: `409 MISSING_SOURCE`, `messageCode=AUTHORING_REFERENCE_MISSING`. Kind mismatch/ambiguous mapping: `422 INVALID_CONTRACT`, `messageCode=AUTHORING_REFERENCE_AMBIGUOUS`; reject before session/budget/publication writes. Duplicate declaration names are a `400 INVALID_AUTHORING` write refusal. These reuse existing error-code vocabulary. Missing plain value is missing source; intentional empty/whitespace values remain exact valid values and must never be null-hashed.

The existing immutable revision `references` JSON gains `authoringIdentityVersion:1` and `authoredDeclarations` (closed shapes in the schema). The latter contains every referenced text/context/global identity, independently of whether execution materialized it. Preserve `variables` and `secrets` arrays for ordinary replay/V17, containing only the **effective executed** recipe references as today. Secret declaration identity is `{referenceId,kind:"secretRef",secretId}` with no secret value; plain identity is `{referenceId,kind:"plain",valueHash}`. `AuthoringRevisionInputs.nonsecretReferencedValues` contains the complete matching plain set. New identity computation uses canonical-v1 for plain value strings, global context, step contexts and contextDigest; the existing v2 authoring shape is unchanged. `authoringIdentityVersion:1` identifies complete canonical input identity, not a second authoring or execution generation.

Read the base only from its frozen authoring, authoring_revision_inputs, configuration, references, artifact and V15 snapshot maps. Require complete version-1 identity and exact maps; missing historical alias/value hash/snapshot metadata yields `NEEDS_RELEARN` at the first draft step with `readinessReason=BASE_IDENTITY_INCOMPLETE`. Start with omitted boundary then refuses `409 REVISION_CONFLICT`, `messageCode=BASE_IDENTITY_INCOMPLETE`. An **explicit** `firstLearnStepId` equal to the first current step requests full learning and may proceed without reusing the insufficient base. It still validates the current head/base, scope, policy and source revisions. It creates one normal new complete revision; no historical rewrite, no automatic fallback, no guessed old hash, and no database recreation are authorized here.

Source: `AuthoringRevisionIdentity:127-157`, `AuthoringRevisionInputs:13-19`, `GuidedSourceClassifier:69-189`, `GuidedPublicationRepository:227-240`, `StudioVariable`, `VariableReferenceValidator` and the frozen context examples. Complete identity capture is part of T1/publication, not an optional follow-up. Current-side comparison/start recomputes complete identity from locked raw authoring/declarations instead of trusting a stale derived draft cache. The session source manifest freezes that identity. Immediately before revision INSERT, publication rechecks exact current inputs and refreshes only `ui_tests.authoring_revision_inputs` in the same transaction; the unchanged V12 capture trigger copies it. No authored field, source/config counter or historical revision is rewritten.

## 3. Durable prefix and model-free preparation

Insert immutable `relearn_plan` with original boundary, verified base digest and prefixProgramHash before assignment. A nonempty pending prefix is the durable predicate: initial boundary index >0 and no switch row. Model reservation, attempt insertion and model counters are refused on that predicate, including PREPARING bootstrap. Session public state becomes/stays REPLAYING_PREFIX through observation/admission/consumption/outcome/completion. Both translation state and Java continuation enum include REPLAYING_PREFIX; coordinator routes the existing plans endpoint's prefix branch before SOURCE_PLAN. Runner ACTIVE includes it. No extra public HTTP operation is added.

PrefixProgram is the closed program in the schema: verified base actions minus admission IDs, each joined to its exact replay guard; no old values, authorization or evidence. Its hash is pinned in session data and runner context. The prefix branch materializes only its required inputs model-free, imports verified IDs/producer intent, assigns and boots exactly one recorded `GuidedBrowser.handle`, and replays with the observed adapter.

Factor observed adapter acquisition and execution into prepare/performPrepared helpers accepting the guided handle **and existing ObservationSession**. Ordinary replay may construct its own session; guided prefix may not accidentally create a different observation lineage. Each prefix prepare request binds current evidenceHash and historical input version. The existing runner prepare route accepts the new request variant. It returns PREPARED with a fresh exact Action/proof, WAIT for bounded absent/visibility acquisition, or DRIFT with authenticated proof. The backend verifies the operation/guard against PrefixProgram before policy admission. No target is invented by a model.

WAIT uses the existing bounded observation acquisition window and refreshed evidence. Issue at most one request per (coordinate,evidenceHash), at most session.maxObservations (<=400); same digest retries return the same response. No WAIT after lease/session/step deadline. Every fresh observation is acknowledged by the backend before its request is issued, so a proof never substitutes a different observation after admission. Target ambiguity or bounded acquisition exhaustion becomes pre-admission drift; a policy refusal remains a run failure.

A single immutable switch row leaves prefix, by BOUNDARY after all prefix semantic coordinates succeed, or DRIFT after the exact receipt below. It stores initial/effective step, next semantic ordinal, fully completed step count, ordered retained successful prefix admissions and their hash. Boundary → SOURCE_PLAN at k; drift → SOURCE_PLAN at j. Duplicate switch receipt returns the existing transition; never re-enter prefix. k=1 uses ordinary full learning with an EMPTY_PREFIX switch record if a base exists; first-ever learning has no incremental metadata. No empty suffix is introduced.

## 5. Authenticated no-invocation drift and attempts

The receipt schema is a closed union. PRE_ADMISSION binds the exact durable prefix request; admissionId/preparationId are null and no action attempt exists. ADMITTED_PRE_INVOCATION binds that request plus exact consumed admission, preparation, original proposal digest, operationHash, input version, owner/fence, evidence and context. Both have attemptOrdinal=0 and nativeInvocationStarted=false. ReceiptHash hashes every other field using canonical-v1; it is an integrity hash, **not authentication**.

Authority is the existing owning-worker RS256 service JWT plus connector-validated mTLS (`GuidedInternalSecurity`), exact assignment/subject and current lease/fence/context. A model/client boolean, HTTP200, forwarded identity, missing success or SQL absence proves nothing. Even PRE_ADMISSION is committed through the authenticated existing outcomes callback variant; prepare response alone is not commit authority. Exact duplicate callback may return its committed result after switch; a first late/stale callback cannot resurrect a terminal/expired session.

The trusted runner's per-admission native fence is monotonic: NOT_BEGUN → INVOKING before the first browser API call, or NOT_BEGUN → REFUSED_BEFORE_INVOCATION on a recognized target/observation refusal. Set INVOKING synchronously and durably before entering native dispatch; any failure/uncertainty writing the journal stops UNKNOWN_OUTCOME. Persist REFUSED and its receipt before callback. REFUSED cannot become INVOKING. Only that positive REFUSED transition can issue the receipt. Cancellation, policy, assertion failure, native-started error, context loss or missing acknowledgement never does. Existing consumption journal remains append-only and a spent admission is never resent or recovered into another browser.

There is at most **one drift switch and one receipt per session**. Semantic action ordinal remains 0..7 and respects maxStatementsPerStep. Add server attemptOrdinal 0..1 to action/association identity. Attempt 1 is permitted only for the drift coordinate after its exact attempt-0 ADMITTED_PRE_INVOCATION proof; PRE_ADMISSION drift starts learning with ordinary attempt 0. At most one live/invoked/succeeded attempt exists per semantic coordinate; only immutable no-invocation failure permits a replacement. Every admitted attempt charges maxActions (<=200); receipts/preparation do not evade observation/session/evidence budgets. Later suffix failures use the existing terminal behavior; this is not a retry loop.

For admitted drift, persist the original ledger as FAILED/TARGET_CHANGED, its receipt and the switch atomically; suppress generic session stop only on this exact validated branch. Do not overwrite/reopen the spent action. Preserve every successful earlier operation including earlier ordinals of j. First suffix plan acceptance may replace unexecuted prefix-import obligations plus the sole positively noninvoked failed obligation; all prior successful meanings/admission IDs remain exact. One immutable first-suffix acceptance guards this exception. Subsequent plan patches retain ordinary monotonic rules. A new effective plan contains >=1 actual successful semantic action per source step, contiguous successful ordinals; it may omit an unperformed tail obligation when learning verifies the step is already satisfied, but cannot renumber previous successful operations or leave an ordinal hole.

If a secret was released before the final target check, preserve its existing append-only RELEASE and existing conservative non-OK USAGE=UNKNOWN_OUTCOME mapping. The receipt does not manufacture NOT_USED/REFUSED or alter existing usage vocabulary. A new valid learned admission gets its own authorization, read/release sequence and per-version lineage. Policy/password ambiguity failures still stop; no automatic retry of possibly typed secret bytes is allowed.
