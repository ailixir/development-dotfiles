## Why the old basis is insufficient

`deriveObservedArtifact` reconstructs the candidate learned plan from the basis. The old basis has ordered step text, execution configuration, effective admissions, input metadata, historical input hashes and incremental transition records. It has neither full normalized authoring contexts/global context nor the complete referenced declaration identities. A sourceManifestHash is an opaque commitment, not its preimage. PrefixProgram has old actions and guards but no old authoring/configuration/snapshot-map preimages.

The fixture's `underdeterminationCounterexample` holds every old basis field constant and changes an unexecuted authored context at step 2. The approved `StepInput` changes there, so chains and snapshots 2–3 change. The old pure function receives identical inputs in these two cases and therefore cannot correctly derive both maps. Hashing text alone, inventing empty contexts, copying a claimed map or trusting a supplied inputChain is prohibited.

## Required closed evidence

Add required `ValidationBasis.snapshotEvidence` with exactly:

- `schemaVersion:3`.
- `current:{authoringIdentityVersion:1,authoring,authoredDeclarations}`. `authoring` is the complete normalized v2 source: globalContext and ordered `{id,text,context}` steps. Declarations contain only exact IDs/kinds and plain valueHash or secretId, never resolved values. The sorted declaration array is the exact referenced union, including unexecuted authored references; unused declarations are absent.
- `pinnedBase:null|{revisionId,revisionDigest}`. This comes from the original session's immutable publication base and relearn plan, not today's draft head or a client hint.
- `baseProof:null|{revision,authoringIdentity,configuration,artifact}`. `revision` uses the existing closed Revision shape and exact RevisionIdentity preimage; `authoringIdentity` has the same shape as `current`; configuration and artifact use existing production contracts. There is no recursive previous basis, no second replay generation, and no public operation.

Current configuration is already `basis.configuration`; do not duplicate it in current. No claimed StepInput/StepChain/inputChain/snapshot-map outputs are added to current evidence. Every one is recomputed. The base contains its full artifact because snapshot semantics, bindings and per-step maps must be recomputed and bound to the existing artifactHash; a digest plus claimed map would leave the original gap open.

The old base publication's digest preimage retains its exact existing fields. Hash its full existing RevisionIdentity, compare with `revision.revisionDigest`, the immutable pin and PrefixProgram.baseRevisionDigest. Recompute sourceHash, authoringHash, configurationHash, artifactHash, learnedPlanHash, referencePolicyHash, operationEquivalenceHash and profileHash from the supplied base facts. Existing admission/publication/run-authorization commitments remain historic receipt facts, joined to the actual stored publication by Java. This correction does not recursively rerun every past publication or manufacture cryptographic proof that a database row is immediate. That authority comes from the backend's immutable original-start capture and authenticated, fenced validation request. The pure validator verifies all corresponding IDs/digests and recomputes snapshots, rather than trusting their claimed values.

## Normalization and privacy

Use the same normalized source bytes for Java identity hashing and evidence. Empty/null omitted global/step contexts normalize to `{entries:[],evidenceReferences:[]}`. Context arrays keep source order. `TargetHint` is the normalized record shape, including explicit nullable `scope`/`exact`; do not silently turn an absent exact into false in one implementation. Authored evidence timestamps are canonical ISO strings, with no conversion to numeric timestamps; preserve the stored lexical source representation used by the identity algorithm. Every context object is closed. Strings retain exact Unicode and whitespace; no trim or normalization. Canonical-v1 safe integer and surrogate rules stay unchanged. No new per-context collection threshold is invented: existing source/request limits and the unchanged whole basis limit bound them.

Authored context literals/text are source content, like the existing basis.sourceSteps text. Their preimages are necessary to recompute the existing approved algorithm; hashes cannot replace these contexts without changing that algorithm. This is an internal pure-validation source projection only. It is never a model/provider/public response, log payload, UI explanation or recorder annotation. Referenced plain values, resolved Vault values, configurationValues and materialized input values remain excluded. Materialization evidence keeps metadata-minus-value and full private-document inputHash as previously approved. Plain declaration valueHash is the already-approved identity input, verified against private values by Java before basis freeze; it is not a newly trusted claimed snapshot hash.

`GuidedSourceClassifier` currently freezes declaration/context hashes plus only text contexts. Add a private immutable `authoringSnapshot` to the original source manifest before planning/assignment. It must be the exact normalized v2 source. Existing positive model projections must continue to select allowed fields and never copy it. The existing sourceManifestHash preimage is the manifest minus configurationValues; retain authoringSnapshot in that preimage. Existing source-manifest JSON storage and immutable guards suffice; no new DDL, old migration edit, backfill or user database recreation.

Java verifies `snapshotEvidence.current` equals this frozen authoringSnapshot/declarations, recomputes declaration hashes from the frozen private source values, and checks locked current source/config/identity against the session freeze immediately before publication. Never reconstruct the historical base from live draft variables. On ordinary immutable replay, verify the revision's own authoring/identity/configuration/artifact, retaining existing authorization and readiness integrity.

Insufficient historical identity plus an omitted/positive reuse boundary keeps its original BASE_IDENTITY_INCOMPLETE refusal; there is no automatic fallback.
