# ARCH015-05: admitted retained producer at the replay child boundary

Aria. **Design only; implementation held for independent Quinn mapping review and Orion release.** This corrects the existing deleted-last-consumer / ordinary deterministic replay obligation. It does not close story QA or change the six ACs, prior immutable rulings, raw model rules, public operations, database schema or migration scope.

The omission is genuine. Full `ValidationBasis` validation proves an actual successful retained-prefix producer after its last effective consumer is removed. `effectiveGraph` checks its imported base read, coordinate, recipe, origin and retained current admission; `deriveSnapshotMaps` checks the immutable immediate base, exact program and retained prefix. Artifact structure validation now derives a narrow local set from the published learned plan. However `launcher.ts` projects each historical binding to `RuntimeBinding`, dropping all admission/base/incremental metadata. Both launcher and child call `validateObservedExecute`, whose graph validator has no such provenance and requires a transfer. A valid finalized artifact therefore cannot reach ordinary replay. An ID-only set, trusting a runtime read, inventing a consumer, removing the read, or a caller-supplied boolean would not resolve the distinction safely.

## Smallest complete existing preimage

Add one optional, closed internal IPC property, `Execute3.retainedArtifact`, referencing the **existing whole Artifact3 schema**. It is required semantically if and only if at least one runtime binding has no transfers. It is absent for ordinary graphs with consumers. Absence cannot authorize a zero-consumer read; unnecessary, null, malformed or unknown-field proof is refused. Keep the field out of the raw model, public request/response, job and admission schemas. No new hash domain, proof format, operation or alternate replay generation is introduced.

The whole artifact is used because `Launch3.admission.request.artifactHash` already commits its exact canonical preimage. A learned-plan-only witness can bind actions and provenance via `learnedPlanHash`, but cannot independently reconstruct all original guard metadata, input recipes and scope. A fragment plus a claimed hash cannot be checked against a whole-document SHA256 commitment. Reusing Artifact3 avoids a new commitment scheme and lets the child compare **all** executable metadata with the admitted artifact. The artifact remains inert validated data, never code or a path to load.

## Authority and lifetime

The runner parent continues accepting only a job validated against the backend-issued execution binding and fresh admission. Build the ordinary `Launch3` first. Its admission already names execution/attempt/admission, current revision/digest, artifact, learned-plan, reference-policy, publication-evidence, configuration, scope, profile, build and current-policy commitments. The parent attaches the exact already-validated `job.artifact` only when its final binding graph has an empty consumer list, then validates the Execute against that launch before spawning/sending.

The child retains the **same accepted Launch3 for the lifetime of this one process run**. It never takes the expected hash from Execute, its proof, a model result, environment, a new request, or a mutable global. The NEW → READY → EXECUTING → DONE state machine, one Execute, run/attempt/config/profile equality, initial context, live deadlines, policy/build checks and cleanup remain. Do not replace the launch, mutate its admission request, authorize a second execution, reuse a previous run's proof or accept an Execute-supplied admission. Use a private immutable snapshot of the accepted launch facts if needed to prevent in-process mutation.

`validateObservedExecute` must receive the accepted launch context for this branch, and the executor's own revalidation must receive that same context. A direct executor call with no accepted launch remains strict and refuses zero consumers. A plain serializable boolean/set/hash parameter is not an authority interface. A suitable bounded implementation is an optional typed Launch3 context argument with an absent-context strict path; only launcher and childRuntime supply their already-validated launch. It must validate the necessary closed launch shape/identity and all equality checks below, not silently assume a typed argument was authenticated. This preserves existing no-proof callers and avoids a new public API. No exported generic orphan bypass or caller-authorized allowlist is added. A fabricated complete Launch+admission from a compromised runner parent is outside the existing child trust boundary; schema parsing is not authentication.

## Exact child checks, before any native action

1. Parse a closed Execute3 under the bounded limits below. Compute the exact zero-transfer binding set Z from the complete runtime arrays. Enforce `hasOwn(retainedArtifact) == (Z.size > 0)`. Existing binding/action/transfer uniqueness and all read/guard/origin/recipe/target checks still run. No read can be omitted from binding accounting and no actual binding use can lack its exact transfer.
2. For Z, require the retained accepted launch. Check closed Launch3 shape and existing identities: Execute run/attempt/configuration/profile match launch and its admission request; scope equals the accepted launch scope and hashes to its scopeHash; request scope/config/profile/build identities remain the accepted ones. The existing childRuntime checks remain in place rather than moving admission into the proof. Admission start-time validation occurs when Launch is accepted; **do not reapply the startDeadline after a legitimate Ready wait**. Current run deadline/cancellation stays enforced by existing runtime controls.
3. Independently call `validateReplayArtifact(retainedArtifact)` with its existing one-MiB limit. Recompute with `hashObserved`: SHA256 of UTF8 `canonicalObserved`, sorted ASCII object keys, original array order, valid Unicode, exact strings/nulls and safe integer rules; never pretty JSON, locale order, a caller hash or normalized copies. Require exact `hashObserved(A) == launch.admission.request.artifactHash`. Also require `hashObserved(A.learnedPlan) == A.learnedPlanHash == request.learnedPlanHash`, `hashObserved(A.replayPolicy) == request.referencePolicyHash`, `A.replayPolicy.publicationEvidenceHash == request.publicationEvidenceHash`, `A.configurationHash == Execute.configurationHash == request.configurationHash`, and profile equality with launch/request. These are existing commitments; do not recompute publication history from missing facts or substitute a new hash domain.
4. Remove only principalId from the **accepted replay scope**, and require the resulting requirements object exactly equals `A.replayPolicy.scope`. Match initial context and all existing current-origin/capability checks. Guided learnedPlan.scopeHash is a different historical scope type: do not compare it to the current replay Scope hash or claim historical guided authorization transfers to this run.
5. Exact canonical projection equality: Execute.steps == A.steps; guards == A.guards; bindings == A.replayPolicy.bindings mapped in order to `{bindingId,producer,recipe,origin:sourceOrigin}`; transfers == A.replayPolicy.transfers. Artifact validation already joins learnedPlan actions, guards, recipes, consumers and transfers. Require input array length/order/IDs/step/kind/intendedSlot and secret referenceName exactly match the existing inputRecipes projection (nonsecret kind destination/nonsecretText; secretRef configuration referenceName/fill.value). Do not compare resolved runtime values to recipe metadata: values are released separately and remain governed by the existing type/size/origin/secret rules. No additional input, transfer, binding, action, guard or alternative executable copy is allowed.
6. Derive the exception locally from this hash-bound artifact, never from Execute-supplied IDs. Z must equal exactly the artifact bindings with consumers.length0. For each, require nonnull incremental metadata, actual matching learnedPlan read action, matching binding ID/producer coordinate/recipe/origin, matching producer admission/provenance.sourceIntentStepId, the same guard at that operation, and membership of that admission in retainedPrefixAdmissionIds. Require unique admission IDs and the retained list to be exactly the ordered initial segment of learnedPlan.actions admission IDs; every retained admission must identify one actual action. Initial/effective boundary step IDs must belong to sourceSteps and effective index must not exceed initial. A baseRevisionId is the incremental **historical base**, not the current request.revisionId. Do not equate them. This enforces the available published joins without inventing unavailable base data.
7. Pass only the exact internally derived Z into the existing structural graph helper for this invocation. The public Execute validator still has no permissive set argument. The executor rechecks the same accepted launch, proof, equality and graph before action dispatch; adapters retain all live drift, password-read, read-rule, policy, value-byte, withholding, same-origin, at-most-once, timeout and cancellation checks. Retained reads execute at their original coordinates and recapture fresh values; they are not skipped or replaced with cached values. No model call is added. Clear references to the proof with the Execute on teardown; do not log it or add it to reports/video/results.

## Honest process-boundary guarantees

The backend's immutable revision verification, grants/admission authority and Java history audit, plus the independent complete-basis pure validator, prove actual SUCCEEDED dispatch1 read, original preparations/availability/input version, immediate base artifact/digest/program, raw intent/edge partition, exact first-suffix exclusion and absence of hidden successful consumers. The published artifact contains commitments and derived provenance, **not** those full original ledgers/base evidence. The child does not independently recreate that hidden history, authenticate the backend via SHA256, or prove a native historical success from a retained ID. It proves that this run executes the exact artifact admitted by its retained launch, and that the published local retained-producer joins and every existing child safety rule hold. The established parent/backend admission channel remains the authority root. These layers compose; none is replaced by a `trusted` assertion. Raw model consumers minItems1 remains byte-exact; new model/suffix/orphan needs cannot acquire a successful admitted artifact through this correction.

## Bounds and data handling

Preserve all existing caps. For a frame without retainedArtifact, keep Execute2097152 bytes. On the proof branch, independently bound the frame **with only retainedArtifact omitted** at2097152 bytes and Artifact3 at1048576 bytes, and permit at most **3145792 bytes (3MiB+64)** for the combined frame. JSON.stringify adds exactly20 bytes for the comma plus `"retainedArtifact":` when inserted into a nonempty object, so the64-byte headroom is conservative. Check the combined cap before schema traversal, then the two separate caps before semantic work; retain the existing depth32/node1000000/Unicode checks for the combined frame and each component. Do not raise the ordinary cap, artifact cap, secrets/input limits, job4MiB, basis6MiB or validation8MiB. The optional field adds one nesting level to an already structurally shallow Artifact3; boundary tests must cover combined depth/node refusal. Use a separate internal proof-frame constant or explicit derived cap rather than silently widening OBSERVED_LIMITS.execute for every call.

Artifact3 carries existing learned metadata/locators/recipes and hash-only source identity, not current source text, raw observations, a ValidationBasis, base artifact recursion, resolved binding values, Vault material or model prompts. Do not enrich it. Existing released input/secret values stay exclusively in their current IPC fields with their current withholding/clearing behavior. The duplicate artifact is a witness only: executable arrays remain the existing Execute arrays and must equal its projection. Do not create two authorities, select the more permissive copy, execute from both, introduce a source fallback or route any proof data to providers, stdout/stderr, environment, argv, reports, media or public API. A negative proof rejects before any native **replay action**; Launch may already have opened the recorded browser under the existing protocol.
