## Why the head negative is reachable and faithful

V21 `studio_015_materialization_capture` and deferred `studio_015_version_commit` validate canonical payload/hash, counts, version envelope and actual normalized input entries. They do not compare a future proposal sourceInputId with those entries. `studio_015_preparation_version` validates the current version identity. `studio_015_action_attempt_guard` checks document/proposal version equality, exact preparation/proposal digest, current version, bounds and attempt identity; it adds no SQL reference-input FK. V14 action checks preserve action coordinates/state/dispatch and proposal immutability. Thus the one pre-hash missing-ID variation can retain every relational/version constraint.

The current V21 `studio_secret_guided_input_reference` joins the action's proposal contextRevision/authoredInputsHash to the actual snapshot, then searches for its exact sourceInputId and declaration provenance. The chosen fixture has zero matching inputs, so the actual helper returns NULL. V17's still-installed audit guard then executes precisely the original fail-closed branches: NOT_USED refuses whenever any consumed secretRef admission has unknown reference lineage; an admission-bearing audit first requires a nonnull exact reference. This is the intended production guard and original SQL boundary, not a toy or a historical surrogate. The plan does not claim this malformed reference can pass the production Java admission path: `GuidedProposalValidator` and `GuidedDispatchService.secretInput` require a real matching materialized secret input.

Current `SecretAuditLifecycle.guidedReferenceId` and guidedTerminal use `studio_guided_materialization_snapshots` with historical context/hash. They cannot truthfully be tested as current Java against pre-V21 schema. In a missing-input state, Java terminal classification's attempted unreached summary is still constrained by the actual SQL audit guard; no Java success is claimed by this database-only port. Backend-owned Java lineage and terminal transaction regressions remain separate and required; no assertion is removed from their suites.

Pruning is not a route to the old state. V19 `studio_guided_prune_session` retains session/source/action/materialization data, prunes selected progress/model safe_result and unpublished publication copies only. V21 does not widen that scope; normalized version/input history is immutable and remains retained. `GuidedMaterializationService.stop` sets live=false rather than deleting rows.
