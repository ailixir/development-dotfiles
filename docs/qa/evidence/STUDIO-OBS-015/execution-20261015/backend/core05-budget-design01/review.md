# Core05 budget architecture decision

The two Core05 failures are a truthful per-session output reservation stop under the existing fixture ceiling. They are not evidence of a reservation leak, the former outcome-validation defect, or a browser UNKNOWN retry problem. Recommend a separate immutable **2048-output controlled-fixture JVM**, using the existing supported translation property, while retaining the original **4000-output JVM** and exact accounting witnesses. Do not change production accounting or budgets.

## Decision boundary

Recommend the task/JVM partition as the minimal faithful **test-only configuration** route, conditional on source review and actual capacity/input/routing/coverage proofs above. No owner scope amendment is needed merely to exercise an already-supported lower immutable controlled-fixture configuration while keeping all original proofs; root still must explicitly release implementation files through the established process. There is no evidence justifying production reservation refunds, a32000/262144 increase or a new purpose-specific production allocator. If the approved acceptance explicitly requires this ten-step flow at default4096 rather than a supported configuration, or if actual supported lower-capacity runs cannot satisfy the unchanged workload, that narrower conflict requires product/owner review. This read-only decision does not grant that amendment and does not mark anything Done.
