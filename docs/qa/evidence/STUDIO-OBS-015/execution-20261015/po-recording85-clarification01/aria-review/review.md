Two concrete characterization details must be resolved before source readiness:

1. **Actual backend authority boundary.** `GuidedSessionEvidenceService.record:79` authenticates owning-worker name/fence/scope/context/version and applies `acceptAndDerive` to `evidence.ledger(id)`. `GuidedSessionEvidenceRepository.ledger:76` reads actual studio_guided_actions; arbitrary recording IDs in an in-memory list do not pass that route. The proposal must name a separate isolated **fixture-owned** session/ledger seed, exact enabled SQL constraints and real HTTP callback/result/media path, and demonstrate lawful fixture reachability without disabling guards, adding a bypass or inserting characterization readings into either genuine production admission. Any synthetic SQL admission/receipt remains explicitly synthetic; a real database row or JWT does not upgrade its native authority. No such complete seed/callgraph is supplied by the PO proposal, and this review does not invent one. A recorder test with an explicit synthetic LedgerAction Map and callback shim is a lawful lower-level experiment, but does **not** satisfy the proposal's actual authenticated backend/DB/result clause; do not substitute it silently.
2. **Exact fractional sample retention.** Recorder readings are private in evidence.ts; the wire intentionally retains only rounded integers. Extra clock calls before/after begin are not the begin/end sample. Retaining fractional evidence needs an exact read-only, non-transforming test observation of the actual returned begin/end samples at the existing recorder boundary, with no altered source/clock object/reading and no new timing field or production disclosure. The proposal has not mapped that observation mechanism. It must be reviewed before implementation; do not inject a test clock or use guessed interpolation as “raw samples.”
