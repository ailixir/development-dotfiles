# Native feedback01 bounded remediation design

This independent Aria source review explains the captured 42-case result (30 PASS, 12 FAIL, zero skipped) and recommends bounded changes. It is not a QA gate, implementation release, native rerun, authority proof or story completion. The captured first failures and their original private media remain immutable. No code, test source, dist, fixture configuration or runtime was changed by this review.

## Verified failure partition

The original mixed ten-step case fails at `targetFor` with `NODE_source`; the new partial-step case fails at `partialTarget` with `MISSING_NATIVE_FACT`. Both stop before their first read, so they have not proved fresh binding capture, mixed suffix execution or ordinary replay. In the source fixture, the original source is an unlabeled generic DIV; the partial fixture similarly uses an unlabeled generic DIV. `observationCollector.ts` requires a safe nonempty semantic label for export, and application region read grants only authorize ordinary scalar OUTPUT/DD/TD/status surfaces, not arbitrary generic subtrees. A test ID alone does not grant reading. This is faithful policy enforcement, not a production read defect.

Five new secret branches (bad-origin, zero-password, two-passwords, focus-typeflip, stopped-lease) fail at the later `scan(native.scratchDirectory)` after the owning runtime already closed. The real `launchGuidedBrowser.close` closes Chromium and immediately removes that private scratch directory. Missing-root ENOENT must not become a passing empty privacy scan. The valid and oversize-frame branches instead reach journal postchecks and fail because each line is parsed as JSON. `GuidedJournal.consume` writes a bare 64-character hash followed by newline; `fence` writes a canonical JSON NativeFenceEvent followed by newline. Both record formats are intentional and must remain checked.

The older native-guard diagnostic case expects FAILED but the captured result is UNKNOWN_OUTCOME. This expectation conflicts with current durable invocation semantics: `fillPassword` commits `beginInvocation` before the isolated-world fill call; the fixture changes the password input type during focus, so the trusted refusal occurs after that native call started, even though no value was written. `GuidedRuntime.dispatch` deliberately requires `!nativeFence.started` for FAILED or drift. The new R1 tests already preserve this distinction. The older injected-released-value diagnostic case passed and must remain unchanged as a countercontrol.

The two older ordinary replay cases with zero or two password candidates expect POLICY_REFUSED with secretUse REFUSED, but instead receive INTERNAL_ERROR. `prepareObservedAction` calls `observations.preparePassword` outside `performPreparedObservedAction`'s mapping catch. Trusted `PasswordNoEffect(PASSWORD_TARGET_ABSENT|PASSWORD_TARGET_AMBIGUOUS)` therefore escapes the ordinary adapter and the executor correctly classifies the unrecognized raw error as INTERNAL_ERROR. This is a real ordinary-adapter error translation gap. The preparation itself performs no fill and the existing native tests verify empty DOM/no login receipts.

## Production correction boundary

Add a narrow catch around the ordinary adapter's `prepareObservedAction` await, in `createObservedReplayAdapter.perform`. Recheck `control.check()` and `guardLive()` before classifying a rejected asynchronous preparation so cancellation, deadline and withdrawn authority retain precedence. Only in password-control secret-fill preparation, while still PREPARING, translate the trusted private `PasswordNoEffect` instance with exact approved preparation codes: ABSENT/AMBIGUOUS to `ObservedRefusal(POLICY_REFUSED, approvedConstant, true)`; TARGET_CHANGED to `ObservedRefusal(TARGET_DRIFT, approvedConstant, true)`. Prefer spelling exact known constants rather than carrying arbitrary exception text. Preserve existing ObservedRefusal objects after authority checks. Rethrow all other errors unchanged, including ordinary Error with identical text, unknown PasswordNoEffect codes, transport/native failures or impossible late phases. The executor continues to export its closed error code only, without raw exception messages. No call to beginInvocation, no synthetic timing, no retry, no reacquisition and no browser restart belong in this catch.

Do not put this translation in the shared `prepareObservedAction` helper: GuidedRuntime.acquirePrefix also calls it and intentionally handles raw password preparation failures by closing, while TARGET_CHANGED has its governed drift handling. Do not broaden executor.replayError globally, alter `PasswordNoEffect` trust construction, touch the performPrepared catch, or make no-effect claims for an already started native fill. This repair needs one production lease only: observedReplayAdapter.ts.

That wrapper sees explicit stop, automatic preparation-failure close and automatic post-invocation UNKNOWN close. This retains the consumption and at-most-once subjects while correcting the parser.

For the old native-guard diagnostic case, replace its stale FAILED expectation only with stronger evidence: actual exactly-one fill INVOKING event, UNKNOWN_OUTCOME/TARGET_CHANGED, dispatchCount1, accepting false, no drift receipt, repeat dispatch refused and zero DOM writes observed before actual close. If adding a recorder to that older diagnostic case would create unnecessary fixture changes, the new R1 focus-typeflip case supplies the actual recorded null-end companion; explicitly cross-reference that tier and do not claim a timing check inside an unrecorded test.

Assert failed preparation never reaches fill or beginInvocation, no added observation retry, one disposal, unchanged rejected native phase. Existing password transport tests remain controls against promoting postwrite text or malformed private facts to no-effect. These are behavioral safety regressions, not tests mirroring a new mapping helper.
