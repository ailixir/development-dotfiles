# Terminal-settlement implementation design

Authority: fresh corrected Pax GO `t2-t3-po-bootstrap-closure-revalidation.json`, applied exact text in `bootstrap-closure-application/receipt.json`; root explicit D/B release follows source-bound root143/D41 baseline. This is development design, no QA/lifecycle verdict.

Distinct CLOSED-only `studio_observed_terminal_secret_settlements` stores safe accepted execution/history/attempt/revision/digest/binding/full scope, actual database-captured before_state/before_updated_at/before_snapshot_revision, planned terminal code and exact COALESCE terminal-time locator, unique bounded disjoint no_read_ids/possible_read_ids and its own occurred_at. Planned error/time are proposals only, independently compared with actual winning history at commit; any existing history endedAt is captured for the close COALESCE rule. No lease is supplied or borrowed; a lost/expired claim can be closed by the actual terminal winner under the existing state matrix. The API is `boolean recordObservedTerminalSettlement(UUID executionId, String plannedErrorCode, Instant plannedEndedAt)` in the actual caller transaction before its terminal transition. Non-observed/ineligible/already-terminal owners append nothing; raw attempted insertion against a wrong before-image refuses. Empty remaining declaration inventory needs no new receipt.

The insertion guard independently locks the actual owner and history, requires QUEUED/CLAIMED, no dispatch attempt/admission/observed receipt and PENDING history, and captures/compares the actual before-image. After any waited owner lock it runs a separate fresh VOLATILE SQL statement for current declared IDs and committed scoped read entries; Java classification is also post-lock. Existing actual decisions or summaries take precedence and are excluded. Caller state/error labels/booleans cannot establish before-image or choose omitted/invented IDs. Exact accepted no-read IDs under B's universally enforced committed write-before-value-read protocol settle NOT_USED; exact possible entries with no committed decision settle audit-only UNKNOWN_OUTCOME. No version/resolution/use/refusal is inferred from a marker, and physical read counters remain separate joined evidence.

Pending terminal receipt fences new read-entry, RELEASE and dispatch/admission/requeue transitions. The only subsequent execution-authority transition is actual DONE, with terminal ERROR history. B generic close, immediate cancel, pending reaper and kill-switch preserve their existing predicates; request-only cancel/losers do not invoke a successful receipt or throw to roll back if CAS loses. Every receipt/complete new summary and owner/history update commits or rolls back in the same physical REQUIRED transaction.

Deferred guards on current/future plain leaves require owner, history, receipt and new summary row versions to belong to the current top-level PostgreSQL transaction, with exact locator/binding/attempt and complete classification. Savepoint/subtransaction writes for these transitions are deliberately prohibited by this top-XID invariant and tested as refusals. No transaction ID is persisted as long-term identity. Immediate cancellation need not populate generic close terminal_error fields; its actual ERROR/CANCELLED history/time, DONE owner/cancel marker and advancing snapshot must match the proposal. Generic populated owner terminal fields must match as well. Both actual owner/history row versions must be this transaction.

The new family follows occurred_at monthly partitions, no DEFAULT, existing twelve-month Q3 retention and stable owner/attempt dedup across months. No self-FK prevents bounded expiry. Immutable parent/leaf UPDATE/DELETE/TRUNCATE and initial/future partition installation are mandatory. Existing live-owned completed-resolution no-send CLOSED/REQUEUED/outage authority remains separate and unchanged. No new wire field/enum or additional provider read/send is introduced.

Actual B provider/control crash/read/send/cancel/reaper/kill-switch and Core joins remain mandatory; data fixtures prove SQL/transaction/race metadata only. The retained pre-amendment zero-summary oracle will map explicitly to one authentic UNKNOWN after an entered/no-decision terminal winner; historical result remains preserved.

The retained read marker is conservative possible-read evidence, not authority for another read. B's fresh committed-entry verifier requires creator lease_owner to match the actual current owned claim before calling the provider. An abandoned marker under another owner therefore cannot authorize an extra value call on the same accepted attempt. Terminal classification still includes that scoped marker as UNKNOWN rather than false NOT_USED; a genuine outage/definite-refusal fresh attempt carries its own marker. No database receipt proves a physical read count.

The source-bound candidate `t2-terminal-settlement-candidate.json` retains all original41 data case names and32 active pre-V34 migration bytes against the root143 ZIP. Three historical incomplete-summary assertions are explicitly mapped under the new canonical terminal authority: entered/no-decision closes with scoped UNKNOWN; completed partial no-send retains its LATER NOT_USED row and separately settles FIRST UNKNOWN; an empty completed no-send receipt retains its receipt/closure assertions while the separate terminal family adds genuine no-read NOT_USED. Original red/green143 snapshots remain immutable. The twelve additional cases cover independent raw scope/beforeimage/set refusals, missing summaries, cross-month identity, actual commit locator/rollback, retained positive facts, dispatch/read/release cut, waited writer freshness, actual savepoint refusal, ordinary writer append-only/DDL denial and real partition retention. These are pending test claims until fresh PostgreSQL XML.
