# Approved data A/B implementation design

Root released this stage after the source-bound mechanical gate. Exact authority: `t2-t3-po-architecture-revalidation.json` items A/B and applied receipt. No lifecycle/QA verdict.

Guided unreached identity uses the exact immutable manifest referenceId/declaring step and current terminal fence. Actual ordinal/admission/resolution/release/version/sequence are absent. Stable declaration duplication and any retained real consume/decision/summary exclude false unused across fences/time. Consumed unknown keeps real admission/ordinal/proposal/materialization source-reference provenance/fence, with no fictitious release sequence.

B agrees `recordObservedReadEntry(binding, actualLeaseOwner, secretId)` in a committed caller transaction before each existing value read; no additional provider call. `recordObservedNoSend(binding, actualLeaseOwner, positivelyNotEnteredIds, CLOSED|REQUEUED)` appends a safe receipt and unlinked NOT_USED rows before the winning owner transition in the same locked transaction. IDs originate positively from the accepted declaration iterator minus entered reads and actual decisions, never missing FINAL/decision rows. Receipt insertion validates live owned CLAIMED/no current attempt/admission/receipt and the accepted binding/revision/scope. A per-leaf deferred constraint verifies the final logical CLOSED (actual ledger DONE/history ERROR) or outage QUEUED state and exact accepted identity. CLOSED preserves the existing recorded owner or a cleared lease; QUEUED requires the existing cleared lease, plus actual ledger row version written by this transaction and exactly one summary for each positive ID. Receipt-only commit, rollback, stale/losing closure and post-send inference refuse. No new retry authority.

Both safe evidence families use occurred_at partitions under existing 12-month retention, no DEFAULT, owner-row→owner-advisory→event lock order, immutable row and direct-leaf TRUNCATE guards. Actual read-entry/receipt linkage is scoped and verified at insert; no self-FK prevents bounded partition retention. Actual caller/Vault counters and joined kill/crash/send oracles remain B/T4 obligations.

PostgreSQL15 documents that each update creates a row version whose xmin is the inserting transaction identity; xid8 can be cast to xid. The deferred comparison is local to the current transaction, not a long-term transaction-ID identity. Current B caller uses one physical joined transaction without savepoint-based state transitions. Deferred constraints are installed on plain leaf partitions; future partition manager installs identical guards.

Primary sources: [system columns](https://www.postgresql.org/docs/15/ddl-system-columns.html), [transaction functions](https://www.postgresql.org/docs/15/functions-info.html), [constraint triggers](https://www.postgresql.org/docs/15/sql-createtrigger.html).

An ordinary replay read-entry followed by controller crash before a committed resolution has no approved unlinked UNKNOWN shape. This stage refuses false NOT_USED and retains the unmatched summary obligation explicitly for a narrow independent Aria/PO proposal; SQL metadata is not physical-read proof.
