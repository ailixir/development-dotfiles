# Studio evaluation harness

Two layers live here. The observed-authoring benchmark (STUDIO-OBS-009 AC-7 to AC-10) is the live one. The compile-era oracle and report layer is kept only as far as it still applies.

## Observed-authoring benchmark (`observed-authoring/`)

The compile-era driver `lifecycle.mjs` is gone: under the single path (ADR-SC-005) there is no `/compile` or `/confirm-compile`, so a driver for them was dead code. `observed-authoring/evaluate.mjs` replaces it and talks to the **public** Studio API only: create a draft, start a guided session, poll it, answer a clarification only when the case script names the choice (otherwise count it and cancel), finalize exactly once, replay, read the result. It scores each run against an oracle that is independent of the model, the learned plan and the runner.

What is committed, and what it is not:

| File | Purpose |
|---|---|
| `observed-authoring/manifest.json` | 25 workflows: 19 class P, 1 class F, 5 class N. Candidate metadata is deliberately unfrozen until actual QA/re-freeze (`manifestFrozenAt`, `manifestSha256` are null). Pins the sha256 of every step text, page, expected outcome, fixture server and the 2026-10-04 `results.jsonl`. |
| `observed-authoring/pages/<case>/` | Re-authored fixture pages (loopback, ephemeral port), the step text and the expected outcome of each case, and `pages/server.mjs`, the host that logs page views and posted events itself. |
| `observed-authoring/cases/*.json` | The two STUDIO-OBS-015 incremental cases. Owned by 015, consumed unchanged. |
| `observed-authoring/evaluate.mjs` | Manifest validator and freezer, outcome oracle and its four mutation controls, canary scan, isolation check, run driver, scoring and accounting, replay-stability scoring, B7 measurement, budget-admission ledger, start guard and stop rule. |

Rules the harness enforces:

- **Ported means re-authored.** Each of the 13 ported cases carries a fidelity record: what is known from the 2026-10-04 record (cited by `results.jsonl` row lines and the file's sha256), what was re-authored, and an `invented` list that must be empty. `comparisonClaim` is `NONE_NO_COMPARISON_TO_20261004`; no 2026-10-04 number is a baseline.
- **Independent oracle per case.** The oracle is the fixture's own record (page views logged by the host, events the page posts, or the existing fixtures' receipts), never the runner's DOM check and never the system's own PASSED. Class F and N cases expect no side effect at all. Expected outcomes are written and hashed before any run; a run that starts before `manifestFrozenAt` is refused.
- **Mutation controls.** Wrong target, reversed assertion, dropped submit and literal substitution are each injected against every oracle and must be rejected.
- **RS-1.** Every case has an explicit RS-1 mark (`[]` when it reads no value). Pages are not edited to dodge it. `rs1NonScalarReadGaps`, `authoredEchoUnobservableTargets` and `focusMutationRefusedFills` are present as integers on every run record, 0 confirmed events when none are classified; causeAssessment remains UNKNOWN until actual closed review and independent adoption establish coverage. Default0 is never verified absence.
- **Gate arithmetic is computed, not typed.** Class P only: 19 x 3 = 57 runs, at least 52 completions (51 of 57 fails), at most 5 failed. With the two staging cases unrun it is 51 runs, at least 46, and the result is `PARTIAL`, never a pass. The class-P denominator and negative iframe boundary follow PO85506e3d / architectb602698e. E3 does not establish correct-refusal quality or successful iframe support. D3/incrementals select mixedVisible by corpus design; D2/E1 stay separately uninspected UNKNOWN. No optional N-RS1 or exact-P predicate change is included.
- **Budget admission before any provider call.** `budget-admission.json` is an append-only, hash-chained ledger. A `D_C` run starts only if its latest entry is `ADMITTED` for exactly this manifest digest. With the price or the headroom unknown the status reads `ADMISSION_REFUSED_PRICE_UNKNOWN` or `ADMISSION_REFUSED_HEADROOM_UNKNOWN` and the harness makes zero provider calls. The token caps and the cost bound come from an explicit proposal plan (planned proposals x contingency x the per-call ceiling for output; x bytes per call, or one named cap, for input), not from sessions x session totals (MODEL-SIZING, 2026-10-18). The stop rule halts after the session that crosses 80 percent of the allocation, or at the first false pass or leak; a session with unknown public budget counters is charged what it recorded as reserved, and only a session with nothing recorded is charged the session totals. These are conservative protective charges, not observed provider usage/billing.
- **Self-tests are not evidence.** Runs driven by a scripted client are labelled `HARNESS_SELF_TEST_NOT_D_C_EVIDENCE` and their verdict is `NOT_EVIDENCE`.

Commands, from `studio-runner/` (Node 24):

```sh
node evaluation/cli.mjs validate-corpus                 # structure, arithmetic, every pin re-read from disk
node evaluation/cli.mjs freeze-corpus                   # fills the pins, stamps manifestFrozenAt / manifestSha256
node evaluation/cli.mjs corpus-mutation-control         # positive control plus four mutants per oracle
node evaluation/cli.mjs admission-record LEDGER --create --planned-proposals N --contingency F (--input-bytes-per-call N | --input-token-cap N) --plan-basis TEXT [--price-in --price-out --price-source --headroom --headroom-source --allocation]
node evaluation/cli.mjs admission-guard LEDGER          # exit 0 only when the latest entry is ADMITTED for this manifest
node evaluation/cli.mjs b7 EVIDENCE.json...             # proposals per session from fixture-provider budget evidence
node evaluation/cli.mjs benchmark CONFIG NEW_DIR        # live D_C raw/unreviewed records plus original execution/admission snapshot
node evaluation/cli.mjs benchmark-report CONFIG NEW_DIR # offline immutable originals + cause-only annotations; zero API/provider calls
pnpm --config.package-manager-strict=false exec vitest run test/evaluation --coverage.enabled=false
```

What cannot be done from here, and who owns it: any model call, the AC-8 gateway probe (ED-01 owner), the deployed stack and internal image (U4), the staging login and SSO cases D2 and E1 (U3, application owner), the budget figures (user: headroom; ED-01 owner: price list), the actual U13/AUTHORED-ECHO-01 disposition before its coding/first real call (FOCUS-MUTATION-01 remains credited), and the human C-17 masked-video reviewer. The HTTP binding `createPublicApiClient` was written from the OpenAPI text and has not been run against a live backend. The incremental case checks only what the public API shows (per-step `learnedFromThisRun` and `reusedFrom`, counters around finalize); backend reservations per prefix step and merged-revision replay model calls stay with the backend integration tests.

## Cause review and offline report binding

The existing builder reports `gateP`, `creditedAllClasses` and `allAttempts` separately. Counts are classified-event claims; verified totals require complete bound independent review, otherwise total is null. Earlier excluded attempts and all original false-pass/leak facts remain. Code checks exact bindings and closed types; it does not authenticate a reviewer, infer causal truth from a name/hash, or supply actual independent QA adoption. Generic BUDGET_EXCEEDED, page marks, successful sessions, missing canaries and display hints never establish cause or absence.

`benchmark-report` config names `manifest`, optional `corpusRoot`, pinned `rawRuns` and `causeAnnotations` references, `reviews` references, `independentQaAdoption`, `originalExecution` and `admissionLedger`. Each reference is `{path,sha256}` over exact file bytes. Raw original JSONL is never rewritten. The annotation header binds its hash; exactly one ordinal/canonical-record-hash/manifest/case/rep/attempt annotation covers every original position, including UNKNOWN. Only cause counts, cause-event arrays and causeAssessment may differ; events/counts already present cannot decrease. Non-cause details, completion/oracle/hard facts, modes, infra, timestamps, sessions and counters stay original. Disputed raw facts need a separately authorized successor retaining their original claims.

Closed review records bind each cause, original raw record, authored-goal/outcome/location pins and justified observation scope. Independent adoption must cover those exact records and actual original execution/configuration evidence. A hash-shaped claim alone stays UNKNOWN/non-adoptable. The CLI preserves original/refusal artifacts and writes only a fresh destination. HARNESS_SELF_TEST cannot become D_C. The admission reference must identify the immutable original-time ledger snapshot (future live output `admission-ledger.json`), not a later mutable ledger substituted as permission. It verifies the effective original entry and admittedAt before the execution start and every included D_C run. Legacy missing original receipt/snapshot/provenance remains UNBOUND/refused; no rescore-time timestamp or inferred limits identity repairs it. Later ledger entries neither admit earlier work nor rewrite its retained snapshot.

Learn sessions preserve separate base/suffix facts. Each started learn is charged once; a base failure, leak or existing stop starts no suffix. A partial repetition retains real base SUCCEEDED with whole published:false and explicit incomplete oracle; base success alone is not a final false pass. Later hard facts share the existing latch without charging again. The three scopes expose logical attempts, known started sessions, unknown scope, per-value known subtotals and null incomplete totals. An empty population is not observed zero; an affirmative complete no-start record can establish zero. Public proposal/reservation counters and conservative/fallback stop charges remain `PUBLIC_BUDGET_COUNTERS`/named protective bases. Proposals are not actual wire calls. Actual provider tokens/cost remain null/UNAVAILABLE; this code does not manufacture ED-01 or MODEL-SIZING per-call evidence.

An observation failure retains only public replies already captured by the existing driver. Known base/suffix session facts and protective charges survive; an unacknowledged start keeps `learnSessionsComplete:false`, unknown top-level counters, and an omitted `suffixStarted` rather than an invented not-started assertion. Its potential consumption uses the existing conservative fallback charge separately from observed session counts. The driver stops before another logical attempt. No backend state or infrastructure exclusion is fabricated. Process death or fixture cleanup failure before the original receipt is emitted still leaves original provenance UNKNOWN; this is not a durable crash journal. Actual independent review and deployed configuration evidence must be supplied by their existing owners: the current `admission-record` code-default/pinned:null record alone cannot establish the original deployed configuration for adoption.

The numeric gate is only a completion/hard-fact subgate, not completed D-C or pilot acceptance while required usage, staging/security/U13/privacy/human evidence is missing. Required evaluator/CLI/page-server source pins, actual source QA, existing freezer and a new prior admission remain necessary after actual application; old e4785112 admissions do not transfer. All75 logical runs/81 model sessions/122 contingency sessions and the original25 workflow/page/outcome bytes remain unchanged. Actual provider prices, sharedUSD500 headroom, configuration/staging facts and independent review adoption are UNBOUND here.
