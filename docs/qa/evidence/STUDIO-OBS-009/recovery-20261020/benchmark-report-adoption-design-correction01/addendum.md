## C1 — Replace §1's reviewed-JSONL replacement with a cause-only overlay

The proposed thin `benchmark-report` branch takes **both** immutable original runs JSONL and separate cause annotations. Its config names each input's path/SHA256 plus the original manifest, original execution receipt/admission reference, actual closed cause-review records and independent QA adoption record. The new report binds their separate hashes, including the exact original file hash and complete original attempt identity/multiplicity. It never writes originals.

The overlay header binds `rawRunsSha256`. Each annotation names `rawOrdinal` (1-based record position), `rawRecordSha256` (canonical original record), and its original manifest/case/rep/attempt. Require exactly one annotation per original ordinal, including an explicit UNKNOWN annotation where review is incomplete. Reject omissions, inserted references, repeated ordinals, wrong hashes and identity changes. Preserve duplicate/invalid raw identities as original invalid evidence; never deduplicate them into a valid run. Ordinal/hash are local file bindings, not new runtime or limits identities.

Construct scoring records **from the original array**. The only permitted overlay paths are the three cause counts, their `details[CauseField]` arrays and `causeAssessment`. Reject other keys; preserve every non-cause detail (including canaryFindings). Completion/oracle/falseSuccess/leak, mode/manifest, infrastructure classification, timestamps, original session/learnSessions/counter facts and all other observations come from the immutable raw records. A cause annotation cannot repair or populate missing usage/session facts. Known original positive cause events/counts cannot disappear or decrease through this adapter; retain their identity/provenance. A disputed original attribution or other raw fact needs a separately authorized reviewed successor/disposition retaining the original claim; this bounded adapter does not silently correct it.

The same existing `buildBenchmark` scores the projected records; c12's all-attempt hard-gate logic stays unchanged. Reference the preserved original identity fields after any permitted detail merge. All-attempt and completion selections therefore receive the exact original attempt population and immutable hard facts.

## C2 — Tighten §1/§4's adoption and original-time admission

The named closed review records must actually exist and match their hashes; each binds the original raw file/record, manifest/case/rep/attempt, relevant pinned goal/location/step/slot and the justified observed scope. The independent QA adoption record must actually review those exact records/input hashes and identify accepted versus unresolved fields. Hash/shape/name validation does **not** authenticate a reviewer or establish causal truth. Code validates bindings; the existing non-author QA process establishes actual adoption. No authentication service, signature registry or new approval framework is requested. A caller typing VERIFIED or supplying an unrelated plausible hash never supplies that adoption.

Missing/mismatched independent adoption or incomplete causal scope yields UNKNOWN and null aggregate totals; it cannot yield an adopted D_C pass. Known positive events remain visible. The branch may refuse adoption or write an explicitly non-adoptable draft containing the preserved hard facts, but cannot promote self-tests/calibration or certify a complete-zero scope from empty arrays.

Admission belongs to the **original execution**, not rescore time. Bind the real original execution receipt, raw-input hash, manifest and actual admission ledger entry (sequence/entry hash, purpose `ac7-benchmark`, manifest, recorded price/headroom/allocation/configuration references). Verify ledger integrity and the entry that was effective at original start, including no intervening same-purpose refusal/stop before that start. Require `admittedAt < original execution start` and `< every included D_C runStartedAt`. Do not merely call today's `guardStart` with now: its current comparison is only admittedAt-before-now, and a later admission cannot authorize an earlier run. Entries appended after execution do not retroactively authorize it or erase its then-effective admission.

Missing/invalid original start evidence, original admission, actual required price/headroom/configuration evidence or independent adoption is UNKNOWN/refused for D_C adoption. Do not infer a trustworthy original start from an operator-entered timestamp alone; QA verifies the existing execution receipt/provenance. Offline reporting appends no admission and contacts no provider. Future code/metadata freeze still needs its own new admission **before future execution**. No limits identity is added or inferred from a manifest digest.

## C3 — Make §3's per-session stop and partial repetition explicit

Use the proposed at-most-two `learnSessions` records to preserve each started phase's real sessionId, terminal/publication facts, counters and any independently observed phase hard facts. Add closed local fields to the existing `incremental` object: `logicalStatus:'COMPLETE'|'INCOMPLETE'`, `suffixStarted:boolean`, and `notCompletedBecause:null|'BASE_NOT_SUCCEEDED'|'STOPPED_BUDGET_80'|'STOPPED_HARD_GATE'`. These are harness repetition metadata, not new API session states.

Order in the existing incremental driver:

1. Learn base; retain its actual state/counters and perform the existing scoped canary scan. Call existing stopRule.record **once for that base**, before any suffix start. A failed base, base hard fact or stop prevents the suffix. No second charge is issued for the base.
2. Only if base succeeded and nextSessionAllowed remains true, perform the existing token-free base finalization/current-draft update and start the suffix. Recheck the existing latch immediately before starting it. Preserve any hard facts found during those intervening operations. Learn suffix and retain its actual facts; charge it exactly once. Finalize/evaluate only the actually reached phases.
3. Facts learned after a session was charged must still stop subsequent sessions. Refactor the existing stop-rule latch into one small `observeHardGate({falsePass,leak})` method, shared by record, which latches STOPPED_HARD_GATE without incrementing sessions or spend. It may retain a hard fact even after a budget stop; preserve both observed reasons in the run's existing `details` extension surface as `details.stopObservations` with closed phase/reason rows (phase base/incremental/final-oracle; reason STOPPED_BUDGET_80/STOPPED_HARD_GATE). These are immutable emitted facts, not cause-overlay keys. Never call record again on an already charged session or after a stop. This is the same protective rule/threshold, not another engine; createStopRule's conservative unknown-counter fallbacks remain.

For a stopped/failed base with no suffix, preserve the base's real terminal state, even SUCCEEDED, in its phase record and the current last-session projection. Set whole-incremental `session.published:false`, `logicalStatus:INCOMPLETE` and the actual suffixStarted:false/reason. Do not manufacture a backend CANCELLED state. Do **not** feed a legitimate successful base alone into the final whole-workflow `evaluateOutcome`: its current claimsSuccess test would wrongly call missing suffix phases a false success. Instead emit the explicit incomplete repetition verdict `{correct:false,falseSuccess:false,failures:['incremental-not-completed']}` unless a genuine independently observed phase false pass exists. Preserve such a genuine false pass as top-level oracle.falseSuccess:true and retain its phase evidence; preserve all genuine leak facts likewise. Base SUCCEEDED by itself is not such a fact. With published:false and correct:false, the existing P completion selection grants no completion; the P attempt stays counted as an unsuccessful logical repetition. No infrastructure exclusion is invented for a budget stop.

A complete repetition still uses the unchanged final independent oracle. A partial repetition's absent suffix is **not** an unknown started session: it is affirmatively not started. Any ambiguity about whether a session actually started remains unknown coverage instead.

## C4 — Complete §2/§3's missingness and units

Add proposed `learnSessionsComplete:boolean` to emitted records: true only when the driver has complete knowledge of which learns started; absent on old records means UNKNOWN. The cause-only overlay cannot add/change it. Keep each known session's proposal/input/output value nullable independently. Raw infrastructure attempts with unknown session-start scope remain in unknown-attempt scope; never disappear from raw spend summaries.

For each existing report scope (gate-P, credited-all and all-attempt/session charge views), retain known subtotals and named unknown attempts/sessions. A complete total is a number only when session coverage and every included value are known; otherwise null. Report logical-attempt denominator separately from known-started-session count and unknown scope. An empty input population has null totals/percentiles, not measured zero. An affirmative, complete original record proving no session started can establish zero for that nonempty attempt scope; missing records cannot. Quantiles from incomplete samples must either remain null for the requested complete population or be explicitly labelled known-sample-only with their missing denominator.

In particular, replace the current proposal-counter filter/reduce that can turn missing counters into total0. Public modelProposals counts reservations/proposals; it is not independent observation of actual provider wire calls. Keep its complete/known-subtotal/unknown-session summaries explicitly labelled as proposals. `modelCalls.total` as an actual wire-call claim remains null/UNAVAILABLE without the actual required closed call evidence; do not relabel complete proposals as measured calls. The same missingness rule applies to session counts and input/output budget-charge totals. Preserve PUBLIC_BUDGET_COUNTERS labels, conservative stop fallback amounts/bases, and actual provider token/billed cost UNKNOWN until their actual independent evidence exists. A conservative charge or fallback never fills an observed-usage field.
