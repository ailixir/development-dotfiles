**Correction1 — scope the conditional evaluator change accurately.** `evaluate.mjs:151–155` rejects P only when `fixture.server` contains `guided-dataflow` **and** mode is exact. It does not prohibit every RS-1 P case: current D2/E1 have `fixture.kind:staging` and no such server. Finding a genuine staging RS-1 therefore requires accurate P/RS-1 manifest pins, run classification and accounting, but does **not by itself** require editing EXACT_MODE_CASE_IN_CLASS_P. No current25-case mode/class change is needed or recommended.

The blanket predicate is nevertheless incompatible with AC-7 RS-1(b) **if an actually approved unambiguous exact guided-dataflow P workflow needs admission**. Before activating that case/configuration, permit that narrowly identified P configuration only when its required unreachable location is explicitly marked/reviewed as RS-1; retain mode-required validation, consistent valueLocations, class-P completion oracle, independent pins and all thresholds. Do not mark it N, silently change mixedVisible to exact, or rewrite the page to OUTPUT. One minimal predicate narrowing can preserve rejection of *unmarked* exact-P fixtures while allowing correctly marked/reviewed RS-1 P. QA must prospectively verify the actual authored goal/location/oracle; the boolean alone is not evidence. The old B5 “no exact P / optional N-RS1 outside57” text is not adopted over AC-7(b).

**Correction2 — make adoption accounting concrete rather than changing labels alone.** Current source initializes run cause fields to0 (`newRun`, around880), aggregates RS-1 over all credited classes (`zero`, around498), and derives false-pass/leak arrays only from final `credited` attempts (496–497). The existing synthetic RS-1 test annotates records; that is no live classification mechanism. Before D-C credit, the existing report/record path must obtain reviewed actual run classifications (including explicit verified zero), preserve known-local vs unknown-staging scope, and separately publish the P gate-denominator RS-1 count/details and raw all-class/all-attempt counts. Require evidence behind a nonzero cause and behind a claimed zero; do not infer RS-1/AE solely from generic BUDGET_EXCEEDED. Existing P cause failures remain denominator failures.

Hard-gate observations on an earlier infrastructure/calibration/scheduling attempt cannot disappear when a later final attempt is credited. Within one report input, aggregate observed false-pass/leak facts from **all supplied attempts**, retaining attempt IDs; compute completion only from the allowed final P attempts. Preserve excluded/calibration histories with different manifests/limits as separate records and include their hard-gate disposition in the cumulative T4 analysis; do not mix incompatible limit sets into the P gate. This is enforcement of the proposal's existing zero-hard-gate promise, not a new product criterion. The per-session live stop rule does not make the current final-attempt-only report correct by itself.
