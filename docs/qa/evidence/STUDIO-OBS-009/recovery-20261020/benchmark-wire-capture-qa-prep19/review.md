Consequently an unavailable collector cannot be represented by omission/zero alone. Existing details.driverObservations, OBSERVATION_UNAVAILABLE, corpus-loop interruption and gate INVALID/INCOMPLETE/problem machinery support a small internal completeness extension without changing any public application API. learnSessionsComplete belongs to session accounting; the three CauseAssessment fields govern RS-1/authored-echo/focus causes and must not be repurposed for wire inspection. A full otherwise-passing population with one unknown local inspection is the key aggregate regression.

The existing two-million bound is text.length in JavaScript string units. Inspection must cover the complete text already consumed by response.text, including an over-bound tail, while raw oversize text lives only through transient scanning. Preserve strict refusal, no raw response/parser message/error code/cause in serialized output, and source-controlled closed observation labels rather than URLs or raw server fields. Full successful decoded responses must still reach the existing capture before revision validation.

An interrupted supplied extraTexts collector must not disappear, run twice at the same stage or erase prior findings when it fails. Its rejection/missing shape is explicit unavailable coverage, with fixed diagnostics and the original operation failure retained. The absence of a CLI collector is not proof that external gateway, audit, SSE, logs or video were inspected. API response capture remains a local subset of AC-10; the authored positive canary and manual masked-video gate still require their real independent evidence.

Both partial-start and already-charged-base scenarios must retain truthful unknown usage and exactly one applicable charge. No GET/PUT retry, suffix after a stop, phantom session or pricing/headroom fact is permitted.
