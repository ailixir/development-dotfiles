## Source findings and accepted coverage

The current c12 evaluator already preserves false-pass/leak facts from every supplied attempt (`evaluate.mjs:497–498`) and has the two genuine recovery controls. Preserve it rather than implementing a second hard-gate fix.

The remaining defects described by the design are present:

- `newRun:875–883` initializes three zero fields without cause observation; `validateRunRecord:431–447` validates nonnegative integers but no review coverage or count/detail binding. Drivers replace details with canary findings. The result schema has generic failure codes and no RS-1/AE/FM attribution or declared `failure.stepNumber`. Generic BUDGET_EXCEEDED, a page mark, successful completion, absent canaries or frontend hint cannot identify an actual cause or prove its absence.
- `zero:499–502` aggregates credited P/F/N attempts, not gate-P or all-attempt scope, and spreads details over identity. The proposed gateP/creditedAllClasses/allAttempts scopes, authoritative run identities, explicit unknown denominators and event-versus-affected-run distinction correct this without changing completion selection. Failed/clarified P runs remain in the gate; F/N stays outside completion. Invalid accounting must not hide hard-gate facts.
- D2/E1 currently combine false RS-1 marks with UNKNOWN_UNTIL_STAGING_PAGES_ARE_READ. Null only for explicitly blocked/unknown inspection, named unknown counts and reviewed local location invariants avoid turning unknown staging into a confirmed zero. Retain all25 IDs/classes,19P/57/52 and blocked17P/51/46 arithmetic,75 logical runs/81 planned sessions/122 contingency sessions, existing case bytes and mixedVisible predicate. E3 proves the negative boundary, not model refusal quality. No optional N-RS1 workflow is added by this review.
- `driveIncremental:949–988` starts the suffix before applying the stop rule and retains only `(edit ?? base)` counters. The proposed at-most-two-session accounting and per-learn existing stop check are necessary. Ordinary sessions also need explicit PUBLIC_BUDGET_COUNTERS basis.
- Backend `reserveModel:1553–1574` charges reservations and `settleModel:1578–1623` retains them, adding overage without refunds. Thus `costUsd:549` currently mislabels priced public counters as provider-reported usage. Actual measured cost must remain unavailable without independent actual-usage/price evidence. Conservative charge cost is a separately labelled stop-budget calculation, with incomplete inputs disclosed and existing fallback/stopping behavior preserved.

The proposed metadata/source-pin adoption and re-freeze route is sound. Require evaluator/CLI/corpus-server pins through the existing generic sources surface, correct repository root and validation before execution or rescore. Preserve the old frozen manifest and refused admissions; new code/metadata pins require a new freeze/digest and new admission before future calls. No limits identity exists in RunRecord. Configuration changes need separate honestly bound report histories and cumulative disclosure of bad facts/spend, not a synthetic limits key or a new manifest hash presented as proof of actual limits.

## Required adoption conditions

**C1 — P1: make the thin rescore an immutable-input overlay, not replacement evidence.** Current all-attempt hard gates see only the `runs` array supplied to `buildBenchmark`; removing an earlier attempt or changing its fields upstream defeats that protection. “Preserve raw runs” and hashing a newly reviewed JSONL alone do not establish that preservation.

Bind the immutable original runs input and its complete case/rep/attempt identity/status multiplicities, manifest, execution/admission provenance and original input hash in the new report. Bind the review overlay and actual referenced closed review records separately. Require every original attempt exactly once, reject omissions/duplicates/inserted runs and changes to immutable execution facts: oracle/falseSuccess, secretOrPiiLeak, terminal/publication/clarification state, mode, infrastructure exclusion, timestamps, session/counter facts and original identity. Limit overlays to the defined causal classifications/details/provenance; preserve original observations and known bad cause events rather than silently decreasing them. A correction of an actual erroneous attribution must retain the original claim and an explicit reviewed correction trail. Derive completion and hard-gate inputs from preserved original facts; do not let a caller-provided reviewed record redefine them. This is a narrow check in the existing adapter/scorer path, not another engine or collector.

Group6 must include an old false-pass/leak attempt plus clean recovery, then attempted deletion, zeroing, changed infrastructure/mode/identity and completion alterations through the overlay. Each attempt to launder the inputs is refused or remains visibly non-adoptable; legitimate causal review leaves the c12 hard facts and completion arithmetic unchanged.

**C2 — P1: VERIFIED is a reviewed evidence claim, not authentication by shape.** The design correctly says a valid hash/identity is not causal proof. Implementation and report adoption must preserve that limit: a caller typing VERIFIED, an arbitrary reviewer name or a plausible hash cannot establish independent review. The referenced closed review must actually exist, match its hash, bind the original run/manifest/attempt and relevant pinned goal/value/step/slot/location, and be verified through the existing independent QA adoption record. An empty event array supports a verified zero only with complete justified observation scope. Otherwise preserve explicit count0 with UNKNOWN coverage and null aggregate total. Positive confirmed events survive incomplete coverage; missing/unclassifiable events are not silently dropped.

Preserve per-field count/detail consistency, bounded closed types and unique event references without treating two legitimate same-element-kind observations as identical solely because their labels match. Reject forged detail identity keys. Synthetic reviewed inputs remain synthetic and HARNESS_SELF_TEST remains NOT_EVIDENCE; source shape checks cannot create an adopted D_C gate pass.

Offline reporting must validate the actual admission bound to the original execution and its manifest/purpose/configuration, including admission before the relevant run began. Current `guardStart:726` checks admittedAt before **now**; reusing only that check during a later rescore could accept a post-run admission. The new offline branch makes no calls, appends no retroactive permission and cannot upgrade old self-tests/calibration into D_C. Missing real approval, pricing, headroom or configuration evidence stays unknown/refused. Existing independent QA receipt/provenance is enough; no reviewer-authentication service is requested.

**C3 — P1: stopped incremental bases need truthful partial-record semantics.** Keep each actually started phase/session once, record its charge once, and check the existing stop rule before any suffix start. A failed base, budget stop or base leak starts zero suffix sessions; preserve completed base counters, known leaks and incomplete later scope. Do not call `record` again on the same base or after it has stopped. Unknown session counters remain unknown and use existing conservative stop fallback where applicable.

Do not feed a successful base into the final incremental oracle as if it claimed the whole repetition completed. `evaluateOutcome:301` flags a claimed SUCCEEDED state with missing full-workflow phases as falseSuccess. A newly introduced budget stop between phases must therefore retain the base's real state and an honest stopped/incomplete repetition without inventing a final success, false-pass accusation or completion credit. Conversely, preserve any genuine independent false pass/leak already observed. Group5 must test base/suffix order, failed base, stop after base, no duplicate charge, retained partial data and this distinction between base success and an overall claim. These are refinements of the design's existing per-session/partial-repetition requirement, not a new workflow or threshold.

**C4 — P2: incomplete usage totals must stay incomplete at every reduction.** Besides token totals/cost, update the existing modelCalls reduction consistently: `evaluate.mjs:513/547` filters missing proposal counters and can emit numeric total0 for an unknown scope. Report the known subtotal with its sample/unknown denominators, and leave a claimed complete total unavailable whenever an included started session lacks that counter. Apply the same rule separately to credited logical repetitions and raw all-attempt/session charges; do not drop infrastructure attempts or count suffix-only usage as the total. Empty scope is not observed zero. Preserve actual conservative stop arithmetic and distinguish its fallback basis from provider usage. Group5 should cover one missing base counter, missing suffix counter, mixed known/unknown proposals and empty scopes; pricing conservative charges must never yield a falsely labelled measured provider bill.
