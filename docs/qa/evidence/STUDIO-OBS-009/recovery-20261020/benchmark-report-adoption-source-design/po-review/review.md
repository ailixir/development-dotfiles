## Required correction: bind reviewed scoring to immutable emitted records

The thin offline adapter is justified: the current CLI's `summarize` branch belongs to the compile-era report, while live observed `benchmark` emits records before human/QA cause review. Reusing `buildBenchmark` for reviewed records avoids repeating model calls solely to attach reviewed accounting. A fresh exclusive output directory and zero API/provider calls are the appropriate boundary.

However, design §1 names a reviewed JSONL input and its hash without explicitly requiring the original emitted JSONL as a checked input. Keeping an original file on disk is insufficient: a reviewed copy could omit an earlier hard-gate attempt or change its leak/oracle/usage facts while still being independently well-formed. Pinning evaluator source and the reviewed file alone does not detect that loss.

The smallest acceptable correction is within the proposed existing CLI adapter and existing validation/tests:

1. Bind the exact original emitted input hash and the reviewed input hash in the new report/provenance. Preserve original files and existing reports; write new artifacts exclusively.
2. Reconcile original and reviewed attempt multiplicity and identities exactly, including case/rep/attempt, mode and manifest binding. Reject omission, insertion, duplication, relabelling or an unexplained mismatch. This compares two supplied public/closed record inputs, not protected runtime payloads or a new collector.
3. Permit only the declared cause-assessment/count/detail annotations to differ for this review step. Preserve original non-cause facts, including oracle/outcome/publication, infrastructure classification, all false-pass/leak observations and canary findings, timestamps, sessions and usage. Any legitimate correction to a raw fact needs its own explicit reviewed successor/disposition; it cannot silently enter through causal annotation.
4. Add a focused synthetic control in the existing evaluation tests: an earlier false-pass/leak attempt cannot disappear or become clean through offline review, while a cause-only annotation of the identical original attempt set scores through the same existing builder. These are harness controls, never real-model evidence.

The raw emitted record binding also gives the closed cause review an exact executed-record referent beyond manifest/case/rep/attempt labels. It does not validate the causal assertion automatically. This correction enforces existing no-hidden-attempt and zero-hard-gate promises; it changes no AC or threshold.
