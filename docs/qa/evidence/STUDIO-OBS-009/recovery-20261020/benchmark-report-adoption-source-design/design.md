## 1. Extend existing run records with review provenance, not another collector

Retain the three existing integer fields and existing `details[field]` event arrays. Counts mean **confirmed classified events**; `0` remains explicitly written, never omitted. Add one proposed field in RunRecord:

```ts
causeAssessment?: Record<CauseField, {
  status: 'VERIFIED' | 'UNKNOWN';
  evidenceSha256: string | null;
  manifestSha256: string | null;
  caseId: string; rep: number; attempt: number;
}>;
```

Here CauseField is exactly the existing three ZERO_FIELDS, not a new free-form taxonomy. VERIFIED means the existing run's relevant cause review is complete; it requires the SHA256 of a public/closed review record bound to this manifest + caseId + rep + attempt. The repeated identity fields must match the enclosing run. UNKNOWN means that coverage/classification is incomplete; zero is only the number of confirmed events so far, **not proof that none occurred**. A positive confirmed count can coexist with UNKNOWN if the remaining scope is unresolved. The report must expose that distinction, never present an UNKNOWN zero as a verified zero. Shape/identity/hash-format validation cannot establish the truth of a human causal attribution: independent QA must actually verify the named closed review and its file hash. Do not describe a syntactically valid hash as automatic causal proof.

Use existing `details[field]` rows for event data: RS-1 requires `elementKind`; AE requires `step` and `slot`; FM requires `step`, matching the actual story obligations. Each positive count must equal its event-row count, with valid bounded field types and no duplicate event identity. Derive caseId/rep/attempt from the enclosing run **after** spreading detail fields, or reject reserved identity keys. Do not store raw page values, authored literals, arbitrary exception text, credentials or private paths in this extension.

`newRun` writes all three counts as 0 and all three assessments UNKNOWN. It must not infer VERIFIED from `entry.rs1.isRs1Case === false`, a successful run, missing failure detail, or a lack of canary hits. `validateRunRecord` validates the new structure; for D_C, absent/UNKNOWN assessments produce an existing denominator-ledger validation problem, so the existing INVALID path cannot emit a gate pass on unreviewed accounting. Historical/self-test records can remain readable and NOT_EVIDENCE, but never gain a verified-zero claim. Current synthetic test inputs explicitly supply synthetic reviewed assessments; they remain unit inputs, not real evidence. This extends record validation rather than creating a second analysis gate.

**Production evidence owner:** @dev prepares the existing per-run closed classification; @qa verifies it. A causal hit needs the actual run link, pinned authored goal/required value location and a reviewed observation explaining why it failed/clarified/refused. Manifest marks alone are insufficient. VERIFIED zero needs a complete reviewed scope, not an empty array. If the currently available public observations cannot distinguish RS-1 from another BUDGET_EXCEEDED cause, leave UNKNOWN and name the missing closed evidence: RS-1 actual unreachable element/required read; AE affected step+slot and observed withholding attribution; FM affected step and target-local versus unrelated-focus change. Do not manufacture a public backend field or parse a display hint as authority. Any future product instrumentation is a separate explicitly scoped task, not this unit.

For an executable review path, reuse `buildBenchmark` with reviewed RunRecords. The current CLI has **no observed-authoring rescore command**: `summarize` is the legacy compile-era report. Add one thin branch to the existing CLI, proposed `benchmark-report CONFIG NEW_DIR`, that reads the named manifest, reviewed runs JSONL, their existing admission record and price source, validates pins/records and calls the existing `buildBenchmark`; writes new files exclusively and makes **zero API/provider calls**. Preserve raw emitted runs; record the reviewed-input hash in the new report. This is a narrow adapter to the existing scorer, not a new report engine, observer or admission. It may conservatively report UNKNOWN/INVALID and cannot create missing execution, spend, approval or configuration facts. The live `benchmark` command continues to emit honest unreviewed records until actual review exists.

## 2. Publish three explicit accounting scopes

Change the current `accounting[field]` object to three named summaries using one small existing-code reduction, not parallel scoring implementations:

- `gateP`: final credited class-P runs only. Use the same P run selection as completion; retain planned full/runnable counts, actual runsCounted and missing/blocked references. Failed or clarified P cause hits stay inside it.
- `creditedAllClasses`: every credited P/F/N run, replacing the old unqualified scope honestly.
- `allAttempts`: every supplied P/F/N attempt, including infrastructure attempts. Preserve case/rep/attempt for events and unknowns; do not erase earlier cause facts after recovery.

Each summary has `confirmedTotal`, `total` (number only if every included assessment is VERIFIED; otherwise null), `runsCounted`, `verifiedRuns`, `unknownRuns` and authoritative `items`/unknown identities. No included observations means total null, not an empty-scope confirmed zero. Existing numeric run fields stay explicit; aggregate null communicates incomplete coverage. The report must describe units as classified events and separately list affected run identities, not call events “runs.” Preserve completion arithmetic and c12 all-attempt hard gates unchanged. Hard-gate facts remain visible even when unrelated validation makes the overall verdict INVALID.

Add a small corpus inspection scope to the same report: known-local case IDs/count, actual RS-1 case IDs/count, and unknown-staging IDs/count. For the blocked D2/E1 entries, propose changing the existing `rs1.isRs1Case` to **null**, retaining their explicit UNKNOWN state and empty unknown locations; extend its declaration/validator accordingly. Null is permitted only for externally blocked cases with an explicit unknown inspection state; a READY_LOCAL case must have a real reviewed boolean/location invariant. This removes a misleading false sentinel without inventing a staging observation. Do not add N-RS1, change mixedVisible, widen exact-P admission or alter any corpus page/class/oracle.
