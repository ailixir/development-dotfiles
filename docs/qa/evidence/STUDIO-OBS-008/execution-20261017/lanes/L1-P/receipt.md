- Progress: `stepCount` = frozen `sourceSteps`; `activeStep` from durable `progress.stepIndex` (absent = 0, the codebase convention), resolved to the frozen step id and the authored sentence from the session's own `studio_guided_source_manifests`. Null for FINALIZING, every terminal state, an out-of-range or non-integer index, a step id that is not a UUID, a missing manifest, or an over-long sentence. In AWAITING_CLARIFICATION a `clarification.coordinate.stepId` that disagrees with the active step is `INVALID_CONTRACT` 422 (integrity refusal).
- Explanation: actions from `studio_guided_actions` (all attempts) with `operationKind` from the recorded proposal, `safeLabel` from the closed vocabulary, `outcome` = ledger state, `referenceIds` = opaque input/binding ids from the operation (never a value). `completed` = step index below the durable `stepIndex` and at least one effective action, all SUCCEEDED (effective = not the 015 excluded drift attempt). `learnedFromThisRun` = completed and at or after the learning window start (0 for an ordinary session; the switch's effective step for an incremental one; never before a switch exists). `reusedFrom` = pinned base revision and the step id, only for completed steps before the effective boundary of an existing switch. `relearnedAfterDrift` = DRIFT switch, completed, effective j <= i < initial k. `referenceFlows` = `studio_guided_consumer_edges` joined to both actions, both SUCCEEDED.
