## User Story

**As the** Checks Studio delivery team,
**I want** one frozen authoring-context v2 wire contract with matching pure frontend and backend models,
**so that** global and per-step context, stable step identity and exact literals can move through later save/compile/review work without competing shapes or index-based attachment.

## Acceptance Criteria

1. **FR-1 / AC-1, AC-2 — canonical v2 shape.** `docs/specs/studio/openapi.yaml` defines the authoring request/response shape with optional `globalContext` and ordered `steps[{id,text,context}]`. `id` and `text` are required; context is optional and defaults empty. A documented legacy adapter maps the existing ordered string steps to v2 with empty context while preserving each source string byte-for-byte.
2. **FR-4 / AC-7 — stable identity invariants.** The schema rejects missing or duplicate step IDs and mixed legacy/v2 step arrays. Contract prose requires reorder/edit to retain IDs, insertion to create an ID, copy to create a fresh ID and deletion to remove only the deleted step's metadata. Array position is not identity.
3. **FR-2, FR-7 / AC-3, AC-4, AC-11, AC-12 — typed context values.** The contract distinguishes plain context text, explicit literal input, nonsecret variable reference, secret reference, target hint and contextual default. It records precedence as explicit step intent/value → step context → global context, while policy remains authoritative; unresolved contradictions are diagnostics and never silent substitution.
4. **FR-5 / AC-8, AC-9 — revision inputs.** Contract metadata identifies global context, step context, nonsecret referenced values and selected evidence references as execution-affecting inputs to configuration/context identity. The contract requires stale publication protection but leaves persistence/state transitions to later stories built on 10.4.
5. **FR-6, FR-9 / AC-10, AC-15 — pure review/diagnostic models.** Freeze backend/frontend shapes for resolved operation, target, exact literal or safe reference, context provenance and unresolved diagnostic. Required diagnostic categories include missing context, conflicting value, ambiguous target, incompatible/stale evidence, literal mismatch and unsupported operation.
6. **FR-3 / AC-5, AC-6 — evidence references only.** Authoring v2 may select a typed evidence reference carrying source (`supplied|observed`), CSI, environment, route, state, step ID, capture timestamp, completeness and hash. The request cannot submit raw observed provenance as trusted fact; an imported/user-supplied reference remains `supplied`.
7. **Boundary.** Ordinary Compile remains browser-free and Run remains confirmed-artifact, LLM-free execution. This story defines no learning-session endpoint, browser action or observed-evidence capture; those remain mapped to WP-06–WP-10 and require unresolved retention/auth/security decisions.
8. **Backend parity.** Pure Java DTO/value types deserialize every valid authoring v2 example and reject invalid examples using existing validation conventions. No entity, repository, migration, controller behavior or service transition changes in this story.
9. **Frontend parity.** Pure TypeScript types and legacy adapter accept every valid example, preserve exact empty/Unicode/quoted/backslash/newline/whitespace literals, and reject/diagnose invalid identity combinations. No page component, Redux state, API orchestration or MSW handler behavior changes in this story.
10. **Contract tests.** Shared valid/invalid fixtures cover legacy empty context, global plus per-step context, reorder/copy/delete identity rules, exact literals, duplicate/orphan IDs, mixed shapes, unsupported fields, invalid secret/reference placement and false observed provenance. Backend and frontend tests consume the same fixture files.
11. The OpenAPI diff and pure-model tests pass. Backend targeted tests plus Spotless, Checkstyle and SpotBugs must be green; `./gradlew check` is attempted and any environment-only failure is recorded. Frontend focused type-check, lint and tests must be green, and repository-wide commands must introduce no failure beyond the frozen carry-forward baseline in `docs/qa/carry-forward-2026-09-16.md` (two known `@put/core-components` TS2307 errors, the existing invalid ESLint preset, and the documented expected-red test files). Modified classes/modules meet existing coverage gates.
12. **Authenticated protected-page sequence.** A shared valid fixture represents login followed by protected navigation with stable steps for username input, opaque password reference, submit, authenticated-state verification and protected-page navigation. Context/evidence is state-scoped: login-page evidence cannot verify the protected page, the secret remains a reference, and later authoring/learning work must infer each transition from the actual current state. The contract makes clear that per-step authoring inference may occur during Learn while normal confirmed execution remains LLM-free.

## Dev Notes

- Global means test-scoped authoring context, inherited by steps. Step-local context specializes global context; explicit intent/value wins over defaults. [Source: parent planning artifact `docs/specs/studio-context/spec.md` §3.2–3.4]
- Context and evidence selection are immutable-revision inputs. [Source: parent planning artifact `docs/specs/studio-context/spec.md` §3.1]
- Stable step identity is separate from presentation order. [Source: parent planning artifact `docs/specs/studio-context/spec.md` §3.2]
- The existing restricted artifact and exact-confirmation lifecycle remain authoritative. [Source: `docs/architecture/studio-execution.md` §4.2, §4.5–4.6]
- Do not introduce a second OpenAPI document, a parallel frontend wire type or another mock framework. Story 10.1 remains the contract/MSW foundation.
