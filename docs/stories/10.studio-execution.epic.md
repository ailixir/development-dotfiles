# Epic 10 — Checks Studio Execution (MVP)

| Field | Value |
|---|---|
| Status | Draft implementation backlog; revised 2026-09-10 |
| Epic | R4 — Checks Studio |
| Stories | 10.1–10.19 (IDs preserved) |
| Estimate | Re-estimation required: revision safety, durable results, SSE and recovery expand the earlier scope |
| Technical baseline | [Studio architecture v2.1](../architecture/studio-execution.md) |

**MVP done when:** a CSI-authorized user writes steps, reviews generated actions/source, confirms the exact revision, runs it, observes SSE progress, and views/downloads private step-linked video in staging. Failed steps stop execution; later steps are skipped. Infrastructure/evidence failure is reported honestly. API restart, stale confirmation, duplicate delivery, and wrong-CSI access pass the acceptance cases below. No runtime LLM and no Chromium on API/worker pods.

This epic supersedes its former completion-only HTTP and polling-first contracts. SSE is the preferred V1 observation channel, with GET fallback. The architecture owns shared schemas/state transitions; stories must not invent alternatives such as auto-confirmation or retrying an ambiguous run.

## Build order and prerequisites

- Start 10.1 contracts/migrations, 10.2 validator, 10.3 reference, 10.4 revisions, and 10.5 gateway work together where staffing permits.
- 10.6 runner admission/control skeleton follows 10.2; 10.7 backend acceptance, CSI, progress/SSE and recovery follows 10.1, 10.4, and 10.6.
- Compiler track: 10.8 → 10.9 → 10.10 → 10.11. Browser track: 10.12 → 10.13 → 10.14. Local browser fixtures can proceed independently of the live compiler.
- Evidence: 10.15 → 10.16. Secret plumbing: 10.17 after backend/runner safety contracts. Deployment 10.18 can be scaffolded early, with acceptance after all required runtime pieces. 10.19 validates the integrated result.
- Open external dependencies immediately: gateway access; real trusted identity and vault implementation; Sonic write/read credentials and lifecycle behavior; approved application and auth-provider destinations; internal Playwright image; actual ingress/session SSE and media route.

**Release ordering:** fixture-only development may precede the full compiler. A deployable real execution path requires 10.7 authorization/admission, 10.8 readiness, 10.9 exact confirmation, 10.13 runtime safety, and 10.17 authorized secret resolution when secrets are used. No temporary gate bypass or production auto-confirmation is allowed. Existing authentication/vault stubs cannot satisfy staging acceptance. The security prerequisites may be delivered outside this epic, but must have linked completed tickets before a credentialed pilot.

## 10.1 — Execution schema and typed snapshot contract

**Scope:** implement architecture §8 migrations and freeze one OpenAPI/JSON-schema contract with frontend MSW fixtures.

- Add globally unique unpartitioned dispatch ledger with history partition locator, durable principal-scoped idempotency, attempt/admission identity, lease/deadlines, report sequence and snapshot revision.
- Execution states `PENDING | RUNNING | PASSED | FAILED | ERROR`; step states `PENDING | RUNNING | PASS | FAIL | SKIPPED`; evidence states `PROCESSING | AVAILABLE | FAILED | UNAVAILABLE | EXPIRED`.
- Keep legacy partition `started_at` immutable as acceptance time; add `browser_started_at`. SQL and Java end/duration fields become nullable. Repositories respect the physical composite history key.
- Add revision/CSI snapshot, step results, structured bounded redacted logs, evidence fields and actual runtime provenance. `streamComplete` settles execution/evidence processing. Include log truncation metadata.
- Update `last_run_status` to support ERROR and prevent older completions overwriting newer projections. Backfill known CSI/history; quarantine ambiguous ownership rather than exposing it.
- Canonical request uses ordered English strings, typed variables, environment, and nested configuration. Normalize legacy `chrome` to `chromium`, structured IR to source lines, flattened configuration/JSON strings to the typed DTO. Migrate browser constraints. Legacy history has no fabricated confirmation metadata.
- Execution listing supports optional `testId`, always with readable execution-CSI filtering before pagination. Protected video URL is derived from the execution API path; raw storage keys are not authorization.

**Acceptance**

- [ ] Migrations and real JPA insert/update pass on historical/current/default/new partitions, including month-boundary queued runs.
- [ ] Snapshot GET and SSE example payloads use the same DTO and include every original step; skipped timings are null.
- [ ] Contract examples cover create/save/compile/confirm/run/history, legacy adapters, all terminal outcomes and evidence states.
- [ ] Frontend MSW fixtures follow the real API shape; lists and pagination cannot leak other CSIs.
- [ ] Nullable timings, globally unique execution lookup, idempotency and late last-run projection behavior are covered by meaningful integration cases.

No live dispatch is enabled by this story alone. Revision table integration follows 10.4; preserve a migration dependency between the two where required.

## 10.2 — Exact artifact language and trusted executor

**Scope:** architecture §4.5. The model emits Playwright source; trusted code walks a default-deny AST subset and calls permitted browser operations. Maintain this execution-language schema explicitly.

- Validate every statement, receiver chain, option, argument, reference and bound. Reject all unsupported syntax, including computed properties, prototypes/constructors, callbacks, arbitrary expressions, imports, declarations/loops, process/filesystem APIs, evaluation and browser/context management.
- Permit only the navigation, locators, actions and assertions enumerated in architecture §4.5. Per-method schemas control argument types/options; constrain regex forms, AST depth and input sizes.
- Enforce source/index alignment and exact token correspondence. Secret references occur only in approved action-value positions, never URLs/selectors/assertions. Never claim to recognize every unknown secret literal.
- Export browser-free validation plus a trusted operation executor testable with fake Playwright adapters. No `eval`, `Function`, async IIFE, or VM execution of generated source.

**Acceptance**

- [ ] Valid source fixtures execute the expected trusted calls; every unsupported node/receiver/option fails closed.
- [ ] Adversarial nested expressions, prototype access, oversized input, unsafe regex, undeclared/extra secret references and forbidden argument positions are rejected.
- [ ] Diagnostics are bounded and redacted; invalid artifacts cannot start a browser.

## 10.3 — Pinned Playwright syntax reference

**Scope:** versioned reference examples and compatibility CI, required in V1.

- Keep runner Playwright package/image and reference examples aligned. Record validator, executor and supported artifact versions.
- CI parses/validates reference examples and checks API usage against the pinned runtime; integration fixtures cover supported behavior.
- Runtime upgrades revalidate compatibility without rewriting approved source. Explicitly block incompatible/revoked revisions.

**Acceptance**

- [ ] Deliberate reference/package/image mismatch fails CI.
- [ ] Allowed examples validate and execute on the pinned fixture runtime.
- [ ] An incompatible artifact produces the documented error rather than silent reinterpretation.

## 10.4 — Immutable revisions and compile state

**Scope:** architecture §§4.2 and 8.1.

- Separate mutable draft/source/configuration revisions from immutable `ui_test_revisions`.
- States: `STALE | COMPILING | AWAITING_CONFIRMATION | READY | NEEDS_REVISION`.
- Persist compile request identity. Only the current request/source revision may publish a result.
- Execution-affecting configuration changes require a new candidate/confirmation; name/description changes do not compile. CSI is immutable and registered/non-null.
- Persist hashes, configuration, references, compile/runtime provenance and write-once confirmation audit fields. Retain immutable history after editing/soft deletion.

**Acceptance**

- [ ] Concurrent stale saves reject with 409; reversed compile results cannot replace the current candidate.
- [ ] Metadata-only changes preserve readiness; relevant configuration changes invalidate it without needless LLM work.
- [ ] Moving a test between CSIs is rejected, including attempts to transfer historical evidence.
- [ ] Queued/history executions retain their original approved revision after a draft edit.

## 10.5 — Citi/R2D2 LLM gateway client

**Scope:** backend gateway authentication, pinned model/version metadata, bounded timeout/concurrency and transport retries. Repair is owned by 10.9.

- Verify structured-output and temperature controls with the platform; unsupported controls do not justify claims of deterministic generation.
- Audit metadata only: CSI/test/user, model/prompt versions, latency and result. Never dump resolved values or full request bodies.
- Draft persistence remains available during gateway outage.

**Acceptance**

- [ ] Stub tests cover valid output, malformed/oversized JSON, timeout/outage and bounded retries.
- [ ] Captured gateway requests contain tokens only and audits contain no injected secret canaries.
- [ ] Gateway capabilities and access dependency are recorded before pilot use.

## 10.6 — Runner admission and reporting service

**Scope:** architecture §8.4 internal HTTP routes and callback client, initially using fake browser/storage adapters.

- `POST /v1/validate` wraps the pure validator with bounded work.
- `POST /v1/runs` reserves capacity, validates immutable job identity/configuration, and completes the API admission CAS before returning 202 or launching any work. Admission identity belongs to this runner instance/run.
- 429 guarantees no admission/no effects. Competing admission gets 409; ambiguous transport/5xx is not permission to replay. No automatic POST retry.
- Report cumulative STARTED/PROGRESS/FINAL snapshots with attempt/admission identity and increasing runner sequence. Final delivery is retried idempotently within a deadline; durable manifest implementation follows 10.14.
- Service identity on internal routes, configured callback destination, structured redacted logs. No DB/vault/CSI/LLM access. `health` is liveness; `ready` is safe admission, false while draining; busy capacity alone returns 429 without making readiness false.

**Acceptance**

- [ ] Valid dry-run admission returns 202 and fake progress/final callbacks follow the frozen contract.
- [ ] No callback acknowledgment/admission means no browser side effects; competing runner instances cannot both own the attempt.
- [ ] Pool saturation rejects with definite 429 while validation stays responsive; draining rejects new admissions.
- [ ] Duplicate reports, callback outage and wrong service identity behave as specified; request logging never exposes job values.

## 10.7 — Authorized durable dispatch, SSE and recovery

**Scope:** backend execution lifecycle, CSI enforcement, internal admission/progress handlers and SSE. Use dedicated Studio worker capacity.

- Durable execute idempotency and acceptance transaction; check source/configuration/revision readiness. Until 10.8/10.9 ship, non-fixture real execution remains disabled.
- Authenticate/authorize every Studio route, including unfiltered lists/history/media/SSE. Internal callbacks use restricted service identity and are absent from public ingress.
- Claim queued work with leases; record an attempt before send. Admission CAS grants exclusive runner/admission ownership. Recheck permissions/secret use immediately before dispatch.
- Only definite 429 may retry within SLA. Do not re-dispatch ambiguous attempts after timeout/restart. Commit progress/result before acknowledgment; enforce sequence/state ownership and assign snapshot revisions.
- Ship pending/running/finalization reapers and known-key manifest reconciliation in V1, using a fake store until 10.14 integration. Late reports cannot overwrite final history.
- Add MVC SSE endpoint, initial/reconnect full snapshot, per-pod batched watched-run DB reads, bounded senders/subscriptions, heartbeat/lifetime, coalescing, authorization refresh, and cleanup. GET uses the same DTO. No transaction/DB connection is held for the stream lifetime.
- Kill switch returns `503 DISPATCH_DISABLED` for new executes, closes undispatched queued work explicitly, and lets admitted work report/finish. Reads, callbacks and recovery remain active.

**Acceptance**

- [ ] Duplicate execute across API replicas returns one execution; conflicting key payload rejects. Lost admission response does not launch another attempt.
- [ ] API/dispatcher restart before send, after admission, during execution and after manifest write yields the documented truthful result without repeated effects.
- [ ] Both reapers close stuck work; stale callbacks cannot regress final states. Pending and browser runtime deadlines use separate timestamps.
- [ ] Callback on replica A becomes visible to an SSE subscriber on replica B; reconnect restores current state.
- [ ] Real HTTP streaming tests observe separate events before response closure; timeout/disconnect releases subscriptions and sender capacity.
- [ ] Readers can view their CSI; owners can execute; wrong/no identity, forged headers and cross-CSI lists/history/SSE reject. Production auth bypass is absent before pilot.
- [ ] Slow consumers and Studio overload do not exhaust ordinary check/REST capacity.

## 10.8 — Compile pipeline and readiness gate

**Scope:** asynchronous compile request publication, fenced source/reference/contract prompt, validator call, candidate persistence and execute readiness.

- Save draft first; compile outside request/DB transaction with bounded work and persisted request identity.
- Source inputs contain tokens only; enforce authoring limits and known credential-pattern rejection without claiming perfect secret detection.
- Valid output becomes `AWAITING_CONFIRMATION`, never READY automatically. Invalid output carries per-step diagnostics; repairs follow 10.9.
- Gate execute on the exact confirmed revision/source/configuration/hash and runtime policy. 409 explains what needs confirmation or compatibility work.

**Acceptance**

- [ ] Gateway outage leaves saved draft retryable and unchanged confirmed tests runnable.
- [ ] Out-of-order compile completion, including two compiles of the same source, cannot publish an older candidate.
- [ ] Unconfirmed/stale/incompatible revisions never reach a runner; no production auto-confirm fallback exists.

## 10.9 — Repair, diagnostics and exact confirmation

**Scope:** at most two repair attempts with bounded diagnostics; exact confirmation transaction.

- Confirm body: `{revisionId, artifactHash, sourceRevision, configurationRevision}`.
- Verify current valid candidate and all hashes/revisions conditionally; record confirmer/time once.
- Invalid steps yield NEEDS_REVISION and readable reasons; syntax validity is not asserted as semantic correctness.

**Acceptance**

- [ ] Valid candidate confirms to READY; mixed invalid steps block confirmation.
- [ ] A stale tab cannot approve a newer artifact, even when source text is unchanged.
- [ ] Changed configuration/source or concurrent recompile returns 409 without approving unseen code.
- [ ] Repairs stop after two attempts and redact diagnostics.

## 10.10 — Readable action review and confirmation

**Scope:** show each English line, trusted action/target/assertion summary, expandable executable source and diagnostics.

- Confirm exact displayed revision identity; refresh on 409 without silently accepting new code.
- Distinguish compiling, revision-needed and awaiting-confirmation states. Explain unsupported workflows.
- Keep confirmation accessible to nontechnical users; source review alone is not the trust metric.

**Acceptance**

- [ ] Author → save → review → confirm works in one Studio flow with accessible controls.
- [ ] Replaced candidate or changed configuration visibly requires fresh review.
- [ ] Representative nontechnical-user trial can explain what the confirmed actions/assertions will do.

## 10.11 — Run gate and SSE progress

**Scope:** replace the primary 700 ms polling loop with a centralized API-service subscription, using the same rendering state and GET fallback.

- Disable Run until READY; handle authoritative 409, 429, 503 errors. Remove legacy English grammar as execution gate and retire Python generation; Code view renders the confirmed source.
- Prefer native EventSource on the verified cookie route; use a header-capable client if required by platform auth. Do not reuse Axios's 30-second timeout or put credentials in URLs.
- Replace state by monotonic snapshot revision, preserve offset/duration fields, expose current step and retained logs, and label transport reconnecting separately from test failure.
- Reconnect restores snapshot; bounded fallback uses the normal authorized GET client. 401/403 stops rather than bypasses access controls.
- Close streams on `streamComplete`, unmount and scenario switch. A terminal check outcome alone does not end updates while evidence is PROCESSING. Disconnect never cancels/re-executes.

**Acceptance**

- [ ] Mocked and real paths show STARTED/step completion/log updates during execution.
- [ ] Duplicate/older snapshots, network loss, reconnect to another replica and polling fallback preserve correct state.
- [ ] Terminal evidence arrival is displayed; stream cleanup prevents accumulating subscriptions.
- [ ] Source language, status mapping and transport behavior match the typed contract in standalone and federated modes.

## 10.12 — Chromium execution and native recording

**Scope:** one Chromium browser/context/page per run in a killable child, driven by the trusted executor from 10.2.

- Revalidate artifact and current policy before launch; no generated-source evaluation.
- Report browser start and cumulative step updates with monotonic timing; fail first failing step and mark the rest SKIPPED with null timing.
- Close context to flush native webm where possible, with explicit readable recording size. Total deadline enforcement follows 10.13.
- Single-page V1: report unexpected popup/unsupported workflow explicitly. No silent flow change or multi-page video merge.

**Acceptance**

- [ ] Controlled page fixture runs allowed navigate/action/assert sequences and produces readable native video.
- [ ] Failed assertion produces FAILED with later steps SKIPPED; attempted offsets/durations exist.
- [ ] Forbidden artifact cannot launch Chromium; observed start is distinct from dispatch time.

## 10.13 — Timeouts, redaction and cleanup

**Scope:** parent-enforced browser deadline, bounded finalization/delivery work, safe outbound diagnostics and resource cleanup.

- Step timeout defaults to 30 s; total runtime to 120 s within API bounds. A hung child cannot block the parent control endpoint or extend the maximum deadline via heartbeat.
- Scrub resolved secret/variable values and tested encoded variants from logs/results/manifests; cap messages and retained logs.
- Clean process trees/scratch and release slots on success/failure/timeout/upload/callback error; retry delivery must not retain unlimited resources.

**Acceptance**

- [ ] Hung child is terminated, next run succeeds, and validator/control endpoints remain responsive.
- [ ] Canary values never appear in stdout, progress, final JSON, manifests or persisted diagnostics.
- [ ] Abrupt loss reports honest unavailable/partial evidence rather than promising a complete video.

## 10.14 — Sonic video and durable result manifest

**Scope:** architecture §§5.3 and 6.2; local fake/compatible store plus real Sonic integration.

- Deterministic video and `.result.json` keys include execution/attempt and immutable CSI identity.
- Upload video, settle evidence disposition, then store a redacted terminal manifest before acknowledgment-sensitive final delivery. If storage fails, send result directly with evidence error.
- Retries are bounded/idempotent; recovery reads known manifest keys. Runner writes only; API/recovery read only.
- Logical expiry is 30 days; lifecycle configuration must cover physical deletion/versioning and incomplete uploads. Track deletion behavior rather than assuming exact-time object removal.

**Acceptance**

- [ ] Crash after manifest upload but before result acknowledgment is recoverable without browser replay.
- [ ] Video upload failure preserves assertion outcome and yields FAILED evidence state.
- [ ] API+storage outage followed by runner loss resolves honestly via reaper; no invented recovered result.
- [ ] Private key derivation, credential scopes, redaction and local scratch cleanup are verified.

## 10.15 — Authorized video stream and download

**Scope:** execution-CSI authorization, Sonic proxy, Range and attachment handling.

- Support full 200, single-range 206 and invalid/unsatisfiable-range 416. Derive object key server-side.
- `?download=true` shares the same authorization; clear unavailable/expired responses.
- Real ambient session/gateway route for media is prerequisite; same-origin alone does not provide bearer headers.

**Acceptance**

- [ ] Reader succeeds, owner succeeds, wrong-CSI/no identity denies; soft deletion does not change historical CSI.
- [ ] Seeking/download use valid bytes and headers; expired evidence is denied regardless of delayed physical deletion.
- [ ] No public URL or durable presigned URL is stored or returned as authority.

## 10.16 — Evidence state, playback and step seek

**Scope:** display video PROCESSING/AVAILABLE/FAILED/UNAVAILABLE/EXPIRED independently of check outcome; show partial video explicitly.

- Seek attempted steps by returned `offsetMs`; skip entries have disabled seeking.
- Download uses the authorized endpoint. Handle session/expiry errors visibly.
- Replace placeholder seek arithmetic; preserve historical step text from execution revision after test edits.

**Acceptance**

- [ ] Controlled fixture seeks within the architecture's 500 ms target, including initial navigation/failure; staging validates the target before release claims.
- [ ] An assertion step seeks to its start, not a falsely claimed success instant.
- [ ] Late evidence readiness and unavailable/expired/partial video states render correctly without altering check outcome.

## 10.17 — Authorized variable and secret plumbing

**Scope:** token correspondence, typed variable adapter, vault-use authorization and dispatch-only resolution.

- Resolve only references in the approved revision for its CSI/principal/environment. Validate allowed destination/action positions again before use.
- Queued work persists references only; recheck revoked/rotated values at dispatch. Record nonsecret vault version identifier when supported.
- Real vault integration can be a separate prerequisite ticket, but stub `REDACTED` resolution/plaintext storage cannot pass this story's credentialed staging acceptance.

**Acceptance**

- [ ] Tokenized compile request contains no resolved values; unauthorized or missing reference prevents browser launch.
- [ ] Revoked permission while queued produces a clear execution error; rotation does not expose or persist a value.
- [ ] Real approved credentialed fixture passes; secret canaries and destination misuse negative tests pass.

## 10.18 — Hardened staging deployment and SSE route

**Scope:** runner Deployment, callback network path, Sonic controls, real SSE/media route and operations handover.

- Non-root Chromium sandbox, compatible seccomp, no privilege escalation, restricted service-account access, per-run scratch, `/dev/shm` sizing, resource limits and process reaping. Do not silently disable sandbox.
- `ready` false on drain, true when merely busy; grace period covers admitted work/finalization budget. Start one slot/pod and 1–2 runner replicas; validate sizing under bounded load.
- Enforce approved destinations including DNS, redirects/subresources/auth providers, Sonic and internal API callbacks. Standard NetworkPolicy is not URL filtering; identify the actual platform domain/egress mechanism.
- Configure SSE buffering/idle timeouts through every proxy, session-cookie or header-capable auth, bounded reconnect authorization and sender/stream limits.
- Checks squad owns a V1 runbook for Chromium, egress, stuck runs, SSE, manifest recovery, evidence expiry and kill switch. Platform/SRE supports infrastructure controls.

**Acceptance**

- [ ] Timed SSE events arrive separately before closure through actual ingress; heartbeat idle test and cross-replica reconnect pass.
- [ ] Real auth, video Range/download, forged-header denial and CSI revocation cases pass through ingress.
- [ ] Sandbox is active; unapproved destinations/control endpoints cannot be reached, including tested redirects.
- [ ] Private storage credential scopes and logical/physical expiry configuration are verified, with Sonic lifecycle caveats recorded.
- [ ] Kill switch/drain/recovery and bounded overload preserve ordinary REST/check service; runbook and accountable owner recorded.

## 10.19 — Integrated staging validation and sign-off

**Scope:** technical pilot acceptance plus documented unresolved platform facts. This is not the BRD's GA approval.

**Acceptance**

- [ ] Representative user completes write → compile → readable review → exact confirm → run → live SSE → seek/download against an approved internal single-page workflow.
- [ ] Success, assertion failure/skipped steps, total timeout, missing/revoked secret, unavailable video, partial evidence and expiry are visible and truthful.
- [ ] Concurrent save/recompile/configuration changes cannot approve unseen artifacts; old execution evidence retains its source and CSI.
- [ ] Dispatcher/API/runner restart, lost response, duplicate admission/report and delayed manifest scenarios never replay ambiguous UI actions or leave work pending indefinitely.
- [ ] Reader can view SSE/history/video, owner can execute, wrong-CSI/no/forged identity denies; real vault and secret canary cases pass.
- [ ] SSE actual-ingress latency/reconnect, seek target, readable video and bounded overload evidence recorded.
- [ ] QA and PO technical acceptance, runbook/Checks ownership, rollback procedure and remaining GA dependencies are linked. Do not mark Security/Platform/Sponsor GA approvals complete without actual sign-off.
