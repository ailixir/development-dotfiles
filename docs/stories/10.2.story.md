## User Story

**As the** Studio runner that must execute LLM-proposed Playwright source without ever evaluating it as JavaScript,
**I want** a default-deny validator that accepts only an exact AST subset and a trusted executor that performs the accepted operations through its own Playwright calls,
**so that** a hostile or mistaken artifact can at most be rejected, never gain capabilities beyond the enumerated navigation, locator, action and assertion surface.

---

## Problem Statement

The repository has no `studio-runner/` today; the frontend still carries a client-side grammar (`utils/studio/ir/parseSteps.ts`) and Python generation, both retired by architecture v2.1. The review's first P1 finding: a call allowlist plus a function scope is not a security boundary, and Node's `vm` explicitly is not one either. Architecture §4.5 therefore defines an **exact language**: bounded sequences of awaited permitted calls; approved receiver chains from `page`; per-method typed argument schemas; `vars.get/secret` only for declared references in approved positions; everything else rejected; execution through trusted harness functions with no `eval`, `Function`, async IIFE or VM.

This story creates the package (layout, toolchain, pins and lint rules fixed by [ADR-001](../architecture/ADR-001-studio-runner-scaffolding.md)) and delivers the validator and executor with fake Playwright adapters. No browser is launched in this story.

## Acceptance Criteria

### Package scaffold (ADR-001 §3–§7)
- [x] **AC-1:** `studio-runner/` exists as a standalone private npm package: `package.json` (`"private": true`, `"type": "module"`, `packageManager`, `engines`, exact-pinned dependencies), `package-lock.json`, `.npmrc` (`save-exact=true`, `engine-strict=true`), `.nvmrc`, `tsconfig.json` + `tsconfig.build.json` (`NodeNext`, `ES2022`, strict + the ADR §5 flags, no `DOM` lib), `eslint.config.js` (ESLint 9 flat + typescript-eslint type-checked), `vitest.config.ts` (unit, node env), `vitest.fixtures.config.ts` (fixture tier, may be empty of tests here), `Dockerfile` skeleton using `ARG PLAYWRIGHT_VERSION` and `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`.
- [x] **AC-2:** ESLint errors on `eval`, implied eval, `new Function`, imports of `vm`/`node:vm`/`worker_threads` anywhere, and `child_process` outside `src/run/**`; `import/no-extraneous-dependencies` is on. A test fixture containing each forbidden construct fails lint (verified by a Vitest test that runs ESLint programmatically on `fixtures/lint/`).
- [x] **AC-3:** `npm ci && npm run type-check && npm run lint && npm test && npm run build` succeed on a plain Node image (no browser). The `playwright` **library** package (not `@playwright/test`) is the only browser-related runtime dependency.
- [x] **AC-4:** `.gitignore` gains `studio-runner/node_modules/`, `dist/`, `coverage/`, `test-results/`, scratch/video output directories.

### Artifact schema validation (§4.4)
- [x] **AC-5:** `validator` accepts an artifact `{version: 1, steps: [{stepIndex, originalText, code}]}` and the ordered source lines; it rejects with per-step diagnostics when: entry count ≠ source line count, `stepIndex` not equal to array position, `originalText` not byte-identical to the source line, unknown top-level or step keys, or total artifact bytes / step count / per-step code length exceed configured bounds.

### Default-deny language (§4.5)
- [x] **AC-6:** Each `code` string parses into an AST; the only accepted program shape is a bounded sequence of `ExpressionStatement` nodes whose expression is `await <permitted call>`. Every other node kind (declarations, assignments, loops, conditionals, callbacks/functions, `new`, spread, computed member access, optional chaining into non-permitted members, template literals with expressions, imports, `process`/`require`/filesystem, `page.evaluate`, browser/context management, unsupported TypeScript syntax) is rejected with a diagnostic naming the node and step.
- [x] **AC-7:** Permitted calls are exactly: navigation `page.goto(url, opts?)`, `page.waitForURL(urlOrRegex, opts?)`; locators as receiver chains rooted at `page` using `getByRole`, `getByText`, `getByLabel`, `getByPlaceholder`, `getByTestId`, `locator` (CSS only); actions `click`, `fill`, `press`, `check`, `uncheck`, `selectOption`, `hover` on a permitted locator; assertions `expect(locator).toBeVisible/toContainText/toHaveValue` and `expect(page).toHaveURL/toHaveTitle`. Anything else on any receiver is rejected.
- [x] **AC-8:** Per-method argument schemas: string/number/boolean literals with length bounds, option objects with only known keys and typed values, regex literals restricted to a safe subset (no backreferences, no nested quantifiers beyond configured depth, bounded length), permitted locator expressions, and `vars.get('NAME')` / `vars.secret('ID')` references. Unknown option keys, arbitrary expressions, getters and computed properties are rejected.
- [x] **AC-9:** Reference rules: `vars.get`/`vars.secret` may only name references declared for the artifact; a `secret` reference is accepted only as the value argument of `fill` (the single V1 approved position; `press`, `selectOption` and every other position are rejected until a documented case adds them), never in URLs, selectors, assertion arguments or option values; undeclared or extra references, and declared references never used where the source line mentions them, are rejected. The validator does not claim to detect unknown secret literals.
- [x] **AC-10:** Bounds are configuration, not constants: max statements per step, max AST depth, max selector length, max regex length, max artifact bytes; defaults documented in `README.md`.
- [x] **AC-11:** Validation is pure and browser-free; it exports `validateArtifact(artifact, source, references, policy) → {ok, steps: [{stepIndex, ok, operations?, diagnostics?}]}` where `operations` is a typed, serializable operation list (not code) for accepted steps.

### Trusted executor
- [x] **AC-12:** `executor` consumes the typed operation list and invokes a `BrowserAdapter` interface (`goto`, `waitForURL`, `locate(chain)`, `click`, `fill`, …, `expectVisible`, …) with the validated arguments and resolved values. It contains no code path that turns a string into code: no `eval`, `Function`, `vm`, dynamic `import()` of generated text, or async IIFE over artifact contents (enforced by AC-2 lint and a grep-based test over `dist/`).
- [x] **AC-13:** Secret values are resolved only at the moment of the permitted action call and are never included in operation objects, thrown errors, logs or diagnostics; every diagnostic passes through a redaction step that scrubs known resolved values and their URL-encoded and base64 variants.
- [x] **AC-14:** The executor reports per-step start/finish through a `StepReporter` interface with monotonic timestamps and stops at the first failing step, marking the remaining steps `SKIPPED` with `null` timings.
- [x] **AC-15:** Diagnostics are bounded (message length, count per step) and never echo full artifact code beyond the failing node's excerpt.

### Versioning
- [x] **AC-16:** The package exports `VALIDATOR_SCHEMA_VERSION` and `EXECUTOR_VERSION`; both are included in `runtime-versions.json` generated by `npm run build` (the CI equality check is 10.3).

### Tests
- [x] **AC-17:** `fixtures/reference/` contains at least one valid artifact per permitted method (navigation, each locator kind, each action, each assertion, both reference kinds) and each executes the expected `BrowserAdapter` calls in order against a fake adapter.
- [x] **AC-18:** `fixtures/adversarial/` contains at least one rejected artifact per denied class: every node kind in AC-6, every non-permitted receiver/method, unknown option keys, computed properties, prototype/constructor access, nested expressions, oversized input, unsafe regex, undeclared/extra references, secret reference in a forbidden position, index/text misalignment. Each is asserted to fail closed with a diagnostic and to produce **no** adapter call.
- [x] **AC-19:** Redaction test: canary secret values in plain, URL-encoded and base64 forms never appear in any diagnostic, error message or reporter payload.
- [x] **AC-20:** Vitest coverage ≥ 85% lines / 80% branches for `src/validator/**` and `src/executor/**`; AC-18's per-class fixture list is checked by a test that maps every denied class to at least one fixture (missing class → test failure).

## Implementation Notes

- Parser choice is this story's decision (TypeScript compiler API or `@typescript-eslint/typescript-estree`); pin it exactly, record it in `provenance` via `VALIDATOR_SCHEMA_VERSION`, and log the choice and rationale in the Change Log.
- Model the accepted language as data (a schema of receivers → methods → argument schemas) so 10.3's reference corpus and the backend prompt's syntax reference can be generated from the same source later.
- `BrowserAdapter` is the seam for 10.12: keep it minimal and synchronous-looking (`Promise`-returning methods, no Playwright types leaking into validator/executor).
- Treat the whole artifact as untrusted input including its size; parse only after schema and byte bounds pass.
- Keep the adversarial corpus as JSON files with an `expectedClass` field so AC-20's completeness check is mechanical.
