## Story

**As a** release owner for the Studio R2D2 rollout,
**I want** to know, from evidence, whether the enterprise R2D2 proxy accepts the per-status `anyOf` provider schema the compile client now sends (`providerSchemaVersion = 2`) and whether a real compile succeeds through it,
**so that** we do not roll out to R2D2 with a schema that, if rejected, makes every production compile fail and for which no fallback switch exists (QA-2).

## Context (verified by the drafter by reading; nothing was run, no live call was made)

- **The schema.** `GenAiLlmGatewayClient.java:454-477` builds the per-status `anyOf` schema; `PROVIDER_SCHEMA_VERSION = 2` (`:431`). It was introduced by VAL-030: the version-1 schema required only `stepId`/`status` while the parser required `reason`+`message` on refusals, so 52/60 correct refusals ended `GATEWAY_PARSE_FAILURE`; `anyOf` gave 8/8.

## Acceptance Criteria

1. **Prerequisites recorded before any call.** The story's Dev Agent Record starts with a table naming: the approved environment, who approved it, the source of the R2D2 endpoint/project/location/model and the service credentials (ED-01 deliverables), and the accountable SPK-01 owner. **If any entry is "TBD" or unavailable, no call is made** and the story is reported as Blocked with that table; nothing is simulated. No live call is made against R2D2 from a developer workstation, shared environment or CI job without that approval. `studio.compile.gateway.enabled` is set to `true` only in the approved environment, for the probe, and returned to its default afterwards. *(@po, validation)* The SPK-01 *Pilot-use gate* forbids that flag in **any shared environment** until every *Findings* row is signed. So the approved environment is either non-shared, or the table records an explicit, named exception to that gate granted by SPK-01's accountable owner for this probe only. Without one of the two, no call is made.
2. **Probe the schema, not a mock.** In the approved environment, send the actual per-status `anyOf` provider schema that `GenAiLlmGatewayClient` builds at `providerSchemaVersion = 2` (not a hand-copied approximation: the probe reuses the client's own schema builder) to R2D2 and record: the request outcome (accepted / rejected), the HTTP status and the proxy's error text if rejected, and the schema version. The probe input is non-sensitive and contains no real credentials, secrets or enterprise data (A8 is unverified, so assume request bodies may be logged).
3. **A real compile succeeds through it.** Run one real Studio compile of a small test through the R2D2 path with the version-2 schema and show it reaches a validated outcome (publication as `READY` under the current Run-confirm flow), with no `GATEWAY_PARSE_FAILURE` and no schema rejection. Also run the VAL-030 refusal case ("Check the server CPU is below 50%") and show `NEEDS_REVISION UNSUPPORTED_CAPABILITY` in **one attempt**. Record the attempt count, latency and the audit-log line (`GatewayAuditLogger`) for each; quote them.
4. **Same-session observations (do not gate the verdict).** From the same session, record, as observed facts only, whether R2D2 accepted: `systemInstruction`; `thinkingConfig` at LOW; and whether usage fields are returned (decision item 8; narrowed SPK-01). "Not exercised" is a valid entry; none is invented.
5. **Verdict and stop rule.** The evidence states one of: **ACCEPTED** (AC-2 and AC-3 met), **REJECTED** (the proxy refused the schema, or the compile failed because of it), or **INCONCLUSIVE** (with reason). **If REJECTED or INCONCLUSIVE: stop.** No fallback switch, flag, schema variant or client change is built in this story. The finding is reported to @architect and @po so a separate fallback story can be drafted (decision item 8).
6. **Evidence committed and signed.** The evidence goes under `docs/qa/spikes/SPK-01/` (the existing scaffold) in a new dated record, containing no credentials, tokens or bodies of enterprise data. It is **narrow**: it answers only the questions above, and does not close SPK-01. SPK-01's `Result` line and the ED-01 entry are updated **only** by their accountable owner (Architecture with the R2D2 gateway owners) under the register's closure rule; this story prepares the record and requests the signature but does not sign for them.
7. **Release gate pointer.** On ACCEPTED, the validation plan's QA-2 row and release condition 3 receive a one-line pointer to the committed evidence (@po or @qa decides the wording at close). On REJECTED, they receive a pointer stating the rollout remains blocked.
8. **Confinement.** The diff is documentation and evidence under `docs/qa/spikes/SPK-01/`, plus the validation-plan pointer of AC-7. If a probe harness is needed it lives in test or tooling code, is not on the production path, adds no dependency, and changes no default. No `application*.yml` default, `providerSchemaVersion`, `PROMPT_VERSION`, schema builder or gateway client behaviour is modified. @qa lists `git diff --stat`.
