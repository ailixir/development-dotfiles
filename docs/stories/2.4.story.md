## User Story

**As a** platform operator running put-checks on 2+ replicas,
**I want** ShedLock (JDBC-backed) to ensure that `@Scheduled` tasks execute on exactly one pod at a time,
**so that** the cron dispatcher doesn't fire duplicate check executions and the partition DDL scheduler doesn't race on concurrent `CREATE TABLE` / `DETACH CONCURRENTLY`.

---

## Acceptance Criteria

- [ ] **AC-1:** `net.javacrumbs.shedlock:shedlock-spring` + `shedlock-provider-jdbc-template` dependencies added to `build.gradle.kts`.
- [ ] **AC-2:** `@EnableSchedulerLock(defaultLockAtMostFor = "10m")` on a config class.
- [ ] **AC-3:** `ShedLockConfig` bean providing `LockProvider` backed by `JdbcTemplateLockProvider` using the existing `shedlock` table from V1 migration.
- [ ] **AC-4:** `CronDispatcher.dispatchDueSchedules()` annotated with `@SchedulerLock(name = "cronDispatcher", lockAtMostFor = "5m", lockAtLeastFor = "30s")`.
- [ ] **AC-5:** The `shedlock` table already exists in V1 migration — no new migration needed. Verify the schema matches ShedLock's expected format: `(name VARCHAR PRIMARY KEY, lock_until TIMESTAMPTZ, locked_at TIMESTAMPTZ, locked_by VARCHAR)`.
- [ ] **AC-6:** Integration test `ShedLockIT`: start 2 Spring application contexts in the same JVM (sharing the same embedded Postgres), trigger a scheduled task on both, assert via DB query that the `shedlock` row is locked by exactly one instance.
- [ ] **AC-7:** Integration test `ShedLockCronDispatcherIT`: seed a due schedule, trigger cron dispatcher on both contexts, assert exactly 1 execution result row created (not 2).
- [ ] **AC-8:** JaCoCo coverage ≥ 80%.

## Implementation Notes
- **ShedLock table in V1:** The V1 migration already creates `shedlock` with the exact schema ShedLock expects. No migration needed.
- **Two-context IT:** Use `@SpringBootTest` with different `spring.application.name` or `shedlock.lockedBy` values. Both share the same datasource (Zonky embedded PG). Execute the scheduled method directly (bypass `@Scheduled` timing).
- **lockAtLeastFor:** `30s` prevents rapid re-execution if the lock holder finishes quickly. This matches the 30s poll interval of the cron dispatcher.
