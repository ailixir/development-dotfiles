   The problem: before every fill, the runner focuses the field. If anything else on the page changes during that focus, other than a `class` or `style` attribute, the runner refuses the fill as `POST_FOCUS_CHANGED`, and the whole session ends `UNKNOWN_OUTCOME`. An application whose fields do that remains blocked for the reviewed workflow; the fill cannot complete.

   This obligation does not change the final-closure D-C gate or the meaning of any other AC.

   a. **The check, at T0, for every application in the reviewed workflows.**
      - Reviewed applications are the approved staging application with real login, plus any other application used by the reviewed workflows.
      - Run a real-Chromium probe for every fill target authored in the reviewed workflow. Follow the D5 `probe/probe.mjs` pattern:
        - use the pinned Playwright of the runner;
        - use the collector from the **runner `dist` used by the reviewed workflow**, recorded by digest (OBS-009 AC-12 i);
        - install the collector in the isolated world, as `browser.ts` does;
        - perform the fill on the real page.
      - A target **passes** when the fill returns without `POST_FOCUS_CHANGED`.
      - Record the following per application and target:
        - the outcome;
        - the mutation record types and attribute names seen during `focus()`, value-free;
        - the `dist` digest.
      - No secret value is typed into a real application for this check. Password fields are probed with a non-secret placeholder on the approved test account only, or are recorded as "not probed, reason".
   b. **The gate.**
