# DailyChecks (DC) Bridge — Splunk enablement runbook

## What this is

PUT Checks executes **Splunk** checks by calling the **DailyChecks (DC)** API through a shared `DailyChecksAdapter` (Proposal B). Splunk stays disabled until you point the app at a real DC endpoint and flip the source flag.

## Provisional DC contract

> Adjust path/fields when DC inventory is confirmed. Current provisional shape:

`POST {checks.dc.base-url}{checks.dc.execute-path}`

Request body:

```json
{
  "sourceType": "SPLUNK",
  "checkId": "uuid-or-null",
  "csiId": "174523",
  "name": "Check name",
  "configuration": {
    "query": "search index=main | stats count",
    "index": "main",
    "timeRange": "15m",
    "expectedCount": 0,
    "countOperator": ">"
  }
}
```

Response (outer **status + comment**):

```json
{
  "status": "SUCCESS",
  "comment": "human readable detail",
  "deepLink": "https://optional",
  "actualCount": 12
}
```

`status` accepts: `SUCCESS`/`PASS`, `FAILURE`/`FAIL`, `WARNING`, `TIMEOUT`.

## Config (env)

| Variable | Purpose | Example |
|---|---|---|
| `CHECKS_DC_ENABLED` | Master bridge switch | `true` |
| `CHECKS_DC_BASE_URL` | DC base URL | `https://dailychecks.example` |
| `CHECKS_DC_EXECUTE_PATH` | Execute path | `/api/v1/execute` |
| `CHECKS_DC_AUTH_MODE` | `none` \| `basic` \| `bearer` \| `header` | `bearer` |
| `CHECKS_DC_AUTH_TOKEN` | Bearer token (if mode=bearer) | *(secret)* |
| `CHECKS_DC_AUTH_USERNAME` / `PASSWORD` | Basic auth | *(secret)* |
| `CHECKS_DC_AUTH_HEADER_NAME` / `VALUE` | Custom header auth | `X-Api-Key` / *(secret)* |

In `application.yml`, Splunk source defaults to **off**:

```yaml
checks:
  sources:
    SPLUNK: false
```

## Enable Splunk in an environment

1. Set DC URL + auth env vars.
2. Set `checks.sources.SPLUNK: true` (or env override if you add one).
3. Restart backend.
4. UI: Create Check → Splunk should be selectable (sources API).
5. Save → Run → confirm history shows success/failure from DC.

## Disable quickly

- `checks.sources.SPLUNK: false` — blocks execute + hides/disables in UI type picker  
- `CHECKS_DC_ENABLED=false` — adapter returns “bridge disabled” for any DC-backed type
