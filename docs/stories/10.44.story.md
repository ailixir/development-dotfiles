## Story

**As a** Studio author,
**I want** my plain-English steps to reach the approved translator without matching a fixed grammar,
**so that** I can describe checks naturally while generated code and secrets stay constrained.

## Acceptance Criteria

1. Compilation never refuses a step for its English phrasing; `SupportedEnglishIntentParser` and the
   expected-intent correspondence are removed from backend and runner.
2. Step references are authorized by a structural reference policy (ADR-SC-003), persisted with the
   revision and re-verified at confirmation, readiness and dispatch.
3. The editor no longer marks plain-English steps as invalid; `/validate-steps` is removed.
4. The prompt syntax reference matches the validator vocabulary, guarded by a drift test; the syntax
   reference version is bumped in every pin.
5. A `goto` whose URL comes from a variable refuses any value that is not an absolute http(s) URL.
6. A secret can be filled only while the page origin is one of the secret's declared
   `allowedOrigins`; a secret without declared origins cannot be filled.

## Out of scope (deferred)

Operation vocabulary expansion; regex-DoS hardening; CSS selector parser; secret value-oracle block;
replacing output-contract rule 6; network destination controls (covered by the internal network).

### Re-review 2026-10-06 — Aria (@architect, quality gate) at `0d93a9bf1`

**Gate: PASS** (was CONCERNS). Status stays `Done`. The [gate file](../qa/gates/10.44-remove-english-grammar-gate-bind-secrets-to-origins.yml) has a `history` entry for each review.

- **S-1 (medium): resolved.** After the target wait, `fillSecretPinned` (`playwrightAdapter.ts:536-561`) pins the target with `locator.elementHandle()`. It re-checks the origin of the element's `ownerFrame()` and of `page.url()`, then fills through that handle. A handle cannot follow a navigation, so the time-of-check/time-of-use gap is closed as far as the adapter can control. The up-front check still refuses early. Non-secret fills are unchanged.
- **No secret in logs or errors:** `requireSecretOrigin` names only the secret id. `act()` maps Playwright errors to fixed phrases (`describeActionFailure`) and never echoes the message. The `ownerFrame()` and `dispose()` calls carry no value.
- **S-2 (low): resolved** by `4fcb5a2cb` (ADR-002 §13 row).
- **S-4 (low, new, accepted residual):** this gap is inside Playwright's own fill. In Playwright 1.63.0 (`coreBundle.js:20394-20406`), fill focuses and selects in the element's document, then calls `page.keyboard.insertText`, which is page-scoped. A navigation that commits between those two calls would type the value into whatever field has focus in the new document. The window is one CDP round trip, and only a navigation started by the bound origin can land in it. Not reproduced. Advisory follow-up: after the fill, verify that `ownerFrame()` is still attached and the page origin is unchanged. If not, fail with a fixed code that flags possible exposure so the secret can be rotated. The alternative, setting the value with a single `evaluate`, would prevent the leak but gives up keyboard fidelity.
- **S-3 (low):** still open (documentation).
