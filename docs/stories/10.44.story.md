## Story

**As a** Studio author,
**I want** my plain-English steps to reach the approved translator without matching a fixed grammar,
**so that** I can describe checks naturally while generated code and secrets stay constrained.

## Acceptance Criteria

1. Compilation never refuses a step for its English phrasing; `SupportedEnglishIntentParser` and the
   expected-intent correspondence are removed from backend and runner.
2. Step references are authorized by a structural reference policy (ADR-SC-003), persisted with the
   revision and re-verified at confirmation, readiness and dispatch.
3. The editor no longer marks plain-English steps as invalid; `/validate-steps` is removed.
4. The prompt syntax reference matches the validator vocabulary, guarded by a drift test; the syntax
   reference version is bumped in every pin.
5. A `goto` whose URL comes from a variable refuses any value that is not an absolute http(s) URL.
6. A secret can be filled only while the page origin is one of the secret's declared
   `allowedOrigins`; a secret without declared origins cannot be filled.

## Out of scope (deferred)

Operation vocabulary expansion; regex-DoS hardening; CSS selector parser; secret value-oracle block;
replacing output-contract rule 6; network destination controls (covered by the internal network).
