## User Story

**As a** report creator or editor,
**I want** the `next_delivery_at` column to be automatically computed and set whenever I create, update, pause, or resume a report,
**so that** the delivery dispatcher always has an accurate, up-to-date timestamp to poll against.

---

## Acceptance Criteria

### On create

- [x] **AC-1:** `ReportsService.create()` calls `reportScheduleResolver.nextDelivery(schedule)` and sets `report.nextDeliveryAt` before persisting. If the report is created with status `draft`, `nextDeliveryAt` is set to `null`.

### On update

- [x] **AC-2:** `ReportsService.update()` recalculates `nextDeliveryAt` from the (potentially changed) schedule JSONB. If the report status is not `active`, `nextDeliveryAt` is set to `null`.

### On pause

- [x] **AC-3:** `ReportsService.pause()` sets `nextDeliveryAt = null` (removes from dispatcher polling).

### On resume

- [x] **AC-4:** `ReportsService.resume()` recalculates `nextDeliveryAt` from the existing schedule JSONB.

### On soft delete

- [x] **AC-5:** `ReportsService.softDelete()` sets `nextDeliveryAt = null` (the partial index already excludes `deleted_at IS NULL`, but explicit nulling is defense-in-depth).

### Tests

- [x] **AC-6:** `ReportLifecycleIT`: create with status active, verify `nextDeliveryAt` is in the future. Pause, verify null. Resume, verify recalculated. Update schedule, verify recalculated. Soft delete, verify null.
- [x] **AC-7:** `ReportDraftIT`: create with status draft, verify `nextDeliveryAt` is null.
- [x] **AC-8:** Existing report CRUD tests still pass.

## Implementation Notes

- **Schedule JSONB parsing:** `ReportsService` stores schedule as a `String` (raw JSON). Use `ObjectMapper.readTree(report.getSchedule())` to parse before passing to `ReportScheduleResolver`.
- **Draft status handling:** New reports default to `status = "draft"`. Draft reports should NOT have a `nextDeliveryAt` (they're not ready for delivery). Only `active` reports get scheduled.
- **Duplicate:** `ReportsService.duplicate()` creates a copy with `status = "draft"`, so `nextDeliveryAt` should be null for the copy.
