## User Story

**As a** user creating and running UI tests in Checks Studio,
**I want** test CRUD, execution, and validation features backed by the real backend,
**so that** UI tests are persisted in the database, executions are tracked with real results, and step validation uses server-side logic.

---

## Acceptance Criteria

### Backend — New StudioController

- [ ] **AC-1:** `StudioController` created at `/api/v1/studio` with all endpoints matching the MSW contract.

**Tests CRUD**
- [ ] **AC-2:** `GET /api/v1/studio/tests?csiId={optional}` — list UI tests. Response: `{data: UITestDto[], total}`. Filtered by CSI if provided. Authorization: scoped to user's CSIs.
- [ ] **AC-3:** `POST /api/v1/studio/tests` — create UI test. Body: `UITestRequest` `{name, description, csiId, steps, variables, browser, viewport, schedule}`. Response: 201 + `UITestDto` (status: `paused`).
- [ ] **AC-4:** `GET /api/v1/studio/tests/{id}` — get test by ID. Response: `UITestDto`.
- [ ] **AC-5:** `PUT /api/v1/studio/tests/{id}` — update test. Response: updated `UITestDto`.
- [ ] **AC-6:** `DELETE /api/v1/studio/tests/{id}` — soft delete. Response: 204.

**Execution**
- [ ] **AC-7:** `POST /api/v1/studio/tests/{id}/execute` — start execution asynchronously. Body: `{variables?: Record<string, any>}`. Returns 202 Accepted with `{executionId, status: "started"}`. Dispatches to async executor (uses `checkExecutor` or a dedicated `studioExecutor` qualifier). NOTE: actual Playwright execution is a future M5 concern (spec §9). For M3, the executor records the execution with status `PENDING` and returns immediately. Actual browser automation is out of scope.
- [ ] **AC-8:** `GET /api/v1/studio/executions/{id}` — poll execution status. Response: `UITestExecutionDto` with step results and logs. For M3, returns the recorded execution with whatever status was set (since no real browser runs yet, status stays `PENDING` or can be marked `COMPLETED` after a simulated delay).
- [ ] **AC-9:** `GET /api/v1/studio/executions?testId={optional}` — list executions. Response: `{data: UITestExecutionDto[]}`.

**Validation**
- [ ] **AC-10:** `POST /api/v1/studio/tests/{id}/validate-variables` — body `{variables: Record<string, any>}`. Checks required variables are provided. Response: `{isValid: boolean, missing: string[]}`. Logic: load test's `variables` definition, filter for `required=true`, check if all are present in the provided map.
- [ ] **AC-11:** `POST /api/v1/studio/validate-steps` — body `{steps: string[]}`. Validates step syntax. Response: `{isValid: boolean, results: [{stepIndex, isValid, suggestion?}]}`. Valid step prefixes: "go to", "navigate to", "click", "type", "wait for", "check that", "check url contains", "scroll", "hover", "select", "press", "upload". Invalid steps get a suggestion.

**Data model**
- [ ] **AC-12:** `UITest` JPA entity mapping to `ui_tests` table: id, name, description, csi_id, steps (JSONB string array), variables (JSONB), browser (VARCHAR), viewport (JSONB `{width, height}`), status, schedule (JSONB), created_by, created_at, updated_at, deleted_at.
- [ ] **AC-13:** `UITestExecution` JPA entity mapping to `ui_test_executions` table: id, test_id (FK), status, started_at, ended_at, step_results (JSONB), logs (JSONB), video_url (nullable), error_message.

**Service + repository**
- [ ] **AC-14:** `StudioService` with full CRUD + execute + validate logic.
- [ ] **AC-15:** `StudioRepository` + `UITestExecutionRepository`.

**Tests**
- [ ] **AC-16:** Integration tests: `StudioTestsCrudIT` (lifecycle), `StudioValidationIT` (variable + step validation), `StudioExecutionIT` (start + poll).

## Implementation Notes

### Execution stub for M3
The execution endpoint creates a `ui_test_executions` row with `status=PENDING` and returns immediately. There's no background process to run the test. When M5 adds Playwright integration, the execute endpoint will dispatch to the Playwright executor. The FE polling logic is the same regardless — it works for both the stub and the real executor.

### Step validation (server-side)
```java
private static final Set<String> VALID_PREFIXES = Set.of(
    "go to", "navigate to", "click", "type", "wait for",
    "check that", "check url contains", "scroll", "hover",
    "select", "press", "upload"
);

public StepValidationResult validate(String step) {
    String normalized = step.trim().toLowerCase();
    boolean valid = VALID_PREFIXES.stream().anyMatch(normalized::startsWith);
    return new StepValidationResult(valid, valid ? null : suggestPrefix(normalized));
}
```
