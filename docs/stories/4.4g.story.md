## User Story

**As a** QA gate reviewer,
**I want** end-to-end integration tests that verify the full report delivery pipeline — from scheduled poll to SMTP delivery — using GreenMail as an embedded SMTP server,
**so that** we have confidence that all components work together correctly before shipping.

- [x] **AC-1:** `com.icegreen:greenmail-junit5` test dependency added to `build.gradle.kts`.
- [x] **AC-2:** GreenMail starts an embedded SMTP server on a dynamic port, wired to `spring.mail.host` and `spring.mail.port` via `@DynamicPropertySource`.

### End-to-end delivery test

- [x] **AC-3:** `ReportDeliveryDispatcherIT`:
  1. Seeds a user, CSI, 3 HTTP checks, and a report with `status = 'active'`, `nextDeliveryAt` in the past, `recipients = ["test@example.com"]`.
  2. Calls `reportDeliveryDispatcher.pollAndDeliver()`.
  3. Verifies `report_executions` row created with status `"success"`.
  4. Verifies `nextDeliveryAt` advanced to a future timestamp.
  5. Verifies `lastSentAt` updated.
  6. Verifies GreenMail received exactly 1 email.
  7. Verifies email subject matches `"[PUT Checks] {reportName} — {date}"`.
  8. Verifies email body contains rendered HTML (check names visible).

## Implementation Notes

- **GreenMail setup pattern:**
  ```java
  @RegisterExtension
  static GreenMailExtension greenMail = new GreenMailExtension(ServerSetupTest.SMTP)
      .withConfiguration(GreenMailConfiguration.aConfig().withDisabledAuthentication());

  @DynamicPropertySource
  static void configureSmtp(DynamicPropertyRegistry registry) {
      registry.add("spring.mail.host", () -> "localhost");
      registry.add("spring.mail.port", () -> String.valueOf(greenMail.getSmtp().getPort()));
  }
  ```
- **ShedLock cleanup:** Same pattern as `CronDispatcherDriftIT` — delete/update shedlock row in `@BeforeEach` to prevent lock contention between tests.
- **Seed data isolation:** Use unique CSI IDs and report names per test class to avoid cross-test interference.
