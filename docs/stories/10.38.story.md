## Story

**As a** Studio author editing a draft,
**I want** pure client-side authoring state that keeps global and per-step context attached to stable step IDs,
**so that** add, edit, reorder, copy, delete and draft selection cannot silently move context to another instruction.

## Acceptance Criteria

1. **FR-1 / AC-1:** a pure authoring model stores `selectedDraftId`, saved source/configuration revision tokens, optional global context and ordered v2 steps from 10.36. Initial empty state is valid and contains no generated placeholder step.
2. **FR-1 / AC-2:** loading a legacy draft uses the 10.36 adapter once at the model boundary; exact step text is preserved and context defaults empty. The resulting v2 model is used for every later reducer operation.
3. **FR-4 / AC-7:** `addStep` creates a fresh stable ID; `editStep` preserves it; `reorderStep` changes order only; `copyStep` copies text/context into a fresh ID; `deleteStep` removes only the addressed ID. No operation keys by array index beyond locating presentation order.
4. Setting global context does not mutate step context. Setting one step's context does not mutate global or sibling context. Empty, Unicode, quotes, backslashes, newlines and surrounding whitespace are preserved exactly.
5. Selecting a different draft replaces the complete authoring buffer and revision tokens atomically; actions carrying a stale/nonselected draft ID are rejected or no-op according to one documented reducer rule. State from the prior draft cannot leak into the new selection.
6. Duplicate/missing step IDs and mixed legacy/v2 inputs are rejected at hydration before becoming editor state. Reducer invariants ensure all IDs remain unique after every operation.
7. The model exposes pure selectors for current draft, global context, ordered steps and step-by-ID. Selectors return immutable/read-only views and never synthesize new IDs.
8. Dirty-state calculation distinguishes source changes (step text/order/add/copy/delete) from configuration/context changes (global/step context and selected evidence reference). Selection/hydration resets dirty state to the supplied saved revisions.
9. Deterministic tests cover every operation individually and in sequences, including reorder after edit, copy then delete original, deletion of selected step, switching drafts, stale action identity, legacy hydration and exact literal preservation. Tests assert IDs and context associations, not only rendered order.
10. `npm run type-check`, focused ESLint and Vitest pass with no new failures beyond the recorded repository baseline.
