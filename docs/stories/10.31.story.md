## User Story

**As** a reviewer of the Studio contract and of this route's own tests,
**I want** `getExecutionVideo` to declare the `401`, `403` and `503` it already answers, the document's `401` envelope to say which body its own filter actually writes, and every hand-kept test copy of this route's status set to agree with the document in the same PR that changes it,
**so that** the two escalations this route has carried since story 10.15 (ESC-1, ESC-2) close by ruling rather than by invention, DEF-09(b)'s finding — that this route's two refusals do not share an envelope — stops being an undeclared fact, and nobody has to discover either gap by reading code instead of the contract.

## Problem Statement

Everything below is either the authorized text of ADR-002 §24/§25 (verified by reading
`docs/architecture/ADR-002-internal-contract-surface.md` directly, at the section numbers cited) or a
fact re-verified against the merged tree at `82322e084` on this branch, each with the file and line
that was actually read.

**1. `getExecutionVideo` still declares exactly `{200, 206, 404, 410, 416}`.** Verified:
`docs/specs/studio/openapi.yaml:739-784`. `ExecutionVideoContractEscalationTest` (both tests) is
still red for exactly the reason its Javadoc states — the route answers `403` for an unauthorized
caller and `503` for an unreachable store today, and declares neither. Nothing about the running
system needs to change; only the document needs to catch up (ADR-002 §24.2: *"This declares
behaviour that is already shipped and tested. It chooses nothing new, apart from the `503` that
ESC-2 asked for."*).

**2. The document's `401` lies about its own producer, on every public operation that declares one.**
`BffSessionAuthenticationFilter.java:248-256` writes
`{"error":{"message":"Session required","traceId":"<32 hex>","code":"UNAUTHENTICATED"}}` — `error` is
an **object**. `docs/specs/studio/openapi.yaml`'s `components.responses.Unauthorized` (line 1292)
declares `ErrorResponse`, whose `error` is a **string** (`components.schemas.ErrorResponse`, line
1316). Eleven public operations point their `401` at `Unauthorized`
(`docs/specs/studio/openapi.yaml:141,227,347,388,418,468,518,576,640,687,721` — `listTests`,
`createTest`, `getTest`, `updateTest`, `deleteTest`, `compileTest`, `confirmCompile`, `executeTest`,
`listExecutions`, `getExecution`, `streamExecution`), and every one of them has never been tested
with no identity until story 10.15's `ExecutionVideoAuthorizationIT` did so by accident (run log,
*DEF-09*). Two internal callbacks — `claimAdmission` (line 1006) and `reportProgress` (line 1155) —
**also** point at `Unauthorized`, and for them it is **correct**: `ServiceIdentityAuthenticationFilter.java:94-101`
writes the flat `{"error":"SERVICE_IDENTITY_REQUIRED","message":"..."}`, which really is
`ErrorResponse`.

**3. This is not a Studio decision, and ADR-002 says so itself (§25.2).** Which envelope the
application standardises on is a backend-wide question the ADR explicitly declines to settle,
recorded as **O-19**, owned by @architect with @pm, outside Epic 10. What Epic 10 does meanwhile is
make the document tell the truth about what its own filter sends **today** — a new response
component, `SessionUnauthorized`, carrying a new schema, `PlatformErrorResponse` — without touching
`Unauthorized` itself, because `Unauthorized`'s other two users (the internal callbacks) already
match it.

**4. The two refusals this route actually sends do not share a shape, and nothing has read that until now.**
Run log `EPIC-10-RUN-LOG.md:1549-1561` (*"DEF-09's byte difference, read rather than guessed"*), byte-for-byte:

| Row | Status | Bytes | Body |
|---|---|---|---|
| a principal on a different CSI | `403` | 87 | `{"error":"STUDIO_FORBIDDEN","message":"You do not have access to this Studio resource"}` |
| no identity headers at all | `401` | 110 | `{"error":{"message":"Session required","traceId":"<32 hex>","code":"UNAUTHENTICATED"}}` |

`error` is a string in one and an object in the other. ADR-002 §25.3 states plainly that **no suite
validates a `401` body against the document today** — `apiClient.ts:69` branches on
`error.response?.status` alone, and the Studio transport tests stub their own `401` bodies. This
story closes that specific gap for the two bodies this route can actually produce (AC-7); it does
not, and may not, decide which envelope wins backend-wide (O-19).

**5. Two hand-kept test copies of this route's status set exist, and a grep found no others load-bearing.**
`ExecutionVideoContractTest.theVideoOperationsStatusSetIsUnchanged` (`ExecutionVideoContractTest.java:272-278`)
and `StudioContractTest.noOperationsStatusSetOrMarkerMovedWhileTestDtoGainedTwoProperties`
(`StudioContractTest.java:311-351`, the `GET /executions/{id}/video` row at line 317) both hard-code
`200,206,404,410,416` today. A repository-wide grep for the same literal (`200,206,404,410,416` and
`200.*206.*404.*410.*416`, run against `backend/src`, `frontend/src`, `studio-runner/src`,
`studio-runner/test` and `docs/`) found exactly these two, plus two **non-code** occurrences in a
closed QA gate file — see *Dev Notes → The hand-kept-copy search* for the full result and why the
two gate-file hits are not touched.

**6. The frontend mock still answers `404` for exactly the case ADR-002 §24.3 says must be `403`.**
`frontend/src/services/mocks/studio/handlers.ts:124-127`, `serveExecutionVideo`'s first branch,
answers `404 VIDEO_UNAVAILABLE` when `readable(allExecutions()).find(...)` returns `undefined` —
which happens for **both** an unknown execution id **and** an execution on a CSI the mock's
`readable()` filter (line 27-28) has already excluded. ADR-002 §24.3: *"one `403` for 'forbidden' and
'absent' alike... Using `404` for an unknown id as well would be the existence oracle that AC-4a
exists to prevent. The MSW mock currently makes exactly that choice."* Two tests currently assert the
`404` and the "serves no 401 or 403" framing directly:
`frontend/src/services/mocks/studio/studioContract.test.ts:879-899` (two `not.toContain` lines and a
five-element produced-status array) and
`frontend/src/services/mocks/studio/studioVideoHandler.test.ts:122-127`.

**7. The runner's contract pin will be red twice before this story's PR, once by 10.30 and once by
this story's own edit**, and `FOC-07` names the order and the rule: re-read `shasum -a 256` from the
file as merged, never transcribe a digest from ADR-002, from the other story, or from the
studio-inference program.
