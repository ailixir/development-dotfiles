## User Story

**As the** backend compile pipeline that must ask the R2D2 gateway to propose Playwright source,
**I want** a bounded, audited gateway client built on the Vertex AI SDK with pinned model/version metadata, disabled SDK auto-retries and stub-testable behavior,
**so that** compilation cost, latency and failure modes are controlled, no resolved value or request body ever reaches audit logs, and draft saving never depends on the gateway.

---

## Problem Statement

Architecture §4.1: R2D2 is a proxy in front of Vertex-hosted models, so the backend integrates through the Google Vertex AI SDK with endpoint/project/location/credentials as deployment configuration (§8.5), and must disable SDK-level automatic retries that could exceed the two repair attempts of §4.3. Structured output and temperature zero reduce variance but are not guarantees, and the proxy is the authority on reachable models, parameters and quotas; those facts are established by spike **SPK-01** in the [staging spike register](../architecture/studio-staging-spikes.md), which gates this story's pilot-use acceptance but not its implementation.

The backend has no gateway client today. `build.gradle.kts` includes `resilience4j-spring-boot3` (bounded timeouts/retries) and `wiremock-standalone` (stub tests); no Vertex artifact is declared.

## Acceptance Criteria

### Client and configuration
- [x] **AC-1:** New bounded context package `studio/compile/gateway/` with `LlmGatewayClient` interface: `propose(CompileRequest) → CompileResponse` where `CompileRequest` carries opaque token inputs only (fenced ordered source lines with `<secret ID>`/`<var NAME>` placeholders, the versioned syntax reference, the output contract) and metadata (`testId`, `csiId`, `principal`, `compileRequestId`, `attempt`). Prompt assembly is 10.8; this story defines the request type and transport.
- [x] **AC-2:** `VertexLlmGatewayClient` implements the interface with the Google Vertex AI Java SDK generative-model client configured from `studio.compile.gateway.*` properties: `endpoint`, `project`, `location`, `model`, `credentials` (service credentials for the Studio compile workload, never a user token), `requestTimeout`, `maxConcurrency`, `maxInputBytes`, `maxOutputBytes`, `structuredOutput` (boolean), `temperature`. None are hardcoded; missing required values fail startup with a clear message when `studio.compile.gateway.enabled=true`.
- [x] **AC-3:** The exact SDK artifact and version are pinned in `build.gradle.kts` and recorded in `docs/qa/spikes/SPK-01/` once verified; until SPK-01 closes, the version is the one used for the stub tests and is marked `unverified-against-R2D2` in a comment.
- [x] **AC-4:** SDK-level automatic retries are disabled. The client's own retry applies **only** to definite transport failures (connection refused/reset, HTTP 429 with `Retry-After`, 503) with a bounded count (default 2) and jittered backoff, never to timeouts or ambiguous 5xx after bytes were received; total attempts are observable in the audit record.
- [x] **AC-5:** Concurrency is bounded by a semaphore sized from `maxConcurrency`; when saturated, `propose` fails fast with `GATEWAY_BUSY` and does not queue indefinitely. Input larger than `maxInputBytes` is rejected **before** any network call with `COMPILE_INPUT_TOO_LARGE`; responses larger than `maxOutputBytes` are discarded with `GATEWAY_OUTPUT_TOO_LARGE`.
- [x] **AC-6:** `studio.compile.gateway.enabled=false` (default) yields a `DisabledLlmGatewayClient` that returns `GATEWAY_UNAVAILABLE` without network access; draft save/update paths never call the gateway synchronously (asserted by a test that saves a draft with the client bean replaced by one that throws).

### Structured output and parsing
- [x] **AC-7:** When `structuredOutput=true` the request asks for a JSON response conforming to the artifact contract (`docs/specs/studio/artifact.schema.json` from 10.1); when `false` the client requests plain text. In **both** modes the response is parsed defensively: extract the JSON document, validate it against the schema, and return `CompileResponse{artifact | parseFailure(reason)}`. No code path assumes the proxy honoured the schema (SPK-01 constraint).
- [x] **AC-8:** `temperature` is sent as configured (default `0`); the client records the values actually sent and, when the SDK exposes them, the model/version identifiers actually returned, into `CompileResponse.provenance` (`model`, `modelVersion`, `promptVersion` passthrough, `sdkVersion`, `structuredOutput`, `temperature`).

### Audit and secrecy
- [x] **AC-9:** Every call emits one structured audit log line with: `testId`, `csiId`, `principal`, `compileRequestId`, `attempt`, `model`, `promptVersion`, `syntaxReferenceVersion`, `latencyMs`, `outcome` (`OK|PARSE_FAILURE|TIMEOUT|TRANSPORT|BUSY|TOO_LARGE|DISABLED`), `inputBytes`, `outputBytes`, `retries`. It never contains the prompt, the response body, resolved values or placeholders' surrounding text.
- [x] **AC-10:** Canary test: a `CompileRequest` whose source lines contain a canary string and a `<secret ID>` placeholder produces a captured HTTP request (WireMock) containing the placeholder token but not any resolved canary value, and audit output containing neither the canary nor the source text.
- [x] **AC-11:** Exceptions thrown by the SDK are wrapped; their messages are truncated and scrubbed before logging so gateway error bodies cannot leak request content.

### Tests (WireMock stub of the Vertex REST surface)
- [x] **AC-12:** `VertexLlmGatewayClientTest` covers: valid structured JSON → artifact; valid text with embedded JSON → artifact; malformed JSON → `PARSE_FAILURE`; schema-invalid JSON → `PARSE_FAILURE` with the schema path; oversized response → `GATEWAY_OUTPUT_TOO_LARGE`; oversized input → rejected pre-flight; timeout → `TIMEOUT` with no retry; `503` twice then `200` → success with `retries=2`; `503` three times → `TRANSPORT` after the bounded count; saturation → `GATEWAY_BUSY`.
- [x] **AC-13:** `GatewayDisabledIT`: with the flag off, creating and updating a draft succeeds and no outbound connection is attempted (WireMock records zero requests).
- [x] **AC-14:** `GatewayAuditTest` asserts AC-9/AC-10 on captured log events.
- [x] **AC-15:** JaCoCo ≥ 80% on `studio/compile/gateway/**`; `./gradlew check` green.

## Implementation Notes

- Keep the interface free of SDK types so 10.8 and tests depend on `LlmGatewayClient` only; the Vertex implementation is the single place that knows the SDK.
- Schema validation in AC-7 reads the schema path from configuration; tests carry a fixture copy of `artifact.schema.json` so this story does not block on 10.1a. Replace the copy with the real file once 10.1a merges.
- Point the SDK at R2D2 through its endpoint/base-URL setting rather than a bespoke HTTP client (§4.1); if the pinned SDK version cannot target a custom endpoint, stop and escalate to @architect. Do not write a raw HTTP client as a workaround without an ADR note.
- Use resilience4j `TimeLimiter`/`Retry`/`Bulkhead` (already on the classpath) for AC-4/AC-5 rather than hand-rolled loops; configure retry predicates explicitly so timeouts never retry.
- The audit line is the only log at INFO; SDK debug logging must stay off in all profiles except `local`.
- The WireMock stub should mirror the Vertex `generateContent` REST shape the SDK emits; record one real staging exchange's shape (headers redacted) into the SPK-01 folder when available and update the stub to match.

### Decisions and deviations

1. **SDK pin.** `com.google.cloud:google-cloud-vertexai:1.52.0`, marked `unverified-against-R2D2`
   in `build.gradle.kts`. Verified only against the WireMock stub.
2. **Custom endpoint — review requested by @architect.** The Implementation Note asked to point the
   SDK at R2D2 through its endpoint setting and to escalate rather than hand-roll HTTP. The SDK
   *can* target a custom endpoint, but not through `VertexAI.Builder.setApiEndpoint`, which formats
   the value as `{endpoint}:443` and gives no hook to disable gax retries. Both requirements are met
   by building `PredictionServiceClient` / `LlmUtilityServiceClient` from
   `PredictionServiceSettings.newHttpJsonBuilder()` and injecting them through
   `setPredictionClientSupplier` / `setLlmClientSupplier` (`VertexAiClientFactory`). No bespoke HTTP
   client was written; request/response shapes, structured output and deadline handling remain the
   SDK's. Flagging it because it is a reading of the note, not a literal follow of it.
3. **Deprecated generative-model surface.** 1.52.0 deprecates
   `com.google.cloud.vertexai.generativeai.GenerativeModel` and `ResponseHandler`; the replacement
   lives in the separate `com.google.genai:google-genai` artifact, and
   `com.google.cloud.vertexai.genai.Client` in this artifact exposes agent engines only, not models.
   Architecture §4.1 names the Vertex AI SDK generative-model client, so that is what is used, with
   `@SuppressWarnings("deprecation")` and a documented rationale. Which SDK R2D2 actually supports
   is SPK-01 question 1 (assumption A3).
   *Corrected 2026-09-11 (QA MED-001).* As first written this decision was contradicted by the build:
   `com.google.genai:google-genai:1.47.0` arrived transitively anyway, because 1.52.0 ships a flattened
   POM. `javap`/constant-pool scan of `google-cloud-vertexai-1.52.0.jar` shows every reference to
   `com.google.genai` is confined to the unused `com.google.cloud.vertexai.genai.*` package —
   `VertexAI`, `GenerativeModel` and `ResponseHandler` have none — so the artifact is now excluded in
   `build.gradle.kts` and the decision holds literally. LOW-005 (the `gson 2.12.1 → 2.10.1` downgrade
   for `google-genai`) is moot as a consequence; `gson` stays because
   `com.google.cloud.vertexai.generativeai` uses it.
4. **429 `Retry-After` not honoured.** AC-4 names "HTTP 429 with `Retry-After`" as retryable. The
   SDK's httpjson transport does not surface response headers on `ApiException`, so the client
   retries `RESOURCE_EXHAUSTED` using its own jittered backoff instead of the server's hint. Still
   bounded by `retry.max-retries` (default 2). Recorded as assumption A10 in the SPK-01 record.
5. **TimeLimiter not used.** resilience4j `Retry` and `Bulkhead` are used as the note directs. The
   deadline comes from gax's logical timeout (`RetrySettings.setLogicalTimeout`), the SDK-native
   mechanism, rather than a resilience4j `TimeLimiter` that would need its own thread pool to wrap a
   blocking call. `VertexLlmGatewayClientTest.timeoutIsNotRetried` proves the deadline fires and is
   classified as `TIMEOUT` with `retries=0`.
6. **Runtime schema validation.** `com.networknt:json-schema-validator` moved from
   `testImplementation` to `implementation`: AC-7 validates gateway responses at runtime, not only
   in tests.
7. **Artifact schema fixture.** `backend/src/main/resources/studio/artifact.schema.json` is a
   fixture copy transcribed from architecture §4.4, carrying a `$comment` that says so. It lives in
   `main` rather than `test` resources because the parser loads it at runtime. Replace it with the
   canonical file when 10.1a merges; the location is configurable via
   `studio.compile.gateway.artifact-schema`.
8. **Canary test reading.** AC-10 is implemented as: the request carries the `<secret LOGIN_PW>`
   placeholder and never the canary value, and the test asserts the captured WireMock body contains
   the placeholder and not the canary, and that neither audit nor diagnostic output contains the
   canary or the source text. Handing the client a resolved canary would contradict AC-1.

### Judgements on the three flagged deviations

**SDK deviation (Dev Decision 2) — sound, not bespoke.** The `%s:443` constant is real, so
`setApiEndpoint` genuinely cannot express `http://host:port`; and because
`VertexAI.getPredictionServiceClient()` is a bare supplier read, the injected client is consumed by
the SDK's own generated `generateContentCallable`. Request/response shapes, structured output and
deadline handling stay the SDK's. No raw HTTP client was written.

**Retries — provably disabled, verified two independent ways.** `disableSdkRetries` clears the
retryable code set and sets `maxAttempts(1)` on the exact `UnaryCallSettings` the call path uses;
and empirically the SDK's own defaults already produce one attempt on a permanent 503
(`getRetryableCodes()` is `[]` out of the box). The story's
`threeUnavailableResponsesExhaustTheBoundedRetry` sees exactly 3 serve events for `maxRetries=2`.
**There is no gax + resilience4j double-retry.** Client backoff is
`ofExponentialRandomBackoff(250ms, 2.0, jitter 0.5)` capped at `maxRetries+1` — bounded and
jittered as claimed.

**AC-4 `Retry-After` (Dev Decision 4) — a genuine SDK limitation, not a shortcut.** Confirmed in
bytecode: `ApiException` exposes no header map, `getMetadata()` returns `null` without `ErrorInfo`,
and the httpjson factory never supplies `ErrorDetails`. Response headers are structurally
unreachable on this transport.

**AC-16 — an honest deferral.** ED-01 is `status: open` and its `gate_note` blocks precisely
pilot-use acceptance while permitting stub tests. `docs/qa/spikes/SPK-01/README.md` is headed
`Status: OPEN. Nothing here is verified against R2D2 yet`, records ten assumptions each mapped to a
spike question, and leaves every Findings row blank. Nothing unverified is asserted as fact.

**Fixture schema — permitted and clearly marked.** The story's *Depends on* row and Implementation
Notes explicitly authorise a local fixture copy pending 10.1a. The file carries a `$comment` naming
10.1a and the path is configurable, with a `FIXTURE COPY` comment in `application.yml`.
