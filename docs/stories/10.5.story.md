## User Story

**As the** backend compile pipeline that must ask the R2D2 gateway to propose Playwright source,
**I want** a bounded, audited gateway client built on the Vertex AI SDK with pinned model/version metadata, disabled SDK auto-retries and stub-testable behavior,
**so that** compilation cost, latency and failure modes are controlled, no resolved value or request body ever reaches audit logs, and draft saving never depends on the gateway.

---

## Problem Statement

Architecture §4.1: R2D2 is a proxy in front of Vertex-hosted models, so the backend integrates through the Google Vertex AI SDK with endpoint/project/location/credentials as deployment configuration (§8.5), and must disable SDK-level automatic retries that could exceed the two repair attempts of §4.3. Structured output and temperature zero reduce variance but are not guarantees, and the proxy is the authority on reachable models, parameters and quotas; those facts are established by spike **SPK-01** in the [staging spike register](../architecture/studio-staging-spikes.md), which gates this story's pilot-use acceptance but not its implementation.

The backend has no gateway client today. `build.gradle.kts` includes `resilience4j-spring-boot3` (bounded timeouts/retries) and `wiremock-standalone` (stub tests); no Vertex artifact is declared.

## Acceptance Criteria

### Client and configuration
- [ ] **AC-1:** New bounded context package `studio/compile/gateway/` with `LlmGatewayClient` interface: `propose(CompileRequest) → CompileResponse` where `CompileRequest` carries opaque token inputs only (fenced ordered source lines with `<secret ID>`/`<var NAME>` placeholders, the versioned syntax reference, the output contract) and metadata (`testId`, `csiId`, `principal`, `compileRequestId`, `attempt`). Prompt assembly is 10.8; this story defines the request type and transport.
- [ ] **AC-2:** `VertexLlmGatewayClient` implements the interface with the Google Vertex AI Java SDK generative-model client configured from `studio.compile.gateway.*` properties: `endpoint`, `project`, `location`, `model`, `credentials` (service credentials for the Studio compile workload, never a user token), `requestTimeout`, `maxConcurrency`, `maxInputBytes`, `maxOutputBytes`, `structuredOutput` (boolean), `temperature`. None are hardcoded; missing required values fail startup with a clear message when `studio.compile.gateway.enabled=true`.
- [ ] **AC-3:** The exact SDK artifact and version are pinned in `build.gradle.kts` and recorded in `docs/qa/spikes/SPK-01/` once verified; until SPK-01 closes, the version is the one used for the stub tests and is marked `unverified-against-R2D2` in a comment.
- [ ] **AC-4:** SDK-level automatic retries are disabled. The client's own retry applies **only** to definite transport failures (connection refused/reset, HTTP 429 with `Retry-After`, 503) with a bounded count (default 2) and jittered backoff, never to timeouts or ambiguous 5xx after bytes were received; total attempts are observable in the audit record.
- [ ] **AC-5:** Concurrency is bounded by a semaphore sized from `maxConcurrency`; when saturated, `propose` fails fast with `GATEWAY_BUSY` and does not queue indefinitely. Input larger than `maxInputBytes` is rejected **before** any network call with `COMPILE_INPUT_TOO_LARGE`; responses larger than `maxOutputBytes` are discarded with `GATEWAY_OUTPUT_TOO_LARGE`.
- [ ] **AC-6:** `studio.compile.gateway.enabled=false` (default) yields a `DisabledLlmGatewayClient` that returns `GATEWAY_UNAVAILABLE` without network access; draft save/update paths never call the gateway synchronously (asserted by a test that saves a draft with the client bean replaced by one that throws).

### Structured output and parsing
- [ ] **AC-7:** When `structuredOutput=true` the request asks for a JSON response conforming to the artifact contract (`docs/specs/studio/artifact.schema.json` from 10.1); when `false` the client requests plain text. In **both** modes the response is parsed defensively: extract the JSON document, validate it against the schema, and return `CompileResponse{artifact | parseFailure(reason)}`. No code path assumes the proxy honoured the schema (SPK-01 constraint).
- [ ] **AC-8:** `temperature` is sent as configured (default `0`); the client records the values actually sent and, when the SDK exposes them, the model/version identifiers actually returned, into `CompileResponse.provenance` (`model`, `modelVersion`, `promptVersion` passthrough, `sdkVersion`, `structuredOutput`, `temperature`).

### Audit and secrecy
- [ ] **AC-9:** Every call emits one structured audit log line with: `testId`, `csiId`, `principal`, `compileRequestId`, `attempt`, `model`, `promptVersion`, `syntaxReferenceVersion`, `latencyMs`, `outcome` (`OK|PARSE_FAILURE|TIMEOUT|TRANSPORT|BUSY|TOO_LARGE|DISABLED`), `inputBytes`, `outputBytes`, `retries`. It never contains the prompt, the response body, resolved values or placeholders' surrounding text.
- [ ] **AC-10:** Canary test: a `CompileRequest` whose source lines contain a canary string and a `<secret ID>` placeholder produces a captured HTTP request (WireMock) containing the placeholder token but not any resolved canary value, and audit output containing neither the canary nor the source text.
- [ ] **AC-11:** Exceptions thrown by the SDK are wrapped; their messages are truncated and scrubbed before logging so gateway error bodies cannot leak request content.

### Tests (WireMock stub of the Vertex REST surface)
- [ ] **AC-12:** `VertexLlmGatewayClientTest` covers: valid structured JSON → artifact; valid text with embedded JSON → artifact; malformed JSON → `PARSE_FAILURE`; schema-invalid JSON → `PARSE_FAILURE` with the schema path; oversized response → `GATEWAY_OUTPUT_TOO_LARGE`; oversized input → rejected pre-flight; timeout → `TIMEOUT` with no retry; `503` twice then `200` → success with `retries=2`; `503` three times → `TRANSPORT` after the bounded count; saturation → `GATEWAY_BUSY`.
- [ ] **AC-13:** `GatewayDisabledIT`: with the flag off, creating and updating a draft succeeds and no outbound connection is attempted (WireMock records zero requests).
- [ ] **AC-14:** `GatewayAuditTest` asserts AC-9/AC-10 on captured log events.
- [ ] **AC-15:** JaCoCo ≥ 80% on `studio/compile/gateway/**`; `./gradlew check` green.

### Pilot-use record (gated by SPK-01 / ED-01)
- [ ] **AC-16:** Before any non-stub use, `docs/qa/spikes/SPK-01/` records the verified SDK version, reachable model identifiers, structured-output and temperature behavior, quotas, and the credentials-issuance reference; the story is not Done for pilot use until that record exists and `enabled=true` has been exercised in staging. Fixture/stub acceptance (AC-1..15) may complete earlier.

## Implementation Notes

- Keep the interface free of SDK types so 10.8 and tests depend on `LlmGatewayClient` only; the Vertex implementation is the single place that knows the SDK.
- Schema validation in AC-7 reads the schema path from configuration; tests carry a fixture copy of `artifact.schema.json` so this story does not block on 10.1a. Replace the copy with the real file once 10.1a merges.
- Point the SDK at R2D2 through its endpoint/base-URL setting rather than a bespoke HTTP client (§4.1); if the pinned SDK version cannot target a custom endpoint, stop and escalate to @architect. Do not write a raw HTTP client as a workaround without an ADR note.
- Use resilience4j `TimeLimiter`/`Retry`/`Bulkhead` (already on the classpath) for AC-4/AC-5 rather than hand-rolled loops; configure retry predicates explicitly so timeouts never retry.
- The audit line is the only log at INFO; SDK debug logging must stay off in all profiles except `local`.
- The WireMock stub should mirror the Vertex `generateContent` REST shape the SDK emits; record one real staging exchange's shape (headers redacted) into the SPK-01 folder when available and update the stub to match.
