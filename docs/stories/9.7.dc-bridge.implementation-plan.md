---

## 1. Goal

Enable PUT Checks to **execute** Splunk / Grafana / ITRS / AppDynamics (and later other DC sources) by calling the **DailyChecks (DC) API as a temporary integration layer**, normalizing results into our existing `ExecutionOutcome` model.

This is a **bridge**, not a native reimplementation of those tools. Later we can swap adapters for native clients without changing the Checks domain or dispatcher.

---

## 2. Architecture (what to build)

**Decision vs alternatives**

| Option | Summary | Verdict |
|---|---|---|
| **Proposal A** | Each executor owns auth/send/retry/map/deep-link/metrics | Reject as default — duplicates shared mechanics |
| **Proposal B** | Central `DailyChecksAdapter` + thin executors + per-tool mappings | **Adopt** |
| Earlier Hybrid | Named per-source adapter + shared `DcClient` | Same family as B; use B’s concrete shape/names |

```text
POST /api/v1/checks/{id}/execute
        ↓
CheckExecutorDispatcher   (unchanged: source flags + per-type semaphore / throttle)
        ↓
SplunkCheckExecutor       (thin — supplies SplunkMapping only)
        ↓
DailyChecksAdapter        (ONE shared engine: auth, send, retry, outer map, deep link, metrics)
        ↓
DailyChecks API
        ↓
ExecutionOutcome (Success | Failure | Warning | Timeout | Throttled)
```

### Package layout (new)

```text
backend/src/main/java/com/citi/put/checks/dc/
├── DailyChecksAdapter.java      # shared engine (Proposal B)
├── DcClient.java                # optional low-level RestClient wrapper used by adapter
├── DcClientConfig.java
├── DcProperties.java            # checks.dc.*
├── DcAuthHandler.java
├── DcErrorMapper.java           # transport / outer envelope → outcome helpers
├── mapping/

│   ├── GrafanaMapping.java
│   ├── ItrsMapping.java
│   └── AppDynamicsMapping.java
└── support/                     # optional helpers
```

Thin executors stay in the existing package:

```text
backend/src/main/java/com/citi/put/checks/checks/executors/
├── SplunkCheckExecutor.java
├── GrafanaCheckExecutor.java
├── ItrsCheckExecutor.java
└── AppDynamicsCheckExecutor.java
```

### Key contracts

```java
// Shared engine — owns auth, send, retry, outer mapping, deep links, metrics
public class DailyChecksAdapter {
  public ExecutionOutcome run(
      Check check,
      ExecutionContext ctx,
      Function<Check, DcRequest> toRequest,
      Function<DcResponse, String> parseDetail) { /* ... */ }
}

// Thin executor — tool-specific pieces only
@Component
public class SplunkCheckExecutor implements CheckExecutor {
  private final DailyChecksAdapter adapter;

  public CheckType supportedType() { return CheckType.SPLUNK; }

  public ExecutionOutcome execute(Check check, ExecutionContext ctx) {
    return adapter.run(check, ctx, SplunkMapping::toRequest, SplunkMapping::parseDetail);
  }
}
```

### Design rules (non-negotiable)

1. **DC is the only outbound API** for these sources in v1 — no native Splunk/Grafana/ITRS/AppD SDKs.
2. **Do not leak DC DTOs** into `checks.model`, REST DTOs, or persistence — only `ExecutionOutcome`.
3. **Keep 1:1** `CheckType` → thin `CheckExecutor` (preserves dispatcher, source flags, concurrency).
4. **Shared mechanics live only in `DailyChecksAdapter`** — not copied into each executor (reject Proposal A drift).
5. **Throttling stays in the Dispatcher** — do not reimplement in the adapter.
6. **Do not** invent a catch-all `DC_LEGACY` check type.
7. **Do not** build a YAML/descriptor connector engine in v1.
8. **Do not** put DC wire models in 9.5 import or 9.6 ROD code.
9. Secrets/credentials via config / secret refs — never plaintext in check JSON.
10. Mutable settings in YAML (`checks.dc.*`, Resilience4j) — no hardcoded base URLs/timeouts.
11. If a tool is too irregular for the shared outer map, thicken that tool’s `*Mapping` first; only then consider an A-style exception for that type.

### Error mapping

| Situation | Result |
|---|---|
| Source disabled | existing `CheckSourceDisabledException` |
| Semaphore exhausted | `ExecutionOutcome.Throttled` (Dispatcher) |
| DC connect/read timeout | `Timeout` |
| DC 5xx / circuit open / network | `Failure` (“DC unavailable…”) |
| DC 401/403 | `Failure` (“DC auth failed…”) |
| DC 200 + business fail | `Failure` (+ deep link if DC provides one) |
| Unexpected body / parse error | `Failure` (“Unexpected DC response…”) + redacted log |

Transport + outer envelope → `DailyChecksAdapter` / `DcErrorMapper`. Tool-specific detail → **each `*Mapping`**.

### Phase 1 — `DailyChecksAdapter` skeleton (`9.7.1`)

**Size:** M  
**Depends on:** Phase 0 for auth/timeout facts (can scaffold with TODOs if blocked)

**Create**

| File | Purpose |
|---|---|
| `dc/DailyChecksAdapter.java` | Shared engine: `run(check, ctx, toRequest, parseDetail)` |
| `dc/DcProperties.java` | `@ConfigurationProperties` for `checks.dc.*` |
| `dc/DcClientConfig.java` | `RestClient` bean, timeouts |
| `dc/DcClient.java` | Low-level exchange API used by the adapter |
| `dc/DcAuthHandler.java` | Inject auth headers/credentials |
| `dc/DcErrorMapper.java` | HTTP/transport + outer envelope → outcome helpers |
| `application.yml` | `checks.dc.*` + Resilience4j `dailychecks` CB/retry |

**Follow existing patterns**

- `RemoteCsiApiClient` / `CoreServiceClient` — `RestClient` + Resilience4j `@CircuitBreaker` / retry
- Keep a master kill switch: `checks.dc.enabled`

**Config sketch**

```yaml
checks:
  dc:
    enabled: true
    base-url: ${CHECKS_DC_BASE_URL:}
    auth:
      mode: ${CHECKS_DC_AUTH_MODE:none}   # none|basic|bearer|header — from inventory
    timeout:
      connect-ms: 3000
      read-ms: 60000

resilience4j:
  circuitbreaker:
    instances:
      dailychecks: { /* ... */ }
  retry:
    instances:
      dailychecks: { /* retry transport only, never business FAIL */ }
```

**Acceptance**

- [ ] `DailyChecksAdapter.run(...)` calls a WireMock stub successfully with a dummy mapping
- [ ] CB/retry wired; kill switch disables client/bean behavior safely
- [ ] No secrets committed

**Tests**

- WireMock IT for adapter/`DcClient` (happy path, 5xx → mapped failure, timeout)
