## User Story

**As the** put-checks platform running a partitioned `execution_results` table,
**I want** an automated scheduler that creates future monthly partitions ahead of time, a startup bootstrap that ensures partitions exist on fresh deploys, and a health indicator that alerts 3 days before partition exhaustion,
**so that** INSERTs never fail due to a missing partition and ops gets early warning if the scheduler misfires.

## Acceptance Criteria

### Partition scheduler
- [x] **AC-1:** `PartitionScheduler` bean with `@Scheduled(cron = "0 0 3 25 * ?")`. Creates partitions for current + next 2 months using idempotent `CREATE TABLE IF NOT EXISTS ... PARTITION OF`.
- [x] **AC-2:** `@SchedulerLock(name = "partitionCreator", lockAtMostFor = "10m", lockAtLeastFor = "30s")` prevents multi-pod races.
- [x] **AC-3:** Partition naming convention: `execution_results_YYYY_MM`.
- [x] **AC-4:** DDL executed via `JdbcTemplate.execute()`.

### Startup bootstrap
- [x] **AC-5:** `@EventListener(ApplicationReadyEvent.class)` runs the same partition-creation logic at boot.
- [x] **AC-6:** Bootstrap is idempotent — `CREATE TABLE IF NOT EXISTS` produces no errors on existing partitions.

### Health indicator
- [x] **AC-7:** `PartitionHealthIndicator` (bean name "partitions") returns UP/DOWN based on +3-day partition existence. DOWN includes `missing_partition` detail.
- [x] **AC-8:** Health check queries `pg_class` + `pg_inherits` — no DDL.

### Generalization
- [x] **AC-9:** `PartitionManager` generalized class accepts table name. Scheduler iterates over `execution_results`, `ui_test_executions`, `report_executions`.
- [x] **AC-10:** `PartitionManager.isPartitionedTable()` checks `pg_partitioned_table`. Non-partitioned/missing tables skipped with debug log.

### Metrics + logging
- [x] **AC-11:** Gauge `partition.future_months_available` — future monthly partitions for `execution_results`.
- [x] **AC-12:** Structured log: `partition_created table=... range=[..., ...)`.

### Tests
- [x] **AC-13:** `PartitionSchedulerIT`: trigger → verify next 2 months exist.
- [x] **AC-14:** `PartitionBootstrapIT`: app start → current + next 2 months exist.
- [x] **AC-15:** `PartitionHealthIT`: (a) UP with partitions, (b) DOWN after dropping +3-day partition.
- [x] **AC-16:** `PartitionIdempotencyIT`: run twice → no errors.

## Implementation Notes
- **Partition DDL format:** `CREATE TABLE IF NOT EXISTS execution_results_2026_06 PARTITION OF execution_results FOR VALUES FROM ('2026-06-01') TO ('2026-07-01')`. The `IF NOT EXISTS` makes it idempotent.
- **Date math:** `YearMonth.now(ZoneOffset.UTC).plusMonths(offset)` for month calculation.
- **Health check query:** `SELECT c.relname FROM pg_class c JOIN pg_inherits i ON c.oid = i.inhrelid WHERE i.inhparent = 'execution_results'::regclass` lists all child partitions. Parse month from name and check coverage.
- **Generalized PartitionManager:** constructor takes `(JdbcTemplate, String tableName, PartitionInterval)`. `ensurePartitions(int lookaheadMonths)` creates missing partitions. `checkHealth(int lookaheadDays)` returns health status.

## Dev Notes / QA Gate Notes

### Dev Notes (2026-04-19)

- **No split needed** — implemented as single story. PartitionManager generalized class + PartitionScheduler (bootstrap + cron) + PartitionHealthIndicator all fit naturally.
- **PartitionBootstrapListener merged into PartitionScheduler** — the `@EventListener(ApplicationReadyEvent)` bootstrap method lives in the same component as `@Scheduled`, keeping related logic together.
- **`pg_partitioned_table` catalog check** used to detect whether a table is partitioned. `ui_test_executions` and `report_executions` are non-partitioned regular tables in V1 — gracefully skipped.
- **`DETACH PARTITION ... CONCURRENTLY`** used in PartitionHealthIT to drop a partition for the DOWN test case.
