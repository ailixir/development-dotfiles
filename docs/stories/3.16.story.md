## User Story

**As a** operations engineer viewing the Needs Attention panel on the dashboard,
**I want** the Acknowledge and Assign actions to persist so that acknowledged checks stay dismissed until the next new failure and assigned checks show who is investigating,
**so that** my team can triage failures without the same items reappearing on every refresh.

---

## Acceptance Criteria

### Backend — Schema migration

- [ ] **AC-1:** Flyway migration `V11__check_acknowledge_assign.sql` adds two nullable columns to the `checks` table:
  - `acknowledged_at TIMESTAMPTZ` — when the current failure was acknowledged
  - `assigned_to VARCHAR(255) REFERENCES users(email)` — who is investigating
- [ ] **AC-2:** Index `idx_checks_assigned_to` created on `checks(assigned_to) WHERE deleted_at IS NULL AND assigned_to IS NOT NULL`.

### Backend — Check entity update

- [ ] **AC-3:** `Check.java` entity gains `acknowledgedAt` (Instant) and `assignedTo` (String) fields with JPA column mappings.
- [ ] **AC-4:** When a check's status transitions from PASSING to FAILING (or FAILING to PASSING), `acknowledgedAt` is reset to `null`. This ensures a new failure requires a fresh acknowledgement. The reset happens in the existing status-update logic.

### Backend — DashboardService persistence

- [ ] **AC-5:** `DashboardService.acknowledgeCheck(String checkId, UserIdentity identity)` sets `checks.acknowledged_at = NOW()` on the check. Returns the updated timestamp.
- [ ] **AC-6:** `DashboardService.assignCheck(String checkId, String assigneeEmail)` sets `checks.assigned_to = :email` on the check. Returns `{id, userId}`.
- [ ] **AC-7:** The attention query in `getAttentionItems` filters out acknowledged checks: adds `AND c.acknowledged_at IS NULL` to the WHERE clause. This makes acknowledged checks disappear until their next status change resets the field.

### Backend — DashboardController wiring

- [ ] **AC-8:** `POST /api/v1/dashboard/attention/{id}/acknowledge` is wired to `DashboardService.acknowledgeCheck()` using `@AuthenticationPrincipal UserIdentity`. No longer returns a hardcoded response.
- [ ] **AC-9:** `POST /api/v1/dashboard/attention/{id}/assign` is wired to `DashboardService.assignCheck()`. The `userId` comes from the request body.

### Frontend — Use real user identity for assign

- [ ] **AC-10:** `AttentionPanel.tsx` assign action uses the authenticated user's email instead of the hardcoded `'current.user@citi.com'`. The email is obtained from the `/api/v1/users/me` endpoint via a lightweight hook or direct call at component mount. If user info is unavailable, fall back to disabling the Assign button.

### Frontend — Show assigned user on attention items

- [ ] **AC-11:** `AttentionItem` type in `dashboardTypes.ts` gains an optional `assignedTo?: string` field.
- [ ] **AC-12:** The `AttentionItemDto` backend DTO includes `assignedTo` from the check.
- [ ] **AC-13:** When `assignedTo` is present on an attention item, the row displays a small avatar/chip showing the assignee's email (truncated to name portion before @) next to the status chip.

### Verification

- [ ] **AC-14:** `./gradlew check` passes.
- [ ] **AC-15:** `npm run type-check` passes.
- [ ] **AC-16:** Browser verification: acknowledge removes item persistently (survives refresh); assign shows assignee chip and persists; re-failing after recovery resets acknowledgement.

### Status-change acknowledge reset
The status update happens in `CheckService` or the execution flow when a check transitions status. Look for where `check.setStatus()` or `status = X` is set. Add `check.setAcknowledgedAt(null)` there when the new status differs from the old one.

### Attention query — current WHERE clause
Current filter: `c.status IN ('FAILING', 'WARNING') AND c.deleted_at IS NULL`
New filter adds: `AND c.acknowledged_at IS NULL`

### UserIdentity on frontend
`usersApi.getMe()` exists but has no Redux slice. The simplest approach: call `usersApi.getMe()` in a `useEffect` inside `AttentionPanel` and cache the email in local state. This avoids creating a global auth store for a single use case.

### AttentionItemDto — current fields
```java
record AttentionItemDto(String id, String name, String csiId, String csiName,
                        String status, Instant since, String reason)
```
Add `String assignedTo` as 8th parameter.
