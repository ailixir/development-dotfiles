## Story

**As a** Studio author executing a confirmed context-aware UI test,
**I want** readiness to prove that its persisted expected intent still equals the intent derived from the immutable authored revision,
**so that** semantically changed or obsolete expectations cannot create execution state or reach the runner.

## Acceptance Criteria

1. Compilation and readiness use the same pure, bounded, explicitly versioned authoring-to-intent
   derivation implementation; it performs no repository, LLM, browser, runner, network or vault call.
2. Readiness derives only from one consistent immutable candidate revision: saved source, authoring,
   stable step identities, CSI and configuration environment. It never reads or interprets the
   current mutable draft.
3. Persisted expected intent must equal the derived canonical JSON exactly, including operation
   count/order, locator chains, literals/references, keys, assertions and options. Object property
   order and insignificant JSON whitespace may differ; array order and string bytes may not.
4. Missing/corrupt authoring, missing/malformed/mismatched intent, derivation failure or semantic
   corruption returns bounded `COMPILE_REQUIRED` before execution, ledger, quota admission,
   reference/secret resolution, runner or browser activity.
5. Every new authoring-v2 candidate persists an immutable `intentDerivationVersion`; missing or
   unsupported versions fail closed with no implicit current-version fallback.
6. Revision identity/deduplication includes derivation version so recompiling a pre-version v2 row
   can create a new candidate even when artifact and expected-intent bytes are identical. A complete
   identical identity still deduplicates.
7. Confirmation applies the same semantic verification predicate before write-once confirmation.
   An invalid candidate cannot be confirmed.
8. Readiness reconstruction is verification-only. Confirmation and dispatch retain and send the
   exact saved expected-intent snapshot that passed compilation.
9. Legacy revisions without authoring, unchanged valid confirmed revisions during optional compile
   failure, and metadata-only edits preserve existing behavior. Historical v2 rows without required
   provenance require recompilation without fabricated provenance.
10. Contextual variable and secret references remain step-scoped and opaque. Diagnostics, logs,
    provenance and snapshots contain no secret values or user literal excerpts.
11. Parsing and derivation enforce byte, nesting, step and collection bounds; duplicate JSON keys,
    trailing documents, unknown fields and type coercion fail without external work.
12. Tests cover semantic mutations, identity/context/canonicalization/version rollout, the real
    acceptance boundary with zero side effects on refusal, positive login/protected execution and
    confidentiality. Independent QA must PASS 10.42 before targeted 10.41 and 10.39 re-reviews.

## Dev Notes

- Use saved revision authoring/configuration, never a synthetic or current `UITest` draft.
- Compare canonical expected-intent documents without Playwright default normalization.
- Dispatch the saved snapshot after verification; reconstructed output is never substituted.
- Version the full derivation pipeline, not only the expected-intent wire schema.
- A co-stored digest or MAC does not replace semantic derivation for this threat model.

## Testing

- Mutate URL, fill value, reference kind/ID, key, assertion, locator/name/exact, options and operation order.
- Mutate source text, step ID/order/count, CSI/environment/evidence and derivation version.
- Verify property-order/JSON-whitespace equivalence and literal/array-order inequality.
- Verify duplicate keys, trailing documents, type coercion and bound overflow refuse safely.
- Assert refusal leaves execution/ledger counts unchanged with zero resolver/vault/runner calls.
- Reuse the canonical login/protected fixture and existing real `/v1/runs` Chromium regression.

## Risks / Non-goals

- Derivation version must be bumped whenever parser, resolver, scope, assembler or canonicalization semantics change.
- No general-purpose English expansion, live-page learning, runner operation expansion or cryptographic database signing.
- Database-administrator compromise that rewrites every authority is outside this story's threat model.

### Gate Verdict

FAIL. The shared versioned deriver closes the original 10.41 changed-target gap, but it does not
validate or authenticate the complete immutable `authoringRevisionInputs` snapshot. Both
confirmation and readiness therefore accept missing or altered context/evidence identity when the
remaining authoring semantics still derive the saved expected intent.

### Code Quality Assessment

`VersionedIntentDeriver` is local, deterministic, bounded and shared by compilation and immutable
revision verification. `IntentRevisionVerifier` compares canonical saved and derived intent, and
both confirmation and readiness invoke it before their writes. V23 adds immutable version
provenance and version-aware identity cleanly. The blocking flaw is that deserializing the identity
record is treated as validation: Jakarta constraints are never invoked and none of its hashes or
collections participates in verification.

### Refactoring Performed

None. Independent QA was limited to review, probes and gate artifacts.
