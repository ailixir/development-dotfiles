## User Story

**As a** developer wiring up report scheduled delivery,
**I want** a `ReportScheduleResolver` that translates the report's `schedule` JSONB into a Spring `CronExpression` and computes the next delivery `Instant`,
**so that** the lifecycle hooks (4.4c) and dispatcher (4.4d) have a single, tested resolution path for all supported frequency types.

---

## Context & Rationale

Reports store scheduling configuration as JSONB with different frequency patterns:
```json
{"frequency": "daily", "time": "06:00", "timezone": "America/New_York"}
{"frequency": "weekly", "daysOfWeek": [1,3,5], "time": "08:00", "timezone": "UTC"}
{"frequency": "custom", "cron": "0 0 6 * * MON-FRI", "timezone": "America/New_York"}
```

A single `ReportScheduleResolver` encapsulates the JSONB-to-cron translation, keeping the dispatcher and lifecycle hooks clean.

## Acceptance Criteria

- [x] **AC-1:** `ReportScheduleResolver` Spring `@Component` in `reports/schedule/` package.
- [x] **AC-2:** `String toCronExpression(JsonNode schedule)` — translates `frequency` field to a Spring 6-field cron expression:
  - `daily` + `time` ("HH:mm") — `0 {mm} {HH} * * *`
  - `weekly` + `daysOfWeek` ([1-7]) + `time` — `0 {mm} {HH} * * {days}`
  - `monthly` + `dayOfMonth` + `time` — `0 {mm} {HH} {day} * *`
  - `custom` + `cron` — passthrough (validated via `CronExpression.parse`)
- [x] **AC-3:** `Instant nextDelivery(JsonNode schedule)` — resolves cron + timezone into the next delivery `Instant`. Uses `CronExpression.next(ZonedDateTime.now(zone))`.
- [x] **AC-4:** `Instant nextDeliveryFrom(JsonNode schedule, Instant base)` — same as AC-3 but advances from a given base instant (for drift-free advancement, per story 2.8 pattern).
- [x] **AC-5:** Throws `IllegalArgumentException` for unknown frequency, missing required fields, or invalid cron expressions.
- [x] **AC-6:** Defaults timezone to `"UTC"` when not specified in the schedule JSONB.
- [x] **AC-7:** Unit tests (not IT — no Spring context needed):
  - Daily resolution: `{"frequency":"daily","time":"06:00","timezone":"UTC"}` produces `0 0 6 * * *`.
  - Weekly resolution: `{"frequency":"weekly","daysOfWeek":[1,3,5],"time":"08:00","timezone":"UTC"}` produces `0 0 8 * * MON,WED,FRI`.
  - Custom passthrough: `{"frequency":"custom","cron":"0 0 6 * * MON-FRI"}` returns the cron as-is.
  - Invalid frequency throws `IllegalArgumentException`.
  - `nextDelivery()` returns a future `Instant`.
  - `nextDeliveryFrom()` advances from given base.

## Implementation Notes

- **Spring CronExpression format:** 6 fields — `second minute hour day-of-month month day-of-week`. No year field.
- **Day-of-week mapping:** JSONB uses ISO-8601 (1=Monday..7=Sunday). Spring `CronExpression` uses SUN-SAT or 0-6 (0=Sunday). Map accordingly.
- **Validation:** `CronExpression.parse()` throws `IllegalArgumentException` for invalid expressions — use it as the validation gate for custom crons.
