## User Story

**As a** maintainer of the put-checks frontend,
**I want** all MSW mock infrastructure removed from the production codebase,
**so that** there's no dead code, no mock data shipped in bundles, and no confusion about which data source is active.

---

## Acceptance Criteria

- [ ] **AC-1:** `VITE_ENABLE_MSW` set to `false` in `.env.development`. App boots and all features work against real backend.
- [ ] **AC-2:** All MSW handler files deleted: `checksHandlers.ts`, `csiHandlers.ts`, `dashboardHandlers.ts`, `reportsHandlers.ts`, `studioHandlers.ts`, `tagsHandlers.ts`, `secretsHandlers.ts`, `templatesHandlers.ts`, `handlers/index.ts`.
- [ ] **AC-3:** All mock data files deleted: `mockData/checksData.ts`, `mockData/csiData.ts`, `mockData/reportsData.ts`, `mockData/studioData.ts`, `mockData/templatesData.ts`.
- [ ] **AC-4:** Extended mock data file deleted: `src/data/mockCSIData.ts`.
- [ ] **AC-5:** MSW infrastructure files deleted: `browser.ts`, `server.ts`, `initMsw.ts`, `mockMode.ts`, `inlineMockAdapter.ts`.
- [ ] **AC-6:** `public/mockServiceWorker.js` deleted.
- [ ] **AC-7:** `apiClient.ts` cleaned up: remove inline mock adapter chain (`setupTransportAdapter`, `tryResolveInlineMock`, `getInlineMockResolver`). Remove `isInlineMockModeEnabled` import. The adapter should be plain HTTP only.
- [ ] **AC-8:** `apiClient.ts` cleaned up: remove `__slow`, `__fail`, `__empty` debug param injection (MSW-specific debugging).
- [ ] **AC-9:** MSW-related env vars removed from `.env.development`: `VITE_ENABLE_MSW`, `VITE_ALLOW_INSECURE_MSW_FALLBACK`, `VITE_DISABLE_MSW_DOMAINS`. Keep `VITE_API_BASE_URL` and `VITE_DEBUG_MODE`.
- [ ] **AC-10:** `appConfig.ts` cleaned up: remove `enableMSW`, `allowInsecureMswFallback` from `APP_CONFIG`. Update `AppConfig` type in `commonTypes.ts`.
- [ ] **AC-11:** App entry point (`main.tsx` or `index.tsx`) cleaned up: remove MSW initialization (`ensureMswWorkerReady()` call and conditional import).
- [ ] **AC-12:** `msw` package removed from `package.json` dependencies.
- [ ] **AC-13:** Any component or store that imports from `mockData/` or `mocks/` updated to remove those imports. If any component had a fallback to mock data, that fallback is removed.
- [ ] **AC-14:** `src/store/index.ts` cleaned up: remove mock user hydration from `mockUsers`.
- [ ] **AC-15:** Bundle size verified: `npm run build` produces a smaller bundle (MSW + mockData was ~200-400KB of dead weight in production builds).
- [ ] **AC-16:** `npm run type-check` passes.
- [ ] **AC-17:** `npm run lint` passes (no unused imports, no dead references).
- [ ] **AC-18:** `npm run test` passes (test setup file `server.ts` for MSW-based tests needs to be re-evaluated — if Vitest tests used MSW for API mocking in tests, those tests need to be updated to use direct mocks or a test-specific MSW setup that's separate from the production mock layer).
- [ ] **AC-19:** All pages verified in browser against running backend. Smoke test: Dashboard, All Checks, Check Details, Create Check, Reports, Studio, search, tag filter.

## Implementation Notes

### Test MSW setup
If Vitest tests rely on `src/services/mocks/server.ts` for API mocking in tests, those need a separate solution:
- Option A: Keep a `test/mocks/` directory with test-specific handlers (not production mock data).
- Option B: Use Vitest's built-in `vi.mock()` for API modules.
- Option C: Keep `msw` as a devDependency and maintain a minimal test-only handler set.

**Recommended: Option C** — keep `msw` in devDependencies, create `test/mocks/testHandlers.ts` with minimal test handlers. Delete all `src/services/mocks/` production files.
