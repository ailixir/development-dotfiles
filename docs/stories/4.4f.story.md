## User Story

**As a** report delivery dispatcher,
**I want** a `ReportDeliveryService` that orchestrates the full delivery pipeline — resolve sections, render HTML, send via SMTP, and persist a `ReportExecution` audit record,
**so that** each delivery attempt is tracked end-to-end with status, duration, check counts, and per-recipient outcomes.

---

## Context & Rationale

The existing `ReportsService.runNow()` already implements a partial version of this pipeline (resolve + render + persist audit). `ReportDeliveryService` extracts the delivery orchestration into a dedicated service, adding the SMTP send step and replacing the stub created in 4.4d.

---

## Acceptance Criteria

### Delivery orchestration

- [x] **AC-1:** `ReportDeliveryService` in `reports/` package with `@Service`.
- [x] **AC-2:** `ReportExecutionDto deliver(Report report)` method that:
  1. Resolves sections via `SectionResolver` (existing).
  2. Counts total checks and failing checks.
  3. Renders HTML via `ReportRenderer` (existing).
  4. Sends via `ReportMailSender.send()` (from 4.4e).
  5. Determines status: `"success"` (all recipients OK), `"partial"` (some failed), `"failed"` (all failed or no mail sender).
  6. Persists `ReportExecution` record with: status, recipientCount, checksIncluded, checksFailed, generationDurationMs, emailContent, errorMessage.
  7. Updates `report.lastSentAt`.
- [x] **AC-3:** If `ReportMailSender` bean is absent (no SMTP configured), log a warning and persist a `ReportExecution` with status `"failed"` and errorMessage `"SMTP not configured"`.

### Graceful degradation

- [x] **AC-4:** Rendering failures (e.g., malformed section config) are caught, logged, and result in a `"failed"` `ReportExecution` with the error message.
- [x] **AC-5:** SMTP failures per-recipient are handled by `SendResult` (from 4.4e). The `ReportExecution.errorMessage` includes the list of failed recipients.

### Integration with existing code

- [x] **AC-6:** Replaces the stub `ReportDeliveryService.deliver()` from story 4.4d.
- [x] **AC-7:** `ReportsService.runNow()` refactored to delegate to `ReportDeliveryService.deliver()` instead of duplicating the resolve+render+persist logic. The `runNow` method becomes a thin wrapper that calls `deliver()`.

### Tests

- [x] **AC-8:** `ReportDeliveryServiceTest` (unit test with mocked SectionResolver, ReportRenderer, ReportMailSender, ReportExecutionRepository):
  - Full success: all recipients OK, status=success, duration tracked.
  - Partial failure: 2/3 recipients OK, status=partial, failedRecipients in errorMessage.
  - All fail: status=failed.
  - No mail sender: status=failed, errorMessage="SMTP not configured".
  - Rendering failure: status=failed, exception message captured.

## Implementation Notes

- **Optional injection for ReportMailSender:** Use `Optional<ReportMailSender>` in the constructor since the mail sender is `@ConditionalOnProperty`. When absent, `deliver()` skips SMTP and logs.
- **Duration tracking:** `System.currentTimeMillis()` before resolve, measure after SMTP send. Persist in `generationDurationMs`.
- **emailContent storage:** The rendered HTML is stored in `ReportExecution.emailContent` for audit/replay purposes. Consider truncating to a max length (e.g., 500KB) to prevent DB bloat from very large reports.
