# STUDIO-SCHED-001 implementation contract

Owner: Aria. Date: 2026-10-05. This freezes executable design choices for the authorized local implementation, subject to independent spec critique. Existing scheduling planning proposals remain historical analysis; this document chooses their concrete implementation alternatives. Real PUT Core production grants and externally gated Studio evidence remain release prerequisites, not claimed integration results.

## Adopted implementation defaults

Individual saved Studio tests; one stable schedule anchor per test; create Paused; explicit Resume acknowledges the currently ready confirmed revision and uncertain executions. No implicit save/compile/confirm. Exact activated revision, source/configuration counters/hashes/reference policy and runtime readiness gates remain mandatory. Minute-granularity cron with seconds exactly `0`; minimum interval is **fixed at 60 seconds** in this first implementation, with no unsupported configurable-minimum property. Five-field input prepends `0`. Grace is independently configurable and defaults to 300 seconds. Explicit IANA region/UTC; overlap chooses earlier offset once per local slot; gaps skip nonexistent slots. Preview and due processing share one resolver and injected clock.

Grace defaults to configurable 300 seconds; bounded backoff starts at 5 seconds and caps at 30 seconds within original grace. Skip historical backlog; evaluate at most the latest slot inside grace; record a bounded misfire-range summary with unknown missed count when exact enumeration exceeds budget. Skip scheduled overlap with any non-DONE run of the same test, including manual work; manual admission policy remains unchanged. Block future recurrence after unacknowledged terminal DISPATCH_UNKNOWN/START_TIMEOUT/STALE. START_TIMEOUT joins the inherited uncertainty policy because `RunningReaper.java:28` represents admission without confirmed start and `reportingStepReporter.ts:71,94,107` sends STARTED asynchronously after the browser has launched; absent start confirmation does not prove absent effects. Root adopted this research-derived conservative decision. No replay of terminal/ambiguous browser work. Pause/removal preserves accepted runs; test deletion/quarantine preserves established pre-send refusal. Global execution kill switch remains independent.

## API wire contract

All public paths below prepend `/api/v1`; JSON uses camelCase. Schedule read/capabilities/occurrences use existing CSI read authorization; mutations use CSI write and normal Studio nondisclosing missing/inaccessible-resource semantics. Controllers run on `!worker`. The scheduling capability flag defaults off: reads stay inspectable, mutations return 503/SCHEDULING_DISABLED while unavailable, and due producer never runs. Existing dispatcher/recovery/cancel remains operational independently.

| Method and path | Request | Response |
|---|---|---|
| GET `/studio/tests/{id}/schedule/capabilities` | none | 200 capability DTO, scoped to test CSI/environment |
| GET `/studio/tests/{id}/schedule` | none | 200 schedule DTO or JSON null if absent/removed |
| POST `/studio/tests/{id}/schedule` | `{cronExpression,timeZone,executionPrincipal}` | 201 paused schedule. Existing nonremoved anchor gives 409/SCHEDULE_EXISTS. Recreate reuses removed anchor, monotonic version and retained occurrence/ack history. |
| PUT `/studio/tests/{id}/schedule` | `{expectedVersion,cronExpression,timeZone,executionPrincipal}` | 200 updated schedule; any changed scheduling/execution-principal config leaves Paused and requires explicit Resume. |
| PATCH `/studio/tests/{id}/schedule/enabled` | `{expectedVersion,enabled,confirmedRevisionId?,acknowledgedUncertaintyExecutionIds?}` | 200 schedule. Enabling requires exact confirmed revision and exact current uncertainty set. Disabling only requires version, independently of any malformed unsaved cron. |
| DELETE `/studio/tests/{id}/schedule?expectedVersion=N` | none | 204; tombstone paused anchor retained, accepted work unaffected. |
| POST `/studio/schedules/preview` | `{cronExpression,timeZone}` | 200 preview DTO, read-only for authenticated application users; no principal enumeration. |
| GET `/studio/tests/{id}/schedule/occurrences?page=0&size=20` | size 1..100, page >=0 | Existing Studio envelope `{data,page,size,totalElements,totalPages}`, ordered nominal due descending, UUID tie break. Removed anchor history remains readable. |

Schedule DTO:

```json
{
  "id":"uuid", "testId":"uuid", "csiId":"CSI123", "version":1,
  "cronExpression":"0 */5 * * * *", "timeZone":"America/New_York",
  "executionPrincipal":"studio-local", "state":"PAUSED", "requestedEnabled":false,
  "blockedCode":null, "activatedRevisionId":null,
  "activationId":null, "activatedBy":null, "activatedAt":null,
  "nextDueAt":null, "pollAfterAt":null, "deletedAt":null,
  "createdAt":"2026-10-05T12:00:00Z", "updatedAt":"2026-10-05T12:00:00Z",
  "unacknowledgedUncertaintyExecutionIds":[], "latestOccurrence":null
}
```

Capability DTO: `{enabled:boolean,canManage:boolean,availableExecutionPrincipals:string[],localAuthorizationOnly:boolean,policy:{minIntervalSeconds:60,misfireGraceSeconds:300,overlap:"SKIP",dstOverlap:"EARLIER_OFFSET"}}`. Principal references are exposed only after the test's read authorization and only from the configured allowlist for that CSI/environment. An empty list truthfully means no unattended authority. `localAuthorizationOnly` is true for the configured local adapter; no production authorization assurance is implied.

Preview DTO: `{normalizedCronExpression,timeZone,occurrences:[{scheduledAt,localScheduledAt,offsetSeconds}],policy:{minIntervalSeconds:60,misfireGraceSeconds:300,overlap:"SKIP",dstOverlap:"EARLIER_OFFSET"}}`, exactly next five eligible UTC/local slots. `localScheduledAt` is an ISO local date-time without offset; `scheduledAt` is a UTC instant. A preview is advisory, not acceptance.

Occurrence DTO: `{id,scheduleId,scheduleVersion,testId,csiId,environment,executionPrincipal,activationId,activatedRevisionId,activatedBy,activatedAt,scheduledAt,localScheduledAt,timeZone,offsetSeconds,decision,code,executionId,acceptedAt,retryAt,graceExpiresAt,createdAt,updatedAt,missedFrom,missedUntil,missedCount}`. Decision is `ACCEPTED|REFUSED|SKIPPED|DEFERRED`. `executionId/acceptedAt` are nullable and derived from the ledger JOIN. Activation actor/time are derived from the immutable activation event, never the mutable current schedule or test. `missedCount` can be null when bounded summary cannot determine exact count. Latest occurrence uses the same DTO. No duration/video for a nonaccepted occurrence.

HTTP validation codes: `INVALID_SCHEDULE`, `INVALID_TIME_ZONE`, `INVALID_SCHEDULE_VERSION`, `INVALID_PAGINATION` (400); `SCHEDULE_EXISTS`, `SCHEDULE_VERSION_CONFLICT`, `SCHEDULE_NOT_FOUND`, `ACTIVATION_REVISION_MISMATCH`, `UNCERTAINTY_ACKNOWLEDGEMENT_REQUIRED` (409); existing readiness codes such as COMPILE_REQUIRED/RUNTIME_INCOMPATIBLE retain 409; `BACKGROUND_AUTHORIZATION_DENIED` (403), `BACKGROUND_AUTHORIZATION_UNAVAILABLE` and `SCHEDULING_DISABLED` (503). Follow Studio error DTO and add a stable code to schedule errors without exposing sensitive content.

Occurrence codes: `ACCEPTED`, `COMPILE_REQUIRED`, `ACTIVATION_REVISION_MISMATCH`, `RUNTIME_INCOMPATIBLE`, `TEST_DELETED`, `TEST_QUARANTINED`, `BACKGROUND_AUTHORIZATION_DENIED`, `REFERENCE_UNAVAILABLE`, `PENDING_QUOTA_EXCEEDED`, `BACKGROUND_AUTHORIZATION_UNAVAILABLE`, `VAULT_UNAVAILABLE`, `OVERLAP`, `MISFIRE`, `GRACE_EXPIRED`, `DISPATCH_DISABLED`, `UNCERTAIN_EXECUTION`, `SCHEDULE_PAUSED`, `SCHEDULE_UPDATED`, `SCHEDULE_REMOVED`. Capacity/temporary infrastructure codes defer; readiness/auth/ref failures refuse and block; overlap/misfire/grace expiry and schedule lifecycle cancellation of unaccepted slots skip. Manual execution's established error vocabulary and behavior remain unchanged.

Existing run/list/snapshot DTO adds optional nullable `triggerSource` (`MANUAL|SCHEDULED`, null for legacy), `scheduleId`, `scheduleVersion`, `occurrenceId`, `scheduledAt`, `activationId`, `activatedBy`, `activatedAt`. The activation trio comes from the immutable event linked by the accepted occurrence, so GET/list/SSE and `withTestName` preserve the same human activation provenance. Existing clients tolerate absent optional fields; updated clients display Unknown for null. Manual/legacy activation metadata remains null. The run revision remains the actually accepted immutable revision. No runner wire change is required.

## Storage decisions closing E-02

Reserve additive **V26** against current baseline containing V25. Dedicated JDBC-backed `studio_schedules` / `studio_schedule_occurrences`; no mutation of legacy schedule JSON/status and no automatic legacy activation. Stable schedule anchor survives removal/recreation and versions never reset.

- Ownership constraints: supporting UNIQUE `(id,csi_id)` on `ui_tests`; schedule `(test_id,csi_id)` FK to it, plus schedule UNIQUE `(id,test_id,csi_id)`; supporting UNIQUE `(id,test_id,csi_id)` on revisions, with schedule/occurrence activated-revision composite ownership FK. New schedule CSI must be registered. These constraints supplement current confirmation/readiness checks.
- Immutable `studio_schedule_activations`: UUID `id`; owned `schedule_id,test_id,csi_id`; positive `schedule_version`; `revision_id`; immutable `environment,execution_principal`; server-derived human `activated_by` and `activated_at`. Restrictive composite ownership FKs bind stable schedule/test/CSI and confirmed revision; updates/deletes of activation provenance are rejected. Every successful Resume creates one event, including reenabling the same revision after pause; current schedule `activation_id` points to its most recent event, retained while paused/blocked/removed. Each occurrence stores `activation_id` and immutable environment/principal/revision snapshot constrained to the event. Current schedule and occurrence DTOs project `activationId,activatedBy,activatedAt`; old occurrences never adopt a later actor or grant. Uncertainty acknowledgment rows also reference the activation event so the operator's investigation decision remains attributable.
- Schedule state invariant: ENABLED requires requestedEnabled, nondeleted, unblocked, activated revision/principal and nominal+eligible cursor; PAUSED has false intent and null blocked code; BLOCKED has true intent and nonnull blocked code. Tombstone is PAUSED. Preserve activation/cursor audit while paused or blocked. Version increments only on user mutation/invalidation, not every tick/defer.
- Cursor: `next_due_at` is immutable nominal current slot during deferral; separate `poll_after_at` supplies bounded retry eligibility. Grace is fixed per occurrence. Partial due indexes bound worker discovery.
- Occurrence unique `(schedule_id,schedule_version,scheduled_at)` and `(schedule_id,time_zone,local_scheduled_at)` independent of version/offset; immutable provenance and terminal decisions. DEFERRED alone can transition to ACCEPTED/REFUSED/SKIPPED. Add bounded status/shape CHECKs plus immutable identity transition enforcement.
- **Choose ledger-joined execution linkage.** Ledger nullable UNIQUE `scheduled_occurrence_id` FK owns the link; scheduled rows require null manual key/digest CHECK. Occurrence DTO execution/acceptedAt derives from this unique ledger JOIN. Do not duplicate occurrence→ledger execution fields or create circular inserts. Occurrence inserts precede accepted history/ledger, and terminal accepted consistency must be enforced at commit by a reviewed deferred constraint trigger that requires exactly one matching scheduled ledger for ACCEPTED and none for other terminal decisions. Matching includes immutable test ID, CSI and execution principal against the occurrence, plus accepted revision/environment against its activation snapshot; count alone is insufficient. No FK into partitioned history is introduced.
- Ledger uncertainty summary: add nullable `terminal_error_code`/`terminal_error_at` to durable ledger; backfill retained existing DISPATCH_UNKNOWN/START_TIMEOUT/STALE by history locator. Modify `StudioDispatchLedgerStatements.close` history RETURNING to include final code/time; ledger sets summary from RETURNING atomically. No callback/reaper writes to schedule or acquisition of new test locks. Preserve summary once DONE. Already-pruned historical outcomes cannot be inferred; release/restore reconciliation must cover these gaps rather than fabricate known effects.
- `studio_schedule_uncertainty_ack` key `(schedule_id,execution_id)` references stable schedule and durable ledger, with human actor/time. Under test lock, activation/tick query DONE DISPATCH_UNKNOWN/START_TIMEOUT/STALE ledger for that test minus acknowledged IDs. Resume acknowledges exactly the current returned set; extra/stale/omitted identities conflict. Check active ledger conservatively without locking it. An old accepted run becoming uncertain after Resume remains unacknowledged and blocks the next tick. No timestamp watermark that loses this case.
- History adds nullable trigger/source fields with immutable attribution; no FK from occurrence into partitioned history. Retain schedule/occurrence/ack/ledger identity anchors indefinitely in this implementation; no new cleanup job. Existing history/video retention proceeds independently; detail payload archival and production retention horizon remain release sizing decisions. Missing historical detail is honestly unavailable.
- Restore older than executed cursor requires operator reconciliation before enabling the default-off producer; code cannot infer effects erased by a database restore. Runbook explicitly records this release/restore obligation.

## Admission, invalidation and background authorization boundaries

One candidate/test/occurrence per transaction: test → schedule → occurrence → global quota → CSI quota → new history/ledger. Native test lifecycle locking includes deleted/quarantined rows with `FOR UPDATE OF t SKIP LOCKED`; subsequent JDBC reads/current JPA refresh eliminate stale managed snapshots. Nonlocking EXISTS reads active ledger/uncertainty; no test-held locks of existing ledger. Schedule CRUD/save/delete use test-first order. Do not cancel existing runs inside these transactions.

Refactor existing acceptance to a plain shared core returning typed accepted/refused/deferred expected outcomes, called inside the scheduler transaction without crossing a throwing transactional proxy. Manual `accept()` remains transactional and translates a core refusal through its established exceptions; manual digest/unique-race resolution stays unchanged. All expected conditions are resolved before execution writes; SQL or unexpected failures roll back the entire occurrence/history/ledger/cursor unit. Typed trusted identity is ManualIdentity or ScheduledOccurrenceIdentity; no client trigger field chooses scheduling admission.

`StudioService.updateTest` and v2 authoring write paths invalidate active schedule in the same test-held transaction on actual source/configuration/authoring changes; paused intent remains paused. Both soft-delete overloads must take the test lock and pause/block future due work. Exact confirmed revision changed by `CompileStateService.confirm` blocks active scheduling but never auto-resumes. Failed optional recompilation with unchanged confirmed inputs does not block. Per-tick readiness/pin equality remains defense in depth across writers. Update read summaries to reveal persisted blocked state immediately.

**Deferred lifecycle settlement:** after authorization/version validation and while holding test → schedule → occurrence locks, pause settles an existing DEFERRED slot as SKIPPED/SCHEDULE_PAUSED; cron/principal configuration update settles it as SKIPPED/SCHEDULE_UPDATED; removal settles it as SKIPPED/SCHEDULE_REMOVED. Source/configuration invalidation settles it as REFUSED/COMPILE_REQUIRED, confirmation replacement as REFUSED/ACTIVATION_REVISION_MISMATCH, and deletion/quarantine as REFUSED/TEST_DELETED or TEST_QUARANTINED. Settling clears retry eligibility while preserving nominal identity, immutable activation provenance and decision audit. The schedule state/version update and occurrence decision commit together. Resume calculates strictly future work and never revives a settled old slot. No mutation may leave an orphan DEFERRED occurrence on a paused/blocked/removed schedule. ACCEPTED and other terminal decisions remain unchanged.

**Capability disable/reenable:** disabling the capability stops the due producer and mutations; it does not rewrite schedule intent or fabricate an occurrence decision. Existing DEFERRED records remain persisted and inspectable with original grace/cursor. Capability-aware read/UI presentation explicitly says “Scheduling disabled” and, after grace expiry, “Grace expired; awaiting scheduler settlement”; it never represents an expired record as eligible retry. On reenable the processor first inspects any existing DEFERRED identity before seeking a newer slot. If expired, atomically settle SKIPPED/GRACE_EXPIRED with no acceptance/send and advance strictly beyond current time; do not replace it with a catch-up execution. If still within grace and all existing gates pass, the same identity may be accepted once. This is distinct from explicit pause/update/remove, which settle the slot at mutation commit as above. Feature-off lifecycle edits/deletion still invoke shared invalidation/settlement because authoring authority is independent of scheduling capability.

The implemented `StudioBackgroundAuthorization` seam exposes approved principal references and a live `require(principal,csi,environment)` guard. Local dispatch attribution remains provisional principal metadata; the production integration must supply actual policy/grant identity and version before the live-authorization release gate closes. Default provider denies. Configured local provider accepts only explicit per-CSI/environment principal allowlists when separately enabled in local/test mode; no arbitrary principal, copied session/JWT or principal inferred from confirmer. Activation and due admission call it, plus existing secret preflight. The `StudioScheduledDispatchAuthorization` helper is invoked inside existing `ProvisionalDispatchAuthorization`; for scheduled ledger rows it rechecks approved principal against immutable occurrence environment/principal before any send. Aria selected this integration to preserve existing primary test authorization beans and constructor compatibility without adding a second primary dispatch bean. Existing manual path keeps provisional behavior. Scheduling feature off stops new work but does not skip live checks of accepted scheduled work.

Temporary authority lookup failure is distinct from denial: before acceptance defer until grace; after acceptance existing dispatcher handling must produce a terminal no-send failure or pre-send defer within pending SLA, never treat unavailable as permission. The local provider's live configuration is rechecked each call so revocation tests can remove principal without recreating immutable runs. Secret-use remains the existing separate resolver policy; this feature supplies no permissive secret entitlement.

## Concrete implementation seams and sequence

1. V26 additive schema/constraints including immutable activation events and acknowledgment links + migration tests; new `studio/scheduling` DTOs, JDBC repository, properties and shared cron resolver with exact DST tests.
2. `StudioScheduleService` / `StudioScheduleController` implement CLI-usable API, expected versions, paused creation/stable tombstones, explicit activation/acknowledgment, scoped capability reads and occurrence envelope.
3. Background authorization interface/default/local adapter and scheduled dispatch authorization helper; preserve manual signature/test construction; failclosed tests before producer activation.
4. Incremental shared acceptance-core extraction; ledger entity scheduled occurrence field, existing history/entity/DTO mapper attribution; existing manual idempotency tests retained. Durable uncertainty close/backfill/ack behavior before due production.
5. `StudioService` authoring/update/delete and `CompileStateService` confirmed-revision hooks, following current locks/transactions; true metadata changes do not invalidate.
6. Bounded `StudioScheduleProcessor` and worker/local poller under separate default-off feature; candidate discovery rotates CSIs, per-CSI cap, fixed batch/time budget, same occurrence deferral; accepted run handed only to existing ledger dispatcher. Bounded backlog resolver seeds at grace-window start and records older-range summary without years of iteration.
7. Frontend owner prepares typed centralized API/MSW first, then MUI Schedule editor/Test actions, paused/blocked/version/error remedies, next-slot preview and occurrence history; update existing Runs/detail source fields. Root owns OpenAPI/runbook additions using this wire contract.
8. Real PostgreSQL multiworker/write rollback/edit-confirm-pause/callback/manual-overlap/DST/defer/uncertainty-prune tests; frontend mock/component/a11y flows; repository quality gates and independent QA. Production integration/load/pilot evidence remains release gated and default-off.

No new framework/runtime dependencies. Core scheduling SQL correctness and compatibility must be tested with real PostgreSQL, including deferred acceptance-link integrity. Mocks alone cannot approve browser-effect atomicity or production principal authorization.
