## User Story

**As a** platform operator monitoring PUT Checks in production,
**I want** health indicators and alerting-ready metrics for the dispatch system,
**so that** persistent failures surface in `/actuator/health` and Prometheus alerting before they impact users.

---

## Problem Statement

Both dispatchers (`CronDispatcher`, `ReportDeliveryDispatcher`) count success/failure metrics, but:
1. No health indicator aggregates dispatch health into `/actuator/health`.
2. No metric tracks dead-lettered items (retries exhausted).
3. No gauge exposes the pending retry queue depth.
4. Operations has no way to distinguish "system is healthy" from "system is silently failing" without reading logs.

---

## Acceptance Criteria

### A — Dispatcher health indicator

- [ ] **AC-1:** New `DispatcherHealthIndicator` registered at `/actuator/health/dispatchers`.
- [ ] **AC-2:** Reports `UP` when: dead-lettered count (last 24h) = 0 AND pending retry count < threshold (default 50).
- [ ] **AC-3:** Reports `DOWN` when: any dead-lettered items exist in last 24h.
- [ ] **AC-4:** Reports `WARNING` (via `Health.status("WARNING")`) when: pending retry count >= threshold.
- [ ] **AC-5:** Health detail includes: `deadLetteredLast24h`, `pendingRetries`, `oldestPendingRetry`.

### B — Alerting-ready metrics

- [ ] **AC-6:** Gauge `checks.dispatch.dead_lettered_total{type}` — count of dead-lettered records per type (CHECK/REPORT).
- [ ] **AC-7:** Gauge `checks.dispatch.pending_retries{type}` — count of pending retries per type.
- [ ] **AC-8:** Counter `checks.dispatch.auto_disabled_reports_total` — reports auto-disabled due to consecutive failures (from 6.1 AC-17).
- [ ] **AC-9:** All metrics tagged with `type` (CHECK/REPORT) for per-type alerting.

### C — Scheduled metrics refresh

- [ ] **AC-10:** Metrics refresh every 60s via `@Scheduled` (lightweight: 3 COUNT queries).
- [ ] **AC-11:** No ShedLock needed — each instance reports its own view (eventually consistent).

### D — Tests

- [ ] **AC-12:** `DispatcherHealthUpIT`: no failed dispatches → health UP.
- [ ] **AC-13:** `DispatcherHealthDownIT`: insert dead-lettered record → health DOWN with detail.
- [ ] **AC-14:** `DispatcherHealthWarningIT`: insert 50+ pending retries → health WARNING.
- [ ] **AC-15:** `DispatcherMetricsIT`: verify gauge values match DB state after insert.
- [ ] **AC-16:** JaCoCo coverage >= 80%.

## Implementation Notes

- **Health status mapping:** Spring Boot Actuator supports custom `Status` values. Use `Health.status("WARNING")` for the threshold case. Ensure the status is ordered correctly in actuator config: `management.endpoint.health.status.order=DOWN,WARNING,UP`.
- **Query efficiency:** `SELECT COUNT(*) FROM failed_dispatches WHERE retry_count >= max_retries AND created_at >= now() - interval '24 hours'` is cheap with the existing index.
- **Metric refresh scheduling:** Use `@Scheduled(fixedRate=60000)` — not `fixedDelay` — to keep refresh cadence predictable regardless of query time.
