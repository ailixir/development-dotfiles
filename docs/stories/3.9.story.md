## User Story

**As a** user who needs to temporarily pause a check or view upcoming scheduled executions,
**I want** the pause, resume, and upcoming-executions endpoints implemented in the backend,
**so that** these features work with real data instead of MSW mocks.

---

## Acceptance Criteria

### Backend — New endpoints on CheckController

- [ ] **AC-1:** `POST /api/v1/checks/{id}/pause` added. Sets check status to `PAUSED` (or a `paused` flag) and disables the associated schedule (`schedules.enabled = false`). Returns updated `CheckDto`. Authorization: `canWrite(auth, check.csiId)`.
- [ ] **AC-2:** `POST /api/v1/checks/{id}/resume` added. Clears the paused state and re-enables the associated schedule. Returns updated `CheckDto`. Authorization: `canWrite(auth, check.csiId)`.
- [ ] **AC-3:** `GET /api/v1/checks/upcoming?limit={20}&csiId={optional}` added. Returns checks with enabled schedules, ordered by `next_execution_at ASC`. Response: `{data: [{checkId, checkName, nextExecution, csiName}], total}`. Uses `schedules` JOIN `checks` JOIN `csi_systems`. Authorization: scoped to user's CSIs (unless admin).
- [ ] **AC-4:** Design decision: pause/resume can be implemented as either (a) a `paused` boolean on the `checks` table, or (b) purely through schedule enable/disable. Option (b) is simpler if "pause" only means "stop running on schedule" — the check can still be executed manually. Document the choice.
- [ ] **AC-5:** `CheckService` extended with `pause(UUID checkId, Authentication)`, `resume(UUID checkId, Authentication)`, `getUpcoming(String csiId, int limit, UserIdentity)`.
- [ ] **AC-6:** Integration tests: `CheckPauseResumeIT` (pause sets schedule disabled, resume re-enables, manual execute still works while paused), `CheckUpcomingIT` (correct ordering, CSI filter, empty when no schedules).

### Frontend — Wire remaining checks endpoints

## Implementation Notes

### Pause via schedule disable (recommended approach)
```java
@PostMapping("/{id}/pause")
public ResponseEntity<CheckDto> pause(@PathVariable UUID id, Authentication auth) {
    var check = checkService.findById(id, auth);
    scheduleService.findByCheckId(id)
        .ifPresent(s -> scheduleService.setEnabled(s.getId(), false, auth));
    // Optionally set check.status = PAUSED if you want a visible state
    return ResponseEntity.ok(checkMapper.toDto(check));
}
```

### Upcoming query
```sql
SELECT c.id as check_id, c.name as check_name, 
       s.next_execution_at, cs.name as csi_name
FROM schedules s
JOIN checks c ON s.check_id = c.id
JOIN csi_systems cs ON c.csi_id = cs.id
WHERE s.enabled = true AND c.deleted_at IS NULL
  AND (:csiId IS NULL OR c.csi_id = :csiId)
ORDER BY s.next_execution_at ASC
LIMIT :limit
```
