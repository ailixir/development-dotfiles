## User story

**As** the Checks platform  
**I want** to run integration checks (Splunk, Grafana, ITRS, AppDynamics, …) through DailyChecks (DC)  
**So that** we ship those sources in R3 without building native tool clients yet

---

## Context

Dev proposed two ways to call DC from our `CheckExecutor` SPI:

| | **Proposal A** | **Proposal B** |
|---|---|---|
| Idea | Each executor owns auth, send, retry, mapping, deep links, metrics | One shared `DailyChecksAdapter`; executors stay thin |
| Fit | Tools highly irregular | Tools share an outer status + comment shape |
| Risk | Shared logic duplicated and drifts | Abstraction must fit the shared envelope |

**Decision: Proposal B.** DC tools share an outer response shape, so auth/send/retry/outer map/deep links/metrics belong in one adapter. Each executor only shapes its request and parses its reply detail.

```java
return adapter.run(check, ctx, SplunkMapping::toRequest, SplunkMapping::parseDetail);
```

Dispatcher keeps type routing + throttling. Native tool SDKs and a YAML connector engine are out of scope.

---

## Scope (first slice)

- Shared `DailyChecksAdapter` + DC client config (`checks.dc.*`, retry/CB)
- Thin executors + mappings for: **SPLUNK, GRAFANA, ITRS, APPDYNAMICS**
- Results → existing `ExecutionOutcome`; sources gated by `checks.sources.*` (default off)
- WireMock/unit tests + short enablement runbook

**Out of scope:** DC config import (9.5), ROD execute API (9.6), remaining ~20 sources, native SDKs, Proposal A as default.

---

## Acceptance criteria

1. `DailyChecksAdapter` owns auth, HTTP send, retries, outer mapping, deep links, metrics  
2. Each of the four types has a thin executor + `*Mapping` (no duplicated shared mechanics)  
3. Execute path returns correct `ExecutionOutcome` for success, business fail, timeout, auth fail  
4. DC types stay inside the DC bridge package (not on Checks APIs)  
5. Sources disabled by default; can enable per env after tests are green  
6. WireMock/unit coverage for the adapter + each mapping  
7. Runbook: DC URL/auth + how to flip source flags
