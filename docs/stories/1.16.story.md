## User Story

**As a** put-checks developer adding or modifying a REST endpoint,
**I want** springdoc-openapi to generate `/v3/api-docs` at runtime AND a CI test that diffs that output against a committed `docs/specs/backend/openapi.yaml`,
**so that** unintended API-contract changes (a removed field, a type change, a new 401 response) fail the build before merge rather than surfacing as FE-BE integration regressions in 1.17.

---

## Acceptance Criteria

- [ ] **AC-1:** `springdoc-openapi-starter-webmvc-ui` added to `build.gradle.kts`; `/v3/api-docs` (JSON) + `/swagger-ui.html` (HTML) expose the generated OpenAPI 3.1 spec in dev mode.
- [ ] **AC-2:** Swagger UI is DISABLED in production via `springdoc.swagger-ui.enabled=false` in `application-prod.yml`. `/v3/api-docs` remains available for internal tooling.
- [ ] **AC-3:** Every REST controller has class + method-level OpenAPI annotations sufficient for the generated spec to include: summary, operationId, path parameters, request body schema, all response codes (incl. 401/403/429/503), response body schemas.
- [ ] **AC-4:** Security schemes documented: `CookieAuth` (HTTP cookie `put_session`) — **not** `BearerAuth` (DEBT-04).
- [ ] **AC-5:** `docs/specs/backend/openapi.yaml` committed as the current snapshot of the contract. Generated by a Gradle task `./gradlew generateOpenApiSnapshot` that runs the app headless, fetches `/v3/api-docs`, and writes the yaml.
- [ ] **AC-6:** `OpenApiContractDiffTest` (@SpringBootTest) starts the app, fetches current `/v3/api-docs`, diffs against the committed `openapi.yaml`. Fails the build on any difference. Clear error message includes a diff summary (added paths / removed paths / changed schemas).
- [ ] **AC-7:** The diff test ignores cosmetic differences: YAML key ordering, whitespace, version-stamp fields (e.g., springdoc's x-generated-by).
- [ ] **AC-8:** A developer flow documented in `backend/README.md`: when an intentional change lands, run `./gradlew generateOpenApiSnapshot` + commit both the code change + the updated yaml. The PR review surfaces the contract delta.
- [ ] **AC-9:** The committed snapshot is verified against a pinned OpenAPI 3.1 schema (using, e.g., `io.swagger.parser.v3:swagger-parser` in the test) so hand-edited yaml can't drift into invalid shape.
- [ ] **AC-10:** Integration tests: `OpenApiReachableIT` (happy path — endpoint responds), `OpenApiContractDiffTest` (matches), `OpenApiContractDiffTest_DriftDetected` (artificially adds an endpoint + asserts diff fails).
- [ ] **AC-11:** JaCoCo coverage ≥ 80% for any custom code.

## Implementation Notes

- **Headless snapshot generation:** the Gradle task starts the app on an ephemeral port, curls `/v3/api-docs`, writes to `docs/specs/backend/openapi.yaml`. Use Spring Boot's `test` mode with a `@TestPropertySource` disabling Flyway (if snapshot generation doesn't need the DB).
- **Diff library:** consider `net.javacrumbs.json-unit:json-unit-assertj` (JSON/YAML-aware, ignores ordering, supports regex matching for version stamps). Avoid string-level diff — YAML reordering will bite.
- **Annotation conventions:** establish a one-liner `@ApiResponse` template that every controller method reuses for the common 401/403/429/503 responses. Avoid duplicating the full schema at each method.
- **Intentional-change flow:** make the "did you update the snapshot?" prompt obvious in the test failure message — link back to the README command.
