## User Story

**As a** user creating a new check,
**I want** to browse pre-built check templates from the real backend,
**so that** I can start from a template with sensible defaults instead of configuring everything from scratch.

---

## Acceptance Criteria

### Backend — New TemplatesController

- [ ] **AC-1:** `TemplatesController` created at `/api/v1/check-templates` with 2 endpoints.
- [ ] **AC-2:** `GET /api/v1/check-templates?q={search}&type={checkType}` — list templates. Response: `{data: CheckTemplateDto[], total}`. Filters: `q` (search name/description/tags), `type` (HTTP, TCP, SPLUNK, etc.). Authorization: authenticated (templates are global, not CSI-scoped).
- [ ] **AC-3:** `GET /api/v1/check-templates/{id}` — get template by ID. Response: `CheckTemplateDto`. Returns 404 if not found.
- [ ] **AC-4:** `CheckTemplateDto` record: `{id, title, description, type, difficulty, tags, estimatedSetupMinutes, defaultConfiguration}`. `defaultConfiguration` is a JSON object matching the check type's configuration schema.
- [ ] **AC-5:** Templates are **read-only seed data** — no user CRUD. Loaded via Flyway migration or `data.sql` seed. The 7 templates from the MSW mock data become the initial seed.

**Data model**
- [ ] **AC-6:** `CheckTemplate` JPA entity mapping to a new `check_templates` table (or reuse existing if one exists): id (VARCHAR PK, format `tpl-{type}-{slug}`), title, description, type (CheckType enum), difficulty (ENUM: easy, medium, advanced), tags (JSONB string array), estimated_setup_minutes (int), default_configuration (JSONB).
- [ ] **AC-7:** Flyway migration `V3__check_templates_seed.sql` creates the table and inserts the 7 seed templates.

**Service + repository**
- [ ] **AC-8:** `TemplatesService` with: `list(String query, String type)`, `findById(String id)`.
- [ ] **AC-9:** `TemplatesRepository` extends JpaRepository with search query.

**Tests**
- [ ] **AC-10:** Integration tests: `TemplatesListIT` (list all, search by name, filter by type), `TemplatesGetIT` (get by ID, 404 for unknown).

### Frontend — Wire templates

- [ ] **AC-11:** `templatesApi.ts` verified/updated to match BE contract. Response shape matches existing FE expectation.
- [ ] **AC-12:** Template browser component in CreateCheckPage verified working with real data.
- [ ] **AC-13:** `VITE_DISABLE_MSW_DOMAINS` updated to include `templates`.
- [ ] **AC-14:** `npm run type-check` passes. `./gradlew check` passes.
- [ ] **AC-15:** Template browser verified in browser: search, filter by type, select template populates form.
