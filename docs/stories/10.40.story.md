## Story

**As a** Studio client,
**I want** create/read/update transport for authoring v2 with matching MSW behavior,
**so that** the current selected draft and its exact saved revision identity can be used by later editor and compile wiring without contract drift.

## Acceptance Criteria

1. **FR-1 / AC-1–AC-2:** public create/read/update endpoints accept and return the 10.36 v2 shape with global context and ordered stable-ID steps. Legacy requests/read models adapt through the established adapter and preserve source text with empty context.
2. **FR-4 / AC-7:** controller-bound validation rejects duplicate/missing/orphan IDs and mixed legacy/v2 steps with the documented validation response. Reorder/copy/delete semantics round-trip without index-based context attachment.
3. **FR-5 / AC-8–AC-9:** update requires the saved source/configuration revision identity and returns the new authoritative tokens. Stale writes return `409 STALE_REVISION`; response bodies never suggest a failed edit was saved.
4. `studioApi` exposes typed `createTest`, `getTest` and `updateTest` v2 methods. Update uses `PUT` on the selected test ID; create uses `POST` only when no saved ID exists. Returned IDs/revisions, not stale local values, are the next operation's identity.
5. Transport types reuse 10.36 canonical types. No parallel request/response interface, direct `fetch`, page component mapping or compiler-internal type is introduced.
6. MSW handlers match real method/path/status/body behavior for create, read, update, legacy load, stale revision and validation errors. The existing request-level MSW bootstrap from 10.1 is extended, not replaced.
7. MSW state is CSI-scoped and revision-aware: successful update increments the matching tokens and stale update changes nothing. A request for another CSI cannot expose its context or evidence references.
8. The login → authenticated → protected-page fixture round-trips stable IDs and state-scoped context; password remains an opaque secret reference and login evidence is not relabeled as protected-page evidence.
9. Backend contract/integration tests and frontend transport/MSW tests use shared 10.36 examples and assert parity for payloads, statuses and revision tokens, including slow/stale responses and exact literals.
10. Backend targeted/static checks and frontend type-check, lint and Vitest pass with no new failures beyond the recorded baseline.
11. Existing-route negotiation is explicit and additive: POST/PUT bodies with `authoringSchemaVersion: 2` use `Omit<TestRequest,'steps'> & AuthoringV2Request`; unversioned bodies remain v1. `GET /tests/{id}?authoringSchemaVersion=2` returns `Omit<TestDto,'steps'> & AuthoringV2Response`; unversioned GET remains v1. Metadata, authoring and revision tokens in a v2 response come from one service transaction.
