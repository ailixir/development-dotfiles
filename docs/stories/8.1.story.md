## User Story

**As** Priya (L2 App Support) who creates health checks daily, and David (SRE) who configures complex Splunk/Grafana checks,
**I want** a premium, persona-optimized wizard that puts type selection first, groups check types by category, provides contextual help and test-before-save capabilities,
**so that** I can create checks faster with more confidence, reducing my daily check creation time while ensuring configuration accuracy before committing.

---

## Problem Statement

The current CreateCheckPage (1,723-line monolith) is functional but has several UX issues that slow down daily users:

1. **Inverted hierarchy:** Form fields render above the type selector when a type is already selected, confusing the flow.
2. **Flat type grid:** All 7 check types in an ungrouped 3-column grid. No visual categorization (Basic / Integration / UI Testing).
3. **Duplicate/misleading icons:** Splunk and Grafana share the same `AutoGraph` icon. AppDynamics uses `BugReport`.
4. **No test-before-save:** Users can't validate their HTTP endpoint or Splunk query before creating the check.
5. **Dense review step:** Three equal-weight columns with plain MUI Lists lack visual hierarchy.
6. **No collapsible advanced sections:** All fields shown flat, overwhelming for simple use cases.
7. **No inline help:** No tooltips or contextual guidance on any field.
8. **Cluttered header:** Title, subtitle, save hint, and autosave toggle compete for attention.
9. **Basic scheduling UX:** Radio buttons for frequency, tiny "Next run" chip.
10. **No component decomposition:** Single 1,723-line file makes iteration expensive.

- [x] **AC-6:** All existing functionality preserved — no regressions in create or edit mode. *(tsc --noEmit passes clean)*

### Task 2: Type-First Layout with Category Grouping (P0)
- [x] **AC-7:** In Step 0, the type selector renders **above** the basic information form fields (type-first hierarchy).
- [x] **AC-8:** Check types are grouped under three category headers: "Basic" (HTTP, TCP), "Integrations" (Splunk, Grafana, ITRS, AppDynamics), "UI Testing" (Checks Studio).
- [x] **AC-9:** Each category header uses a subtle label with a thin divider, consistent with the PUT design system.
- [x] **AC-10:** The Checks Studio card spans full width within its category to visually distinguish the flagship feature.
- [x] **AC-11:** When a type is selected, the basic info form fields appear below with a smooth fade-in transition (200ms).

### Task 3: Distinct Icons & Visual Polish (P0)
- [x] **AC-12:** Each check type has a unique, recognizable icon: HTTP=`Http`, TCP=`Cable`, Splunk=`ManageSearch`, Grafana=`ShowChart`, ITRS=`DesktopWindows`, AppDynamics=`Speed`, UI_TEST=`SmartDisplay`.
- [x] **AC-13:** Selected type card shows a subtle elevation change and colored left border (2px) matching the type's color.
- [x] **AC-14:** Disabled ("Coming Soon") types show a lock icon overlay instead of reduced opacity alone.

### Task 4: Configuration Step Refinements (P1)
- [x] **AC-15:** HTTP, Splunk, and Grafana forms group advanced/optional fields into a collapsible `<Accordion>` labeled "Advanced Settings" (collapsed by default).
- [x] **AC-16:** HTTP advanced section contains: Headers, SSL Validation, Follow Redirects, Retry Attempts.
- [x] **AC-17:** Splunk advanced section contains: Index, Count Operator, Expected Count.
- [x] **AC-18:** Each config form shows 1-2 inline help tooltips (via MUI `Tooltip` on `InfoOutlined` icons) for the most technical fields.

### Task 5: "Test Connection" Button (P1)
- [x] **AC-19:** HTTP config form shows a "Test Connection" outlined button below the endpoint URL field.
- [x] **AC-20:** Clicking "Test Connection" fires a dry-run execution via the existing backend execution endpoint (POST `/api/checks/execute`), shows a loading spinner, and displays the result (status code + latency) in an inline `Alert`.
- [x] **AC-21:** TCP config form shows a similar "Test Connection" button that validates host:port reachability.
- [x] **AC-22:** The test result persists visually until the user changes the endpoint/host value.

### Task 6: Review Step Premium Redesign (P1)
- [x] **AC-23:** Review step renders a "hero card" at top spanning full width with: check name (h5), type badge (Chip with icon and color), CSI entity, environment badge, tags as chips, and description.
- [x] **AC-24:** Below the hero card, two stacked cards (not three columns): "Configuration" and "Schedule & Alerts", each with an Edit button linking back to the relevant step.
- [x] **AC-25:** The configuration card shows type-specific details in a clean key-value layout using `<Grid>` pairs instead of `<List>`.
- [x] **AC-26:** A "Test Now" outlined button appears alongside "Create Check" in the final action bar, allowing a dry-run before committing.

### Task 7: Scheduling Step Visual Upgrade (P2)
- [x] **AC-27:** Replace frequency radio buttons with small selectable Chip cards (pill-style) in a horizontal row, matching the day-of-week chip pattern already used.
- [x] **AC-28:** The "Next run" preview is displayed as a prominent `Alert` with `severity="info"` showing the calculated timestamp, instead of a tiny Chip.
- [x] **AC-29:** Alert Configuration section is visually separated into its own `Paper` card with a warning-colored left border.

### Task 8: Wizard Header & Global Polish (P2)
- [x] **AC-30:** The header area shows: page title (h4) with type-colored icon, subtitle below, and autosave indicator as a small dot/badge on the stepper (not inline with the title).
- [x] **AC-31:** The MUI Stepper uses `alternativeLabel` prop for a cleaner horizontal layout with labels below icons.
- [x] **AC-32:** Step transitions use a 200ms CSS fade transition (via MUI `Fade` or `Collapse`) instead of instant content swap.
- [x] **AC-33:** Required fields show a green `CheckCircleOutline` icon when filled and valid, providing continuous visual feedback.

## Scope

### In scope
- Decompose `CreateCheckPage.tsx` into ~8 focused components
- Restructure Step 0 layout (type-first, categorized)
- Replace icons with distinct per-type icons
- Add collapsible advanced sections in Step 1
- Add inline help tooltips on key fields
- Add "Test Connection" dry-run buttons for HTTP/TCP
- Redesign Review step with hero card layout
- Upgrade Scheduling step chips and next-run display
- Clean up header area, add stepper `alternativeLabel`
- Add fade transitions between steps
- Add visual validation indicators on required fields

### Out of scope
- Template library / quick-start bar (separate story)
- Keyboard shortcuts framework (separate story)
- Left sidebar progress rail (separate story)
- "Save as Template" feature (separate story)
- "Similar Checks" suggestions (separate story)
- Backend changes (execution endpoint already exists)

---

## Technical Notes

- All new components go under `frontend/src/components/checks/wizard/`
- Configuration sub-forms go under `frontend/src/components/checks/wizard/configs/`
- Icons imported from `@mui/icons-material` — no external icon libraries
- Test Connection uses existing `POST /api/checks/execute` with `dryRun: true` flag
- Transitions use MUI `Fade` component with `timeout={200}`
- No new dependencies required — MUI Accordion, Fade, Tooltip already available
- Existing autosave/draft/edit-mode logic preserved in orchestrator

---

## Risks

| Risk | Mitigation |
|------|------------|
| Large refactor may introduce subtle regressions in edit mode | AC-6 explicitly requires edit mode preservation; manual testing |
| Test Connection endpoint may not exist yet | Graceful fallback: disable button with "Backend not available" tooltip |
| 1,723-line file decomposition is error-prone | Extract one component at a time, verify after each extraction |
