## User Story

**As a** user filtering checks by tags or discovering related tags,
**I want** tag listing, statistics, and suggestions served from the real backend,
**so that** tags reflect actual check data in the database and stay consistent across users.

---

## Acceptance Criteria

### Backend — New TagsController

- [ ] **AC-1:** `TagsController` created at `/api/v1/tags` with 3 endpoints.
- [ ] **AC-2:** `GET /api/v1/tags?csi={csiId}` — returns all distinct tags. If `csiId` provided, returns tags from checks + CSI tags for that CSI only. Response: `{data: string[], total: int}`. Tags sorted alphabetically. Authorization: authenticated.
- [ ] **AC-3:** `GET /api/v1/tags/stats?csi={csiId}` — returns tag usage statistics. Response: `{data: [{tag: string, count: int}], totalTags: int, totalChecks: int}`. Sorted by count descending. Authorization: authenticated.
- [ ] **AC-4:** `POST /api/v1/tags/suggestions` — body `{selectedTags: string[], csiId?: string}`. Returns tags that co-occur with the selected tags, sorted by frequency. Response: `{data: string[]}`. Max 10 suggestions. Authorization: authenticated.
- [ ] **AC-5:** `TagsService` created with: `getDistinctTags(String csiId)`, `getTagStats(String csiId)`, `getSuggestions(List<String> selectedTags, String csiId)`.
- [ ] **AC-6:** Tag queries use the `tags`, `check_tags`, and `csi_tags` tables from V1 migration. Co-occurrence query: find checks that have ANY of the selected tags, then collect other tags from those checks, count frequency, exclude already-selected.
- [ ] **AC-7:** Integration tests: `TagsListIT` (all tags, filtered by CSI), `TagsStatsIT` (correct counts), `TagsSuggestionsIT` (co-occurrence logic).

### Frontend — Wire tags

- [ ] **AC-8:** New `tagsApi.ts` service created in `src/services/api/` (if not existing) or update existing tag-related code.
- [ ] **AC-9:** Tag-related components (FilterBar, TagSelector, etc.) updated to call `tagsApi` instead of relying on MSW.
- [ ] **AC-10:** `VITE_DISABLE_MSW_DOMAINS` updated to include `tags`.
- [ ] **AC-11:** `npm run type-check` passes. `./gradlew check` passes.
- [ ] **AC-12:** Tag filter, tag stats, and tag suggestions verified in browser.

## Implementation Notes

### Tag co-occurrence SQL
```sql
-- Find tags that co-occur with selected tags
SELECT ct2.tag_id, t2.name, COUNT(DISTINCT ct2.check_id) as frequency
FROM check_tags ct1
JOIN check_tags ct2 ON ct1.check_id = ct2.check_id
JOIN tags t2 ON ct2.tag_id = t2.id
WHERE ct1.tag_id IN (SELECT id FROM tags WHERE name IN (:selectedTags))
  AND ct2.tag_id NOT IN (SELECT id FROM tags WHERE name IN (:selectedTags))
  AND (:csiId IS NULL OR ct1.check_id IN (SELECT id FROM checks WHERE csi_id = :csiId))
GROUP BY ct2.tag_id, t2.name
ORDER BY frequency DESC
LIMIT 10
```
