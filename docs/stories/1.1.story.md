## User Story

**As a** backend developer starting on the put-checks Phase 2 implementation,
**I want** a ready-to-run Spring Boot 3.3+ project scaffold under `backend/` with Gradle (Kotlin DSL), the agreed profile structure, and all quality-gate plugins wired in,
**so that** every subsequent story can add features against a single consistent baseline with a working `./gradlew check` gate, `bootRun` for local iteration, and CI-ready lint/coverage reporting.

---

## Acceptance Criteria

- [ ] **AC-1:** `./gradlew bootRun --args='--spring.profiles.active=local'` (executed from `backend/`) starts the application cleanly and binds port `:8080` within 15 seconds on a clean checkout.
- [ ] **AC-2:** `./gradlew check` completes green on a clean checkout and produces an HTML JaCoCo report at `backend/build/reports/jacoco/test/html/index.html`.
- [ ] **AC-3:** `GET http://localhost:8080/actuator/health` returns HTTP 200 with body `{"status":"UP"}` (minimum) when the app is running.
- [ ] **AC-4:** Four Spring profiles are defined and the app boots cleanly in each: `local` (Zonky embedded PG — placeholder config; real activation in story 1.2), `test` (Testcontainers — placeholder), `staging`, `prod`.
- [ ] **AC-5:** Spotless runs on `./gradlew check` and fails if any source file violates google-java-format; `./gradlew spotlessApply` auto-fixes.
- [ ] **AC-6:** Checkstyle runs as part of `check` with the Citi-standard ruleset (or a sensible google_checks.xml baseline if Citi ruleset is not yet available).
- [ ] **AC-7:** SpotBugs runs as part of `check` and fails the build on new `High` or `Scariest`-priority findings.
- [ ] **AC-8:** JaCoCo enforces a line-coverage gate ≥ **80%** (scoped to the project's own packages; excludes generated code, DTOs, JPA entities with no behavior). Build fails below threshold.
- [ ] **AC-9:** Logs are emitted in **JSON format** via `logstash-logback-encoder`; MDC fields (at minimum `traceId`, `service=checks-backend`) appear in every log line.
- [ ] **AC-10:** A `MaskingPatternLayout` is wired in the Logback config and masks values matching obvious secret/email patterns (integration test injects a log line containing `"password":"...` and asserts the masked output does not contain the raw value).
- [ ] **AC-11:** Gradle wrapper is committed at `backend/gradlew`, `backend/gradlew.bat`, `backend/gradle/wrapper/gradle-wrapper.jar`, `backend/gradle/wrapper/gradle-wrapper.properties` — pinned to Gradle 8.x. (Note: wrapper files already exist at `backend/` from pre-reorg WIP — verify version and update `gradle-wrapper.properties` if needed.)
- [ ] **AC-12:** `backend/README.md` documents the 3 canonical commands (`bootRun`, `check`, `bootJar`) and the profile activation syntax.

## Scope

### In scope (this story)

- `backend/build.gradle.kts` — Kotlin DSL build script with:
  - Spring Boot 3.3.x BOM (pick the latest patch available at implementation time)
  - `org.springframework.boot` + `io.spring.dependency-management` plugins
  - Java 21 toolchain (`kotlin("jvm")` NOT needed — pure Java project)
  - Dependencies: `spring-boot-starter-web`, `spring-boot-starter-actuator`, `spring-boot-starter-validation`, `logstash-logback-encoder`, JUnit 5, AssertJ, Mockito (test scope)
  - Plugins: `spotless`, `checkstyle`, `spotbugs`, `jacoco`
  - Task: `test` uses JUnit Platform; `check` depends on `spotlessCheck`, `checkstyleMain`, `spotbugsMain`, `jacocoTestCoverageVerification`
- `backend/settings.gradle.kts` — root project name `checks-backend`; no subprojects.
- `backend/src/main/java/com/citi/put/checks/ChecksApplication.java` — `@SpringBootApplication` entry point with `main(String[])`.
- `backend/src/main/resources/application.yml` — common config (application name, actuator endpoints exposure, log pattern reference).
- `backend/src/main/resources/application-local.yml` — local profile overrides (placeholder for Zonky — actual Zonky config in story 1.2).
- `backend/src/main/resources/application-test.yml` — test profile (placeholder for Testcontainers).
- `backend/src/main/resources/application-staging.yml` — staging overrides (env-var driven).
- `backend/src/main/resources/application-prod.yml` — prod overrides (env-var driven).
- `backend/src/main/resources/logback-spring.xml` — JSON encoder + MaskingPatternLayout + MDC propagation.
- `backend/config/checkstyle/checkstyle.xml` — ruleset (start with google_checks.xml, annotate deviations in comments).
- `backend/config/spotbugs/exclude.xml` — known false-positive exclusions (empty at story 1.1; grows per-story).
- `backend/README.md` — developer-facing quickstart.
- `backend/.gitignore` additions — `build/`, `.gradle/`, `out/`, `bin/`, `*.log` (mirror root `.gitignore` §"Backend" section).
- One trivial unit test (`ChecksApplicationTest`) with `@SpringBootTest` asserting context loads — provides initial JaCoCo data so the 80% gate is measurable.
- A Logback masking integration test that verifies AC-10.

### Out of scope (deferred to explicit later stories)

- **No Flyway migrations** — added in story 1.2.
- **No Zonky embedded PG or Testcontainers activation** — skeleton profile entries only; wired up in 1.2.
- **No JPA / Hibernate dependencies** — added in 1.2.
- **No authentication / CORS / CoreServiceClient** — added in 1.5.
- **No business domain packages (csi/, checks/, etc.)** — added in 1.6+ as each context lands.
- **No OpenAPI generation** — added in 1.16.
- **No container image (Dockerfile)** — added in 5.2 (Playwright image) and a dedicated M6 story for the production image.

## Implementation Notes (for @dev)

- **Wrapper already on disk:** pre-reorg WIP snapshot (`9486113d8`) placed `gradlew`, `gradlew.bat`, and `gradle/wrapper/` under `backend/`. Verify Gradle version in `gradle-wrapper.properties`; if older than 8.x, regenerate via `gradle wrapper --gradle-version 8.10.2` (or latest patch).
- **Virtual threads:** do **not** enable `spring.threads.virtual.enabled=true` here — story 1.8 owns the virtual-thread executor wiring and associated tests. Leaving it off in 1.1 keeps the JVM footprint predictable for the skeleton.
- **Actuator exposure:** only expose `health`, `info`, `prometheus` in `application.yml`; the additional custom health indicators (`partitions`, `studio-capacity`) come in later stories.
- **JaCoCo 80% scope:** use `classDirectories.from(fileTree(...) { exclude })` to trim generated MapStruct code, JPA entities with no methods, and DTO records. Aim to keep the exclusion list small and explicit.
- **No business logic in `ChecksApplication`** — keep it a bare `@SpringBootApplication` + `main()`. All beans go in `config/` or context packages in later stories.
- **Logback XML vs. YAML:** use XML (`logback-spring.xml`) — Spring Boot supports it cleanly and `logstash-logback-encoder` examples are overwhelmingly XML.
- **Citi-standard checkstyle ruleset:** if unavailable, commit `google_checks.xml` verbatim and note in the README that replacement is tracked as a follow-up chore.

## Testing Strategy

- **Unit:** `ChecksApplicationTest` with `@SpringBootTest` — asserts context loads; gives JaCoCo a baseline.
- **Integration:** `LogMaskingIT` — captures a logger's output via a custom `OutputStreamAppender`, emits a line containing a fake secret, asserts the masked output.
- **Manual:** `bootRun` + `curl /actuator/health` as validation of AC-3 before closing the story.
