## Story

**As a** Studio author or operator working with test and run lists at production scale,
**I want** the Tests and Runs pages to page, search, filter and sort on the server, keep their state in the URL, open run details in a shareable, live-updating drawer, and meet the accessibility findings raised in the audit,
**so that** the lists stay correct and fast as data grows (no duplicate or missing rows, no fetch-everything), runs can be linked and watched live, and the pages are usable by keyboard and assistive technology.

## Context (from the plan)

Three expert audits of `StudioTestsPage` and `StudioRunsPage` found:

- **Scale/correctness:** both pages fetch *every* page (`studioApi.readAllPages`) and filter client-side; Runs also fetches all tests just for names. Backend sorts by `createdAt` only (no id tie-breaker) → duplicate/missing rows during concurrent inserts; refresh races; stale dialog.
- **UX:** run details trapped in a modal, not linkable, no live updates ("Refresh to see the latest result"); raw `toLocaleString()` / `Math.round(ms/1000)` formatting; duplicate buttons per row; no sort; no readiness info; filter state lost on back-nav.
- **A11y:** Create dialog unnamed, Environment select unlabeled, focus lost after delete, no live-region for count/loading, keyboard-unreachable tooltip, buttons used as links.

## Acceptance Criteria

1. Lists page on the server with search/filter/sort; URL reflects state; back button restores it.
2. No duplicate/missing runs under concurrent inserts (id tie-breaker + FE dedupe).
3. Run details open in a drawer at `/checks/studio/runs/:id`, update live, and are shareable.
4. Times relative + absolute tooltip with timezone; durations `850 ms` / `42 s` / `2m 05s`.
5. Each row has one primary link and a ⋮ menu; status never colour-only.

## Dev Notes

### API contract (fixed up front so BE and FE run in parallel) — additive, backward compatible

`GET /api/v1/studio/tests` — new optional params: `environment`, `q` (name/description, case-insensitive), `lastRun` (`PASSED|FAILED|ERROR|NEVER`), `sort` (`name|updatedAt|lastRunAt`,`asc|desc`; default `updatedAt,desc`). Stable tie-breaker `id`.
`GET /api/v1/studio/executions` — new optional params: `csiId`, `status` (`PENDING|RUNNING|PASSED|FAILED|ERROR|CANCELLED`, CANCELLED mapped the same way as `isCancelledOutcome`), `q` (test name), `sort` (`acceptedAt|durationMs`,`asc|desc`; default `acceptedAt,desc`). Stable tie-breaker `id`. Each item gains nullable `testName` (null when the test was soft-deleted).
Unknown sort values → 400 via existing `StudioValidationException`. Size cap 100 unchanged. Access scoping (CSI) unchanged.
