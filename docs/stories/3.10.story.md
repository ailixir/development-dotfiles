## User Story

**As a** user creating and managing operational reports,
**I want** report CRUD, preview, execution, and delivery features backed by the real backend,
**so that** reports are persisted, sections resolve real check data, and email delivery actually sends.

---

## Acceptance Criteria

### Backend — New ReportsController

- [ ] **AC-1:** `ReportsController` created at `/api/v1/reports` with all endpoints matching the MSW contract.

**CRUD**
- [ ] **AC-2:** `GET /api/v1/reports?status={optional}&page=0&size=20` — paginated list. Response: Spring Page envelope with `ReportDto` items. Filters: `status` (active, paused, draft). Authorization: scoped to user's CSIs (checks referenced in report sections).
- [ ] **AC-3:** `POST /api/v1/reports` — create report. Body: `ReportRequest` `{name, description, template, schedule, sections, recipients}`. Response: 201 + `ReportDto`.
- [ ] **AC-4:** `GET /api/v1/reports/{id}` — get report by ID. Response: `ReportDto` with full sections array.
- [ ] **AC-5:** `PUT /api/v1/reports/{id}` — update report. Body: same as create. Response: updated `ReportDto`.
- [ ] **AC-6:** `DELETE /api/v1/reports/{id}` — soft delete (set `deleted_at`). Response: 204.

**Actions**
- [ ] **AC-7:** `POST /api/v1/reports/{id}/pause` — set status to `paused`. Response: updated `ReportDto`.
- [ ] **AC-8:** `POST /api/v1/reports/{id}/resume` — set status to `active`. Response: updated `ReportDto`.
- [ ] **AC-9:** `POST /api/v1/reports/{id}/duplicate` — clone report with name suffix ` (Copy)`, status `draft`. Response: new `ReportDto`.
- [ ] **AC-10:** `POST /api/v1/reports/{id}/preview` — render HTML preview against current check data. Body: `{draft: true}` (optional). Response: `{preview: string, html: string, generatedAt}`. Does NOT persist or send.
- [ ] **AC-11:** `POST /api/v1/reports/{id}/run-now` — execute report immediately: render + persist `report_executions` row. Response: `{ok: true, execution: ReportExecutionDto, report: ReportDto}`.
- [ ] **AC-12:** `GET /api/v1/reports/{id}/executions?page=0&size=10` — execution history. Response: Spring Page of `ReportExecutionDto`.
- [ ] **AC-13:** `POST /api/v1/reports/{id}/send-test` — send test email to the requesting user only. Response: `{ok: true, sentAt}`.

**Data model**
- [ ] **AC-14:** `Report` JPA entity mapping to `reports` table. `sections` stored as JSONB (array of `ReportSection` objects). `schedule` stored as JSONB `{frequency, cron, timezone, daysOfWeek}`. `recipients` stored as JSONB string array.
- [ ] **AC-15:** `ReportExecution` JPA entity mapping to `report_executions` table: id, report_id (FK), status (SUCCESS/FAILURE/PARTIAL), started_at, ended_at, recipient_count, checks_included, email_subject, error_message.
- [ ] **AC-16:** `ReportSection` sealed interface with `ManualSection` (explicit checkIds) and `RuleSection` (filter by csiIds, tags, types, status, timeframe, sort, limit). Section resolution queries checks table to produce the actual check list at render time.
- [ ] **AC-17:** HTML rendering: use Thymeleaf or a simple template to produce the report email HTML. Status chips color-coded (green=passing, red=failing, yellow=warning). Include check name, status, last execution time, duration.

**Service + repository**
- [ ] **AC-18:** `ReportsService` with full CRUD + preview + run-now + send-test logic.
- [ ] **AC-19:** `ReportsRepository` extends JpaRepository with filtered list query.
- [ ] **AC-20:** Section resolver: `SectionResolver.resolve(ReportSection section): List<CheckDto>` — evaluates manual (by checkIds) or rule (by filter query) sections against checks table.

**Tests**
- [ ] **AC-21:** Integration tests: `ReportsCrudIT` (full lifecycle), `ReportsPreviewIT` (HTML rendering), `ReportsExecutionIT` (run-now persists execution), `ReportsDuplicateIT` (copy with suffix).

### Frontend — Wire reports

## Scope

### In scope
- Full `reports` bounded context in backend (controller, service, repository, entities)
- Section resolver (manual + rule)
- HTML report rendering
- Report execution persistence
- Test email sending (mock SMTP in test profile)
- FE wiring + MSW disable
- Integration tests

### Out of scope
- Scheduled report delivery (existing `ReportDispatcher` from spec §10.3 — separate story if not built)
- PDF/CSV export (OOS per spec §1.2)
- Cross-CSI composition optimization (future)
