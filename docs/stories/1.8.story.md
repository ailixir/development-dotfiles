## User Story

**As a** put-checks backend developer writing any @Async method,
**I want** three named `AsyncTaskExecutor` beans — `applicationTaskExecutor` (default, unbounded virtual threads), `checkExecutor` (semaphore-bounded virtual threads for non-UI checks), `uiTestExecutor` (platform threads, stub size-0 until story 5.3) — plus an `MdcTaskDecorator` that propagates correlation IDs and SecurityContext across async boundaries,
**so that** check executions, user-provisioning events, scheduled dispatches, and future UI test runs each have an appropriately-bounded execution surface (no bulkhead starvation), tracing context is preserved end-to-end, and `@Async` semantics are predictable for every downstream story that depends on them.

## Acceptance Criteria

- [ ] **AC-1:** `spring.threads.virtual.enabled=true` in `application.yml`. `./gradlew bootRun` confirms Tomcat request executor runs virtual threads (log line or probe).
- [ ] **AC-2:** `@Bean("applicationTaskExecutor")` of type `AsyncTaskExecutor` uses `Executors.newVirtualThreadPerTaskExecutor()`, wrapped in `TaskExecutorAdapter` with `MdcTaskDecorator` applied. Unbounded — used for low-cost bookkeeping tasks like user provisioning (story 1.6).
- [ ] **AC-3:** `@Bean("checkExecutor")` wraps the virtual-thread executor in a `SemaphoreBoundedExecutor` (custom class) with permit cap = `checks.executor.semaphore-multiplier × spring.datasource.hikari.maximum-pool-size` (default multiplier=4 per spec §4.2 ACC-01).
- [ ] **AC-4:** `@Bean("uiTestExecutor")` is a `ThreadPoolTaskExecutor` with `corePoolSize = maxPoolSize = studio.pool.size` (default 0 — story 5.3 raises to 4). `queueCapacity=0` (fail-fast when full — readiness probe flips; see story 5.8). Uses **platform threads**, not virtual, per spec §4.1 documented exception. MdcTaskDecorator applied. `AbortPolicy` on rejection.
- [ ] **AC-5:** `MdcTaskDecorator` bean implements `TaskDecorator`: captures MDC map (`traceId`, `userId`, `checkId`, `executionId` if present) + wraps the runnable in `DelegatingSecurityContextExecutor`. On execution, restores MDC + SecurityContext; on completion, clears both.
- [ ] **AC-6:** Integration test `VirtualThreadIT` asserts `Thread.currentThread().isVirtual() == true` inside a method annotated with `@Async` (no qualifier — uses default) AND inside one qualified `@Async("checkExecutor")`.
- [ ] **AC-7:** Integration test `PlatformThreadIT` asserts a task submitted to `uiTestExecutor` (once `studio.pool.size` is temporarily set to 1 via test config) runs on a **platform** thread (`isVirtual() == false`).
- [ ] **AC-8:** Integration test `MdcPropagationIT` sets MDC on the submitting thread, dispatches an async task, asserts MDC is visible inside the task AND cleared after completion.
- [ ] **AC-9:** Integration test `SecurityContextPropagationIT` authenticates a request, dispatches `@Async` inside the controller, asserts `SecurityContextHolder.getContext().getAuthentication()` is non-null and matches inside the async task.
- [ ] **AC-10:** Integration test `SemaphoreBoundIT` submits `N+1` tasks to `checkExecutor` (with test config `checks.executor.semaphore-multiplier=1`, `hikari.max-pool-size=2` → cap=2) and asserts the 3rd task blocks until one of the first two completes (verified with a `CountDownLatch`).
- [ ] **AC-11:** Preprod JVM flag `-Djdk.tracePinnedThreads=short` is documented in `backend/README.md` as recommended for pre-production environments to surface residual `synchronized` pinning (per VT-R3).
- [ ] **AC-12:** JaCoCo coverage for `config` package ≥ 80% (all three bean factories + decorator + semaphore wrapper exercised by the test set above).

## Implementation Notes
- **`SemaphoreBoundedExecutor`** — acquire a permit before `execute()`, release in a `try/finally` on task completion. A clean ~30-line wrapper.
- **TaskDecorator order matters:** `MdcTaskDecorator` should capture MDC **before** `DelegatingSecurityContextExecutor` wraps the runnable. The implementation looks like: capture MDC → capture SecurityContext → wrap → decorate. See spec §4.3.
- **Test with `studio.pool.size=0`:** when 0, `ThreadPoolTaskExecutor` can still be instantiated but cannot accept tasks (any submit rejects). For AC-7, use a test-scoped config that raises it to 1.
- **`-Djdk.tracePinnedThreads=short`** output is noisy; don't enable in dev by default. README guidance only.

**Watch-items (non-blocking):**
- `studio.pool.size=0` at M1 is deliberate (Playwright doesn't exist until 5.3). But the `AbortPolicy` (AC-4) means if any code accidentally submits to `uiTestExecutor` before 5.3, the request fails fast with an unhelpful `RejectedExecutionException`. Consider a custom rejection handler that returns a clearer error message mentioning "studio.pool.size=0". Non-blocking — @dev can decide.
- `-Djdk.tracePinnedThreads=short` in README (AC-11) is good, but consider also adding a `preprod` Spring profile that sets it automatically — ops teams don't always read READMEs. Non-blocking; raise in 6.8 runbooks story if still missing.
