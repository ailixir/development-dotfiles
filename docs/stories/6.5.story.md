## User Story

**As a** developer maintaining the PUT Checks backend,
**I want** integration tests that validate circuit breaker behavior under core-service failure and end-to-end report email delivery via GreenMail,
**so that** resilience and email formatting are verified in CI, not discovered in staging.

---

## Problem Statement

1. **Circuit breaker (H6):** Resilience4j is configured for `core-service` (50% threshold, 20-call window, 30s open state, 3 retries with exponential backoff). No test validates that the breaker opens, that retries work, or that the fallback behavior is correct.

2. **Report email delivery (H7):** GreenMail dependency is already in `build.gradle.kts` but no test uses it. `ReportMailSender` sends real MIME messages, but the full pipeline (render + send + verify email content) is untested.

3. **Metrics emission (M7):** Micrometer counters and gauges are registered throughout the codebase, but no test asserts they actually emit the expected values.

---

## Acceptance Criteria

### A — Circuit breaker integration tests

- [ ] **AC-1:** `CircuitBreakerOpenIT`: WireMock stubs core-service to return 500 for 10+ calls. Verify circuit breaker opens after threshold. Verify subsequent calls fail-fast without hitting WireMock.
- [ ] **AC-2:** `CircuitBreakerRecoveryIT`: After breaker opens, wait `wait-duration-in-open-state` (30s in test override to 2s). Verify breaker transitions to half-open, then closed on success.
- [ ] **AC-3:** `RetryExponentialBackoffIT`: WireMock returns 503 twice, then 200. Verify 3 attempts made. Verify exponential delays between attempts (assert via WireMock request timestamps).
- [ ] **AC-4:** `RetryIgnoredExceptionIT`: WireMock returns 401 (maps to `CoreServiceUnauthorizedException`). Verify no retry (ignored exception per config).

### B — GreenMail report delivery tests

- [ ] **AC-5:** `ReportEmailDeliveryIT`: Start GreenMail SMTP server. Create report with 2 recipients + 3 checks (1 failing). Trigger `runNow`. Verify:
  - 2 emails received in GreenMail.
  - Subject matches `[PUT Checks] {name} — {date}` pattern.
  - HTML body contains the failing check's name and "FAILING" status.
  - From address matches `checks.reports.mail.from` config.
- [ ] **AC-6:** `ReportEmailPartialFailureIT`: Configure GreenMail to reject one recipient. Trigger delivery. Verify `ReportExecution` has status `partial` and `failedRecipients` tracked.
- [ ] **AC-7:** `ReportEmailSmtpDownIT`: Don't start GreenMail (no SMTP). Verify `ReportMailSender` bean is not loaded (`@ConditionalOnProperty`). Verify report renders but no email is sent.

### C — Metrics assertion tests

- [ ] **AC-8:** `CheckExecutionMetricsIT`: Execute an HTTP check via API. Assert `checks.execution.total` counter incremented with correct tags (check_type=HTTP, status=SUCCESS).
- [ ] **AC-9:** `ScheduleDispatchMetricsIT`: Trigger cron dispatch cycle. Assert `checks.scheduled.dispatches_total{outcome=success}` incremented.
- [ ] **AC-10:** Use `MeterRegistry` injection in tests to read metric values directly (no Prometheus endpoint scraping needed).

### D — Test infrastructure

- [ ] **AC-11:** Test-specific Resilience4j config override: reduce `wait-duration-in-open-state` to 2s (avoid 30s waits in tests).
- [ ] **AC-12:** GreenMail started via `@RegisterExtension` (JUnit 5 lifecycle). Random port injected via `@DynamicPropertySource`.
- [ ] **AC-13:** JaCoCo coverage >= 80%.

## Implementation Notes

- **WireMock for circuit breaker tests:** Use `@WireMockTest` with scenario state to simulate failure sequences. Example: scenario "core-service-down" starts in state "failing", returns 500 for first 10 calls, then transitions to "recovering".
- **GreenMail setup:**
  ```java
  @RegisterExtension
  static GreenMailExtension greenMail = new GreenMailExtension(ServerSetupTest.SMTP)
      .withConfiguration(GreenMailConfiguration.aConfig().withUser("test", "test"));
  
  @DynamicPropertySource
  static void mailProps(DynamicPropertyRegistry registry) {
      registry.add("spring.mail.host", () -> "localhost");
      registry.add("spring.mail.port", greenMail::getSmtp().getPort);
  }
  ```
- **Circuit breaker config override in tests:**
  ```yaml
  # application-test.yml addition
  resilience4j.circuitbreaker.instances.core-service.wait-duration-in-open-state: 2s
  resilience4j.circuitbreaker.instances.core-service.sliding-window-size: 5
  resilience4j.circuitbreaker.instances.core-service.minimum-number-of-calls: 3
  ```
- **Metrics assertion pattern:** Inject `MeterRegistry`, use `registry.get("metric.name").counter().count()` to assert.
