## Story

**As a** Studio author compiling saved v2 steps,
**I want** deterministic scoped-context resolution and bounded compiler input with independent typed-intent checks,
**so that** the generated proposal cannot silently replace my exact value, target or page-state assumptions.

## Acceptance Criteria

1. **FR-2 / AC-3–AC-4:** a pure resolver applies explicit step intent/value → step context → global context; policy remains authoritative. It returns field-level provenance and a blocking diagnostic for unresolved value/target conflicts.
2. **FR-5 / AC-8–AC-9:** compile input binds the saved `testId`, source/configuration revisions, ordered stable step IDs, context digest and selected evidence identities. Publication uses that identity so a context edit or older completion cannot become current.
3. **FR-7 / AC-11–AC-12:** quoted/typed empty, whitespace, Unicode, quotes, slash and newline values survive resolution and serialization exactly. Variables/secrets remain opaque references; secret canaries never appear in payloads, diagnostics or logs.
4. **FR-3 / AC-5–AC-6:** evidence selection requires matching CSI, environment, route, state and step ID, and preserves supplied/observed/unknown provenance and coverage. Login-page evidence cannot verify authenticated or protected-page state; each transition requires evidence for its actual state.
5. The login → submit → authenticated state → protected navigation fixture resolves each step from its current predecessor state, keeps the password opaque and marks future protected state predicted until separately observed.
6. **FR-8 / AC-13–AC-14:** compiler input requests only the existing allowed locator/action language, preserves one source-step boundary for bounded multi-operation intent and never requests arbitrary waits, broad first-match or selector fallback.
7. **FR-9 / AC-15–AC-16:** ambiguous targets and unsupported transitions yield stable per-step diagnostics. Repairs receive bounded redacted diagnostics, preserve original intent/context and remain within the existing two-repair authoring limit.
8. Prompt assembly structurally separates pinned instructions from untrusted source/context/evidence. Aggregate byte/call/deadline accounting includes proposal, repair and transport retries; oversized essential literals fail rather than truncate.
9. Independent correspondence checks compare resolved typed intent with accepted operation arguments for exact value, reference, target class and requested submit/action sequence. The LLM's explanation cannot satisfy this check.
10. Unit/integration tests cover precedence, conflicts, exact literals, login/protected state isolation, stale save identity, malicious context, secret canaries, aggregate budgets and browser-free compile. Targeted tests and backend static checks pass.
