## User Story

**As the** Checks Studio delivery team building compilation, dispatch, SSE and video on top of the existing prototype,
**I want** one frozen OpenAPI/JSON-schema contract for the Studio API and artifact, plus the execution schema migrations that carry immutable revision/CSI snapshots, durable dispatch identity and evidence state,
**so that** frontend, backend and runner stories can be built against the same typed shapes, and executions are recorded truthfully across API replicas, restarts and partition boundaries.

---

## Problem Statement

The prototype contract is untyped and inconsistent with architecture v2.1:

| Today | Required (architecture §8) |
|---|---|
| `UITestRequest` carries `steps` and `variables` as JSON **strings**, flattened `viewportWidth/Height`, free-text `browser` | `steps: string[]`, typed `variables` (`plain` \| `secretRef`), `configuration: {browser, viewport, timeoutSeconds, waitStrategy}`, `environment` |
| `ui_tests.browser` CHECK allows `chrome, firefox, safari, edge`; frontend `TestIR.browser` uses `'chrome'` | Canonical `chromium`; legacy `chrome` normalized; other engines rejected before execution |
| `ui_test_executions` (range-partitioned by `started_at` since V7, PK `(id, started_at)`) has `ended_at`/`duration_ms` **NOT NULL**, status `PASSED\|FAILED\|ERROR`, `video_url TEXT`, no revision/CSI snapshot, no step results | Nullable end/duration, status `PENDING\|RUNNING\|PASSED\|FAILED\|ERROR`, `browser_started_at`, immutable `revision_id`/`csi_id`, `step_results`, bounded logs, video key/state/error/expiry/partial, runtime provenance |
| `ui_tests.last_run_status` CHECK allows only `PASSED, FAILED` | Must include `ERROR`; older late completions must not overwrite newer projections |
| Frontend `ChecksStudioPage` polls every 700 ms and switches on `COMPLETED`/`TIMEOUT` statuses; `videoUrl` is a raw URL | Same snapshot DTO for GET and SSE; protected `/executions/{id}/video` path; timeouts are `ERROR` with a code |
| No dispatch ledger; no durable idempotency (in-memory filter only) | Globally unique unpartitioned ledger with principal-scoped idempotency key/digest, attempt/admission identity, lease/deadlines, runner sequence, snapshot revision, manifest key |
| MSW is **not installed**: no `msw` dependency, no `mockServiceWorker.js`, `MswGate` is a pass-through, no `msw:init` script (CLAUDE.md and architecture §8.3 still assume MSW fixtures) | MSW fixtures generated from the frozen contract; `msw` reintroduced for the Studio routes |

Latest migration is `V11`. Story 10.4 owns `V12` (`ui_test_revisions`); this story's execution-history migration references that table, so it is versioned **after** V12 (FOC-01 in the manifest).

## Acceptance Criteria

### Frozen contract
- [x] **AC-1:** A committed contract set exists under `docs/specs/studio/`: `openapi.yaml` (public `/api/v1/studio` routes per architecture §8.3 **and** internal routes per §8.4, tagged `internal`), and `artifact.schema.json` (architecture §4.4 source artifact: `version`, `steps[{stepIndex, originalText, code}]`, exactly one entry per source line, index-aligned). Location confirmed by @po on 2026-09-10 (closes ADR-001 open item O-3).
- [x] **AC-2:** Test create/update request body is `{name, description, csiId (create only), environment, steps: string[], variables: [{name, kind: 'plain'|'secretRef', value?|secretId?}], configuration: {browser: 'chromium', viewport: {width, height}, timeoutSeconds, waitStrategy}, sourceRevision, configurationRevision}`. Clients never submit executable code; the server generates artifacts.
- [x] **AC-3:** The execution snapshot DTO (used by `GET /executions/{id}`, `GET /executions?testId=` items and the SSE `execution.snapshot` payload) contains: `executionId`, `testId`, `csiId`, `revisionId`, `status ∈ PENDING|RUNNING|PASSED|FAILED|ERROR`, `errorCode` (nullable; includes `TIMEOUT`, `DISPATCH_FAILED`, `DISPATCH_UNKNOWN`, `START_TIMEOUT`, `STALE`, `DISPATCH_DISABLED`), `acceptedAt`, `startedAt` (nullable), `endedAt` (nullable), `durationMs` (nullable, browser time only), `stepResults[]` with one entry per original step `{stepIndex, originalText, status ∈ PENDING|RUNNING|PASS|FAIL|SKIPPED, offsetMs|null, durationMs|null, message|null}`, `logs[]` (bounded) + `logsTruncated`, `video: {status ∈ PROCESSING|AVAILABLE|FAILED|UNAVAILABLE|EXPIRED, error|null, expiresAt|null, partial}`, `videoPath` (protected API path, never a storage key), `runtime: {playwright, chromium, validator, executor, image}`, `revision` (API snapshot revision, monotonic), `streamComplete`.
- [x] **AC-4:** Legacy adapters are specified in the contract and implemented server-side: `browser: 'chrome'` → `chromium` (other engines → `400 INVALID_CONFIGURATION`); legacy structured `TestIR` steps → ordered `originalText`; JSON-string `steps`/`variables` → typed fields; flattened viewport → `configuration.viewport`; legacy execution statuses `COMPLETED` → `PASSED`, `TIMEOUT` → `ERROR` + `errorCode=TIMEOUT`.
- [x] **AC-5:** Contract examples cover create/save/compile/confirm/execute/history, the legacy adapters, every terminal outcome and every evidence state. Skipped/unstarted step timings are `null` in the examples.

### Migrations (forward-only, after V12)
- [x] **AC-6:** `V13__studio_dispatch_ledger.sql` creates unpartitioned `studio_dispatch_ledger`: `execution_id UUID PRIMARY KEY`, `execution_accepted_at TIMESTAMPTZ NOT NULL` (history partition locator), `test_id`, `csi_id`, `principal`, `idempotency_key`, `request_digest`, `UNIQUE (principal, idempotency_key)`, `attempt_id UUID`, `admission_id UUID`, `runner_instance_id`, `state VARCHAR(20)` (provisional values `QUEUED|CLAIMED|DISPATCHING|ADMITTED|RUNNING|FINALIZING|DONE`; the CHECK constraint is added by 10.7 when the dispatcher state machine is final), `lease_owner`, `lease_expires_at`, `pending_deadline_at`, `start_deadline_at`, `run_deadline_at`, `last_runner_sequence BIGINT`, `snapshot_revision BIGINT`, `manifest_key TEXT`, timestamps. Partial indexes: `(state, lease_expires_at)` for queued work, `(state, start_deadline_at)`, `(state, run_deadline_at)`. **No foreign key** to the partitioned history table.
- [x] **AC-7:** `V14__studio_execution_history_v2.sql` alters `ui_test_executions` (all partitions): status CHECK → `PENDING|RUNNING|PASSED|FAILED|ERROR`; `ended_at` and `duration_ms` → nullable; add `browser_started_at TIMESTAMPTZ NULL`, `error_code VARCHAR(40)`, `revision_id UUID REFERENCES ui_test_revisions(id)`, `csi_id VARCHAR(20)`, `principal VARCHAR(255)`, `environment VARCHAR(50)`, `configuration_snapshot JSONB`, `step_results JSONB`, `logs JSONB`, `logs_truncated BOOLEAN DEFAULT false`, `video_key TEXT`, `video_status VARCHAR(20)` (CHECK on the five evidence states), `video_error TEXT`, `video_expires_at TIMESTAMPTZ`, `video_partial BOOLEAN`, `runtime_versions JSONB`, `snapshot_revision BIGINT DEFAULT 0`. `started_at` stays the partition key and is never rewritten; public `acceptedAt` maps to it. Existing `video_url` is retained for legacy rows and not written by new code.
- [x] **AC-8:** V14 widens `ui_tests.last_run_status` CHECK to `PASSED|FAILED|ERROR`. The service updates the last-run projection only when the finishing execution is newer by `(acceptedAt, executionId)` than the projected one.
- [x] **AC-9:** V14 backfills `ui_test_executions.csi_id` from `ui_tests.csi_id` where the parent exists and has a non-null CSI; rows that remain `csi_id IS NULL` are excluded from every user-facing query (quarantined) and counted in a migration log line, not exposed.
- [x] **AC-10:** V14 migrates `ui_tests.browser`: rows with `chrome` → `chromium`; any other legacy engine → `chromium` (these rows carry compile state `STALE` from V12 and therefore cannot execute until recompiled and confirmed); CHECK constraint → `browser IN ('chromium')`. The migration logs the count of converted non-`chrome` rows.
- [x] **AC-11:** Legacy history rows acquire no fabricated confirmation metadata: `revision_id` stays `NULL`, `runtime_versions` stays `NULL`, and the DTO exposes `revisionId: null` for them.

## Implementation Notes

- **FOC-01:** do not start V13/V14 until 10.4's V12 has merged or the two stories share one owner. V14's `revision_id` FK requires `ui_test_revisions`.
- Postgres allows a FK from a partitioned table to a regular table (`revision_id → ui_test_revisions`), but not the reverse; the ledger therefore carries `execution_accepted_at` as a locator instead of a FK.
- `ALTER TABLE ... DROP CONSTRAINT`/`ADD CONSTRAINT` on the partitioned parent propagates to partitions; verify against the `default` partition explicitly in `StudioMigrationIT`.
- Keep the internal-route section of `openapi.yaml` tagged so springdoc can exclude it from the public UI while the contract test still covers it.
- The frontend snapshot rendering will be reused behind a transport abstraction in 10.11; keep `stepResults`/`logs`/`video` field names stable from this story on.
- Recommended order: 10.1a first (contract + FE), then 10.1b once V12 is in.

## Dev Agent Record

### Decisions

- **Schema reconciliation (10.5 coordination).** `docs/specs/studio/artifact.schema.json` is the source of truth. `backend/src/main/resources/studio/artifact.schema.json` is a byte-identical copy so the runtime classpath keeps working, and `ArtifactSchemaDriftTest` compares the two byte for byte and fails the build on any divergence. A build-time Gradle copy was rejected: it would hide the divergence instead of reporting it, and the failure mode the coordination note is worried about is a silent edit to one side.
- **`PENDING` status defect.** `POST /tests/{id}/execute` has always written `PENDING`, which the V7 CHECK constraint rejected. V14 widens the vocabulary to `PENDING|RUNNING|PASSED|FAILED|ERROR` per architecture §8.2, which makes the existing write legal rather than papering over it. `StudioMigrationIT.theExecutionStatusVocabularyIsWidened` asserts `PENDING` now persists, and the acceptance path additionally writes the execution CSI, the principal and the ledger row so the accepted run is reachable and scoped. No live dispatch is enabled; 10.7 still owns that.
- **Partition-safe repository access.** `UITestExecution` now uses the real `(id, startedAt)` composite key, so a bare `findById(UUID)` no longer compiles. Single-execution reads resolve the partition locator through the ledger first. V14 backfills a locator row for every pre-existing execution that has a CSI, carrying nothing but the facts already on the row — principal, attempt, admission and lease stay null.
- **`logs` column.** AC-7 asks for `logs JSONB`, and a `logs TEXT` column already existed. V14 converts it in place, wrapping any legacy free text as a single `INFO` entry rather than dropping it.
- **Legacy adapters live at the controller boundary, normalization does not.** `LegacyStudioAdapter` restructures without judging, so the service layer can still reason about a draft carrying a no-longer-supported engine; `validateForWrite` rejects a non-`chromium` engine once, in the controller. This is why a legacy client posting `browser: "chrome"` still succeeds while `firefox` is a `400 INVALID_CONFIGURATION`.
- **[AUTO-DECISION]** AC-18 asks for two Spring contexts against one database. Booting a second `ChecksApplication` under the `test` profile could not be made to bind to the first context's database (the profile resolves its URL dynamically and the second instance kept starting its own), so the test instead exercises an independently constructed `StudioService` — no shared in-memory state — plus a direct assertion that the database itself refuses a second row for the same `(principal, idempotencyKey)`. Reason: that pair proves the property AC-18 is about (idempotency survives a replica that never saw the original request) without a flaky second boot. The contract and the unique constraint are unchanged.
- **[AUTO-DECISION]** `ajv` and `yaml` were added as exact-pinned frontend dev dependencies. Reason: AC-21 requires fixtures to be *validated* against `artifact.schema.json` and the OpenAPI component schemas; without a real validator and a YAML parser the test would only compare shapes it wrote itself.
- **[AUTO-DECISION]** `ConfigurationRevisionTest` no longer lists a browser change among the edits that advance `configurationRevision`. Reason: after AC-10 there is no legal browser change left to make — the column allows only `chromium`. The case was replaced by one asserting the request is rejected instead.

### Findings

- **10.4 AC-20 / `RevisionRetentionIT` activated and fails.** With V14 in place the `information_schema` assumption is satisfied and both test methods run. They fail in `seedTest()`, not on their assertions: the seed inserts `browser = 'chrome'` directly, which AC-10's `ck_ui_tests_browser` constraint now rejects. The revision-retention behaviour itself is untouched by this story. The fix is a one-word seed change in a file this story was instructed not to edit, so it is reported rather than applied.

### Verdict — FAIL

Twenty-one of twenty-two acceptance criteria are implemented and verified on this story's own
surface. The contract is frozen and internally consistent, the typed DTOs and the legacy adapters
do what AC-4 says, the composite key makes a bare `findById(UUID)` against the partitioned table
uncompilable, CSI scoping happens in the `WHERE` clause and therefore before paging, and the
frontend is typed against the document with MSW reinstated and real schema validation behind it.
The authorised one-word seed correction in `RevisionRetentionIT` was applied and 10.4's AC-20 now
genuinely closes: both methods pass on their revision-retention assertions, and the backend failure
count is back to exactly the 23 ED-02 baseline (380 tests, 23 failed, zero in `studio`).

One criterion is unmet, and it blocks deployment rather than merge-readiness in the abstract.

**AC-10 / ISSUE-001 (high).** `V14` section 6 runs
`UPDATE ui_tests SET browser = 'chromium' WHERE browser = 'chrome'` at line 191, but V1's inline
`ui_tests_browser_check` — `CHECK (browser IN ('chrome','firefox','safari','edge'))` — is not
dropped until line 217. The update violates the very constraint it exists to supersede and Flyway
aborts `V14` with SQLSTATE 23514. The backfill *is* correctly ordered before the **new**
`ck_ui_tests_browser`; it is not ordered after the **old** one.

This was reproduced, not inferred. A throwaway QA probe migrated a pristine `postgres:15-alpine`
to V12, seeded exactly one ordinary legacy draft (`browser 'chrome'`, registered CSI, no constraint
tampering) and then migrated toward V14: `flyway_schema_history` stops at 13. The probe was deleted
afterwards and the tree left clean.

Every existing test is blind to this because they all build the schema from scratch, so `ui_tests`
is empty when section 6 runs and both `UPDATE`s match zero rows — a CHECK cannot fire on zero rows.
10.4's `RevisionMigrationIT` is the one two-stage Flyway harness in the repo and it targets 12.
Because Flyway wraps a migration in one transaction, the abort rolls back sections 1–5 as well, so
AC-7, AC-9 and AC-11 never take effect on a real database either. Nothing is corrupted — the
rollback is clean and the database simply stays at V13.

The fix is to move the existing constraint-drop `DO` block (lines 203–220) above the two `UPDATE`s.
No other section has the same hazard: section 3's status updates only ever write `PASSED` and
`ERROR`, which the old V7 CHECK already permitted. Production code was not modified during this
review.
