## User Story

**As the** Checks Studio delivery team building compilation, dispatch, SSE and video on top of the existing prototype,
**I want** one frozen OpenAPI/JSON-schema contract for the Studio API and artifact, plus the execution schema migrations that carry immutable revision/CSI snapshots, durable dispatch identity and evidence state,
**so that** frontend, backend and runner stories can be built against the same typed shapes, and executions are recorded truthfully across API replicas, restarts and partition boundaries.

---

## Problem Statement

The prototype contract is untyped and inconsistent with architecture v2.1:

| Today | Required (architecture §8) |
|---|---|
| `UITestRequest` carries `steps` and `variables` as JSON **strings**, flattened `viewportWidth/Height`, free-text `browser` | `steps: string[]`, typed `variables` (`plain` \| `secretRef`), `configuration: {browser, viewport, timeoutSeconds, waitStrategy}`, `environment` |
| `ui_tests.browser` CHECK allows `chrome, firefox, safari, edge`; frontend `TestIR.browser` uses `'chrome'` | Canonical `chromium`; legacy `chrome` normalized; other engines rejected before execution |
| `ui_test_executions` (range-partitioned by `started_at` since V7, PK `(id, started_at)`) has `ended_at`/`duration_ms` **NOT NULL**, status `PASSED\|FAILED\|ERROR`, `video_url TEXT`, no revision/CSI snapshot, no step results | Nullable end/duration, status `PENDING\|RUNNING\|PASSED\|FAILED\|ERROR`, `browser_started_at`, immutable `revision_id`/`csi_id`, `step_results`, bounded logs, video key/state/error/expiry/partial, runtime provenance |
| `ui_tests.last_run_status` CHECK allows only `PASSED, FAILED` | Must include `ERROR`; older late completions must not overwrite newer projections |
| Frontend `ChecksStudioPage` polls every 700 ms and switches on `COMPLETED`/`TIMEOUT` statuses; `videoUrl` is a raw URL | Same snapshot DTO for GET and SSE; protected `/executions/{id}/video` path; timeouts are `ERROR` with a code |
| No dispatch ledger; no durable idempotency (in-memory filter only) | Globally unique unpartitioned ledger with principal-scoped idempotency key/digest, attempt/admission identity, lease/deadlines, runner sequence, snapshot revision, manifest key |
| MSW is **not installed**: no `msw` dependency, no `mockServiceWorker.js`, `MswGate` is a pass-through, no `msw:init` script (CLAUDE.md and architecture §8.3 still assume MSW fixtures) | MSW fixtures generated from the frozen contract; `msw` reintroduced for the Studio routes |

Latest migration is `V11`. Story 10.4 owns `V12` (`ui_test_revisions`); this story's execution-history migration references that table, so it is versioned **after** V12 (FOC-01 in the manifest).

## Acceptance Criteria

### Frozen contract
- [ ] **AC-1:** A committed contract set exists under `docs/specs/studio/`: `openapi.yaml` (public `/api/v1/studio` routes per architecture §8.3 **and** internal routes per §8.4, tagged `internal`), and `artifact.schema.json` (architecture §4.4 source artifact: `version`, `steps[{stepIndex, originalText, code}]`, exactly one entry per source line, index-aligned). Location confirmed by @po on 2026-09-10 (closes ADR-001 open item O-3).
- [ ] **AC-2:** Test create/update request body is `{name, description, csiId (create only), environment, steps: string[], variables: [{name, kind: 'plain'|'secretRef', value?|secretId?}], configuration: {browser: 'chromium', viewport: {width, height}, timeoutSeconds, waitStrategy}, sourceRevision, configurationRevision}`. Clients never submit executable code; the server generates artifacts.
- [ ] **AC-3:** The execution snapshot DTO (used by `GET /executions/{id}`, `GET /executions?testId=` items and the SSE `execution.snapshot` payload) contains: `executionId`, `testId`, `csiId`, `revisionId`, `status ∈ PENDING|RUNNING|PASSED|FAILED|ERROR`, `errorCode` (nullable; includes `TIMEOUT`, `DISPATCH_FAILED`, `DISPATCH_UNKNOWN`, `START_TIMEOUT`, `STALE`, `DISPATCH_DISABLED`), `acceptedAt`, `startedAt` (nullable), `endedAt` (nullable), `durationMs` (nullable, browser time only), `stepResults[]` with one entry per original step `{stepIndex, originalText, status ∈ PENDING|RUNNING|PASS|FAIL|SKIPPED, offsetMs|null, durationMs|null, message|null}`, `logs[]` (bounded) + `logsTruncated`, `video: {status ∈ PROCESSING|AVAILABLE|FAILED|UNAVAILABLE|EXPIRED, error|null, expiresAt|null, partial}`, `videoPath` (protected API path, never a storage key), `runtime: {playwright, chromium, validator, executor, image}`, `revision` (API snapshot revision, monotonic), `streamComplete`.
- [ ] **AC-4:** Legacy adapters are specified in the contract and implemented server-side: `browser: 'chrome'` → `chromium` (other engines → `400 INVALID_CONFIGURATION`); legacy structured `TestIR` steps → ordered `originalText`; JSON-string `steps`/`variables` → typed fields; flattened viewport → `configuration.viewport`; legacy execution statuses `COMPLETED` → `PASSED`, `TIMEOUT` → `ERROR` + `errorCode=TIMEOUT`.
- [ ] **AC-5:** Contract examples cover create/save/compile/confirm/execute/history, the legacy adapters, every terminal outcome and every evidence state. Skipped/unstarted step timings are `null` in the examples.

### Migrations (forward-only, after V12)
- [ ] **AC-6:** `V13__studio_dispatch_ledger.sql` creates unpartitioned `studio_dispatch_ledger`: `execution_id UUID PRIMARY KEY`, `execution_accepted_at TIMESTAMPTZ NOT NULL` (history partition locator), `test_id`, `csi_id`, `principal`, `idempotency_key`, `request_digest`, `UNIQUE (principal, idempotency_key)`, `attempt_id UUID`, `admission_id UUID`, `runner_instance_id`, `state VARCHAR(20)` (provisional values `QUEUED|CLAIMED|DISPATCHING|ADMITTED|RUNNING|FINALIZING|DONE`; the CHECK constraint is added by 10.7 when the dispatcher state machine is final), `lease_owner`, `lease_expires_at`, `pending_deadline_at`, `start_deadline_at`, `run_deadline_at`, `last_runner_sequence BIGINT`, `snapshot_revision BIGINT`, `manifest_key TEXT`, timestamps. Partial indexes: `(state, lease_expires_at)` for queued work, `(state, start_deadline_at)`, `(state, run_deadline_at)`. **No foreign key** to the partitioned history table.
- [ ] **AC-7:** `V14__studio_execution_history_v2.sql` alters `ui_test_executions` (all partitions): status CHECK → `PENDING|RUNNING|PASSED|FAILED|ERROR`; `ended_at` and `duration_ms` → nullable; add `browser_started_at TIMESTAMPTZ NULL`, `error_code VARCHAR(40)`, `revision_id UUID REFERENCES ui_test_revisions(id)`, `csi_id VARCHAR(20)`, `principal VARCHAR(255)`, `environment VARCHAR(50)`, `configuration_snapshot JSONB`, `step_results JSONB`, `logs JSONB`, `logs_truncated BOOLEAN DEFAULT false`, `video_key TEXT`, `video_status VARCHAR(20)` (CHECK on the five evidence states), `video_error TEXT`, `video_expires_at TIMESTAMPTZ`, `video_partial BOOLEAN`, `runtime_versions JSONB`, `snapshot_revision BIGINT DEFAULT 0`. `started_at` stays the partition key and is never rewritten; public `acceptedAt` maps to it. Existing `video_url` is retained for legacy rows and not written by new code.
- [ ] **AC-8:** V14 widens `ui_tests.last_run_status` CHECK to `PASSED|FAILED|ERROR`. The service updates the last-run projection only when the finishing execution is newer by `(acceptedAt, executionId)` than the projected one.
- [ ] **AC-9:** V14 backfills `ui_test_executions.csi_id` from `ui_tests.csi_id` where the parent exists and has a non-null CSI; rows that remain `csi_id IS NULL` are excluded from every user-facing query (quarantined) and counted in a migration log line, not exposed.
- [ ] **AC-10:** V14 migrates `ui_tests.browser`: rows with `chrome` → `chromium`; any other legacy engine → `chromium` (these rows carry compile state `STALE` from V12 and therefore cannot execute until recompiled and confirmed); CHECK constraint → `browser IN ('chromium')`. The migration logs the count of converted non-`chrome` rows.
- [ ] **AC-11:** Legacy history rows acquire no fabricated confirmation metadata: `revision_id` stays `NULL`, `runtime_versions` stays `NULL`, and the DTO exposes `revisionId: null` for them.

### Backend types and repositories
- [ ] **AC-12:** `UITestExecution` uses nullable `Instant endedAt`, `Instant browserStartedAt`, `Integer durationMs`; `UITestExecutionDto` is replaced by the AC-3 snapshot DTO. `UITestRequest`/`UITestDto` are replaced by the AC-2 typed shapes with the AC-4 adapters applied at the controller boundary.
- [ ] **AC-13:** `UITestExecutionRepository` exposes lookup/update by `(id, started_at)` and a ledger-backed `findByExecutionId(UUID)` that resolves the partition locator first; no code path issues `WHERE id = ?` alone against the partitioned table.
- [ ] **AC-14:** `GET /executions` accepts optional `testId`; both `GET /tests` and `GET /executions` filter by the caller's readable CSIs **before** pagination (using the execution's own `csi_id`, not the parent test's), even when no `csiId` filter is supplied. Authorization semantics beyond scoping (readers/owners) are 10.7.

### Frontend
- [ ] **AC-15:** `frontend/src/types/studio/studioTypes.ts` is replaced by types derived from `docs/specs/studio/openapi.yaml` (generated or hand-mirrored with a Vitest test asserting the example payloads validate against the schema). `studioApi.ts` uses the AC-2/AC-3 shapes; `TestIR` remains only inside a legacy adapter used for reading old drafts.
- [ ] **AC-16:** `msw` is added as an exact-pinned dev dependency; Studio handlers and fixtures live under `frontend/src/services/mocks/studio/` (the path CLAUDE.md documents, currently absent) and are wired through `MswGate` behind a `VITE_ENABLE_MSW` flag for standalone dev and Vitest. Handlers follow the real API shape for create/save/compile/confirm/execute/history/snapshot, all terminal outcomes and all evidence states; list handlers cannot return another CSI's tests or executions. **Decision (@po, 2026-09-10):** reintroduce MSW as architecture §8.3 specifies; the standalone Vite mode is the stakeholder-demo path and needs request-level mocking.

### Tests
- [ ] **AC-17:** `StudioMigrationIT` (Testcontainers-PostgreSQL): V12→V14 apply cleanly; real JPA insert/update succeeds on the historical (`2026_05`), current, future and `default` partitions; a run accepted on the last minute of a month and finished in the next month updates in place.
- [ ] **AC-18:** `StudioIdempotencyIT`: same `(principal, idempotencyKey, digest)` returns the same `executionId` across two API instances (two Spring contexts against one DB); same key with a different digest returns `409`.
- [ ] **AC-19:** `LastRunProjectionIT`: an older execution completing after a newer one does not overwrite `last_run_status`/`last_run_at`.
- [ ] **AC-20:** `StudioContractTest`: springdoc output for `/api/v1/studio/**` matches `docs/specs/studio/openapi.yaml` (diff-gated); snapshot GET and SSE example payloads deserialize into the same DTO class.
- [ ] **AC-21:** Frontend Vitest: MSW fixtures validate against `artifact.schema.json`/OpenAPI component schemas; a list fixture request scoped to CSI A never yields CSI B items.
- [ ] **AC-22:** JaCoCo ≥ 80% on modified backend classes; `./gradlew check` and `npm run type-check && npm run lint && npm test` green.

## Implementation Notes

- **FOC-01:** do not start V13/V14 until 10.4's V12 has merged or the two stories share one owner. V14's `revision_id` FK requires `ui_test_revisions`.
- Postgres allows a FK from a partitioned table to a regular table (`revision_id → ui_test_revisions`), but not the reverse; the ledger therefore carries `execution_accepted_at` as a locator instead of a FK.
- `ALTER TABLE ... DROP CONSTRAINT`/`ADD CONSTRAINT` on the partitioned parent propagates to partitions; verify against the `default` partition explicitly in `StudioMigrationIT`.
- Keep the internal-route section of `openapi.yaml` tagged so springdoc can exclude it from the public UI while the contract test still covers it.
- The frontend snapshot rendering will be reused behind a transport abstraction in 10.11; keep `stepResults`/`logs`/`video` field names stable from this story on.
- Recommended order: 10.1a first (contract + FE), then 10.1b once V12 is in.
