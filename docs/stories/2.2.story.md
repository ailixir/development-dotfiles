## User Story

**As a** put-checks user who monitors infrastructure at the network layer,
**I want** to create a check of type `TCP` that probes a host:port and reports SUCCESS (port open) or FAILURE (connection refused / timeout),
**so that** I can detect network-level outages (firewall rules, service down, DNS failure) without needing an HTTP endpoint.

---

## Acceptance Criteria

- [x] **AC-1:** `TcpConfiguration` record added to the sealed `CheckConfiguration` hierarchy: `record TcpConfiguration(String type, String host, int port, int timeoutMs)`. Default `timeoutMs = 5000`. `@JsonSubTypes` entry added for `"TCP"`.
- [x] **AC-2:** `CheckType.TCP` value added to the enum (was already present).
- [x] **AC-3:** `TcpCheckExecutor` implements `CheckExecutor`, registered for `CheckType.TCP`. Uses `java.net.Socket` with `socket.connect(new InetSocketAddress(host, port), timeoutMs)`. On success: `ExecutionOutcome.Success` with output `"Connected to host:port in Xms"`. On `ConnectException`/`SocketTimeoutException`: `ExecutionOutcome.Failure`.
- [x] **AC-4:** Transport errors (DNS resolution failure, `UnknownHostException`) produce `ExecutionOutcome.Failure` with descriptive error message, not a 500.
- [x] **AC-5:** Micrometer timer `checks_tcp_execute_seconds{host}` recorded per execution (same pattern as `HttpCheckExecutor`).
- [x] **AC-6:** `CheckExecutorDispatcher` auto-discovers `TcpCheckExecutor` via the existing `Map<CheckType, CheckExecutor>` wiring — no manual registration needed.
- [x] **AC-7:** Integration test `TcpCheckExecutorIT`: (a) TCP check against WireMock port → SUCCESS, (b) TCP check against `localhost:1` → FAILURE (connection refused), (c) TCP check with invalid host → FAILURE (DNS).
- [x] **AC-8:** `ExhaustivenessTest` already passes: `CheckType.TCP` covered by `@JsonSubTypes` after adding `TcpConfiguration` to sealed hierarchy.

## Implementation Notes
- **Socket lifecycle:** open → connect with timeout → close in finally. Use try-with-resources.
- **Host from config:** `TcpConfiguration.host()` may be a hostname or IP. `InetSocketAddress` resolves DNS.
- **Metrics tag:** use `host` tag (not `host:port`) to keep cardinality manageable. Port is in the check config.
