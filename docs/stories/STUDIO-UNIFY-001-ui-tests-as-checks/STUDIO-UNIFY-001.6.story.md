Sixth story of `STUDIO-UNIFY-001-ui-tests-as-checks`. The run path now works end to end on the real stack. What is left is what a person sees when learning does **not** go well (a failed learn names no step, marks nothing, and leaves no log or trace) plus four layout and wording defects of the replay path and the Run caption added by .5. It adds no feature. It adds exactly one backend read (the latest learning attempt per test; data that is already persisted), because a failed learn must leave a trace the user can see after leaving the editor. No code starts before @po moves this story to Ready.

## Story

**As a** Checks user whose UI test fails to learn, or who watches a replay start,
**I want** Studio to say which step it stopped at and what to try next, to show what it did in the Logs tab, and to show clean times, step numbers and layout,
**so that** I can fix the test myself instead of reading "learning budget" and guessing.

## Context

## Acceptance Criteria

Each AC is one finding of the re-check; the bracketed tag gives the finding id, the code facts and the decision that carries the default.

- **AC-01 (A failed learn names the step and a next step)** *[N1; explanation `steps[]`, `GuidedCompletion.tsx` L140-165; D1, D2]* Given a terminal guided session with outcome `FAILED` whose result `explanation` proves where it stopped (the first step, in `number` order, whose `completed` is `false`, provided at least one step of the explanation has an action; a step with `completed: true` is never named, even when it holds a `FAILED` action, because the projector counts an excluded drift attempt (`FAILED`, `TARGET_CHANGED`, attempt 0) inside a completed step), when the outcome shows, then the alert additionally states the step: "Studio stopped at step {N}" followed by the authored sentence when `planStepTexts` provides it (never otherwise), and one plain next-step sentence for the code: for `BUDGET_EXCEEDED` that Studio most likely could not find what step {N} describes and that the author can check the page or reword the step and press Run again; for `ASSERTION_FAILED` and `UNSUPPORTED_SURFACE` the same step statement with their existing sentence; for the unnamed failures the step statement only. The existing sentence and the `Nothing starts again on its own.` line stay. Given an explanation that proves nothing (no step has actions and every step reads `completed: false`, or all steps are `completed`), when the outcome shows, then no step is named and the existing text is unchanged. `LOGIN_REQUIRED`, `POLICY_DENIED`, `CANCELLED`, `EXPIRED` and `UNKNOWN_OUTCOME` views are unchanged.

Progress is on the Proof tab." and one line built from the latest poll's `counters`: how many times Studio looked at the page (`observations`) and how many actions it tried (`actions`), updated on each poll. - **AC-09 (Latest learning attempt read)** *[N2; backend; D9, D10, D11, D13, D14, D15; conventions in Context]* Given an authenticated caller, when it sends `GET /api/v1/studio/guided-sessions/latest?testId={uuid}[&testId={uuid}...]` (1 to 50 test ids, repeated parameter), then it answers `200` with `{schemaVersion: 3, attempts: [...]}` validated against the new closed schema `latest-attempts.schema.json` (`additionalProperties: false`), one attempt per requested test that has one, each `{testId, sessionId, state, startedAt, errorCode, explanation}` where: the attempt is the **caller's own** most recent session for that test whose `state` is terminal (`SUCCEEDED`, `PUBLICATION_CONFLICT`, `FAILED`, `UNKNOWN_OUTCOME`, `CANCELLED`, `EXPIRED`) and not pruned; `startedAt` is the session document's `createdAt`; `errorCode` is the session's `progress.errorCode` or `null` (the value the result publishes); `explanation` is `GuidedPublicPresentationProjector.explanation(session)` when `state` is `FAILED` and `null` otherwise.
