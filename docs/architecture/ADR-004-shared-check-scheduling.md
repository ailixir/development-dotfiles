# ADR-004: Shared scheduling for catalog checks and Studio tests

Date: 2026-10-05. Owner: Aria. Decision: architecture-first Option B, independently reviewed for STUDIO-SCHED-002.

The user's follow-up requires actual implementation reuse between HTTP/TCP/Splunk scheduling and Studio. The first Studio increment reused acceptance, dispatch and runner execution but separately implemented recurrence and its polling worker. [Architecture](../stories/STUDIO-SCHED-002/architecture.md) compares three approaches; [independent design review](../stories/STUDIO-SCHED-002/qa-design-review.md) accepts a neutral common coordinator, target worker and recurrence kernel.

`SchedulingCoordinator` owns one due-production heartbeat and submits each `ScheduledTarget` through the same `SchedulingTargetWorker` implementation. `CronDispatcher` is the ordinary target, retaining its existing proxied ShedLock, enabled check-type selection, concurrency permits, transactional cursor advancement and executor/result/retry path. `StudioScheduledTarget` calls the existing atomic Studio producer; accepted work continues through the existing ledger, dispatcher, runner admission, callbacks and recovery. The standalone Studio schedule poller is removed. Studio browser attempts cannot enter ordinary retries.

The common worker isolates each target with bounded execution and no overlapping pass. Cadence uses monotonic time and waits the configured interval after a completed pass; initial delays, feature flags and shutdown remain target-specific. This preserves ordinary completion-based delay and intentionally aligns Studio with that approach, replacing its prior enqueue-callback timing quirk. Nominal cron times, fixed grace, and durable occurrence identity remain unchanged. Heartbeat resolution clamps to the shortest registered target interval, including a disabled target that may later be enabled, preserving existing subsecond polling settings.

`CronRecurrence` owns actual normalization, parsing, zone resolution and next-slot calculation. Catalog checks preserve their existing five-field adaptation, macros, nonzero seconds, accepted ZoneId forms, two-sample interval validation, nullable exhaustion, stored-due advancement and native Spring overlap sequence. Studio explicitly selects canonical minute grammar, UTC/IANA regions and the earlier overlap offset. Report recurrence can reuse these primitives while retaining its existing custom six-field/macro validation without five-field adaptation and short timezone aliases. Shared code does not silently impose Studio policy on other checks.

The coordinator remains available independently of the ordinary dispatcher flag. Its automatic role is `!api | worker`, preserving standalone development/test behavior; the Studio target independently requires `worker | (local & !api)` and its default-off flag. API-only processes do not acquire an automatic due-production owner. Existing browser execution dispatch/recovery timers remain responsible for accepted work.

Public APIs, DTOs, source artifact/runner contracts and storage are unchanged. No catalog row is fabricated for a saved Studio test. The neutral core imports no Studio classes; adapters depend on the shared scheduling port and retain domain-owned transaction and execution safety. [Compatibility evidence](../stories/STUDIO-SCHED-002/) must cover mixed HTTP/TCP/Splunk/Studio dispatch, flags, roles, locks, failure isolation, cadence, recurrence and existing runner/recovery behavior.

Production identity, live grant/policy attribution, capacity/pilot and restore/retention release gates from ADR-003 remain open. Sharing infrastructure does not certify those integrations.
