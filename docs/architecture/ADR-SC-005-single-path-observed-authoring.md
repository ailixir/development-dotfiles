## Decision

UI Studio is unreleased. It ships **one** authoring path, production-ready end to end, with no legacy path, no compatibility layer and no versioned fallback.

**D-A — Observed/guided is the only authoring path; compile-to-READY is removed entirely.** The author writes plain English and presses Run. The first Run learns while acting against sanitized observations of the live page (accessibility/semantic nodes, bounded DOM neighbourhood, never raw HTML, password controls withheld), publishes the exact exercised plan, and later Runs replay it model-free. The compile pipeline (`studio/compile/**`), the artifact-1 TypeScript engine in the runner (`validator/{ast,arguments,language,references,referencePolicy,schema}.ts`, `executor/{operations,executor}.ts`, `run/playwrightAdapter.ts`), the runner routes `/v1/validate` and `/v1/runs`, the public routes `compile` and `confirm-compile`, the compile UI (`components/studio/review/**`, `CodeTab`, `inference/**`, `features/studio/authoring/**`) and the compile pins (`studio.runtime.pin.*`) are deleted. Compile concepts survive only inside the observed path: pre-browser validation (`GuidedProposalValidator`, `/v2/validate-observed`), bounded schema repair, `CredentialPatternScreen` (already wired in `GuidedSourceClassifier:24-29`), and the shared gateway pieces, which move out of `compile/` into a neutral `studio/gateway` package: `GenAiGatewayTransport`, `StudioGatewayConfig`/`Properties`, `BudgetedAuthTransport`, `BoundedCredentialProvider`, `GatewayAudit*`, `ErrorScrubber`, `FailureClassifier`, `PayloadSerializer`, `Provenance` (≈1,580 LOC, panel dev). `compile/validator/StudioRunnerProperties` moves to the dispatch/runner client package.

> **Note 2026-10-17 (@architect, append-only):** "accessibility/semantic nodes" above is how the runner observes target pages. It is product functionality and is **not** affected by [ADR-SC-006](ADR-SC-006-accessibility-scope-functional-only.md) (accessibility scope: functional must-haves only, no WCAG target, user decision 2026-10-17).

**D-B — Migrations re-baselined (pre-release exception to `ARCH.md:123`).** Checks core V1–V11 stay byte-identical. Studio V12–V33 and `backend/db/cutover/V19` are re-authored as seven area migrations, absorbing the planned V34: `V12__tests_revisions`, `V13__executions_ledger`, `V14__guided_sessions`, `V15__publication`, `V16__scheduling`, `V17__secret_use_audit`, `V18__drop_plaintext_secrets` (@data-engineer option A; today's V25 becomes V18). Compile-only state is not carried: `ui_tests` compile columns (V12/V16/V18/V21), `ui_test_revisions` compile identity (V18/V21/V22–V24/V29), `ui_test_step_identities`, `ui_test_compile_requests`, `ui_test_compile_outcomes` (V18), and the V19 cutover. Evidence that no shared environment has ever been deployed: `helm-chart/put-checks/values.yaml:96`, `docs/epics/EPIC-10-EXECUTION.yaml:66-67`, `staging-acceptance-register.md:250`, `docs/runbooks/studio-inference-rollout.md:102` (panel devops). **Residual:** only the user or Platform/SRE can confirm that nothing was ever deployed from an internal remote; this ADR records that confirmation as owed, not obtained. Consequences: dev databases are recreated; the 17 integration tests pinned to Flyway targets are rewritten; Hibernate entities change in the same change.

**D-C — Pilot gate: real-model guided benchmark.** Before any human pilot: ≥ 20 workflows (the 13 compile benchmark cases ported, plus login and multi-step dataflow) × 3 real-model repetitions on the deployed stack with pinned model/prompt/runtime versions; ≥ 90% end-to-end completion without clarification on unambiguous cases; **zero false passes and zero secret/PII leaks are hard gates**; p50/p95 latency, model calls, tokens and configured-provider cost per run are published with denominators. The corpus includes at least two incremental cases (edit step 4 of 10; insert a step) proving that exactly steps k…n were re-learned and 1…k-1 produced zero model calls (D-D). No real-model evidence for guided exists today (`GuidedProviderEvaluationTest.java:58-84` skips `UNAVAILABLE_NOT_RUN`; OBS-006 `review-record.json:259`).

**D-D — GA supports incremental re-learn from the first changed step** (user correction 2026-10-09, binding: "in case we have a 10-step test and we change step 4, only step 4 and beyond (5..10) should be regenerated"). The STUDIO-INC-001 incremental requirement carries over to the observed path. Each published learned plan is an immutable per-step snapshot (revision) with per-step hashes. On edit, the first changed step **k** is the first index whose authored text, referenced variable/secret declarations or step-level configuration differs from the published revision; inserts, deletes and reorders count at the first affected index; multiple edits take the earliest. The next Run replays steps 1…k-1 from the published plan model-free (fresh values recaptured, same drift refusals), switches to learning at step k through the end, and publishes a new revision = reused prefix 1…k-1 + newly learned k…n. Steps after k are **always** re-learned even when their text is unchanged (page state and dataflow may differ). The UX statement is: **"Learn again" re-learns from the first changed or drifted step, not the whole test.** Rules: no edit since the last publish → plain replay; first ever Run → full learn; a test-level configuration change (environment, approved origins, viewport, timeout, browser) → k = 1. Defaults stated by the user and adopted: bindings produced in 1…k-1 are recaptured during prefix replay and are available to k…n planning under their existing server-issued IDs; SOURCE_PLAN for the suffix sees the full checklist but plans only k…n; if prefix replay drifts at step j < k the session continues in learning mode from j and the user is told "steps j… were re-learned because the page changed". **Architect conditions on that last default (flagged, not a disagreement with intent):** (1) only target/observation drift (`TARGET_DRIFT`, locator ambiguity, stale generation) may switch to learning; an assertion `FAIL` or `POLICY_REFUSED` in the prefix stops the run, because re-interpreting a failing check or a refused action is not what the author asked for; (2) the switch point j is recorded in the receipt and the published revision marks steps j…k-1 as re-learned, not reused; (3) prefix actions already dispatched are never repeated (at-most-once stands); (4) steps j…k-1 charge the same session model budget. Implementation is **STUDIO-OBS-015, in the GA wave**; see the placement map for the contract change.

## Panel evidence (2026-10-09)

1. **Architect.** The compile benchmark (`docs/stories/UI-STUDIO-VALIDATION-20261004/benchmark/report.md`) is NEEDS_WORK and its unsolved class is structural (C07 scored 0 under every config: `searchbox` guessed for a `combobox`). Observed proposals choose from observed nodes and the runner refuses dispatch unless the durable locator resolves to the same element — addressed by construction, accuracy unmeasured. Runtime dataflow exists only on observed. Replay is model-free. Cost envelope: 600 s / 100 proposals / 128k+32k tokens per session; 60 s and 4096 output tokens per call (`GuidedSessionProperties`, `GuidedTranslationProperties`). Operational debt: no guided Dockerfile CMD or Helm template; `mtls-required` defaults false and fails closed; `@Profile("!worker")` on `ObservedReplayConfiguration`/`GuidedPublicationConfiguration` leaves worker pods without the observed verifier (`ExecutionReadinessService.java:124-128,264-268`; `StudioDispatcher.java:79,277,388`).
2. **QA (ran on `d954a21c5`).** Backend guided: 26 classes / 482 tests / 0 failures / 1 skip (`GuidedProviderEvaluationTest`, no env), 8 m 19 s. Runner guided/observed: 13 files / 318 pass; real-Chromium guided/observed fixtures 7 files / 152 pass; contract checker PASS; SDC preflight 32/32. Proven in controlled joined integration (real backend + PostgreSQL + guided worker + Chromium): observe → translate (controlled provider) → act → clarify → publish → model-free replay ×2 with video `AVAILABLE` and a 206 range read (`GuidedPublicationReplayIT:680-907`). **Not proven:** any real LLM on guided; enterprise pages (SSO, shadow DOM, iframes, virtualised lists); worker-profile dispatch (no test); deployability; scheduling; login; UI; public-HTTP mid-step cancel of a live guided browser. `translation.enabled` has no default. Sleep-polled ITs of 54–126 s are flake exposure.
3. **Security.** Verified bounds: admitted obligations, author-bound navigate, values never through the model, targets re-acquired before dispatch, password rule. Residuals: **HIGH** un-requested side-effecting clicks — `targetIntent` is model-chosen and the validator checks structure, not correspondence to authored words; MEDIUM same-origin exfiltration; MEDIUM clarification labels are page-derived. LLM boundary: control names/headings/links exported under `allowStructuralDiscovery` can carry PII; the read/discovery policy is one worker-mounted file per deployment (`guidedMain.ts:18-20`) with no owner, approval or audit; the DB persists sanitized observations (`studio_guided_sessions.progress`) and model output (`studio_guided_model_attempts.safe_result`); gateway retention is unknown. Removing the compile path removes the `/v1` goto-anything executor (net SSRF reduction).
4. **UX.** The guided worker records **no video** (grep `video` in `studio-runner/src/guided` → 0; the runbook defers the first guided recording) — a product-thesis gap. The start command has no from-step parameter. First-Run latency is minutes (p95 18 s per call). OBS-008 should split into transport/states/login, references/capability, and compile-UI removal + vocabulary; the full state model with copy is in the UX report handed to @sm.
5. **Dev.** Code health C+. Compile removal ≈ 55–60k lines (~30k JSON fixtures); guided v1 collapse ≈ 19k lines plus 36 ITs ported. Shared gateway ≈ 1,580 LOC must leave `compile/`. Duplicated families to fold: `GuidedRunnerClient`/`ObservedValidationClient` into the dispatch client; `GuidedPublicationAuthorization` into `DispatchAuthorization`; guided worker into the main runner. `GuidedSessionService.claim()` is 606 lines, `checkCommand` 365; runner guided TypeScript is minified-style (lines to 792 chars); 11.3k generated lines are checked in beside their generator; `GuidedSessionReaper`/`GuidedTranslationCoordinator` are `@Scheduled` with no profile gate (inferred: run on every API replica).
6. **Data engineer.** Option A as in D-B. `ui_tests`/`ui_test_executions` are core (V1) and stay. V25 drops the core `secrets` table from inside the Studio range and becomes V18.
7. **DevOps.** No shared environment ever deployed; no CI; personal remote; no external contract consumers (ROD 9.6 Draft targets core APIs).

## Consequences

**Architecture (one path).** MFE `Run` → `GET /tests/{id}` readiness → `POST guided-sessions` (learn) or `POST /tests/{id}/execute` (replay). Learn: SOURCE_PLAN → materialize inputs (`var`/`secretRef`, no values) → assign worker → per action: observe → NEXT_ACTION → validate → prepare/pin → admit → dispatch once → outcome; one clarification on ambiguity; `secretRef` fills resolve from Vault at dispatch into the unique password control and are erased; FINALIZING → client finalize → exact plan → pure validation → Core authorization → revision (`GUIDED_RUN`) + receipt. Replay: acceptance → readiness (observed verifier) → ledger → `/v2/runs` → recorded child + observed adapter, zero gateway calls; drift stops at step N, and "Learn again" starts a mixed-mode session that replays 1…N-1 and learns from N. Incremental re-learn (D-D): `NEEDS_RELEARN{firstChangedStepId: k}` → Run starts a mixed-mode guided session with `baseRevisionId` → `REPLAYING_PREFIX` (observed adapter, model-free, bindings recaptured) → learning from k → publication merges reused prefix snapshots with newly learned steps. Evidence: webm + manifest to Sonic, step offsets for seek, SSE snapshots — **for the first Run too** (STUDIO-OBS-013; today absent).

**Removed / moved / kept** — the architect's keep/remove table (backend, runner, frontend, contracts, migrations, config, docs) is binding; summary: remove compile pipeline and UI, artifact-1 engine, `/v1/*` runner routes, compile public routes, `studio.compile.**`, `studio.authoring.v2-enabled`, `studio.runtime.pin`, guided v1/v2 contract generations and `observed-1`, dual `/internal/v1|v2` mount (`GuidedInternalController.java:17-20`), account-provider machinery, T-INC deferrals (`InferenceStudio`, `compile/incremental`, V2-engine methods, `EvidenceReference` DTO, V19 cutover). Keep readiness/acceptance/dispatch/ledger/admission, secrets, scheduling, evidence, SSE, `RunControl`/`useRunGate` (re-pointed), evidence/seek, lists, scheduling UI, `SecretInput`.

**Contracts and pins.** `contracts/v3` only; one public OpenAPI; one `BASE_SHA256` over the whole public document (`studio-runner/test/run/confinement.test.ts`); `StudioContractTest` op-count over surviving operations; `tools/check-studio-observed-contracts.cjs` reads v3 only; `tools/build-studio-observed-schemas.cjs` regenerates runner/backend bundles from v3 with a CI check that regeneration is byte-identical; `GuidedSessionIT`, `GuidedHttpSecurityIT`, `GuidedBridgeIntegrationTest` ported to v3; `NoRuntimeLlmTest` keeps the authoring-only gateway allowance with the compile edge deleted; `DeReadyCarryForwardTest` asserts zero guided calls through replay.

**Security work becomes stories.** P0 (STUDIO-OBS-014 unless external): compliance approval of page-metadata/origin export and retention of sanitized observations and model output (external approval, recorded as a release gate in OBS-010); per-application read/discovery policy as a governed object (CSI-owner owned, Security-approved, versioned, audited) replacing the single mounted file; SEC-4 provisioning (OBS-009). **Operations.** One runner image/Deployment with a guided mode; mTLS chain provisioned (G-1); backend→runner hop TLS with client certificate (G-2); `@Scheduled` guided beans profile-gated; dumps disabled; Vault least privilege; observed schedules lifted behind G-3 (OBS-009). Dev databases recreated after D-B; runbook row (OBS-010).

**Tests.** Compile suites (383 `@Test` in `studio/compile`, 60 files) and artifact-1 runner suites are deleted by name, counted per the 10.51 rule; v1 guided ITs are ported, not dropped; the benchmark harness becomes a repository artifact, not a scratchpad.

## Alternatives

Keep both paths (GA plan D-1): rejected — doubles the surface to test, secure and operate; the compile path cannot ground targets or carry runtime values, and its measured quality is NEEDS_WORK. Compile-only GA: rejected for the same capability reasons and because the user invested in observed authoring as the product. Model on every run: rejected by the consensus plan (cost, non-reproducibility, schedules). Whole-test re-learn only at GA: rejected by the user (D-D); the hybrid prefix-replay session and publication merge that the publication design lacks are built in STUDIO-OBS-015, reusing STUDIO-INC-001's stable step identities and per-step hashing while INC-001 itself stays superseded as a compile-path specification.
