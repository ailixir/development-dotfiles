## 3. Exact source selection and slot semantics

A bounded `SOURCE_PLAN` covers the full checklist before the first application action. Its closed response carries source references, semantic information needs and per-step obligations. A source reference is the existing v2 union: `sourceSpan` with source revision/step/startUtf16/endUtf16/kind/intendedSlot, or authorized `configuration` reference. It contains neither proposed value bytes nor input IDs. The service validates, canonicalizes and deduplicates the references before `sessions.materialize`; OBS-004 slices exact bytes and issues IDs. Reject split surrogates, out-of-bounds/empty ranges, unsupported transformations/concatenation/decoding, oversized values and unapproved destinations. Whitespace and Unicode are not silently normalized.

An obligation carries `targetIntent` (the bare target label) and `scopeIntent` (a closed qualifier, or null). When the author's step names the region that contains the target ("Click Open in Primary workspace"), the model returns `targetIntent: Open` and `scopeIntent: Primary workspace`. The backend accepts `scopeIntent` only if it occurs, as a whole normalized phrase, in that obligation's authored step text, only for node-target operations, and never when the same phrase is inside `targetIntent`. `scopeIntent` names the accessible name of the nearest enclosing `main`, `region` or `navigation` landmark of the target (the observation's `regionId`). It is a correspondence rule, not a locator and not permission to act. Decision: user, round 057.

| Slot | Independent enforcement, regardless of model confidence |
|---|---|
| `navigate.destination` | `kind=destination`; same source step; exact source/configuration provenance; URL without userinfo; canonical HTTP(S) origin in frozen scope; initialBlank permits only first authored navigation. |
| `fill.value` | `kind=nonsecretText`; same source step; actual supported editable nonsecret target and policy; immutable input ID or successful earlier binding. |
| `selectOption.value` | `kind=nonsecretText`; same source step; supported current control/option correspondence; no generated option value. |
| `assert.expected` | `kind=nonsecretText`; same source step; supported assertion type/polarity and evidenced target; actual assertion outcome required. |

These checks establish provenance, slot compatibility and bounded authority. They cannot establish that one valid span is the intended literal when two plausible spans exist. The semantic resolver compares source-plan obligations, current request and accepted clarification meaning; conflicting/ambiguous associations cause a focused question. There is no confidence threshold that bypasses these rules. Frozen-corpus tests independently specify expected span, target, operation and assertion; a model's self-agreement is not the test oracle.

Freeze all needed authored inputs before sending runner context. Repeated materialization recovers the stored table via idempotency, never allocates new IDs. Later action proposals receive only input ID/kind/source-step/slot and safe provenance metadata, plus approved authored source text; they do not receive the private table values. Missing literal provenance after browser effects cannot mutate the table: stop and require a newly prepared immutable session, never hidden navigation/replay. Pending runtime information needs remain cumulative and can be refined through the real binding allocator before their source state is left.

### Obligation identity prevents a second admission for the same work

OBS-004's at-most-once dispatch guarantee applies to a durable admission. OBS-005 must not turn a repeated model proposal into a fresh admission or ordinal for an already dispatched/fulfilled obligation. When accepting a source-associated step plan, the server allocates stable obligation IDs and occurrence identities with required operation/target intent, source/reference association and completion condition. Model proposals use those supplied IDs; the model cannot allocate new IDs, reset their state or disguise a repeated action with another proposal ID. Persist accepted obligations independently of model attempt IDs and observation generations.

Before `prepareAndAdmit`, validate that the referenced obligation remains permitted/unfulfilled and that the proposed operation, current target correspondence and exact input/binding/argument meaning match its accepted definition. Reserve its coordinate, canonical proposal digest and deterministic admission idempotency key in the translation store under the session/source/translation lock order, then release locks before runner preparation. Bind the actual admission to that obligation atomically inside the existing admission transaction through the coordinated `GuidedSessionService` integration; use server-private persisted state keyed by the admission idempotency key. No OBS-004 action/runner wire field changes are needed. Changed operation/reference meaning cannot reuse the reserved association. Database uniqueness and single-assignment guards prevent concurrent callers from allocating another admission for the same obligation. A failed pre-admission preparation may retry only through the same reserved obligation/coordinate with no existing admission; it cannot erase a dispatched or successful association.

On a repeated NEXT_ACTION, restart or lost coordinator response, inspect the persisted obligation association and recover the existing admission/current ledger outcome. A successful obligation is already fulfilled; a dispatching/uncertain obligation stops or awaits the existing outcome and never generates another action. Repeating `prepareAndAdmit` with its original persisted key/proposal may recover a missing response to the committed admission; do not substitute a new key or ordinal. Completed-work recovery is attempted before asking for another model proposal, but a later model response repeating the business action is still rejected/recovered under the same rule.

Replanning may refine unresolved interpretation and add a genuinely missing required private producer read before leaving its source state.
