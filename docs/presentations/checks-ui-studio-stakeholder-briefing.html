Costs

One-off scripts

Costs

Costs

Code required

Costs

The product

From checklist to reality

One screen separates what you asked for, what the system will do, and the proof that it did it. Studio is the flagship of Checks: other check types query a system to prove it is healthy; Studio uses it the way a customer would, on camera.

User journey

Five steps from a written checklist to an investigated failure

  1. Write

    Priya types numbered steps in plain English, referencing variables and vaulted secrets by name. Pasted passwords are refused.

  2. Press Run

    Run saves the steps and, when needed, the internal AI turns them into browser code. Pressing Run is the go-ahead; there’s no separate approval.

  3. Watch it run

    A real, isolated browser runs the saved version. Step status and logs arrive live; closing the tab doesn’t restart or cancel it.

  4. Review proof

    Pass, fail and not-attempted steps show next to the video. The outcome and the video’s availability are reported separately.

  5. Investigate

    Clicking step 3 jumps the video to the moment it began, so the failure can be watched rather than guessed at.

Each run records the exact version it used. Later runs reuse it until the steps, run settings or platform version change.

How English becomes code

The AI writes the code, a safety check guards it, and the exact version is locked before it runs.

Your own words

No fixed phrasing. One sentence can become several browser actions.

Checked every time

The locked code is checked again before every run, right before the browser starts.

Not an AI call per run

The AI runs only when the steps, run settings or platform version change. Other runs reuse the locked version.

The generated code appears on the Code tab after the first successful run. The AI only ever sees a secret’s name, never its value. Example is illustrative.

How Studio learns

For every step, Studio looks at the page, decides, tries it and proves it.

The authorStudio

A step is only kept once it has passed on its own. Later runs replay it without the AI model.

MVP (V1) scope

What V1 delivers

CapabilityIn V1
AuthoringPlain-English checklists per CSI; variables and vaulted secrets referenced by name only.
TranslationPressing Run has the internal AI turn the steps into browser code. A safety check blocks anything not allowed; if the AI can’t fix it in two more tries, the test doesn’t run.
ExecutionOn-demand, one Chromium browser, one page per run. Pass, fail and not-attempted steps. Uncertain attempts are never automatically replayed.
Live progressStep and log updates as the run happens, with reconnection. Watching a run never controls it.
Video proofPrivate recording, seek by step, authorised download, 30-day expiry. Missing or partial video is shown honestly, separate from the result.
Access & secretsEvery action, including history and video, authorised by CSI. Secret values exist only briefly while a run needs them.

Scheduling is designed but not built in V1. It will reuse the platform’s existing scheduler once on-demand runs have earned trust.

Beyond the MVP

What follows V1, and what V1 deliberately leaves out

Follows V1

Planned after V1

  • Scheduled runs through the platform’s existing scheduler
  • More browser-runner capacity, sized from what MVP v1 measures
  • A remote relay server, to run tests from specific locations or from outside the network
Not in V1

Out of scope for the MVP

  • Browsers other than Chromium; more than 1–2 simultaneous runs per pod
  • Popups, new tabs or windows, and content inside iframes. Moving across pages in one tab works.
  • Screenshots, live video, and public or non-expiring video links
  • Automated fixes for failing checks
  • Python export (retired)
