The problem

Operational health checks are scattered across tools, wikis and scripts

“Every team writes their own bash scripts. When I'm on-call for another team's app, I have no idea where their 'health check' script is.”
David, SRE / DevOps Engineer (PRD persona)

Fragmented tools

ITRS, Grafana, Splunk and AppDynamics are used independently, with no unified strategy.

No single source of truth

Check definitions and statuses are scattered across platforms and team wikis.

Knowledge silos

Monitoring expertise stays trapped inside one team.

Manual incidents

During an incident, engineers correlate alerts from different systems by hand.

User journey

Five steps from a new check to an investigated failure

D

David

SRE / DevOps Engineer

  1. Define

    Builds a Splunk check for the trade pipeline and files it under its CSI.

  2. Schedule

    Runs it every 5 minutes.

  3. Watch

    Sees the CSI’s health on the dashboard.

  4. Share

    Adds it to the daily status email.

  5. Investigate

    Opens the error and jumps to the underlying system.

Architecture

Checks plugs into EAMP and the tools around it

  1. EAMP sign-inHandles COIN
  2. EAMP shell + Checks screensWhat people see
  3. ChecksAPI, worker, database
  4. Studio runnerIsolated browser, video
  5. Sonic · S3 object storagePrivate store for Studio videos and result files
  6. R2D2Citi AI gateway, used while writing a test
  7. VaultSecret values, fetched at run time
  8. Email relayReports
  9. DailyChecksInterim bridge to the monitoring tools
Built for Checks Existing enterprise service

EAMP sign-in identifies people, access follows CSI ownership, secrets stay in Vault, videos stay private in Sonic, and R2D2 is used only while authoring.

Scope

What each milestone delivers, and what we leave out

Scope by milestone
  1. Oct 2026

    Core capabilities

    Checks per CSI (HTTP, TCP, Splunk logs and metrics, ITRS, manual), run on demand or scheduled, CSI dashboards, email reports, role-based access (RBAC) by user role and CSI ownership.

  2. Nov 2026

    UI Studio alpha

    Write plain-English steps, watch a real browser run them, keep the video as proof.

  3. Dec–Feb

    Pilot

    Early adopters use it, feedback shapes it, remaining integrations reach parity via DailyChecks.

  4. Mar 2027

    GA

    Pilot feedback applied, integrations at full parity, ready for general release.

Left out
  • Automated fixes for failures
  • ML anomaly detection
  • PDF or CSV report exports
