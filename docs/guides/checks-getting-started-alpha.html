Getting Started with Checks

October 2026 · About 15 minutes

In about 15 minutes you will create two health checks for your CSI, put them in an emailed Report, and see their status on Home. Checks is one place to define, run, and track standard health checks, organized by CSI. It works alongside ITRS and Splunk.

Before you start

You need three things in place. Without them you will get stuck on the first screen.

  • You can sign in to Checks with SSO.
  • You own, or have write access to, at least one CSI. The CSI picker only lists CSIs you own, so if it is empty, ask your alpha contact.
  • You have a health endpoint (for example https://myapp.example.citi.com/health) and a host:port that Checks can reach. Your own service's health URL is ideal.

Four terms you will see:

TermWhat it means here
CSICiti System Inventory ID. Every check belongs to one, and Home and Reports are organized by it.
CheckA test that runs on a schedule or on demand. This guide uses the two basic types: HTTP/HTTPS and TCP Port.
Check statusPassing (green), Warning (amber), Failing (red), or Pending (grey, meaning it has not run yet).
ReportA scheduled email that summarizes the status of checks you choose, sent to the recipients you list.

Step 1: Create an HTTP check 5 min

This step creates a check that calls your health URL every hour and expects HTTP 200.

  1. In the sidebar, click Checks. Then click Create Check at the top right.
    • Ignore the Splunk prototype banner at the top of the page. It is not part of this tutorial.
  2. What are you monitoring? Under Basic, pick HTTP/HTTPS Check.
  3. Fill in Basic Information:
    • Check Name, for example MyApp – Health endpoint
    • CSI Entity: start typing your CSI ID or name and pick it from the list.
    • Environment: this defaults to Production. Change it if your endpoint is UAT or Staging.
    • Description and Add Tags are optional. Press Enter after each tag.
    • Click Next.
  4. Check Configuration:
    • Endpoint URL: the full URL, including https://. Without it, Next stays greyed out.
    • Leave HTTP Method as GET, Expected Status Code as 200 and Timeout as 30 s, unless your endpoint needs something else.
    • Click Test Connection. You should see Connected followed by the response time in ms. If it fails, fix the URL before you go on.
    • Click Next.
  5. Scheduling Configuration: keep Schedule enabled and Frequency on Hourly. Click Next.
  6. Review: check the summary, then click Create Check.

You'll see Check created successfully, and you land on the check's details page. Its status is Pending until it runs for the first time.

Step 2: Add a TCP port check 3 min

This step checks that a port, such as a database or message broker, accepts connections.

  1. Go back to Checks and click Create Check.
  2. Pick TCP Port Check. Fill in Basic Information with the same CSI as in Step 1, then click Next.
  3. Fill in Host/IP Address and Port, for example mydb.example.citi.com and 5432. Leave Connection Timeout at its default.
  4. Click Test Connection, then Next → keep Hourly → Next → Create Check.

Step 3: Run both checks now 1 min

Run each check by hand once, so you don't have to wait up to an hour for its first status.

  1. Open each check's details page from the Checks list.
  2. Click Execute. After a moment you'll see Executed: PASSING in N ms, or a failure with the reason.
  3. The run appears in the check's history, and the status chip turns green, amber or red.

New checks start as Pending, and Home doesn't count Pending checks. Running them now is what makes them show up on Home in Step 5.

Step 4: Create a Report 5 min

This step creates a daily email that summarizes both checks. You'll send one test to yourself first.

  1. In the sidebar, click Reports, then Create Report.
  2. Under Details, enter a Report Name, for example MyApp – Daily health. Keep Template set to Standard.
  3. Under Sections, click + Manual:
    • Give the section a Section Title, for example Endpoints.
    • In Search checks to add…, type your check name and click Add. Do the same for the second check. Both appear as chips.
  4. Under Schedule, keep the default of Daily at 18:00 (America/New_York), or pick your own time.
  5. On the right, under Delivery, add yourself in Recipients (press Enter after the address). The Subject defaults to the report name.
  6. Click Save Report (Cmd/Ctrl+S). Once it shows All changes saved, the Live Preview fills in with your two checks.
  7. Click Test → Send Test and check your inbox.

Saving keeps you on the builder. Go back to Reports to see your report in the list. Open it to find Send now, Pause and a Recent Sends history.

Step 5: See your status on Home 1 min

Home shows one CSI at a time, so pick yours first.

  1. Click Home in the sidebar. Until you choose a CSI, it says Select a CSI to view data.
  2. In the search box in the header (Select a CSI to search…), pick your CSI. Click Pin so it stays under My CSIs next time.
  3. Read the five panels:
PanelWhat to look for
Overall StatusHEALTHY (green), WARNING (amber) or CRITICAL (red), with counts of Passing, Degraded, Failing and Muted checks
Needs AttentionFailing or degrading checks. If everything passed, it says All clear.
UpcomingWhen your checks and report run next
Activity (24h)The runs you just did. Click Refresh Now if they are missing.
ReportsThe report you created in Step 4

Overall Status and Needs Attention refresh every 60 seconds. The other panels update when you reload the page or change the CSI.

Known rough edges in this alpha build

You may run into these. We already know about them, so you don't need to report them. Do tell us if one blocks you.

  • Next stays greyed out without saying why. The usual cause is a missing required field, or a URL that doesn't start with https://.
  • Overall Status can say HEALTHY before any check has run. Pending checks aren't counted. Click Execute (Step 3) to get a real status.
  • Create Report may reopen with your last report filled in. If it does, clear the fields first, or you'll save a duplicate.
  • Save Report with no name saves an "Untitled Report". Enter the name first.
  • The Splunk prototype banner on Create Check isn't part of this tutorial.
