PUT Platform App Shell Layout Examples

Layout Pattern 1: Header Only (Home/Dashboard)
Use this pattern for the home page, landing pages, or modules that don't require local navigation. The header provides global navigation between modules.
// React Layout Implementation <div style={{ minHeight: '100vh', backgroundColor: '#F8FAFC' }}> <PlatformHeader currentModule={currentModule} onModuleChange={handleModuleChange} notifications={3} user={{ name: 'Bruno Buger', role: 'Senior Vice President' }} /> <main style={{ paddingTop: '64px' }}> <Outlet /> </main> </div>

Key Features:

  • Global Navigation: Header dropdown for switching between modules
  • Clean Layout: Full width content with minimal navigation overhead
  • Welcome Experience: Perfect for onboarding and overview pages
  • 64px Top Padding: Accounts for fixed header height
Layout Pattern 2: Header + Sidebar (Module Pages)
Use this pattern for complex modules that require local navigation within the module. The sidebar content is defined by the module but rendered by the Platform Shell.
// React Layout Implementation <div style={{ display: 'flex', height: '100vh' }}> <PlatformSidebar currentModule={currentModule} currentPage={currentPage} onPageChange={handlePageChange} isCollapsed={sidebarCollapsed} onToggleCollapse={handleToggleSidebar} /> <main style={{ flexGrow: 1, display: 'flex', flexDirection: 'column' }}> <PlatformHeader currentModule={currentModule} onModuleChange={handleModuleChange} notifications={3} user={{ name: 'Bruno Buger', role: 'Senior Vice President' }} /> <div style={{ flexGrow: 1 }}> <Outlet /> </div> </main> </div>

Key Features:

  • Local Navigation: Sidebar for navigating within the current module
  • Collapsible Sidebar: Can be collapsed to icon-only mode (280px → 64px)
  • Module Context: Sidebar content changes based on current module
  • Responsive Content: Main content adjusts when sidebar toggles
  • Full Height Layout: Uses 100vh for full viewport coverage
Module Navigation Configuration
Each module defines its own navigation structure that gets rendered by PlatformSidebar. This follows the micro-frontend principle where modules control their own navigation.
// Module Navigation Example const MODULE_NAVIGATION = { health: [ { id: 'dashboard', label: 'Health Dashboard', icon: DashboardIcon, path: '/health' }, { id: 'monitors', label: 'Monitors', icon: MonitorIcon, path: '/health/monitors' }, { id: 'alerts', label: 'Alerts', icon: AlertsIcon, path: '/health/alerts' }, { id: 'reports', label: 'Reports', icon: ReportsIcon, path: '/health/reports' }, { id: 'settings', label: 'Settings', icon: SettingsIcon, path: '/health/settings' } ], dns: [ { id: 'dashboard', label: 'DNS Dashboard', icon: DashboardIcon, path: '/dns' }, { id: 'domains', label: 'Domains', icon: DomainsIcon, path: '/dns/domains' }, { id: 'records', label: 'DNS Records', icon: RecordsIcon, path: '/dns/records' }, { id: 'zones', label: 'Zone Management', icon: ConfigIcon, path: '/dns/zones' } ] };

Navigation Structure:

  • Module-Specific: Each module defines its own pages and navigation
  • Icon Support: Material-UI icons for consistent visual design
  • Path Mapping: URLs for proper routing integration
  • Extensible: Easy to add new pages or modify existing ones
Component Props Reference
Complete prop interfaces for both PlatformHeader and PlatformSidebar components.
// PlatformHeader Props interface PlatformHeaderProps { currentModule?: string; // Currently active module ID onModuleChange?: (moduleId: string) => void; // Module switch handler notifications?: number; // Notification badge count user?: { // User information name: string; role: string; }; platformTitle?: string; // Platform title in header } // PlatformSidebar Props interface PlatformSidebarProps { currentModule?: string; // Currently active module ID currentPage?: string; // Currently active page within module onPageChange?: (pageId: string) => void; // Page navigation handler isCollapsed?: boolean; // Sidebar collapsed state onToggleCollapse?: () => void; // Collapse toggle handler }

Integration Notes:

  • State Management: Parent component manages all navigation state
  • Event Handlers: Callbacks for navigation changes
  • Responsive Design: Sidebar width automatically adjusts content
  • Material-UI: Built with Material-UI components for consistency
